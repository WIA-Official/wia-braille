제3장: WIA 난민 자격증명 표준 개요

홍익인간 (弘益人間)

"널리 인간을 이롭게 하라"

이 장에서는 WIA 난민 자격증명 아키텍처의 포괄적인 개요를 제공합니다. 기술 사양에 들어가기 전에 이 기초를 이해하는 것이 필수적입니다.

3.1 시스템 아키텍처

WIA 난민 자격증명 시스템은 분산 아키텍처를 따릅니다:

아키텍처 다이어그램 (텍스트)

+------------------+     +------------------+     +------------------+
|   자격증명       |     |   검증           |     |   신뢰 당사자    |
|   보유자         |---->|   네트워크       |---->|   (고용주)       |
|   (난민)         |     |   (WIA 노드)     |     |                  |
+------------------+     +------------------+     +------------------+
        |                        |                        |
        v                        v                        v
+------------------+     +------------------+     +------------------+
|   모바일 앱      |     |   동료 네트워크  |     |   HR 시스템      |
|   (자체 보관)    |     |   평가           |     |   대학           |
|                  |     |   문서 AI        |     |   정부           |
+------------------+     +------------------+     +------------------+

핵심 구성요소

구성요소 역할 기술
보유자 지갑 자격증명 자체 보관 모바일 앱, DID
검증 네트워크 검증 요청 처리 분산 노드
동료 레지스트리 검증을 위한 동료 매칭 암호화된 데이터베이스
평가 엔진 역량 테스트 적응형 테스트 플랫폼
문서 분석기 AI 문서 검증 ML 모델

3.2 데이터 모델 개요

자격증명 데이터 모델은 포괄적인 정보를 캡처합니다:

핵심 데이터 구조

RefugeeCredential
|
+-- metadata
|   +-- credentialId (UUID)
|   +-- version
|   +-- created / updated 타임스탬프
|   +-- status (active/revoked/suspended)
|
+-- holder
|   +-- 신원 정보
|   +-- 생체 바인딩
|   +-- DID 참조
|
+-- credentials[]
|   +-- 교육 기록
|   +-- 역량 기록
|   +-- 언어 능력
|   +-- 업무 경험
|
+-- verification
    +-- 현재 수준 (1-4)
    +-- 신뢰도 점수 (0-100%)
    +-- 증거 목록
    +-- 검증 이력

3.3 보유자 신원 구조

신원 정보는 프라이버시를 보호하면서 검증을 지원합니다:

HolderIdentity 필드

필드 타입 목적
did string 탈중앙화 식별자 (did:wia:...)
names object 다중 문자/번역의 이름
dateOfBirth date 매칭을 위한 생년월일
nationality string[] 국가 코드 (현재 및 이전)
biometricHash string 생체 템플릿의 해시
photo binary 신원 사진 (선택)

이름 처리

{
  "names": {
    "original": "아랍 문자로 된 아랍어 이름",
    "transliterations": {
      "en": "영어 음역",
      "fr": "프랑스어 음역",
      "de": "독일어 음역"
    },
    "preferred": "일상 사용을 위한 선호 이름"
  }
}

[i] 참고: 다중 음역은 철자 변형으로 인한 검증 실패를 방지합니다.

3.4 교육 기록

교육 기록은 검증 메타데이터와 함께 학력 자격증명을 캡처합니다:

EducationRecord 구조

필드 타입 설명
recordId UUID 이 기록의 고유 식별자
institution object 기관 세부정보 (이름, 위치, 유형)
credential object 학위/인증서 세부정보
fieldOfStudy string ISCED 분류 코드
startDate date 입학일
endDate date 졸업/완료일
verification object 검증 수준 및 증거

기관 객체

{
  "institution": {
    "name": {
      "original": "원어로 된 대학 이름",
      "english": "영어로 된 대학 이름"
    },
    "country": "SY",
    "city": "Damascus",
    "type": "university",
    "status": "destroyed" | "operational" | "unknown",
    "wiaId": "inst:sy:dam:univ:001"
  }
}

3.5 역량 기록

역량 기록은 공식 자격증명과 독립적으로 검증된 기술을 캡처합니다:

CompetencyRecord 구조

필드 타입 설명
recordId UUID 고유 식별자
domain string ESCO 직업 코드
skillName string 특정 기술 이름
proficiencyLevel 1-5 EQF 정렬 수준
assessmentType string 기술 평가 방법
assessmentDate date 평가 시점
assessorId string 평가 수행자
confidence 0-100 신뢰도 백분율

숙련도 수준

수준 1: 기초
  - 기본 인식
  - 감독하에 수행 가능

수준 2: 중급
  - 실무 지식
  - 일상적 상황에서 독립적으로 수행 가능

수준 3: 고급
  - 깊은 이해
  - 복잡한 상황 처리 가능

수준 4: 전문가
  - 포괄적 숙달
  - 다른 사람을 가르칠 수 있음, 예외 사례 처리

수준 5: 마스터
  - 인정받는 권위
  - 혁신하고 분야를 이끌 수 있음

3.6 업무 경험

업무 경험 기록은 고용 이력을 캡처합니다:

WorkExperience 구조

필드 타입 설명
recordId UUID 고유 식별자
employer object 조직 세부정보
jobTitle string 역할 직책
escoCode string ESCO 직업 분류
startDate date 고용 시작
endDate date 고용 종료 (현재면 null)
responsibilities string[] 주요 책임
verification object 검증 세부정보

3.7 검증 수준

4개의 검증 수준은 점진적 신뢰를 제공합니다:

수준 1: 자기 선언 (30% 신뢰도)

요구사항:
- 보유자가 자격증명 주장 생성
- 기본 신원 확인 (사진, 이름)
- 외부 검증 불필요

사용 사례:
- 초기 등록
- 초급 고용
- 자원봉사 직위
- 추가 교육 지원

수준 2: 동료 검증 (60% 신뢰도)

요구사항:
- 최소 2명의 검증된 동료가 주장 확인
- 동료는 기관에서 겹치는 시간이 있어야 함
- 블라인드 검증 (동료가 서로의 답변을 볼 수 없음)

사용 사례:
- 숙련 고용
- 대학 입학
- 전문 훈련 프로그램

수준 3: 평가 기반 (80% 신뢰도)

요구사항:
- 도메인별 역량 평가 통과
- 인증된 제공자가 평가 관리
- 해당되는 경우 실기 시연

사용 사례:
- 감독하 전문직 진료
- 전문 훈련 프로그램
- 정부 직위

수준 4: 문서 검증 (95% 신뢰도)

요구사항:
- 원본 문서 인증
- AI 검증 + 인간 검토
- 가용한 기록과 교차 참조

사용 사례:
- 완전한 전문직 인정
- 고위 직위
- 교육/멘토링 역할

3.8 신뢰도 점수

신뢰도는 여러 요소를 사용하여 계산됩니다:

신뢰도 공식

기본 신뢰도 = 수준 기본 점수
  수준 1: 30%
  수준 2: 60%
  수준 3: 80%
  수준 4: 95%

보너스:
  + 다중 동료 검증: 추가 동료당 +5% (최대 +15%)
  + 높은 평가 점수: +5-10%
  + 소스 간 일관된 정보: +10%
  + 디지털 증거 (출판물 등): +5%

페널티:
  - 충돌하는 정보: 충돌당 -10%
  - 오래된 검증: 연간 -1%
  - 불완전한 정보: -5%

최종 신뢰도 = 기본 + 보너스 - 페널티
  (99%에서 상한선 - 100%는 절대 없음)

계산 예시

아흐마드 박사 - 의료 자격증명

기본 (수준 2 - 동료 검증): 60%
+ 3명의 동료 검증 (1명 추가): +5%
+ 동료 간 일관된 날짜: +10%
+ 온라인에서 발견된 출판 연구: +5%
- 검증 2년 경과: -2%

최종 신뢰도: 78%

[OK] 감독하 의료 진료 자격

3.9 증거 유형

다양한 증거 유형이 검증에 기여합니다:

증거 유형 가중치 예시
동료 증언 높음 전직 동료가 고용 확인
평가 결과 높음 의료 역량 시험 통과
문서 스캔 매우 높음 인증된 졸업장 사본
디지털 발자국 중간 LinkedIn 프로필, 출판물
기관 기록 매우 높음 대학 데이터베이스 쿼리
포트폴리오 중간 작업 샘플, 프로젝트 문서

3.10 보안 및 프라이버시

프라이버시 보호

  • 자체 보관 - 보유자가 자신의 데이터 통제
  • 선택적 공개 - 필요한 것만 공유
  • 영지식 증명 - 세부사항 공개 없이 검증
  • 암호화 - 모든 데이터가 저장 시 및 전송 중 암호화

보안 기능

기능 구현
인증 생체 바인딩이 있는 DID 기반
암호화 AES-256 (데이터), CRYSTALS-Kyber (전송)
서명 CRYSTALS-Dilithium (양자 내성)
감사 추적 불변 검증 이력
