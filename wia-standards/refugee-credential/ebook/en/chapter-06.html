Chapter 6: Phase 3 - Communication Protocol

Hongik Ingan

"Benefit all humanity"

Communication protocols enable seamless credential exchange between systems worldwide. This chapter specifies the APIs, endpoints, and security requirements for interoperable implementation.

6.1 REST API Overview

The primary API uses REST principles with JSON payloads:

Base URL Structure

Production: https://api.wia.live/refugee-credential/v1
Staging:    https://staging-api.wia.live/refugee-credential/v1

Common Headers

Required Headers:
  Authorization: Bearer {jwt_token}
  Content-Type: application/json
  Accept: application/json
  X-WIA-Version: 2025-01

Optional Headers:
  Accept-Language: ar,en;q=0.9  (for localized responses)
  X-Request-ID: {uuid}          (for tracing)
  X-Idempotency-Key: {key}      (for safe retries)

Authentication

Authentication Methods:

1. JWT Bearer Token (recommended)
   - Obtained via OAuth 2.0 flow
   - Contains DID and permissions
   - Short-lived (15 minutes)

2. DID Authentication
   - For holder self-custody operations
   - Challenge-response with DID signature

3. API Key (legacy)
   - For server-to-server integration
   - Rate limited

6.6 Storage Protocol

Storage Architecture

Storage Tiers:

Tier 1: Hot Storage (Active Credentials)
  - Location: Distributed cloud storage
  - Latency: <100ms read
  - Retention: Unlimited while active

Tier 2: Warm Storage (Inactive Credentials)
  - Location: Regional data centers
  - Latency: <1s read
  - Retention: 7 years

Tier 3: Cold Storage (Archived)
  - Location: Secure archive
  - Latency: <1 hour retrieval
  - Retention: 25 years minimum

IPFS Integration

POST /storage/ipfs/pin

Request Body:
{
  "credentialId": "550e8400-...",
  "includeEvidence": true
}

Response (200 OK):
{
  "ipfsCid": "Qm...",
  "pinned": true,
  "redundancy": 3,

    "ipfs://Qm.../credential.json",
    "https://ipfs.wia.live/ipfs/Qm..."
  ]
}

6.7 Error Handling

Error Response Format

{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Invalid education record",
    "details": [
      {
        "field": "education[0].endDate",
        "issue": "End date before start date"
      }
    ],
    "requestId": "req-123...",
    "timestamp": "2025-01-15T10:30:00Z"
  }
}

Error Codes

HTTP Code Description
400 VALIDATION_ERROR Invalid request data
401 AUTHENTICATION_REQUIRED Missing or invalid token
403 PERMISSION_DENIED Insufficient permissions
404 NOT_FOUND Resource not found
409 CONFLICT Resource state conflict
429 RATE_LIMITED Too many requests
500 INTERNAL_ERROR Server error
503 SERVICE_UNAVAILABLE Temporary unavailability

6.10 Security Requirements

Transport Security

  • TLS 1.3 required for all connections
  • Certificate pinning recommended for mobile apps
  • HSTS enforced with 1 year max-age

Authentication Security

  • JWT tokens must use RS256 or ES256
  • Token lifetime maximum 15 minutes
  • Refresh tokens with secure rotation

Data Security

  • Encryption at rest using AES-256
  • Field-level encryption for sensitive data
  • Audit logging for all access
