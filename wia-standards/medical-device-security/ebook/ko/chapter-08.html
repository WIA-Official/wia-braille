레거시 의료기기의 현실

많은 병원이 10년, 심지어 20년 이상 된 의료기기를 여전히 사용하고 있습니다. 이러한 레거시 기기는 높은 구매 비용, 긴 감가상각 주기, 규제 승인의 복잡성 때문에 쉽게 교체하기 어렵습니다. 그러나 이들은 심각한 보안 위험을 초래합니다.

레거시 의료기기의 정의

  • 제조업체 지원 종료 (EoL, End of Life): 더 이상 소프트웨어 업데이트나 보안 패치를 제공하지 않음
  • 구형 운영체제: Windows XP, Windows 7, 임베디드 Linux 2.x 등
  • 오래된 프로토콜: 암호화 없는 통신, 취약한 인증
  • 알려진 취약점: CVE 데이터베이스에 공개된 취약점 보유, 패치 불가

레거시 기기의 보안 위험

레거시 의료기기는 여러 면에서 조직을 위험에 빠뜨립니다.

1. 패치 불가능한 취약점

가장 큰 문제는 알려진 취약점이 있어도 패치할 수 없다는 것입니다.

실제 사례: 한 대학병원의 2008년산 X-ray 시스템은 Windows XP를 실행하고 있었습니다. Microsoft가 2014년에 XP 지원을 중단한 이후, 수백 개의 보안 취약점이 발견되었지만 시스템을 업데이트할 수 없었습니다. 제조업체는 "OS 업그레이드 시 FDA 승인이 필요하며, 재인증 비용이 신규 기기 구매와 유사하다"고 답변했습니다.

2. 약한 인증 및 암호화

레거시 기기는 현대적 보안 표준을 지원하지 않습니다:

보안 기능 현대 기준 레거시 현실
인증 802.1X, 인증서 기반 기본 비밀번호 또는 인증 없음
암호화 TLS 1.3, AES-256 평문 전송 또는 DES/3DES
무선 보안 WPA3-Enterprise WEP 또는 WPA (취약)
로깅 상세한 감사 로그 로깅 없음 또는 최소

3. 하드코딩된 자격 증명

많은 레거시 기기는 변경 불가능한 관리자 계정을 가지고 있습니다:

  • 제조업체가 모든 기기에 동일한 비밀번호 설정
  • 사용자 매뉴얼이나 온라인에 비밀번호 공개
  • 비밀번호 변경 기능 없음
  • 백도어 계정 존재 (서비스 목적)

위험 평가 프레임워크

모든 레거시 기기의 위험을 평가하여 우선순위를 정해야 합니다.

레거시 기기 위험 평가 매트릭스
위험 점수 = (환자 영향 × 침해 가능성) + 데이터 민감도

1. 환자 영향 (1-5점)
   5 = 생명 유지 장치 (인공호흡기, 투석기)
   4 = 치료 장비 (수술 로봇, 방사선 치료기)
   3 = 진단 장비 (MRI, CT, 초음파)
   2 = 모니터링 (환자 모니터, 텔레메트리)
   1 = 지원 장비 (프린터, 디스플레이)

2. 침해 가능성 (1-5점)
   5 = 인터넷 연결, 알려진 취약점 다수
   4 = 내부 네트워크 연결, 패치 불가
   3 = 격리된 네트워크, 일부 취약점
   2 = 물리적 격리, 무선 기능 없음
   1 = 독립 실행 (네트워크 미연결)

3. 데이터 민감도 (0-3점)
   3 = PHI 저장/전송 (EMR 연동)
   2 = 환자 식별 정보 포함
   1 = 익명화된 데이터만
   0 = 환자 데이터 없음

예시 계산:
기기 A (Windows XP MRI 스캐너):
  환자 영향: 3
  침해 가능성: 4 (네트워크 연결, 패치 불가)
  데이터 민감도: 3 (환자 영상 + 정보)
  위험 점수: (3 × 4) + 3 = 15점 (높음)

기기 B (독립 실행 혈압계):
  환자 영향: 2
  침해 가능성: 1 (네트워크 미연결)
  데이터 민감도: 0
  위험 점수: (2 × 1) + 0 = 2점 (낮음)

위험 등급:
  20-25점: 위급 (즉시 조치)
  15-19점: 높음 (3개월 내)
  10-14점: 중간 (6개월 내)
  5-9점: 낮음 (1년 내)
  0-4점: 최소 (모니터링만)

보상 제어 (Compensating Controls)

레거시 기기를 즉시 교체할 수 없다면, 보상 제어로 위험을 완화해야 합니다.

1. 네트워크 레벨 보호

A. 극도로 제한적인 VLAN

레거시 VLAN 방화벽 정책
VLAN 99 - Legacy Medical Devices (격리 네트워크)

허용된 트래픽 (화이트리스트):
  → EMR 서버 (10.30.31.10)     포트 TCP 443 (HTTPS만)
  → DICOM PACS (10.20.5.20)    포트 TCP 104 (DICOM)
  → NTP 서버 (10.100.1.5)      포트 UDP 123 (시간 동기화)

거부된 트래픽 (블랙리스트):
  ✗ 인터넷 (any)                전체 차단
  ✗ 다른 레거시 기기 간 통신     상호 격리
  ✗ 업무용 네트워크             접근 불가
  ✗ 환자 Wi-Fi                  격리
  ✗ SMB/CIFS (포트 445)         랜섬웨어 확산 방지
  ✗ RDP (포트 3389)             무단 원격 접속 방지

예외: 관리자 점프박스 (10.100.10.5)만 제한적 접근 허용
  • 다중 인증 (MFA) 필수
  • 세션 녹화
  • 시간 제한 (업무 시간만)
  • 모든 활동 감사 로그

B. 가상 패치 (Virtual Patching)

IPS (Intrusion Prevention System)를 사용하여 알려진 익스플로잇을 차단:

  • 서명 기반 차단: WannaCry, EternalBlue 등 알려진 공격 패턴
  • 프로토콜 이상 탐지: 비정상적인 SMB, RDP 트래픽
  • 지리적 차단: 해외 IP에서의 접근 시도
  • 속도 제한: 과도한 연결 시도 차단 (브루트 포스 방지)

2. 애플리케이션 화이트리스팅

레거시 기기에서 승인된 프로그램만 실행되도록 제한:

화이트리스팅 구현:
  • AppLocker (Windows): Group Policy로 실행 가능한 exe, dll, 스크립트 정의
  • SELinux (Linux): 강제 접근 제어로 프로세스 격리
  • 디지털 서명 검증: 제조업체 서명된 파일만 실행
  • 경로 제한: C:\Program Files\Vendor\ 내 파일만 허용
  • 블록 모드: 화이트리스트에 없는 모든 것 차단 (경고가 아님)

3. 물리적 보안 강화

레거시 기기가 있는 구역의 물리적 접근을 제한:

  • 출입 통제: 카드키, 생체인증으로 방 접근 제한
  • CCTV 모니터링: 24/7 비디오 감시
  • USB 포트 물리적 차단: 에폭시 접착제로 포트 봉인
  • 화면 프라이버시 필터: 어깨 너머 훔쳐보기 방지
  • 자산 태그: 기기 이동 시 알림

4. 행위 기반 모니터링

레거시 기기의 정상 행동을 학습하고 이상을 탐지:

모니터링 대상 정상 기준선 이상 징후 대응
네트워크 트래픽 평일 8-18시, 평균 5MB/h 야간 100MB/h 전송 자동 격리
접속 패턴 EMR 서버만 접속 외부 IP 접속 시도 방화벽 차단
프로세스 실행 승인된 10개 프로세스 새로운 exe 실행 프로세스 종료
파일 변경 시스템 파일 읽기만 파일 암호화 시도 즉시 알림

5. 읽기 전용 모드

가능하다면 레거시 기기를 읽기 전용 모드로 전환:

  • 쓰기 보호 USB: 펌웨어를 읽기 전용 미디어에 저장
  • 불변 파일 시스템: 재부팅 시 모든 변경 사항 삭제
  • Deep Freeze: 시스템 상태를 고정하고 재부팅 시 복원

교체 전략

장기적으로는 레거시 기기를 교체하는 것이 유일한 해결책입니다.

교체 우선순위 결정

교체 우선순위 점수
교체 우선순위 = (위험 점수 × 2) + 비즈니스 영향 - 교체 난이도

비즈니스 영향 (0-10점):
  10 = 사용 빈도 매우 높음, 대체 불가
  7-9 = 중요한 진단/치료 기능
  4-6 = 보조적 역할
  1-3 = 드물게 사용
  0 = 사용 안 함 (즉시 폐기)

교체 난이도 (0-10점):
  10 = 커스텀 제작, 제조업체 폐업
  7-9 = 고가 ($1M+), 긴 조달 기간
  4-6 = 표준 장비, 수개월 소요
  1-3 = 쉽게 구매 가능
  0 = 재고 보유

예시:
기기: Windows XP 방사선 치료기
  위험 점수: 18
  비즈니스 영향: 9 (암 치료 필수)
  교체 난이도: 8 (고가, 복잡)
  우선순위: (18 × 2) + 9 - 8 = 37점 ← 높은 우선순위

교체 우선순위:
  40+ 점: 즉시 (6개월 내)
  30-39점: 높음 (1년 내)
  20-29점: 중간 (2년 내)
  10-19점: 낮음 (3년 이상)
  <10점: 유지 또는 폐기

단계적 교체 로드맵

  • Phase 1 (Year 1): 위급 기기 교체 (40+ 점)
  • Phase 2 (Year 2-3): 높은 위험 기기 (30-39점)
  • Phase 3 (Year 4-5): 중간 위험 기기 (20-29점)
  • Phase 4 (Year 6+): 낮은 위험 기기 또는 계속 보상 제어

폐기 프로세스

레거시 기기를 교체할 때는 안전하게 폐기해야 합니다.

의료기기 폐기 체크리스트
☐ 1. 데이터 백업 (필요 시)
   - 환자 데이터를 규제 요구사항에 따라 보관
   - 최소 7년 (HIPAA) 또는 주 법률에 따라

☐ 2. 데이터 완전 삭제
   - 소프트웨어 삭제만으로는 불충분
   - 하드 드라이브: DoD 5220.22-M (7회 덮어쓰기) 또는 물리적 파괴
   - SSD: ATA Secure Erase 또는 암호화 키 삭제
   - 메모리 카드, USB: 물리적 파괴
   - ROM/EPROM: 칩 제거 및 파괴

☐ 3. 네트워크 해제
   - DHCP 예약 삭제
   - DNS 레코드 제거
   - 방화벽 규칙 정리
   - 인증서 폐기
   - NAC 화이트리스트에서 제거

☐ 4. 자산 관리 업데이트
   - CMDB에서 상태 변경 (Active → Decommissioned)
   - 라이선스 반환 (가능한 경우)
   - 보험 목록에서 제거
   - 감가상각 마감

☐ 5. 물리적 폐기
   - 인증된 ITAD (IT Asset Disposition) 업체 사용
   - NAID AAA 인증 (데이터 파괴)
   - 파괴 증명서 (Certificate of Destruction) 수령
   - 환경 규제 준수 (전자 폐기물)

☐ 6. 문서화
   - 폐기 날짜, 방법, 담당자 기록
   - 데이터 파괴 증거 보관 (감사 대비)
   - 교체 기기와 연결 (자산 추적)

제조업체와의 협력

레거시 기기 제조업체와 협력하여 보안을 개선할 수 있습니다.

제조업체 협상 포인트:
  • 연장 지원 계약: EoL 기기에 대한 보안 패치 연장 (유료)
  • 보안 강화 가이드: 추천 네트워크 구성 및 설정
  • 교체 할인: 신규 기기 구매 시 레거시 기기 반납 인센티브
  • 펌웨어 업그레이드 경로: 하드웨어 교체 없이 소프트웨어만 업그레이드
  • CVD 프로그램: 취약점 발견 시 책임감 있는 보고 채널

규제 고려사항

레거시 기기 관리는 규제 준수 문제도 포함합니다.

  • HIPAA Security Rule: "합리적이고 적절한" 보안 조치 요구 - 보상 제어로 입증
  • FDA 지침: 레거시 기기도 시판 후 사이버 보안 관리 대상
  • Joint Commission: 의료기기 인벤토리 및 위험 평가 요구
  • 사이버 보험: 레거시 기기 비율이 높으면 보험료 증가 또는 거부

결론

레거시 의료기기는 현대 병원의 불가피한 현실입니다. 즉시 교체하기 어렵다면, 네트워크 분할, 가상 패치, 화이트리스팅, 행위 모니터링 등 보상 제어로 위험을 완화해야 합니다.

위험 평가를 통해 가장 위험한 기기를 식별하고, 단계적 교체 계획을 수립하며, 제조업체와 협력하여 보안을 강화해야 합니다. 레거시 기기를 폐기할 때는 환자 데이터를 완전히 삭제하고 규제 요구사항을 준수해야 합니다.

궁극적으로, 레거시 기기 문제는 기술적 해결책만으로는 부족하며, 경영진의 지원, 예산 확보, 그리고 환자 안전에 대한 조직 전체의 헌신이 필요합니다.

전자책 마무리

이것으로 WIA 의료기기 보안 표준의 8개 장을 모두 완료했습니다. FDA 사이버 보안 지침부터 레거시 장비 보호까지, 의료기기 보안의 전 영역을 다루었습니다.

이 지식을 실무에 적용하여 환자 안전을 보호하고, 의료 시스템의 무결성을 유지하며, 사이버 위협으로부터 조직을 방어하시기 바랍니다.
