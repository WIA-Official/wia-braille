Chapter 6: Data Privacy and Security

"弘益人間: Protecting pet location data protects families—privacy and security are not optional, but fundamental rights."

6.1 Privacy Principles

Pet tracking systems collect highly sensitive location data about pets and, by extension, their owners and homes. The WIA-PET-TRACKING standard establishes strict privacy principles that all implementations MUST follow.

Core Privacy Principles

Principle Description Implementation Requirement
Data Minimization Collect only necessary data No collection beyond location, timestamp, device metadata
Purpose Limitation Use data only for stated purposes No use for advertising, marketing without explicit consent
Transparency Clear disclosure of data practices Publicly accessible privacy policy, easy to understand
User Control Users control their data Export, delete, and pause tracking features required
Security Protect data from unauthorized access Encryption in transit and at rest (see 6.2)
Data Retention Keep data only as long as necessary Default 90-day retention, user-configurable
Accountability Responsible for data protection Regular security audits, breach notification

Privacy-by-Design Architecture

PRIVACY-PRESERVING ARCHITECTURE
================================

Edge Processing (on device):
  ✓ Motion detection on-device (accelerometer)
  ✓ Basic geofence checks locally when possible
  ✓ Minimize cloud transmissions
  ✓ Local caching reduces data sent

Data Transmission:
  ✓ TLS 1.3 encryption for all API calls
  ✓ Certificate pinning to prevent MITM
  ✓ Minimal payload (no extraneous data)
  ✓ Batch uploads when appropriate

Cloud Storage:
  ✓ AES-256 encryption at rest
  ✓ Separate encryption keys per user
  ✓ Key management via HSM or KMS
  ✓ Database-level encryption

Data Access:
  ✓ Role-based access control (RBAC)
  ✓ Audit logging of all access
  ✓ Multi-factor authentication required
  ✓ Principle of least privilege

Data Deletion:
  ✓ Immediate soft delete on user request
  ✓ Hard delete within 30 days
  ✓ Backup purge within 90 days
  ✓ Cryptographic erasure (delete keys)

GDPR and Privacy Law Compliance

The standard is designed to comply with major privacy regulations:

Regulation Jurisdiction Key Requirements WIA-PET-TRACKING Compliance
GDPR European Union Consent, right to erasure, data portability ✓ Explicit consent, export/delete APIs, data minimization
CCPA/CPRA California, USA Data disclosure, opt-out, access rights ✓ Privacy policy, data control features, access APIs

6.2 Security Architecture

Robust security prevents unauthorized access to pet location data and protects against various attack vectors.

Authentication and Authorization

AUTHENTICATION FLOW
===================

1. User Registration:
   POST /api/v1/auth/register
   {
     "email": "owner@example.com",
     "password": "secure_password_hash",
     "mfa": {
       "method": "totp",
       "deviceId": "MFA-DEVICE-123"
     }
   }

   Response:
   {
     "userId": "USER-123456",
     "verificationRequired": true,
     "verificationMethod": "email"
   }

2. Email Verification:
   User clicks link in email
   → Account activated

3. Login:
   POST /api/v1/auth/login
   {
     "email": "owner@example.com",
     "password": "secure_password_hash"
   }

   Response:
   {
     "mfaRequired": true,
     "mfaChallenge": "TOTP-CHALLENGE"
   }

4. MFA Verification:
   POST /api/v1/auth/mfa-verify
   {
     "userId": "USER-123456",
     "code": "123456"
   }

   Response:
   {
     "accessToken": "eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9...",
     "refreshToken": "refresh_token_here",
     "expiresIn": 3600
   }

5. API Request (authenticated):
   GET /api/v1/tracking/location
   Headers:
     Authorization: Bearer {accessToken}

TOKEN SECURITY
==============

Access Token:
  - Format: JWT (RS256 signed)
  - Expiration: 1 hour
  - Payload: userId, permissions, deviceId
  - Verified on every API call

Refresh Token:
  - Opaque token, stored in secure database
  - Expiration: 30 days
  - Single-use (rotated on refresh)
  - Revocable by user or admin

Device Binding:
  - Tokens bound to specific device IDs
  - Prevents token theft cross-device
  - User can revoke device access

AUTHORIZATION (RBAC)
====================

Roles:
  - Owner: Full control of own pets/trackers
  - Shared User: View-only or limited control
  - Admin: System administration
  - Support: Limited access for troubleshooting

Permissions:
  - tracking:read:own
  - tracking:write:own
  - tracking:delete:own
  - geofence:manage:own
  - device:configure:own
  - data:export:own
  - data:delete:own

Access Control Check:
  IF user.role includes required permission:
    ALLOW access
  ELSE:
    DENY (HTTP 403 Forbidden)

Data Encryption

Layer Method Key Length Rotation
Transport (HTTPS) TLS 1.3 2048-bit RSA or 256-bit ECC Cert renewal annually
Database (at rest) AES-256-GCM 256-bit 90 days
Backups AES-256-GCM 256-bit Per backup
File Storage AES-256-GCM 256-bit 90 days
Device-Cloud TLS 1.3 + Application-level 256-bit symmetric Per session

Threat Modeling

THREAT ANALYSIS
===============

Threat 1: Unauthorized Location Access
  Risk Level: CRITICAL
  Attack Vector: Stolen credentials, API abuse
  Mitigation:
    - Multi-factor authentication (required)
    - Rate limiting on location queries
    - Anomaly detection (unusual access patterns)
    - IP allowlisting (optional)

Threat 2: Man-in-the-Middle (MITM)
  Risk Level: HIGH
  Attack Vector: Network interception
  Mitigation:
    - TLS 1.3 with certificate pinning
    - HSTS (HTTP Strict Transport Security)
    - No fallback to HTTP
    - Mutual TLS for device-server communication

Threat 3: Data Breach (Server Compromise)
  Risk Level: CRITICAL
  Attack Vector: Server hacking, insider threat
  Mitigation:
    - Encryption at rest (keys in HSM/KMS)
    - Database access controls
    - Audit logging
    - Regular security audits
    - Incident response plan

Threat 4: Physical Device Theft
  Risk Level: MEDIUM
  Attack Vector: Stolen tracker or phone
  Mitigation:
    - Device-specific credentials
    - Remote device deactivation
    - No sensitive data stored on device
    - Tamper detection

Threat 5: Social Engineering
  Risk Level: MEDIUM
  Attack Vector: Phishing, pretexting
  Mitigation:
    - User security awareness
    - Multi-factor authentication
    - No phone/email account recovery
    - Verified support channels only

Threat 6: Denial of Service (DoS)
  Risk Level: MEDIUM
  Attack Vector: API flooding, network attacks
  Mitigation:
    - Rate limiting (per user, per IP)
    - CDN and DDoS protection
    - Autoscaling infrastructure
    - Graceful degradation

Threat 7: GPS Spoofing
  Risk Level: LOW-MEDIUM
  Attack Vector: Fake GPS signals
  Mitigation:
    - Multi-GNSS cross-validation
    - Plausibility checking (speed, distance)
    - Cellular/Wi-Fi verification
    - Anomaly detection algorithms

6.3 Data Sharing and Consent

Pet owners may need to share tracking data with family members, pet sitters, or veterinarians. The standard defines granular sharing controls.

Sharing Permission Levels

Permission Level Capabilities Use Case
View Only See current location and history Family members, friends
View + Alerts View + receive geofence alerts Co-owners, frequent caretakers
View + Control View + configure geofences, settings Primary caretakers, pet sitters
Full Access All capabilities except delete account Co-owners, trusted family
Temporary Link Time-limited view-only access via link Dog walkers, emergency contacts
Emergency Only Access only when lost pet mode activated Emergency contacts, rescue volunteers

Data Sharing API

6.4 Data Retention and Deletion

Users must be able to control how long their data is retained and completely delete it when desired.

Retention Policies

Data Type Default Retention User-Configurable Legal Minimum
Location History 90 days 7 days - 365 days None
Geofence Events 180 days 30 days - 730 days None
Lost Pet Reports 365 days 90 days - Indefinite None
Account Information Until deleted Delete anytime Billing: 7 years
Audit Logs 365 days Not configurable 365 days (security)
Anonymized Analytics Indefinite Opt-out available None

Data Deletion Process

USER-INITIATED DELETION
=======================

Step 1: Request Deletion
  POST /api/v1/data/delete-request
  {
    "scope": "all",
    "confirmDeletion": true,
    "keepAnonymizedData": false
  }

Step 2: Verification
  - Email sent with confirmation link
  - 24-hour grace period before deletion starts

Step 3: Soft Delete (Day 1)
  - Data marked as deleted
  - Inaccessible to user and APIs
  - Account deactivated
  - Billing stopped

Step 4: Hard Delete (Days 1-30)
  - Production databases purged
  - Search indexes cleared
  - File storage deleted
  - Shared data access revoked

Step 5: Backup Purge (Days 30-90)
  - Backup systems purged
  - Archive storage cleared
  - Encryption keys deleted

Step 6: Completion (Day 90)
  - Final confirmation email
  - Certificate of deletion (optional)
  - Audit trail retained (pseudonymized)

RIGHT TO BE FORGOTTEN (GDPR)
=============================

Users can request complete data deletion:
  1. Submit deletion request
  2. Verify identity
  3. Receive confirmation of deletion
  4. Data fully removed within 90 days
  5. Exceptions: Legal obligations, anonymized analytics

6.5 Anonymization and Analytics

Anonymized data can provide valuable insights for improving pet safety without compromising privacy.

Anonymization Techniques

ANONYMIZATION PROCESS
=====================

Original Data:
{
  "userId": "USER-123456",
  "petId": "PET-789XYZ",
  "petName": "Buddy",
  "location": {
    "latitude": 37.774929,
    "longitude": -122.419418,
    "timestamp": "2025-12-25T10:30:00Z"
  }
}

Anonymized Data:
{
  "anonymousId": "hash(USER-123456 + salt)",
  "petSpecies": "dog",
  "petBreedCategory": "large_retriever",
  "locationGridId": "grid_sf_downtown_sector_42",
  "timestamp": "2025-12-25T10:00:00Z",
  "geohash": "9q8yy"
}

Anonymization Steps:
1. Remove PII:
   - User names, emails, phone numbers
   - Pet names
   - Exact addresses

2. Reduce Precision:
   - GPS coordinates → grid sectors (500m×500m)
   - Timestamps → hour precision
   - Ages → age ranges (0-2, 3-5, 6-10, 11+)

3. Generalize Categories:
   - Specific breeds → breed categories
   - Exact weights → weight ranges

4. Add Noise:
   - K-anonymity: Ensure at least K records match
   - Differential privacy: Add statistical noise

5. Remove Linkability:
   - Prevent re-identification by cross-referencing
   - Aggregate data when possible

PERMITTED ANALYTICS
===================

✓ Lost pet recovery statistics (anonymized)
✓ Popular pet park locations (aggregate)
✓ Typical pet movement patterns (generalized)
✓ Geofence effectiveness metrics (aggregate)
✓ Battery life statistics (device model level)
✓ Network coverage quality (grid level)

✗ Individual pet tracking patterns
✗ Specific household locations
✗ Personally identifiable behavior
✗ Data sold to third parties
✗ Advertising profiles

6.6 Security Best Practices

Guidelines for implementers to maintain robust security:

Development Security

  • Secure Coding: Follow OWASP Top 10, use security linters, code review
  • Dependency Management: Regular updates, vulnerability scanning, SBOM
  • Secrets Management: Never hardcode credentials, use vaults (HashiCorp, AWS Secrets Manager)
  • Input Validation: Validate and sanitize all inputs, prevent injection attacks
  • Testing: Security unit tests, penetration testing, fuzzing

Operational Security

  • Infrastructure: Hardened servers, security patches, network segmentation
  • Monitoring: Real-time security monitoring, SIEM, intrusion detection
  • Incident Response: Documented plan, breach notification procedures, forensics
  • Access Control: Principle of least privilege, regular access reviews, MFA required
  • Backups: Encrypted, tested regularly, offline copies, ransomware protection

User Security Education

USER SECURITY RECOMMENDATIONS
==============================

Strong Passwords:
  - Minimum 12 characters
  - Mix of upper, lower, numbers, symbols
  - Unique per service (use password manager)
  - Never share passwords

Multi-Factor Authentication:
  - Always enable MFA
  - Use authenticator app (not SMS when possible)
  - Keep backup codes secure

Device Security:
  - Keep phone/computer OS updated
  - Use screen lock (PIN, biometric)
  - Enable "Find My Device" features
  - Don't jailbreak/root devices

Public Networks:
  - Avoid tracking on public Wi-Fi
  - Use VPN if necessary
  - Verify HTTPS connection

Suspicious Activity:
  - Report unknown logins immediately
  - Review audit logs regularly
  - Revoke unused shared access
  - Monitor for unusual pet locations

Chapter Summary

Key Takeaways:

  1. Privacy by Design: Privacy must be built into the system architecture from the start, not added later—encryption, data minimization, and user control are fundamental.
  2. Layered Security: Multiple security layers (authentication, authorization, encryption, monitoring) provide defense in depth against various attack vectors.
  3. User Control: Users must have granular control over their data: who can access it, how long it's retained, and the ability to export or delete it completely.
  4. Compliance: Adherence to privacy regulations (GDPR, CCPA) is not optional—the standard provides mechanisms to comply with major privacy laws.
  5. Transparency: Clear privacy policies, audit trails, and user notifications build trust and enable informed decision-making about data sharing.
