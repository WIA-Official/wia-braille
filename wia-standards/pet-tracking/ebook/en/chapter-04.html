4.1 Geofencing Fundamentals

A geofence is a virtual geographic boundary defined by GPS coordinates. When a pet tracker crosses this boundary, the system triggers predefined actions such as sending alerts to the owner. Geofencing is one of the most valuable features of modern pet tracking systems.

Geofence Types

Type Shape Use Case Complexity
Circular Center point + radius Home, park, general areas Low
Rectangular Bounding box (lat/lng min/max) City blocks, yards Low
Polygonal Series of coordinate points Property lines, complex areas Medium
Corridor Line + buffer distance Walking routes, trails Medium
Multi-Zone Multiple connected areas Home + backyard + park High

4.2 Geofence Detection Algorithms

Accurate and efficient geofence detection is critical for minimizing false alerts while ensuring real boundary crossings are caught.

Point-in-Circle Algorithm

For circular geofences, detection is straightforward using distance calculation:

CIRCULAR GEOFENCE DETECTION
============================

Given:
  Geofence center: (centerLat, centerLng)
  Geofence radius: R meters
  Pet location: (petLat, petLng)
  Location accuracy: A meters

Calculate:
  distance = haversine(centerLat, centerLng, petLat, petLng)

Determine State:
  IF distance + A < R:
    INSIDE (definitely inside fence)
  ELSE IF distance - A > R:
    OUTSIDE (definitely outside fence)
  ELSE:
    UNCERTAIN (within accuracy margin)

Handling Uncertainty:
  - Maintain previous state if uncertain
  - Only trigger alert on definite crossing
  - Require multiple consecutive readings for confirmation

Example:
  Center: 37.7749, -122.4194
  Radius: 100m
  Pet: 37.7760, -122.4195
  Accuracy: ±8.5m

  distance = 122.4m
  122.4 - 8.5 = 113.9m > 100m → OUTSIDE ✓

  Alert: "Pet has exited Home zone"

Point-in-Polygon Algorithm

For complex polygonal geofences, use the ray casting algorithm:

RAY CASTING ALGORITHM
=====================

Given polygon vertices: [(lat1,lng1), (lat2,lng2), ..., (latN,lngN)]
Point to test: (testLat, testLng)

Algorithm:
1. Cast a ray from point to infinity (horizontally to the right)
2. Count how many polygon edges the ray intersects
3. If count is odd → point is INSIDE
   If count is even → point is OUTSIDE

Pseudocode:
function pointInPolygon(point, vertices):
  x = point.longitude
  y = point.latitude
  inside = false

  j = vertices.length - 1
  for i = 0 to vertices.length - 1:
    xi = vertices[i].longitude
    yi = vertices[i].latitude
    xj = vertices[j].longitude
    yj = vertices[j].latitude

    if ((yi > y) != (yj > y)) and
       (x < (xj - xi) * (y - yi) / (yj - yi) + xi):
      inside = !inside

    j = i

  return inside

Example:
  Polygon: Backyard boundary with 8 vertices
  Point: Pet's current location
  Result: Inside or Outside

Debouncing and Hysteresis

To prevent alert spam from GPS jitter near boundaries, implement debouncing:

Technique Description Parameters
Time-based Debouncing Require state change to persist for N seconds Debounce time: 30-60 seconds
Count-based Debouncing Require N consecutive readings in new state Count threshold: 3-5 readings
Hysteresis Buffer Different thresholds for entry vs. exit Exit at R+10m, Enter at R-10m
Accuracy Filtering Ignore readings with poor accuracy Minimum accuracy: <25 meters

Confidence-Based Alerts

Reduce false alerts by requiring high-confidence detections:

Confidence Level Criteria Alert Behavior
High (>90%) Accuracy <10m, 5+ satellites, 3+ consecutive readings Immediate alert
Medium (70-90%) Accuracy <20m, 4+ satellites, 2+ consecutive readings Alert after 60-second confirmation
Low (<70%) Accuracy >20m, <4 satellites, single reading No alert, wait for better fix

4.8 Geofence Configuration Best Practices

Guidelines for creating effective geofences:

Size Recommendations

  • Minimum Radius: 25 meters (to account for GPS accuracy)
  • Home Zone: 50-150 meters (covers property + small margin)
  • Park/Open Area: 100-500 meters (allows free roaming)
  • Walking Route: 25-50 meter corridor (detects straying)
  • Maximum Zones per Pet: 20-50 (system dependent)

Alert Fatigue Prevention

ALERT MANAGEMENT STRATEGIES
============================

Problem: Too many alerts → User ignores them

Solutions:

1. Smart Scheduling
   - Disable alerts during known walk times
   - Quiet hours (e.g., 10 PM - 6 AM)
   - Snooze for temporary situations

2. Alert Consolidation
   - Group multiple events in single notification
   - "Buddy left Home at 10:32 AM and entered Park at 10:45 AM"

3. Adaptive Thresholds
   - Learn normal patterns
   - Only alert on anomalies

4. Priority Levels
   - Critical: Immediate delivery (restricted areas)
   - High: Standard delivery (home exit)
   - Medium: Batched delivery (park entry)
   - Low: Log only (expected movements)

5. User Preferences
   - Allow per-zone notification settings
   - Do Not Disturb mode
   - Notification channels (push, email, SMS)

Example Configuration:

Chapter Summary

Key Takeaways:

  1. Geofence Types: Circular geofences are simplest and most common, but polygonal and corridor geofences enable complex safety zones for properties and routes.
  2. Detection Algorithms: Point-in-circle and ray-casting algorithms detect boundary crossings, while debouncing prevents false alerts from GPS jitter.
  3. Smart Alerts: Confidence-based alerting, time-based debouncing, and hysteresis buffers reduce false positives and alert fatigue.
  4. Dynamic Zones: Temporary, time-scheduled, and adaptive geofences provide flexibility for travel, camping, and learning normal behavior patterns.
  5. Analytics Value: Tracking time-in-zone, entry/exit counts, and activity patterns reveals pet behavior insights and helps identify anomalies.
