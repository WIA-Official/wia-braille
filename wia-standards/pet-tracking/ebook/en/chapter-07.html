7.1 Cellular Network Technologies

Cellular networks provide the primary communication channel for pet trackers, enabling global coverage and reliable data transmission.

Cellular Technology Comparison

Technology Speed Power Coverage Latency Cost Pet Tracking Suitability
2G (GSM/GPRS) 50-100 kbps Medium Excellent (legacy) 500-1000ms Low Phasing out, not recommended
3G (UMTS) 384 kbps - 2 Mbps Medium-High Good (declining) 100-500ms Low-Medium Legacy support only
4G LTE 5-50 Mbps Medium Excellent 50-100ms Medium ✓ Recommended (standard)
LTE Cat-M1 1 Mbps Low Excellent 100-300ms Low ✓ Recommended (battery)
NB-IoT 20-250 kbps Very Low Excellent 1-10 seconds Very Low ✓ Good for sleep mode
5G 100 Mbps - 1 Gbps High Growing <10ms High Future consideration

LTE Cat-M1 (Recommended)

LTE Cat-M1 offers optimal balance for pet tracking:

LTE CAT-M1 ADVANTAGES
=====================

Power Efficiency:
  - PSM (Power Saving Mode): Device sleeps, wakes only for transmissions
  - eDRX (Extended Discontinuous Reception): Extended sleep cycles
  - Power consumption: 80% less than standard LTE
  - Battery life: 2-3x longer than 4G LTE

Coverage:
  - Uses LTE infrastructure (global availability)
  - Better penetration in buildings than standard LTE
  - Lower frequency bands for rural coverage

Cost:
  - Lower data rates = lower costs
  - Optimized for IoT pricing plans
  - Typical: $5-15/month for tracking data volumes

Mobility:
  - Supports up to 100 km/h movement
  - Seamless handoff between towers
  - Perfect for pet tracking (not vehicle tracking)

Data Rate:
  - 1 Mbps upload/download
  - More than sufficient for location data
  - Can handle photo/video uploads if needed

POWER SAVING MODE (PSM)
========================

Normal LTE:
  Device always listening: 50-100 mA idle
  Battery drain even when not transmitting

PSM Mode:
  Device sleeps between transmissions: <1 mA
  Wakes only to send location updates
  Example cycle:
    - Sleep: 30 seconds (0.5 mA)
    - Wake + GPS fix: 5 seconds (40 mA)
    - Transmit: 2 seconds (200 mA)
    - Sleep: 30 seconds...

Average Power: ~8 mA vs. ~60 mA (87% reduction)

7.2 LoRaWAN for Rural and Remote Tracking

LoRaWAN provides long-range, low-power communication ideal for rural areas without cellular coverage.

LoRaWAN Characteristics

Feature Specification Implication for Pet Tracking
Range 2-15 km urban, 15-50 km rural Excellent coverage in open areas
Data Rate 0.3 - 50 kbps Adequate for location data
Power Very low (years on battery) Extended battery life
Latency 1-60 seconds Acceptable for most tracking
Infrastructure Requires LoRaWAN gateways Limited deployment in some areas
Cost Low (unlicensed spectrum) Affordable monthly fees

LoRaWAN Message Format

{
  "deviceEUI": "70B3D57ED00012AB",
  "timestamp": "2025-12-25T10:30:45Z",
  "fPort": 2,
  "payload": "CiQ3Ljc3NDkyOSwgLTEyMi40MTk0MTgsIDguNQo=",
  "decoded": {
    "latitude": 37.774929,
    "longitude": -122.419418,
    "accuracy": 8.5,
    "battery": 78,
    "satellites": 12
  },
  "rxInfo": [
    {
      "gatewayID": "b827ebfffe7e8c4a",
      "rssi": -95,
      "snr": 8.5,
      "location": {
        "latitude": 37.7800,
        "longitude": -122.4200
      }
    }
  ]
}

Payload Encoding (binary optimization):
  Byte 0-3:  Latitude × 10^7 (int32)
  Byte 4-7:  Longitude × 10^7 (int32)
  Byte 8:    Accuracy (uint8)
  Byte 9:    Battery level % (uint8)
  Byte 10:   Satellite count (uint8)

Total: 11 bytes vs. 200+ bytes JSON

Hybrid Communication Strategy

ADAPTIVE NETWORK SELECTION
============================

Priority Order:
1. Wi-Fi (if available) → Free, fast, low power
2. Cellular 4G/LTE-M → Standard, reliable
3. LoRaWAN (if in range) → Good for rural
4. Satellite → Last resort, expensive

Decision Algorithm:
  IF Wi-Fi available AND trusted network:
    USE Wi-Fi
  ELSE IF Cellular signal >= 2 bars:
    USE Cellular (LTE-M if available)
  ELSE IF LoRaWAN gateway in range (SNR > 0):
    USE LoRaWAN
  ELSE IF Satellite enabled AND critical:
    USE Satellite
  ELSE:
    BUFFER data for later transmission

Cost Optimization:
  - Wi-Fi: Sync large data (history, firmware updates)
  - Cellular: Regular location updates
  - LoRaWAN: Periodic updates in rural areas
  - Satellite: Emergency alerts only

Example Configuration:
{
  "networkPreferences": {
    "primary": "cellular-lte-m",
    "fallback": ["lora", "satellite"],
    "wifi": {
      "enabled": true,
      "autoConnect": ["Home_WiFi", "Office_WiFi"],
      "useForUpdates": true
    },
    "satellite": {
      "enabled": false,
      "emergencyOnly": true,
      "costLimit": 10.00
    }
  }
}

Different protocols optimize for different network types and use cases.

WebSocket TCP Low Medium High Live tracking, bidirectional
gRPC TCP (HTTP/2) Low Medium High High-performance, streaming

MQTT for IoT Tracking

MQTT SETUP
==========

Broker: mqtt://broker.example.com:8883 (TLS)
QoS Levels:
  0 - At most once (fire and forget)
  1 - At least once (acknowledged)
  2 - Exactly once (guaranteed)

Topic Structure:
  wia/tracking/{trackerId}/location
  wia/tracking/{trackerId}/battery
  wia/tracking/{trackerId}/geofence
  wia/alerts/{trackerId}/lost-pet

Publish Location:
  Topic: wia/tracking/TRK-ABC123/location
  QoS: 1 (at least once)
  Payload:
  {
    "lat": 37.774929,
    "lng": -122.419418,
    "acc": 8.5,
    "ts": "2025-12-25T10:30:00Z"
  }

Subscribe (Client):
  Topic: wia/tracking/TRK-ABC123/#
  QoS: 1
  Callback: handleLocationUpdate()

MQTT Advantages:
  - Small overhead (~2 bytes per message)
  - Persistent connections (no HTTP handshake each time)
  - Built-in QoS and reliability
  - Bi-directional communication
  - Perfect for battery-powered devices

Last Will and Testament:
  If device disconnects unexpectedly:
    Topic: wia/tracking/TRK-ABC123/status
    Payload: {"status": "offline", "reason": "connection_lost"}

7.5 Data Transmission Optimization

Minimizing data transmission extends battery life and reduces costs.

Compression and Encoding

JSON (Uncompressed):
{
  "trackerId": "TRK-ABC123",
  "timestamp": "2025-12-25T10:30:45.123Z",
  "location": {
    "latitude": 37.774929,
    "longitude": -122.419418,
    "accuracy": 8.5
  },
  "battery": 78,
  "satellites": 12
}
Size: 202 bytes

CBOR (Binary JSON):
  {1: "TRK-ABC123", 2: 1735122645, 3: {1: 37.774929, 2: -122.419418, 3: 8.5}, 4: 78, 5: 12}
Size: 65 bytes (68% reduction)

Protocol Buffers:
  message LocationUpdate {
    string tracker_id = 1;
    int64 timestamp = 2;
    double latitude = 3;
    double longitude = 4;
    float accuracy = 5;
    int32 battery = 6;
    int32 satellites = 7;
  }
Size: ~45 bytes (78% reduction)

Custom Binary (optimized):
  Bytes 0-7:   Tracker ID hash (uint64)
  Bytes 8-11:  Unix timestamp (uint32)
  Bytes 12-15: Latitude × 10^7 (int32)
  Bytes 16-19: Longitude × 10^7 (int32)
  Byte 20:     Accuracy (uint8)
  Byte 21:     Battery % (uint8)
  Byte 22:     Satellites (uint8)
Size: 23 bytes (89% reduction)

GZIP Compression:
  - Further 30-50% reduction
  - CPU cost for compression/decompression
  - Trade-off: Battery vs. Data

Recommendation:
  - Use Protocol Buffers or CBOR for cellular
  - Use custom binary for LoRaWAN/Satellite
  - Use JSON only on Wi-Fi or debugging

Delta Encoding

Only send changes from the previous update:

Full Update (first):
{
  "lat": 37.774929,
  "lng": -122.419418,
  "acc": 8.5,
  "bat": 78,
  "sat": 12
}
Size: 65 bytes

Delta Update (subsequent):
{
  "Δlat": 0.000023,
  "Δlng": -0.000015,
  "ts": 1735122675
}
Size: 28 bytes (57% reduction)

Every Nth update: Send full update for error correction

Global SIM 100+ countries Medium-High Single SIM, auto-carrier selection
eSIM (eUICC) Global Variable Remote carrier provisioning
Multi-IMSI SIM Regional (e.g., EU) Medium Multiple carrier profiles on one SIM

eSIM Provisioning

eSIM BENEFITS
=============

Traditional SIM:
  - Physical card required
  - One carrier at a time
  - Manual swap for international travel

eSIM (Embedded SIM):
  - Built into device
  - Over-the-air carrier provisioning
  - Switch carriers remotely
  - Multiple carrier profiles

Use Case: International Travel
  1. Pet owner travels from USA to Europe
  2. Device detects new country (MCC/MNC)
  3. Automatically switches to European carrier profile
  4. Tracking continues seamlessly
  5. Owner not charged excessive roaming fees

7.7 Offline Scenarios and Data Buffering

Handling areas with no connectivity gracefully ensures no data loss.

Buffering Strategy

OFFLINE BUFFER MANAGEMENT
=========================

Scenario: Pet wanders into area with no cellular coverage

1. Detection:
   - Network unavailable (no signal)
   - MQTT connection lost
   - HTTP requests timing out

2. Buffer Activation:
   - Enable local storage mode
   - Continue GPS positioning
   - Store locations with timestamps
   - Compress older data

3. Intelligent Storage:
   Priority Levels:
     CRITICAL: Geofence violations, motion changes
     HIGH: Movement periods, hourly snapshots
     NORMAL: Regular interval updates
     LOW: Redundant stationary positions

   Buffer Allocation (1 MB total):
     CRITICAL: 256 KB (retain all)
     HIGH: 512 KB (retain recent)
     NORMAL: 192 KB (retain sparse)
     LOW: 64 KB (retain samples)

4. Connectivity Restored:
   - Detect network available
   - Prioritize critical data upload
   - Batch upload compressed data
   - Delete uploaded data
   - Resume real-time mode

Example Buffer:
{
  "bufferedLocations": [
    {
      "timestamp": "2025-12-25T10:00:00Z",
      "latitude": 37.7749,
      "longitude": -122.4194,
      "priority": "high",
      "reason": "geofence_exit"
    },
    {
      "timestamp": "2025-12-25T10:05:00Z",
      "latitude": 37.7810,
      "longitude": -122.4105,
      "priority": "normal"
    },
    ...
  ],
  "bufferStats": {
    "totalRecords": 145,
    "oldestTimestamp": "2025-12-25T10:00:00Z",
    "newestTimestamp": "2025-12-25T14:30:00Z",
    "sizeBytes": 8456,
    "compression": "gzip"
  }
}

Chapter Summary

Key Takeaways:

  1. LTE Cat-M1 Recommended: Optimal balance of coverage, power efficiency, and cost for pet tracking applications.
