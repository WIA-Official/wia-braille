Chapter 4: Open Badges Standard & WIA Extensions

Open Badges Foundation

WIA-EDU-012 builds upon the Open Badges 3.0 specification, maintained by the 1EdTech Consortium (formerly IMS Global). Open Badges provides the foundational data model and verification framework for portable, verifiable digital credentials. The WIA standard extends Open Badges with additional capabilities for competency mapping, privacy controls, and ecosystem integration.

The Open Badges Data Model

Core Components

Every Open Badge contains three essential entities:

  1. Assertion: The credential itself, linking recipient to achievement
  2. Badge Class: Definition of what the badge represents
  3. Issuer Profile: Information about the credentialing organization

JSON-LD Structure

Badges use JSON-LD (JavaScript Object Notation for Linked Data) to encode credential information in a machine-readable, semantically rich format: 

{
  "@context": "https://w3id.org/openbadges/v3",
  "type": "OpenBadgeCredential",
  "id": "urn:uuid:91537dba-56cb-11ec-a1c3-0b40de2a2a74",
  "issuer": {
    "id": "https://wia.org/issuers/academy",
    "type": "Profile",
    "name": "WIA Academy"
  },
  "issuanceDate": "2025-01-15T00:00:00Z",
  "credentialSubject": {
    "id": "did:example:learner123",
    "type": "AchievementSubject",
    "achievement": {
      "id": "https://wia.org/badges/js-expert",
      "type": "Achievement",
      "name": "JavaScript Expert",
      "description": "Demonstrates mastery of modern JavaScript",
      "criteria": {
        "narrative": "Complete 5 projects using ES6+, async/await,
                     and React"
      }
    }
  },
  "proof": {
    "type": "Ed25519Signature2020",
    "created": "2025-01-15T00:00:00Z",
    "proofPurpose": "assertionMethod",
    "verificationMethod": "https://wia.org/keys/1",
    "proofValue": "z3FXQjecWyz..."
  }
}

WIA Extensions to Open Badges

1. Competency Framework Integration

WIA extends the badge model to explicitly link credentials to competency frameworks like ESCO (European Skills, Competences, Qualifications and Occupations), O*NET (US occupational information), and custom organizational frameworks. 

"wia:competencies": [
  {
    "framework": "https://ec.europa.eu/esco",
    "competencyId": "S1.2.3",
    "competencyName": "JavaScript programming",
    "proficiencyLevel": "advanced"
  }
]

2. Evidence Attachments

Enhanced evidence linking allows badges to reference portfolio artifacts, assessment results, and work products: 

"wia:evidence": [
  {
    "type": "Portfolio",
    "url": "https://github.com/learner/portfolio",
    "description": "React application with test coverage"
  },
  {
    "type": "Assessment",
    "score": "95/100",
    "assessmentType": "practical-examination"
  }
]

3. Privacy Controls

Granular privacy settings allow learners to control badge visibility: 

"wia:privacy": {
  "visibility": "selective",
  "shareWith": ["employers", "educational-institutions"],
  "exposeEvidence": false,
  "anonymizeBeforeDate": "2023-01-01"
}

4. Expiration and Renewal

For credentials with time-limited validity (e.g., certifications requiring renewal): 

"expirationDate": "2027-01-15T00:00:00Z",
"wia:renewal": {
  "required": true,
  "renewalCriteria": "Complete 20 hours continuing education",
  "renewalUrl": "https://wia.org/renew/js-expert"
}

5. Credential Stacking Metadata

Information about how credentials combine toward larger qualifications: 

"wia:stacking": {
  "stacksToward": [
    {
      "credentialId": "https://wia.org/certificates/fullstack-dev",
      "credentialName": "Full-Stack Developer Certificate",
      "progress": "1 of 3 required badges"
    }
  ]
}

Backward Compatibility

All WIA extensions use namespaced properties (prefixed with wia:) to ensure backward compatibility with standard Open Badges validators. A WIA credential can be read by any Open Badges 3.0-compliant system, though WIA-specific features may not be recognized.

Verification Methods

WIA-EDU-012 supports multiple verification approaches:

Hosted Verification

The issuer hosts a public verification endpoint where anyone can validate the credential by checking the badge assertion against the issuer's records.

Signed Badges

Cryptographic signatures embedded in the badge allow offline verification without contacting the issuer. The verifier only needs the issuer's public key.

Blockchain Anchoring

Badge hashes can be anchored to public blockchains (Bitcoin, Ethereum, etc.), creating immutable proof of issuance at a specific point in time.

Decentralized Identifiers (DIDs)

Credentials can reference recipients and issuers via DIDs, enabling verifiable claims without centralized identity providers.
