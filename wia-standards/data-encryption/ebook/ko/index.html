서론

데이터 암호화에 대한 종합 가이드에 오신 것을 환영합니다. 데이터가 네트워크와 장치를 자유롭게 오가는 디지털 시대에 민감한 정보를 보호하는 것이 무엇보다 중요해졌습니다. 이 책은 기본 개념부터 고급 구현까지 현대 암호화 기술에 대한 심층적인 내용을 제공합니다.

"암호학에서 우리는 희망이 아닌 수학을 믿습니다."

암호화가 중요한 이유

전 세계 수십억 명의 사람들이 매일 자신도 모르는 사이에 암호화에 의존하고 있습니다. 다음과 같은 행동을 할 때:

  • 친구에게 메시지 보내기
  • 온라인 쇼핑하기
  • 은행 계좌 접속하기
  • 클라우드에 파일 저장하기
  • 비밀번호 관리자 사용하기

암호화는 배경에서 조용히 작동하며 여러분의 프라이버시와 보안을 보호합니다. 암호화의 작동 방식을 이해하면 디지털 생활에 대해 정보에 입각한 결정을 내릴 수 있습니다.

이 표준은 암호화를 모든 사람이 접근하고 이해하며 유익하게 만드는 사명으로 개발되었습니다. 강력한 암호화는 인권을 보호하고 표현의 자유를 가능하게 하며 전 세계 개인에게 권한을 부여합니다.

제1장: 암호화의 기초

1.1 암호화란 무엇인가?

암호화는 수학 알고리즘과 비밀 키를 사용하여 읽을 수 있는 데이터(평문)를 읽을 수 없는 형식(암호문)으로 변환하는 프로세스입니다. 올바른 키를 가진 사람만 암호문을 평문으로 복호화할 수 있습니다.

평문:    "안녕하세요, 세계!"
      ↓
   암호화 (키 사용)
      ↓
암호문:  "8f7a2c9e1b4d..."
      ↓
   복호화 (키 사용)
      ↓
평문:    "안녕하세요, 세계!"

1.2 암호화의 역사

암호화는 수천 년 동안 사용되어 왔습니다. 주요 이정표:

  • 카이사르 암호 (기원전 100년): 율리우스 카이사르가 사용한 간단한 문자 이동
  • 에니그마 기계 (1940년대): 나치 독일이 사용, 앨런 튜링이 해독
  • DES (1977): 최초의 현대 암호화 표준
  • RSA (1977): 최초의 실용적인 공개키 암호 시스템
  • AES (2001): 현재 대칭키 암호화 표준

1.3 케르크호프스의 원칙

"암호 시스템은 키를 제외한 시스템의 모든 것이 공개되어도 안전해야 합니다."

1883년 오귀스트 케르크호프스가 제시한 이 기본 원칙은 다음을 의미합니다:

  • 알고리즘은 공개적으로 알려질 수 있음
  • 보안은 오직 키에만 의존함
  • 공개 알고리즘은 전문가들의 검토를 받을 수 있음
  • "모호함을 통한 보안"은 진정한 보안이 아님

1.4 암호학의 유형

대칭키 암호화

암호화와 복호화에 동일한 키를 사용합니다. 빠르고 효율적이지만 안전한 키 배포가 필요합니다.

비대칭키 암호화

키 쌍을 사용합니다: 암호화용 공개키, 복호화용 개인키. 키 배포 문제를 해결하지만 느립니다.

해시 함수

데이터의 고정 크기 "지문"을 생성하는 일방향 함수입니다. 역으로 계산할 수 없습니다. 무결성 검증과 비밀번호 저장에 사용됩니다.

핵심 포인트: 현대 시스템은 일반적으로 대칭 암호화(속도)와 비대칭 암호화(키 교환)를 결합한 하이브리드 접근 방식을 사용합니다.

제2장: 대칭키 암호화

2.1 AES: 황금 표준

고급 암호화 표준(AES)은 오늘날 가장 널리 사용되는 대칭 암호화 알고리즘입니다. 2001년 NIST의 엄격한 경쟁을 거쳐 선정된 AES는 수십 년간의 암호 분석을 견뎌냈습니다.

AES 사양

  • 블록 크기: 128비트 (16바이트)
  • 키 크기: 128, 192 또는 256비트
  • 라운드: 10 (AES-128), 12 (AES-192), 14 (AES-256)
  • 구조: 대체-순열 네트워크

2.2 운영 모드

AES와 같은 블록 암호는 고정 크기 블록을 암호화합니다. 더 큰 데이터를 암호화하려면 운영 모드를 사용합니다:

GCM (Galois/Counter Mode) ✅ 권장

GCM은 기밀성과 진정성을 모두 제공하는 AEAD(추가 인증 데이터가 있는 인증 암호화) 모드입니다. AES에 권장되는 모드입니다.

왜 GCM인가?
  • 하나의 작업으로 암호화와 인증을 모두 제공
  • 병렬화 가능 (하드웨어 가속으로 빠름)
  • 인증 태그로 변조 방지
  • 추가 인증 데이터(AAD) 지원

기타 모드

  • CBC (Cipher Block Chaining): ⚠️ 별도의 MAC 필요
  • CTR (Counter Mode): ⚠️ 별도의 MAC 필요
  • ECB (Electronic Codebook): ❌ 안전하지 않음, 사용 금지

2.3 구현 예제

// Node.js AES-256-GCM 예제
const crypto = require('crypto');

function encryptAES(plaintext, key) {
  // 무작위 IV 생성
  const iv = crypto.randomBytes(16);

  // 암호 생성
  const cipher = crypto.createCipheriv('aes-256-gcm', key, iv);

  // 암호화
  let ciphertext = cipher.update(plaintext, 'utf8', 'hex');
  ciphertext += cipher.final('hex');

  // 인증 태그 얻기
  const authTag = cipher.getAuthTag();

  return { ciphertext, iv, authTag };
}

2.4 ChaCha20-Poly1305

ChaCha20-Poly1305는 AES-GCM의 현대적인 대안으로, 특히 모바일 및 임베디드 시스템에서 인기가 있습니다:

  • 소프트웨어에서 빠름 (특수 하드웨어 불필요)
  • 타이밍 공격에 저항
  • TLS 1.3, WireGuard VPN, Signal 프로토콜에 사용됨
  • AES 하드웨어 가속을 사용할 수 없을 때 권장
경험 법칙: AES-NI를 지원하는 시스템(최신 Intel/AMD CPU)에서는 AES-256-GCM을, 모바일 장치와 임베디드 시스템에서는 ChaCha20-Poly1305를 사용하세요.

제3장: 비대칭키 암호화

3.1 키 배포 문제

대칭 암호화에는 근본적인 과제가 있습니다: 안전하지 않은 채널을 통해 두 당사자가 비밀 키를 어떻게 공유할까요? 여기서 비대칭 암호화가 빛을 발합니다.

"비대칭 암호화는 우체통과 같습니다: 누구나 편지를 넣을 수 있지만(공개키로 암호화), 열쇠를 가진 사람만 열 수 있습니다(개인키로 복호화)."

3.2 RSA: 개척자

1977년 Rivest, Shamir, Adleman이 발명한 RSA는 최초의 실용적인 공개키 암호 시스템이었습니다. 오늘날에도 여전히 널리 사용되고 있습니다.

RSA 작동 원리

  1. 키 생성: 두 개의 큰 소수를 선택하여 곱합니다
  2. 공개키: 곱셈 결과에서 파생, 자유롭게 공유 가능
  3. 개인키: 소인수에서 파생, 비밀 유지 필수
  4. 보안: 큰 수의 인수분해 어려움에 기반

RSA 키 크기

  • RSA-2048: 새 시스템의 최소 (112비트 보안)
  • RSA-3072: 장기 보안에 좋음 (128비트 보안)
  • RSA-4096: 최대 실용 크기 (140비트 보안)
중요: RSA는 양자 컴퓨터에 취약합니다. 미래의 양자 후 암호화 이전을 계획하세요.

3.3 타원곡선 암호화 (ECC)

ECC는 훨씬 작은 키로 RSA와 동등한 보안을 제공합니다:

보안 수준 RSA 키 크기 ECC 키 크기
128비트 3072비트 256비트
192비트 7680비트 384비트
256비트 15360비트 521비트

인기 있는 곡선

  • P-256 (secp256r1): 128비트 보안, 널리 지원됨
  • P-384 (secp384r1): 192비트 보안, 새 시스템에 권장
  • P-521 (secp521r1): 256비트 보안, 최대 보안
  • Curve25519: 현대적인 곡선, Signal, SSH에 사용

3.4 디지털 서명

비대칭 암호화는 디지털 서명도 가능하게 하며, 다음을 제공합니다:

  • 인증: 누가 데이터를 생성했는지 증명
  • 무결성: 데이터가 수정되지 않았음을 증명
  • 부인 방지: 서명자가 서명을 부인할 수 없음

제4장: 하이브리드 암호화

4.1 양쪽의 장점

하이브리드 암호화는 대칭 암호화의 효율성과 비대칭 암호화의 편리함을 결합합니다:

  1. 무작위 대칭키 생성 (AES-256)
  2. 대칭키로 데이터 암호화 (빠름)
  3. 수신자의 공개키로 대칭키 암호화
  4. 암호화된 데이터 + 암호화된 키 전송
실제 예: HTTPS 웹사이트를 방문할 때 브라우저는 하이브리드 암호화를 사용합니다:
  • 초기 키 교환에 RSA/ECC 사용
  • 실제 웹 트래픽 암호화에 AES 사용
  • 이것이 TLS (Transport Layer Security) 작동 방식입니다

4.2 성능 이점

1GB 데이터 암호화를 고려해보세요:

  • RSA-4096만 사용: ~92시간 (비실용적)
  • AES-256만 사용: 0.3초 (하지만 키를 어떻게 공유?)
  • 하이브리드: 0.3초 + 0.003초 = 0.303초 ✅
"하이브리드 암호화는 대칭 암호화의 속도와 비대칭 암호화의 편리함을 제공합니다 - 양쪽의 장점을 모두 누릴 수 있습니다."

제5장: 키 관리

5.1 가장 약한 고리

가장 강력한 암호화도 키가 제대로 관리되지 않으면 무용지물입니다. 실제로 대부분의 암호화 침해는 알고리즘 약점이 아닌 키 관리 실패로 인해 발생합니다.

보안 원칙: 암호화된 데이터의 보안은 키의 보안만큼만 강력합니다.

5.2 키 수명 주기

1. 생성

  • 암호학적으로 안전한 난수 생성기(CSRNG) 사용
  • 예측 가능한 소스 사용 금지 (타임스탬프, 사용자 입력)
  • 충분한 엔트로피로 키 생성

2. 배포

  • 키 교환에 안전한 채널 사용
  • 비대칭 암호화 또는 Diffie-Hellman 구현
  • 이메일이나 암호화되지 않은 채널로 키 전송 금지

3. 저장

  • 최고 보안을 위한 하드웨어 보안 모듈(HSM)
  • 클라우드 환경을 위한 키 관리 서비스(KMS)
  • 마스터 키 보호가 있는 암호화된 키 저장소
  • 소스 코드에 키 하드코딩 금지

4. 순환

  • 대칭키: 90일마다 (권장)
  • 비대칭키: 365일마다 (권장)
  • 손상 의심 시 즉시 순환

5. 폐기

  • 중앙 레지스트리에 폐기된 키 표시
  • 새 키로 데이터 재암호화
  • 포렌식을 위해 이전 키 보관 (선택 사항)

5.3 봉투 암호화

데이터 암호화 키(DEK)로 데이터를 암호화한 다음 키 암호화 키(KEK)로 DEK를 암호화합니다:

  • 데이터를 재암호화하지 않고 키 순환 가능
  • KEK는 HSM 또는 KMS에 저장
  • DEK는 암호화된 데이터와 함께 저장
  • AWS, Azure, Google Cloud에서 사용

제6장: 실전 구현

6.1 완전한 시스템 설계

완전한 암호화 메시징 시스템을 설계해 봅시다:

요구사항

  • 종단 간 암호화
  • 완전 순방향 비밀성
  • 메시지 인증
  • 사용자 친화적인 키 관리

아키텍처

  1. 등록: ECC 키 쌍 생성 (P-384)
  2. 키 교환: 공유 비밀을 위한 ECDH
  3. 암호화: 파생된 키로 AES-256-GCM
  4. 인증: ECDSA 서명

6.2 일반적인 함정

❌ IV/논스 재사용

동일한 키로 IV를 재사용하지 마세요. 이는 암호화 보안을 완전히 무너뜨립니다.

❌ 인증 태그 무시

항상 인증 태그를 확인하세요. 이를 건너뛰면 변조 공격이 가능합니다.

❌ 키 하드코딩

소스 코드에 암호화 키를 하드코딩하지 마세요. 환경 변수나 키 관리 시스템을 사용하세요.

❌ ECB 모드 사용

ECB 모드는 데이터의 패턴을 드러냅니다. 항상 GCM과 같은 인증 모드를 사용하세요.

6.3 성능 최적화

하드웨어 가속

  • AES-NI: AES용 Intel/AMD 명령어 세트
  • ARM Crypto Extensions: ARMv8 하드웨어 가속
  • QuickAssist: Intel 전용 암호화 가속기

병렬 처리

GCM 모드는 대용량 파일에서 더 나은 성능을 위해 병렬화될 수 있습니다.

제7장: 고급 주제

7.1 양자 후 암호화

양자 컴퓨터는 현재의 비대칭 암호화를 위협합니다. NIST는 양자 후 알고리즘을 선정했습니다:

  • CRYSTALS-Kyber: 키 캡슐화 (RSA/ECC 키 교환 대체)
  • CRYSTALS-Dilithium: 디지털 서명
  • SPHINCS+: 무상태 서명
타임라인: 지금 양자 후 암호화 이전을 계획하기 시작하세요. 표준은 2024-2025년 예정, 2030년까지 광범위한 채택 예상.

7.2 영지식 증명

무엇을 알고 있는지 드러내지 않고 알고 있다는 것을 증명합니다:

  • 사용 사례: 프라이버시 보호 인증, 익명 자격 증명
  • 예: zk-SNARKs (Zcash), zk-STARKs
  • 이점: 최대 프라이버시, 최소 데이터 노출

7.3 동형 암호화

복호화하지 않고 암호화된 데이터에 대해 계산을 수행합니다:

// 개념적 예
let encrypted1 = encrypt(10);  // E(10)
let encrypted2 = encrypt(20);  // E(20)

// 암호화된 숫자 더하기
let encryptedSum = add(encrypted1, encrypted2);  // E(30)

// 결과를 얻기 위해 복호화
let result = decrypt(encryptedSum);  // 30

응용 분야: 클라우드 컴퓨팅, 의학 연구, 금융 분석

7.4 안전한 다자간 계산

여러 당사자가 입력을 드러내지 않고 함수를 계산합니다:

  • 예: 개인 급여를 드러내지 않고 평균 급여 계산
  • 기술: Shamir의 비밀 공유, garbled circuits
  • 사용 사례: 프라이빗 경매, 안전한 투표, 협업 분석

제8장: 보안 모범 사례

8.1 보안 체크리스트

✅ 알고리즘 선택

  • 대칭 암호화에 AES-256-GCM 사용
  • 비대칭 암호화에 RSA-4096 또는 ECC P-384 사용
  • 해싱에 SHA-256 이상 사용
  • 더 이상 사용되지 않는 알고리즘 피하기 (DES, 3DES, MD5, SHA-1)

✅ 키 관리

  • 모든 키 생성에 CSRNG 사용
  • HSM 또는 KMS에 키 저장
  • 키 순환 정책 구현
  • 소스 코드에 키 하드코딩 금지

✅ 구현

  • 각 암호화마다 고유한 IV/논스 생성
  • 항상 인증 태그 확인
  • 비밀에 대해 상수 시간 비교 사용
  • 사용 후 메모리에서 민감한 데이터 지우기

✅ 운영 보안

  • 모든 암호화 작업에 대한 감사 로깅 활성화
  • 의심스러운 활동 모니터링
  • 암호화 라이브러리 업데이트 유지
  • 정기적인 보안 감사 실시

8.2 투명성을 통한 보안

"공개 알고리즘은 수천 명의 전문가가 검토했기 때문에 더 안전합니다. 비밀 알고리즘은 제작자만 검토했습니다."

이것이 다음과 같은 이유입니다:

  • AES는 오픈 소스이며 공개적으로 검토됨
  • 주요 암호화 라이브러리는 오픈 소스 (OpenSSL, libsodium)
  • 보안 전문가는 투명한 구현을 권장

결론

암호화는 프라이버시, 보안, 자유를 보호하기 위한 인류의 가장 강력한 도구 중 하나입니다. 이 책에서 살펴본 것처럼 현대 암호학은 간단한 메시지에서 복잡한 엔터프라이즈 시스템에 이르기까지 데이터를 보호하기 위한 강력한 메커니즘을 제공합니다.

핵심 포인트

  1. 검증된 알고리즘 사용: AES-256-GCM, RSA-4096, ECC P-384
  2. 키를 신중하게 관리: 모든 암호 시스템의 가장 약한 고리
  3. 하이브리드 암호화 구현: 대칭 및 비대칭의 장점
  4. 최신 정보 유지: 양자 후 암호화 준비
  5. 모범 사례 따르기: 보안 체크리스트, 규정 준수, 테스트

암호화의 미래

앞을 내다보면 여러 트렌드가 암호화의 미래를 형성할 것입니다:

  • 양자 후 암호화: 양자 컴퓨터로부터 보호
  • 동형 암호화: 암호화된 데이터에 대한 계산
  • 영지식 증명: 프라이버시 보호 검증
  • 양자 키 분배: 이론적으로 깨지지 않는 키 교환
