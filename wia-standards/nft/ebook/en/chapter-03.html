CHAPTER 3

Metadata & IPFS Storage

While NFT smart contracts handle ownership and transfers on the blockchain, the actual content and descriptive information live in metadata. Understanding how to properly structure, store, and reference metadata is crucial for creating NFTs that are accessible, permanent, and interoperable across platforms.

NFT Metadata Standards

JSON Metadata Schema

The de facto standard for NFT metadata is JSON (JavaScript Object Notation), a lightweight data format that's both human-readable and machine-parseable. OpenSea, the largest NFT marketplace, established a metadata standard that has become widely adopted across the ecosystem.

{
  "name": "Creature #1",
  "description": "A mysterious creature from the depths",
  "image": "ipfs://QmZc6T7zN8E9pYjH3h4nJ8xK2kL9mP3nQ5oR6sT7uV8wX9y",
  "external_url": "https://myproject.com/creature/1",
  "attributes": [
    {
      "trait_type": "Background",
      "value": "Ocean Blue"
    },
    {
      "trait_type": "Rarity",
      "value": "Legendary"
    },
    {
      "trait_type": "Power",
      "value": 95,
      "max_value": 100
    }
  ]
}

Required and Optional Fields

  • name: The token's name. This is what appears in wallets and marketplaces.
  • description: Detailed description of the NFT, supporting markdown formatting.
  • image: URL to the NFT's visual representation (supports IPFS, HTTP, or data URIs).
  • external_url: Optional link to view the item on your website.
  • attributes: Array of traits that define the NFT's characteristics.
  • animation_url: For video, audio, or 3D content (GLTF, MP4, etc.).
  • background_color: Six-character hex color for display background.

IPFS: The InterPlanetary File System

Why Decentralized Storage Matters

Storing NFT content on centralized servers creates significant risks. If the hosting company goes out of business or the server fails, the NFT metadata and images could disappear, leaving token owners with worthless pointers to non-existent content. This defeats the purpose of blockchain-based permanent ownership.

IPFS (InterPlanetary File System) solves this through content-addressed storage. Instead of location-based URLs that might break, IPFS uses content identifiers (CIDs) derived from the file's cryptographic hash. The same content always generates the same CID, and as long as anyone on the IPFS network has the file, it remains accessible.

How IPFS Works

When you add a file to IPFS, the system generates a unique CID by hashing the content. This CID becomes the permanent identifier for that file. IPFS creates a distributed network where files are split into blocks and distributed across nodes. When someone requests a file, IPFS retrieves it from the nearest available nodes, similar to BitTorrent.

The key innovation is content addressing: changing even one byte of a file produces a completely different CID. This ensures immutability—the CID stored in your NFT will always point to the exact content, unchanged.

Pinning Services

While IPFS is decentralized, files aren't automatically permanent. To ensure content remains available, you need pinning—keeping files actively stored on IPFS nodes. Pinning services like Pinata, NFT.Storage, and Infura provide infrastructure to keep your NFT content permanently available.

// Example: Uploading to Pinata
const pinataSDK = require('@pinata/sdk');
const pinata = pinataSDK(apiKey, apiSecret);

const metadata = {
  name: "My NFT",
  description: "An amazing NFT",
  image: "ipfs://QmImageCID..."
};

const result = await pinata.pinJSONToIPFS(metadata);
console.log(result.IpfsHash); // QmMetadataCID...

Best Practices for Metadata

Attribute Design

Well-designed attributes enhance discoverability and enable marketplace filtering. Use consistent trait types across your collection, include numeric attributes with max_value for statistics displays, and consider rarity distribution for collectibility.

Media Optimization

  • Optimize images for web display (typically under 2MB)
  • Use standard formats (PNG for art with transparency, JPG for photos)
  • For large collections, consider generating thumbnails
  • Store high-resolution originals separately with links in metadata

Metadata Immutability

Once your NFT is minted, the tokenURI should ideally never change. Plan your metadata structure carefully before minting. If you must support updates, clearly communicate this to buyers and consider implementing governance mechanisms for changes.

💡 Provenance and Permanence

True NFT permanence requires three components: immutable smart contract on blockchain, metadata stored on decentralized network (IPFS), and pinning service ensuring long-term availability. Missing any component risks your NFT's longevity.

Advanced Metadata Patterns

On-Chain vs. Off-Chain Metadata

Some projects store metadata entirely on-chain for maximum permanence, though this is expensive due to gas costs. Others use hybrid approaches: essential data on-chain, extended metadata off-chain. Consider your project's priorities and budget when deciding.

Dynamic NFTs

Dynamic NFTs can change over time based on external conditions. This requires careful metadata architecture—typically a base URI that queries current state, or periodic metadata updates with proper versioning.

Multilingual Support

For international projects, consider multilingual metadata using language codes or separate metadata versions. Some platforms support localized_name and localized_description fields.

Conclusion

Proper metadata and storage infrastructure separate successful NFT projects from those that fail. IPFS provides the decentralized permanence that blockchain ownership promises, while standardized metadata ensures interoperability across the ecosystem. Invest time in designing your metadata schema and storage strategy—it's as important as your smart contract code.
