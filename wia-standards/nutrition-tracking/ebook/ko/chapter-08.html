마이크로서비스 아키텍처
======================

인증 서비스 (Auth Service)
-------------------------
  역할:
    • 사용자 로그인/회원가입
    • JWT 토큰 발급
    • OAuth 2.0 (소셜 로그인)
    • 권한 관리

  기술 스택:
    • Node.js + Express
    • JWT
    • bcrypt (비밀번호 해시)

  API:
    POST /auth/register
    POST /auth/login
    POST /auth/refresh
    POST /auth/logout


영양 서비스 (Nutrition Service)
-------------------------------
  역할:
    • 식사 기록 CRUD
    • 영양소 계산
    • 식품 DB 조회
    • 레시피 관리

  기술 스택:
    • Python + FastAPI
    • PostgreSQL
    • Redis (캐시)

  API:
    GET  /foods/search?q={query}
    GET  /foods/{foodId}
    POST /meals
    GET  /meals/{date}
    GET  /nutrition/summary


AI 분석 서비스 (AI Service)
---------------------------
  역할:
    • 식사 사진 인식
    • 음식 분류
    • 분량 추정
    • 바코드 스캔

  기술 스택:
    • Python + TensorFlow/PyTorch
    • GPU 서버
    • Docker

  API:
    POST /ai/analyze-image
    POST /ai/barcode-scan
    GET  /ai/models/version


추천 서비스 (Recommendation Service)
-----------------------------------
  역할:
    • 개인 맞춤 식단 생성
    • 레시피 추천

에러 처리
========

HTTP 상태 코드:
  200 OK                 - 성공
  201 Created            - 생성 성공
  400 Bad Request        - 잘못된 요청
  401 Unauthorized       - 인증 필요
  403 Forbidden          - 권한 없음
  404 Not Found          - 리소스 없음
  429 Too Many Requests  - 요청 제한 초과
  500 Internal Error     - 서버 오류

에러 응답 형식:
  {
    "error": {
      "code": "INVALID_INPUT",
      "message": "Quantity must be a positive number",
      "details": {
        "field": "quantity",
        "value": -10
      }
    }
  }


Rate Limiting
============

제한:
  • 일반 사용자: 1,000 요청/시간
  • 프리미엄: 10,000 요청/시간
  • AI 분석: 100 요청/시간

헤더:
  X-RateLimit-Limit: 1000
  X-RateLimit-Remaining: 850
  X-RateLimit-Reset: 1642248000

  초과 시:
  429 Too Many Requests
  Retry-After: 3600

8.3 데이터 보안 및 프라이버시

데이터 암호화
============

전송 중 암호화 (In-Transit)
--------------------------
  • TLS 1.3
  • HTTPS 전용
  • Certificate Pinning (모바일)

  설정:
    - 모든 API: https://
    - HTTP 리다이렉트 → HTTPS
    - HSTS 헤더 사용


저장 암호화 (At-Rest)
--------------------
  데이터베이스:
    • AES-256 암호화
    • 투명 데이터 암호화 (TDE)

  민감 정보:
    • 비밀번호: bcrypt (salt rounds: 12)
    • 개인정보: 필드 수준 암호화
    • 사진: S3 암호화 저장

  예시 (비밀번호):
    입력: "myPassword123"
    → bcrypt
    → "$2b$12$KIXxPzFH..."


개인정보 보호
============

최소 수집 원칙:
  필수:
    • 이메일
    • 비밀번호
    • 기본 신체 정보 (목표 계산용)

  선택:
    • 이름
    • 사진
    • 위치 (레스토랑 추천용)

데이터 익명화:
  분석 목적:
    user_id → hash(user_id)
    이메일 → 제거
    사진 → 메타데이터만

GDPR/PIPA 준수:
  • 사용자 동의 (opt-in)
  • 데이터 이동권
  • 삭제 요청 (Right to be forgotten)
  • 개인정보 처리방침


접근 제어
========

RBAC (역할 기반):
  관리자 (Admin):
    • 모든 데이터 접근
    • 사용자 관리
    • 시스템 설정

  영양사 (Nutritionist):
    • 할당된 사용자 데이터
    • 식단 계획 작성
    • 리포트 생성

  일반 사용자 (User):
    • 자신의 데이터만
    • 커뮤니티 공유 데이터


감사 로그 (Audit Log)
--------------------
  기록 대상:
    • 로그인/로그아웃
    • 데이터 수정
    • 삭제 요청
    • 관리자 작업

  형식:
    {
      "timestamp": "2025-01-15T10:30:00Z",
      "user_id": "user123",
      "action": "DELETE_MEAL",
      "resource_id": "meal456",
      "ip_address": "192.168.1.1",
      "user_agent": "iOS/16.0"
    }

  보관 기간: 2년


백업 및 재해 복구
================

자동 백업:
  • 일일 전체 백업
  • 시간별 증분 백업
  • 지역 간 복제 (다중 리전)

백업 암호화:
  • AES-256
  • 백업 전송 시 암호화
  • 복호화 키 별도 관리

재해 복구 계획:
  RTO (복구 시간 목표): 4시간
  RPO (복구 시점 목표): 1시간

  절차:
    1. 장애 감지 (자동 모니터링)
    2. 백업 리전으로 Failover
    3. DNS 업데이트
    4. 서비스 복구 확인

   class BarcodeScannerViewModel: ObservableObject {
       let session = AVCaptureSession()

       func startScanning() {
           guard let device = AVCaptureDevice
               .default(for: .video) else { return }

           let input = try? AVCaptureDeviceInput(
               device: device)
           session.addInput(input!)

           let output = AVCaptureMetadataOutput()
           session.addOutput(output)

           output.metadataObjectTypes = [
               .ean13, .qr
           ]
           output.setMetadataObjectsDelegate(
               self, queue: .main)

           session.startRunning()
       }
   }

               HKObjectType.quantityType(

           ]

           healthStore.requestAuthorization(
               toShare: types,
               read: types

               doubleValue: calories)

               type: calorieType,
               quantity: calorieQuantity,
               start: date,
               end: date
           )

           healthStore.save(calorieSample) { _, _ in
               // Handle
           }
       }

   import com.google.android.gms.fitness.Fitness

   class FitnessManager(private val context: Context) {
       fun saveNutrition(
           calories: Float,
           protein: Float,
           timestamp: Long
       ) {
           val dataSource = DataSource.Builder()
               .setAppPackageName(context)
               .setDataType(DataType.TYPE_NUTRITION)
               .setType(DataSource.TYPE_RAW)
               .build()

           val caloriePoint = DataPoint.builder(dataSource)
               .setTimestamp(timestamp, TimeUnit.MILLISECONDS)
               .setField(Field.FIELD_NUTRIENTS,
                   calories)
               .build()

           Fitness.getHistoryClient(context, account)
               .insertData(
                   DataSet.builder(dataSource)
                       .add(caloriePoint)
                       .build()
               )
       }
   }


오프라인 지원
============

로컬 데이터베이스:
  iOS: CoreData / Realm
  Android: Room

동기화 전략:
  1. 오프라인 시 로컬 저장
  2. 온라인 복구 시 자동 동기화
  3. 충돌 해결 (최신 우선)

  예시:
    [오프라인] 식사 기록
    → 로컬 DB에 저장 (pending)

    [온라인 복구]
    → API로 전송
    → 성공 시 pending 제거
    → 실패 시 재시도 큐에 추가
