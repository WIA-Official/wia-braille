4.1 바코드 스캔 기술

바코드 유형
==========

1차원 바코드 (1D Barcodes)
-------------------------
  UPC-A (Universal Product Code)
    • 미국, 캐나다 표준
    • 12자리 숫자
    • 식품, 소비재
    • 예: 012345678905

  EAN-13 (European Article Number)
    • 국제 표준
    • 13자리 숫자
    • 전 세계 사용
    • 예: 8801234567890
    • 한국: 880으로 시작

  EAN-8
    • 소형 제품용
    • 8자리 숫자

  Code-128
    • 영숫자 지원
    • 물류, 재고 관리


2차원 바코드 (2D Barcodes)
-------------------------
  QR Code
    • 빠른 인식
    • 최대 4,296자
    • URL, 텍스트 저장
    • 영양 정보 링크

  DataMatrix
    • 소형 공간
    • 의약품, 소형 제품

  PDF417
    • 높은 데이터 용량
    • 신분증, 티켓


바코드 스캔 프로세스
===================

1단계: 카메라 활성화
-------------------
  • 카메라 권한 요청
  • 후면 카메라 선택
  • 자동 초점 활성화
  • 플래시 옵션 제공


2단계: 바코드 감지
-----------------
  실시간 스캔:
    • 카메라 프레임 분석
    • 바코드 패턴 인식
    • 30-60 FPS 처리

  안내 UI:
    ┌────────────────┐
    │                │
    │  ┌────────┐    │
    │  │ Barcode│    │ ← 스캔 영역 표시
    │  └────────┘    │
    │                │
    │  [조준선]       │
    └────────────────┘


3단계: 바코드 해독
-----------------
  디코딩 라이브러리:
    • ZXing (Zebra Crossing)
    • Barcode Scanner API (ML Kit)
    • QuaggaJS (웹)

  검증:
    • 체크섬 확인
    • 유효성 검사
    • 오류 수정


4단계: 제품 검색
---------------
  로컬 DB 우선:
    SELECT * FROM products
    WHERE barcode = '8801234567890'

  없으면 API 조회:
    → Open Food Facts
    → USDA FoodData Central
    → 제조사 API


5단계: 결과 표시
---------------
  제품 정보:
    📦 제품명
    🏢 브랜드
    📊 1회 제공량
    🔢 영양 정보
    📅 등록일

  액션:
    [✓ 추가]  [ℹ 상세]  [🔄 재스캔]


스캔 최적화 팁
=============

조명:
  ✓ 밝은 곳에서 스캔
  ✓ 그림자 없이
  ✓ 플래시 사용 (필요 시)

거리:
  ✓ 10-30cm 유지
  ✓ 너무 가까우면 초점 문제
  ✓ 너무 멀면 인식 실패

각도:
  ✓ 바코드에 수직
  ✓ 반사 피하기
  ✓ 평평하게 펴기

상태:
  ✓ 깨끗한 바코드
  ✗ 구겨짐, 찢어짐 주의
  ✗ 얼룩, 오염 제거

Open Food Facts API 통합
========================

API 엔드포인트
-------------
  기본 URL: https://world.openfoodfacts.org/api/v2/

  제품 조회:
    GET /product/{barcode}.json

  예시:
    GET /product/8801234567890.json


응답 예시
--------
{
  "status": 1,
  "product": {
    "product_name": "초코칩 쿠키",
    "brands": "오리온",
    "quantity": "300g",
    "serving_size": "30g",
    "nutriments": {
      "energy-kcal_100g": 495,
      "proteins_100g": 5.3,
      "carbohydrates_100g": 66.7,

      "fat_100g": 22.7,

      "fiber_100g": 2.1,
      "sodium_100g": 0.32,

}


데이터 변환
----------
  Open Food Facts → 내부 형식

  energy-kcal_100g   → calories (per 100g)
  proteins_100g      → protein (per 100g)
  carbohydrates_100g → carbs (per 100g)
  fat_100g           → fat_total (per 100g)
  sodium_100g        → sodium (mg per 100g)

  1회 제공량 계산:
    serving_size = 30g
    calories_per_serving = (495 × 30) / 100 = 148.5 kcal

4.3 OCR 기반 영양 정보 추출

OCR 파이프라인
=============

1단계: 영양 라벨 촬영
--------------------
  가이드라인:
    • 라벨 전체가 화면에
    • 수평으로 정렬
    • 밝은 조명
    • 흔들림 방지


2단계: 이미지 전처리
-------------------
  그레이스케일 변환:
    RGB → Gray
    성능 향상 및 노이즈 감소

  이진화 (Binarization):
    Otsu's method
    텍스트와 배경 분리

  노이즈 제거:
    Gaussian blur
    Median filter

  기울기 보정:
    Hough transform
    텍스트 정렬

  대비 향상:
    CLAHE (Contrast Limited Adaptive Histogram Equalization)


3단계: OCR 엔진 실행
------------------
  엔진 옵션:
    • Tesseract OCR (무료)
    • Google Cloud Vision API
    • AWS Textract
    • Azure Computer Vision

  언어 설정:
    한국어: kor + eng
    영어: eng
    다국어: 자동 감지


4단계: 텍스트 파싱
-----------------
  패턴 매칭:
    정규식 (Regex) 사용

  칼로리:
    /(\d+)\s*kcal/i
    예: "495 kcal" → 495

  탄수화물:
    /탄수화물.*?(\d+\.?\d*)g/i
    /Carbohydrate.*?(\d+\.?\d*)g/i

  단백질:
    /단백질.*?(\d+\.?\d*)g/i
    /Protein.*?(\d+\.?\d*)g/i

  지방:
    /지방.*?(\d+\.?\d*)g/i
    /Fat.*?(\d+\.?\d*)g/i

  나트륨:
    /나트륨.*?(\d+)mg/i
    /Sodium.*?(\d+)mg/i


5단계: 데이터 검증
-----------------
  합리성 체크:
    [✓] 칼로리 = 4×탄수화물 + 4×단백질 + 9×지방
    [✓] 범위 체크 (0 < 값 < 1000)
    [✓] 단위 일치 (g, mg, kcal)

  신뢰도 점수:
    높음 (>90%): 자동 적용
    중간 (70-90%): 사용자 확인
    낮음 (<70%): 수동 입력 권장


OCR 정확도 향상
==============

촬영 기술:
  ✓ 영양 성분표만 집중
  ✓ 손떨림 방지 (버튼 대신 타이머)
  ✓ 수직 촬영
  ✓ 그림자 제거

라벨 유형별 최적화:
  • 한글 라벨: Tesseract kor
  • 영문 라벨: Tesseract eng
  • 혼합: 다국어 모드

후처리:
  • 잘못된 문자 교정
    O → 0 (숫자)
    l → 1
    S → 5

  • 문맥 기반 수정
    "탄수호물" → "탄수화물"
    "drotein" → "Protein"


예시: 영양 라벨 OCR
==================

입력 이미지:
  ┌────────────────────┐
  │  영양 성분 표시    │
  │  ─────────────────  │
  │  1회 제공량: 30g   │
  │  총 내용량: 300g   │
  │                    │
  │  칼로리    148kcal │
  │  탄수화물   20g    │
  │  당류      8.5g    │
  │  단백질    1.6g    │
  │  지방      6.8g    │
  │  포화지방  3.4g    │
  │  트랜스지방 0g     │
  │  콜레스테롤 5mg    │
  │  나트륨    96mg    │
  └────────────────────┘

OCR 결과:
  {
    "serving_size": "30g",
    "total_size": "300g",
    "calories": 148,
    "carbs": 20,
    "sugar": 8.5,
    "protein": 1.6,
    "fat_total": 6.8,
    "fat_saturated": 3.4,
    "fat_trans": 0,
    "cholesterol": 5,
    "sodium": 96
  }

검증:
  계산 칼로리 = 20×4 + 1.6×4 + 6.8×9
              = 80 + 6.4 + 61.2
              = 147.6 kcal
  실제 칼로리 = 148 kcal
  차이 = 0.27% ✓ 합격

4.4 식사 사진 촬영 가이드라인

완벽한 식사 사진 촬영법
======================

1. 각도와 거리
-------------
  [권장] 정면 또는 45° 각도
    • 음식 전체 보이도록
    • 너무 위에서 찍으면 깊이 소실
    • 너무 옆에서 찍으면 일부 가려짐

  [권장] 30-60cm 거리
    • 너무 가까우면 일부만
    • 너무 멀면 디테일 손실


2. 조명
-------
  [최고] 자연광
    • 창가 또는 야외
    • 부드러운 음영

  [좋음] 실내 조명
    • 흰색 LED
    • 여러 방향에서

  [피할 것] 직사광
    • 강한 그림자
    • 과다 노출

  [피할 것] 플래시
    • 반사
    • 부자연스러운 색


3. 배경
-------
  [최고] 단색 배경
    • 흰색 접시
    • 나무 테이블
    • 단색 테이블 매트

  [피할 것] 복잡한 배경
    • 패턴있는 식탁보
    • 너무 많은 물건


4. 구도
-------
  중앙 배치:
    ┌────────────────┐
    │                │
    │    🍽️          │
    │   음식         │
    │                │
    └────────────────┘

  참조 물체 포함:
    ┌────────────────┐
    │  🍽️    🥄      │
    │  음식  숟가락   │
    │                │
    └────────────────┘
    → 크기 추정에 도움


5. 다중 각도 (선택)
-----------------
  각도 1: 정면
    • 전체 뷰

  각도 2: 측면
    • 높이/두께 확인

  각도 3: 근접
    • 재료 디테일


촬영 체크리스트
==============

촬영 전:
  □ 접시에 음식 담기 완료
  □ 양념, 소스 추가 완료
  □ 장식, 고명 배치
  □ 주변 정리 (불필요한 물건 제거)

촬영 시:
  □ 밝은 곳 확인
  □ 카메라 안정 (손떨림 방지)
  □ 수평 맞추기
  □ 전체 음식이 프레임에

촬영 후:
  □ 사진 확인 (흐릿하지 않은지)
  □ 재촬영 필요 시 바로
  □ 여러 장 찍기 (최고의 것 선택)


음식 유형별 팁
=============

국/찌개:
  • 그릇 가득 차지 않도록
  • 건더기 보이게
  • 김 올라오는 모습

샐러드:
  • 색감 강조
  • 재료 다양성 보이게
  • 드레싱 전 또는 후

고기/생선:
  • 단면 보이게 (필요 시 자르기)
  • 익힌 정도 확인
  • 결 보이게

면 요리:
  • 면 들어올리기 (동적)
  • 국물과 건더기 함께
  • 색감 대비

디저트:
  • 데코레이션 강조
  • 층 보이게
  • 윤기 표현


실패 사진 vs 성공 사진
====================

[X] 실패 사진:
  • 흐릿함 (손떨림)
  • 너무 어두움
  • 일부만 보임
  • 각도 이상함
  • 색이 왜곡됨

[✓] 성공 사진:
  • 선명함
  • 밝고 자연스러움
  • 전체가 보임
  • 자연스러운 각도
  • 실제 색감

4.5 이미지 전처리 및 최적화

이미지 최적화 파이프라인
=======================

1단계: 리사이징
--------------
  목적: 처리 속도 향상, 저장 공간 절약

  권장 크기:
    분석용: 1024 × 1024 px
    썸네일: 256 × 256 px
    원본 보관: 원본 크기 (선택)

  방법:
    • 비율 유지 리사이징
    • Lanczos 또는 Bicubic 보간법
    • 품질 손실 최소화


2단계: 압축
----------
  JPEG 압축:
    품질 85-90
    파일 크기 감소 60-80%

  WebP (최신):
    품질 80
    JPEG 대비 30% 더 작음
    브라우저 지원 확인


3단계: 색상 보정
---------------
  자동 화이트 밸런스:
    • 색온도 조정
    • 자연스러운 색감

  대비 향상:
    • 히스토그램 평활화
    • 음식 더 선명하게

  채도 조정:
    • 약간 높이기 (+10%)
    • 과하지 않게


4단계: 노이즈 제거
-----------------
  Non-local means denoising
    • 저조도 사진
    • 디지털 노이즈 제거

  Bilateral filter
    • 엣지 보존
    • 부드러운 배경


5단계: 샤프닝
------------
  Unsharp mask
    • 음식 윤곽 강조
    • 디테일 향상
    • 과도하지 않게 (자연스러움 유지)


메타데이터 추가
==============

EXIF 데이터:
  • 촬영 일시
  • 카메라 정보
  • GPS (선택적, 프라이버시)

커스텀 메타데이터:
  • 식사 시간 (아침/점심/저녁/간식)
  • 위치 (집/식당/카페)
  • 동반자 수
  • 분위기 (일상/특별)


품질 평가
========

자동 품질 체크:
  [1] 선명도
      Laplacian variance > 100

  [2] 밝기
      평균 밝기 50-200 (0-255 scale)

  [3] 대비
      표준편차 > 30

  [4] 음식 감지
      AI 모델로 음식 존재 확인

품질 점수:
  90-100: 우수 ⭐⭐⭐⭐⭐
  70-89:  양호 ⭐⭐⭐⭐
  50-69:  보통 ⭐⭐⭐
  < 50:   재촬영 권장


최적화 전후 비교
===============

원본:
  크기: 4.2 MB (4032×3024)
  품질: 원본

최적화 후:
  크기: 180 KB (1024×768)
  품질: 95% 유지
  감소율: 95.7%
  로딩 시간: 23배 빠름


배치 처리
========

여러 사진 동시 처리:
  1. 큐에 추가
  2. 백그라운드 처리
  3. 완료 시 알림
