Chapter 4

Latency Engineering and Optimization

Mastering the critical art of achieving ultra-low latency for natural HMI control

4.1 Why Latency Matters in HMI

Latency - the time delay between signal generation and response - is perhaps the most critical performance metric in human-machine interfaces. While many computer systems can tolerate hundreds of milliseconds of delay, HMI systems must respond within the timeframe of natural biological reflexes to feel intuitive and controllable.

Consider reaching for a coffee cup. Your brain sends motor commands, your arm moves, and you continuously adjust based on visual and proprioceptive feedback - all happening in a tightly-coupled loop with delays measured in tens of milliseconds. If an augmentation device introduces significant additional latency, the control loop breaks down. Users report sensations ranging from subtle "lag" to complete loss of embodiment where the device feels alien rather than like part of their body.

Perceptual Thresholds for Latency

  • <10ms: Imperceptible. Device feels like natural body part.
  • 10-20ms: Detectable by trained users but generally acceptable.
  • 20-50ms: Noticeable lag. Fine motor control degraded but gross movements okay.
  • 50-100ms: Significant lag. Control loops unstable. Requires conscious compensation.
  • >100ms: Severe lag. Most users cannot adapt. Device feels disconnected from intent.

4.2 WIA-AUG-014 Latency Tiers

Recognizing that different applications have different latency requirements, WIA-AUG-014 defines four latency tiers. Devices must declare which tier(s) they support and demonstrate compliance through standardized testing.

Tier Max Latency Applications Example Use Cases
Tier 1 <10ms Motor control, balance, postural control, reflex-like responses Prosthetic hand grip, exoskeleton balance assist, BCI cursor control
Tier 2 <50ms Sensory feedback, grip force modulation, interactive control Haptic feedback in prosthetics, force-sensitive manipulation
Tier 3 <100ms User interface interactions, menu navigation, non-critical adjustments Device settings, mode switching, status displays
Tier 4 <500ms Status updates, analytics data, configuration changes Battery status, usage statistics, firmware updates

4.3 Latency Budget Breakdown

Understanding where latency comes from is essential to optimization. The total latency budget must be allocated across multiple stages in the signal processing pipeline. Let's examine the breakdown for a Tier 1 system targeting 10ms total latency: 

Tier 1 Latency Budget (10ms total):

┌────────────────────────┬──────────┐
│ Signal Acquisition     │   2ms    │  ← ADC conversion, electrode impedance
├────────────────────────┼──────────┤
│ Preprocessing          │   1ms    │  ← Filtering, artifact removal
├────────────────────────┼──────────┤
│ Encoding/Compression   │   1ms    │  ← Signal packet formation
├────────────────────────┼──────────┤
│ Transmission           │   2ms    │  ← Physical layer + protocol overhead
├────────────────────────┼──────────┤
│ Decoding               │   1ms    │  ← Decompression, error checking
├────────────────────────┼──────────┤
│ Motor Execution        │   3ms    │  ← Command to actual motion
├────────────────────────┼──────────┤
│ TOTAL                  │  10ms    │
└────────────────────────┴──────────┘

This budget is extremely tight. Every component must be optimized, and there's no room for inefficiency. A single poorly-chosen algorithm or unnecessary data copy can push the system out of spec.

4.4 Latency Measurement Protocol

WIA-AUG-014 mandates a rigorous latency measurement protocol for certification. Systems must demonstrate consistent performance across diverse conditions. 

interface LatencyMeasurement {
  measurementId: string;
  tier: 1 | 2 | 3 | 4;

  components: {
    acquisition: number;          // ms
    processing: number;           // ms
    encoding: number;             // ms
    transmission: number;         // ms
    decoding: number;             // ms
    execution: number;            // ms
  };

  total: number;                  // ms
  jitter: number;                 // ms (standard deviation)
  percentile_50: number;          // Median latency
  percentile_95: number;          // 95th percentile
  percentile_99: number;          // 99th percentile
  compliance: boolean;            // Met tier requirement?
  timestamp: Date;
  conditions: {
    signalType: string;
    channelCount: number;
    sampleRate: number;
    cpuLoad: number;              // 0-100%
    batteryLevel: number;         // 0-100%
  };
}

// Test must pass these criteria for certification:
// - Mean latency < tier requirement
// - 95th percentile < tier requirement * 1.2
// - 99th percentile < tier requirement * 1.5
// - Jitter < tier requirement * 0.3
// - Sustained for 10 minutes minimum
// - Under varied load conditions

4.5 Optimization Techniques: Signal Acquisition

The signal acquisition stage is where latency first appears. Every design choice affects the eventual total.

ADC Selection and Configuration

Modern analog-to-digital converters introduce latency through conversion time and group delay in their digital filters. Successive-approximation (SAR) ADCs offer the lowest latency (typically <1μs per sample) but require external filtering. Sigma-delta ADCs provide excellent noise performance but higher latency (typically 1-10ms depending on decimation filter).

ADC Latency Optimization

  • Choose SAR over Sigma-Delta for Tier 1: Accept slightly higher noise for dramatically lower latency
  • Minimize decimation filter length: Each additional tap adds delay. Use minimal filter that meets SNR requirements
  • Pipeline conversions: Start next conversion immediately after previous completes
  • Use simultaneous sampling: For multi-channel systems, sample all channels at once rather than multiplexing

Buffering Strategy

Many systems introduce unnecessary latency through excessive buffering. While buffers smooth out timing jitter, they add delay. For Tier 1 applications, minimal buffering is essential:

  • Single-sample processing: Process each sample immediately rather than waiting for a buffer to fill
  • Circular buffers: When buffering is necessary, use circular buffers to minimize memory allocation overhead
  • DMA transfers: Use direct memory access to move data from ADC to processor without CPU involvement

4.6 Optimization Techniques: Processing and Algorithms

Signal processing algorithms vary dramatically in their latency characteristics. The same filter implemented different ways can have 10x difference in delay.

Causal vs. Non-Causal Filtering

Non-causal filters look at future samples to make decisions about current samples. This is fine for offline analysis but introduces latency in real-time systems. WIA-AUG-014 requires strictly causal implementations for Tier 1/2 applications.

Filter Latency Comparison

Filter Type Group Delay Suitable For
IIR (Butterworth, 4th order) ~2 samples Tier 1, very low latency
FIR (Linear phase, 64 taps) 32 samples Tier 2/3, low distortion needed
Wavelet (5-level decomposition) Variable, ~50-100 samples Tier 3/4, offline analysis
Zero-phase FIR (offline) N/A (non-causal) Research only, not real-time

Computational Optimization

Processing time directly contributes to latency. Every microsecond saved in computation reduces total latency.

  • Fixed-point arithmetic: For embedded systems, fixed-point operations are 5-10x faster than floating-point
  • Lookup tables: Pre-compute expensive functions (sin, exp, sqrt) and store in tables
  • SIMD instructions: Process multiple samples simultaneously using vector instructions
  • Hardware acceleration: Offload FFT, filtering to dedicated DSP or FPGA hardware
  • Algorithm selection: Choose O(n) algorithms over O(n²) even if constant factors are higher

4.7 Optimization Techniques: Communication

Transmission latency depends on physical layer choice, protocol overhead, and data packetization strategy.

Packet Size Optimization

Larger packets amortize protocol overhead but increase latency by requiring more samples before transmission: 

Example: 1000 Hz sample rate

Small packets (10 samples):
  - Packet every 10ms
  - Average latency: 5ms (waiting for packet to fill)
  - Protocol overhead: 10% (frequent headers)

Large packets (100 samples):
  - Packet every 100ms
  - Average latency: 50ms (waiting for packet to fill)
  - Protocol overhead: 1% (amortized headers)

Optimal for Tier 1: 2-5 samples per packet
  - Packet every 2-5ms
  - Average latency: 1-2.5ms
  - Protocol overhead: 3-5% (acceptable)

Priority Queuing

When multiple data streams share a physical link, priority queuing ensures low-latency streams aren't delayed by bulk transfers: 

interface PriorityQueue {
  queues: {
    critical: Queue<Packet>;      // Tier 1, always sent first
    high: Queue<Packet>;          // Tier 2, sent if no critical
    normal: Queue<Packet>;        // Tier 3, sent if no high
    bulk: Queue<Packet>;          // Tier 4, sent in idle time
  };

  // Strict priority: Always serve higher priority first
  // With starvation prevention: Bulk gets minimum bandwidth
  minBulkBandwidth: number;       // bytes/second
}

4.8 Jitter: The Hidden Enemy

Jitter - variability in latency - can be as problematic as absolute latency. A system that delivers packets in 8ms, 12ms, 9ms, 15ms is worse than one that consistently delivers in 10ms. Jitter causes control instability and perceptual artifacts.

Sources of Jitter

  • OS scheduling: Non-real-time operating systems introduce variable delays. Real-time OS or bare-metal programming essential for Tier 1.
  • Wireless retransmissions: Packet loss and retransmission cause large jitter spikes. Use FEC instead of ARQ.
  • Garbage collection: Languages with GC (Java, Python) experience pause spikes. Use C/C++/Rust for low-jitter.
  • Interrupt sharing: High-priority HMI interrupts competing with lower-priority device interrupts.

Jitter Mitigation

WIA-AUG-014 requires jitter < 30% of tier latency budget (e.g., <3ms for Tier 1):

  • Real-time OS with priority inheritance: Prevent priority inversion
  • Dedicated processing cores: Pin HMI threads to isolated CPU cores
  • Playout buffers: Trade small constant latency increase for jitter reduction
  • Clock synchronization: Use PTP or GPS to synchronize distributed clocks

Key Takeaways

  • Latency is the most critical HMI performance metric; >20ms delay noticeably degrades control quality
  • WIA-AUG-014 defines four latency tiers from Tier 1 (<10ms) to Tier 4 (<500ms)
  • Total latency must be budgeted across acquisition, processing, transmission, and execution stages
  • Tier 1 systems require SAR ADCs, IIR filters, minimal buffering, and real-time OS
  • Jitter (latency variability) is as important as mean latency; systems must maintain consistent timing
  • Certification requires demonstrating sustained low latency under varied conditions for 10+ minutes
  • Every design choice affects latency: ADC type, filter selection, packet size, OS, programming language
