Data Formats and File Standards

Understanding the essential file formats used in genome sequencing workflows, from raw reads to final variant calls, and mastering their structure and applications.

4.1 The Genomic Data Ecosystem

Genome sequencing generates a complex hierarchy of data types, each serving specific purposes in the analysis pipeline. From the moment DNA molecules pass through a sequencer to the final clinical report, data transforms through multiple standardized formats. Understanding these formats is essential for anyone working with genomic data, as they form the foundation of bioinformatics analysis and enable interoperability between different tools and platforms.

The WIA-BIO-002 standard mandates strict adherence to established file format specifications to ensure data quality, reproducibility, and seamless integration across different analysis platforms. These formats have evolved over decades, refined by the genomics community to balance human readability, computational efficiency, and storage optimization. Each format represents the collective wisdom of thousands of researchers and millions of sequencing runs.

Genomic Data Format Hierarchy: RAW DATA LAYER ├─ FASTQ (Sequence Reads) │ └─ Per-base quality scores │ └─ Sample: 50-200 GB compressed │ ALIGNMENT LAYER ├─ SAM (Sequence Alignment/Map) │ └─ Human-readable text format ├─ BAM (Binary Alignment/Map) │ └─ Compressed binary: 30-80 GB └─ CRAM (Compressed Reference Alignment) └─ Reference-based: 15-40 GB VARIANT LAYER ├─ VCF (Variant Call Format) │ └─ Text format: 100-500 MB ├─ BCF (Binary Call Format) │ └─ Binary compressed variant calls └─ gVCF (Genomic VCF) └─ All positions including non-variants ANNOTATION LAYER ├─ BED (Browser Extensible Data) │ └─ Genomic intervals and features ├─ GFF/GTF (General Feature Format) │ └─ Gene annotations └─ BigWig/BigBed └─ Binary indexed coverage tracks

4.2 FASTQ Format: The Foundation

FASTQ represents the starting point of virtually all modern sequencing analysis pipelines. This deceptively simple format encapsulates both the nucleotide sequence and the confidence we have in each base call. Originally developed at the Wellcome Trust Sanger Institute, FASTQ has become the universal standard for representing raw sequencing reads.

4.2.1 FASTQ Structure and Encoding

@SEQ_ID:INSTRUMENT:RUN:FLOWCELL:LANE:TILE:X:Y 1:N:0:ATCACG
GATTTGGGGTTCAAAGCAGTATCGATCAAATAGTAAATCCATTTGTTCAACTCACAGTTTGCTAGCTGAACGA
+
!''*((((***+))%%%++)(%%%%).1***-+*''))**55CCF>>>>>>CCCCCCC65!!!!!IIIIIIII

Line 1: @SEQ_ID [Header]
  - Sequence identifier with metadata
  - Read number, filter status, index
Line 2: Nucleotide sequence [ACGTN]
Line 3: + [Separator]
Line 4: Quality scores [ASCII Phred+33]
ASCII Character Phred Score Accuracy Error Rate
! Q0 0% 1 in 1
+ Q10 90% 1 in 10
5 Q20 99% 1 in 100
? Q30 99.9% 1 in 1,000
I Q40 99.99% 1 in 10,000

4.3 SAM/BAM/CRAM: Alignment Formats

After sequencing reads are aligned to a reference genome, the results are stored in Sequence Alignment/Map (SAM) format or its compressed variants. These formats represent one of the most significant achievements in bioinformatics standardization, enabling universal compatibility across hundreds of analysis tools.

4.3.1 SAM Format Structure

SAM Header:
@HD VN:1.6  SO:coordinate
@SQ SN:chr1 LN:248956422
@RG ID:SAMPLE1  PL:ILLUMINA SM:PATIENT001

Alignment (11 mandatory fields):
QNAME FLAG RNAME POS MAPQ CIGAR RNEXT PNEXT TLEN SEQ QUAL
FLAG Bit Value Description
0x1 1 Read paired
0x2 2 Proper pair
0x4 4 Read unmapped
0x10 16 Reverse strand
0x400 1024 PCR duplicate

4.3.2 CIGAR String Operations

CIGAR: 10S65M3I8M2D14M

Operations:
M = Match/mismatch
I = Insertion to reference
D = Deletion from reference
S = Soft clip (sequence present)
H = Hard clip (sequence absent)
N = Skipped region (intron)

Example:
50M2I24M = 50 match, 2bp insertion, 24 match

4.4 VCF Format: Variant Calls

The Variant Call Format (VCF) is the standard for representing genetic variants discovered through sequencing. VCF files encode variant positions, alleles, quality metrics, and sample genotypes in a standardized structure. 

##fileformat=VCFv4.3
##reference=hg38
#CHROM POS ID REF ALT QUAL FILTER INFO FORMAT SAMPLE1
chr1 123456 rs123 A G 100 PASS DP=50;AF=0.5 GT:GQ:DP 0/1:99:50
chr1 234567 . GCAT G 85 PASS DP=45 GT:GQ:DP 0/1:85:45

Genotypes:
0/0 = Homozygous reference
0/1 = Heterozygous
1/1 = Homozygous alternate
./. = Missing
0|1 = Phased heterozygous

4.5 BED Format: Genomic Intervals

BED (Browser Extensible Data) format defines genomic regions using a simple tab-delimited structure. Critical: BED uses 0-based coordinates, unlike VCF and SAM which use 1-based coordinates. 

Minimal BED (3 fields):
chr1  1000  2000

Standard BED (6 fields):
chr1  1000  2000  GENE1  100  +

Coordinate Systems:
VCF: chr1:1000 (1-based) → The 1000th base
BED: chr1:999-1000      → The 1000th base
SAM: POS=1000 (1-based) → The 1000th base

4.7 Data Validation Standards

The WIA-BIO-002 standard requires robust validation for all genomic data files. Validation catches format errors before they propagate through analysis pipelines.

FASTQ Validation

  • Sequence and quality lengths match exactly
  • Quality scores within valid ASCII range (33-126)
  • Exactly 4 lines per read
  • Valid nucleotide codes (ACGTN)
  • Paired files have identical read counts

BAM Validation

  • Valid header with @HD, @SQ, @RG
  • All chromosomes defined in header
  • Valid CIGAR strings
  • FLAG values logically consistent
  • Proper coordinate sorting

VCF Validation

  • REF allele matches reference genome
  • ALT alleles differ from REF
  • Genotypes consistent with alleles
  • Positions properly sorted
  • All INFO/FORMAT fields defined in header

Key Takeaways

  • FASTQ format combines sequence data with per-base quality scores using Phred+33 encoding, forming the foundation of all sequencing pipelines.
  • SAM/BAM/CRAM hierarchy provides increasingly compressed alignment storage: SAM for readability, BAM for analysis, CRAM for archival (50% smaller than BAM).
  • FLAG and CIGAR strings encode critical alignment properties; understanding these is essential for quality filtering and variant calling.
  • VCF format standardizes variant representation with quality metrics, genotypes, and annotations in a universally compatible structure.
  • BED format uses 0-based coordinates while VCF and SAM use 1-based coordinates—a critical distinction that frequently causes off-by-one errors.
  • File format validation is mandatory in WIA-BIO-002 compliant systems to prevent errors from propagating through analysis pipelines.
  • Format selection impacts performance: choose BAM for active analysis, CRAM for long-term storage, and validate all files before processing.
