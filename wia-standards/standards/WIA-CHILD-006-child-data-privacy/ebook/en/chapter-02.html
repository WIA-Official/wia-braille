CHAPTER 02

COPPA Compliance Framework

Understanding COPPA: The Foundation of Child Privacy Law

The Children's Online Privacy Protection Act (COPPA), enacted in 1998 and enforced by the Federal Trade Commission (FTC), represents the cornerstone of child privacy protection in the United States. COPPA applies to operators of commercial websites and online services that are directed to children under 13 years of age, or that have actual knowledge they are collecting personal information from children under 13.

COPPA's reach extends far beyond simple websites. It covers mobile apps, gaming platforms, social media services, connected devices (IoT), voice assistants, educational technology platforms, and any digital service that collects, uses, or discloses personal information from children. With penalties reaching up to $50,120 per violation (as of 2025), COPPA compliance is both a legal imperative and a significant financial consideration.

The WIA-CHILD-006 standard provides comprehensive tools and frameworks to achieve and maintain COPPA compliance while exceeding minimum requirements to ensure maximum child protection.

COPPA Enforcement Actions

Recent high-profile COPPA enforcement actions demonstrate the FTC's commitment to child privacy:

  • YouTube (2019): $170 million settlement for collecting personal information from children without parental consent
  • TikTok (2019): $5.7 million penalty for illegally collecting personal information from children under 13
  • Amazon (2023): $30.8 million for retaining children's Alexa voice recordings beyond legal requirements
  • Educational Apps (2022-2024): Multiple settlements totaling over $50 million for privacy violations in educational technology platforms

The Six Pillars of COPPA Compliance

COPPA compliance rests on six fundamental requirements that organizations must implement comprehensively:

Pillar Requirement Implementation Approach
1. Privacy Policy Notice Post clear, comprehensive privacy policy describing information practices Age-appropriate language, prominent placement, detailed disclosure of all data practices
2. Direct Notice to Parents Provide direct notice to parents before collecting child's personal information Email notification with complete disclosure, opportunity to review before collection begins
3. Verifiable Parental Consent Obtain verifiable consent from parents before collection, use, or disclosure Use approved methods: credit card, government ID, video conference, or knowledge-based authentication
4. Parental Access Rights Provide parents ability to review child's personal information Secure parent portal, data export functionality, 30-day response timeframe
5. Conditional Participation Cannot condition child's participation on collecting more information than necessary Tiered service model, optional vs. required data fields, data minimization by default
6. Data Security Maintain reasonable security procedures to protect collected information Encryption, access controls, security audits, incident response plans

Verifiable Parental Consent Methods

COPPA requires "verifiable parental consent" - a mechanism designed to ensure that the person providing consent is actually the child's parent or guardian. The FTC recognizes several methods as acceptable, each with different cost, friction, and security characteristics:

FTC-Approved Consent Methods

Method How It Works Pros Cons
Credit Card Verification Parent provides credit card information (small charge or validation) High verification confidence, widely available, automated Friction in user experience, excludes non-card holders, privacy concerns
Government ID Verification Parent uploads government-issued photo ID for verification Very high confidence, no financial transaction required High friction, privacy concerns, requires manual or AI review
Video Conference Live video call with trained staff to verify parent identity Personal touch, high confidence, can answer questions High cost, not scalable, scheduling friction
Knowledge-Based Authentication Series of questions based on public records that only parent would know No document upload, good user experience Less secure, data breach risks, excludes some demographics
Email Plus (for limited data) Email to parent + additional verification step Low friction, widely accessible Only for limited data collection (email address, name for internal use)

The WIA-CHILD-006 framework implements a hybrid approach that offers multiple consent methods while maintaining security and compliance:

import { ConsentManager, ConsentMethod } from '@wia/WIA-CHILD-006-child-data-privacy'; const consentManager = new ConsentManager({ // Configure available consent methods based on data collection scope availableMethods: [ ConsentMethod.CREDIT_CARD, // For full data collection ConsentMethod.GOVERNMENT_ID, // Alternative for full collection ConsentMethod.EMAIL_PLUS // For limited internal use only ], // Security settings requiresSecondaryAuth: true, // Multi-factor verification verificationExpiration: '12months', // Annual re-verification // Compliance settings ftcCompliant: true, gdprCompliant: true, logAllConsents: true // Maintain audit trail }); async function requestParentalConsent(childInfo, dataCollectionScope) { try { // Determine appropriate consent method based on data collection const consentMethod = determineConsentMethod(dataCollectionScope); // Create consent request const consentRequest = await consentManager.createRequest({ childId: childInfo.tempId, parentEmail: childInfo.parentEmail, parentPhone: childInfo.parentPhone, // Optional secondary contact // Detailed disclosure of data practices dataCollection: { types: dataCollectionScope.dataTypes, purposes: dataCollectionScope.purposes, retentionPeriod: dataCollectionScope.retention, thirdPartySharing: dataCollectionScope.thirdParties || [], geographicStorage: dataCollectionScope.storage }, // Consent method configuration method: consentMethod, allowMethodSelection: true, // Let parent choose from available methods // Notification preferences sendReminders: true, reminderSchedule: ['1day', '3days', '7days'] }); // Send direct notice to parent await consentManager.sendDirectNotice({ requestId: consentRequest.id, parentEmail: childInfo.parentEmail, includePrivacyPolicy: true, includeConsentDeadline: '14days' }); // Return consent request for tracking return { requestId: consentRequest.id, status: 'pending', createdAt: new Date().toISOString(), expiresAt: consentRequest.expirationDate }; } catch (error) { console.error('Consent request failed:', error); throw new ConsentError('Failed to initiate parental consent', error); } } function determineConsentMethod(scope) { // Limited data collection (email, name for internal use only) if (scope.limitedInternalUse) { return ConsentMethod.EMAIL_PLUS; } // Full data collection or third-party sharing return ConsentMethod.CREDIT_CARD; // Default to highest security } // Example: Waiting for and verifying consent async function waitForConsent(requestId) { const consent = await consentManager.pollForConsent({ requestId: requestId, timeout: '14days', checkInterval: '1hour' }); if (consent.status === 'approved') { // Verify consent integrity const verified = await consentManager.verifyConsent(consent.id); if (!verified.valid) { throw new ConsentError('Consent verification failed: ' + verified.reason); } // Store consent proof await consentManager.storeConsentProof({ consentId: consent.id, childId: consent.childId, parentId: consent.parentId, method: consent.method, timestamp: consent.approvedAt, ipAddress: consent.ipAddress, userAgent: consent.userAgent, verificationData: verified.proof }); return consent; } else { throw new ConsentError('Parental consent was not granted'); } }

Privacy Policy Requirements

COPPA requires a comprehensive privacy policy that goes beyond generic disclosure. The policy must be written in clear, understandable language and posted prominently on your website or app.

Required Privacy Policy Elements

Privacy Policy Checklist

  1. Operator Contact Information: Name, address, phone number, and email of all operators collecting information
  2. Types of Information Collected: Detailed list of all personal information collected from children (name, email, photos, location, etc.)
  3. Collection Methods: How information is collected (forms, cookies, passive tracking, etc.)
  4. Use of Information: All purposes for which collected information will be used
  5. Disclosure Practices: Whether information is disclosed to third parties, and if so, which types of third parties and for what purposes
  6. Parental Rights: Clear explanation of parents' right to review, delete, and refuse further collection of their child's information
  7. Contact Procedures: How parents can contact the operator to exercise their rights
  8. Conditional Participation: Statement that no child will be required to provide more information than reasonably necessary to participate

Implementing Parental Access Rights

COPPA grants parents specific rights to review, modify, and delete their children's personal information. Organizations must provide mechanisms to facilitate these rights within reasonable timeframes.

import { ParentalAccessControl } from '@wia/WIA-CHILD-006-child-data-privacy'; class ParentalDashboard { constructor() { this.accessControl = new ParentalAccessControl({ responseTimeframe: '30days', // Maximum time to respond to requests secureAuth: true, // Require authentication to access data auditLogging: true // Log all access and modifications }); } // Allow parent to review all child's data async reviewChildData(parentId, childId) { // Verify parent-child relationship const verified = await this.accessControl.verifyRelationship({ parentId: parentId, childId: childId }); if (!verified.authorized) { throw new AccessError('Unauthorized access attempt'); } // Retrieve all child's personal information const childData = await this.accessControl.retrieveChildData({ childId: childId, includeMetadata: true, // Collection timestamps, purposes, etc. format: 'structured' // Machine-readable format }); // Log access for audit trail await this.accessControl.logAccess({ parentId: parentId, childId: childId, action: 'review_data', timestamp: new Date().toISOString() }); return { personalInfo: childData.profile, activityLogs: childData.activities, thirdPartyDisclosures: childData.disclosures, collectionHistory: childData.history, consents: childData.consents }; } // Allow parent to modify child's data async modifyChildData(parentId, childId, modifications) { const verified = await this.accessControl.verifyRelationship({ parentId: parentId, childId: childId }); if (!verified.authorized) { throw new AccessError('Unauthorized modification attempt'); } // Apply modifications with validation const result = await this.accessControl.updateChildData({ childId: childId, modifications: modifications, validateChanges: true, preserveHistory: true // Keep audit trail of modifications }); // Notify affected systems of data change await this.accessControl.notifyDataChange({ childId: childId, modifiedFields: Object.keys(modifications), reason: 'parental_modification' }); return result; } // Allow parent to delete child's account and all data async deleteChildAccount(parentId, childId, reason) { const verified = await this.accessControl.verifyRelationship({ parentId: parentId, childId: childId }); if (!verified.authorized) { throw new AccessError('Unauthorized deletion attempt'); } // Comprehensive data deletion const deletionResult = await this.accessControl.deleteAllData({ childId: childId, scope: 'complete', // Delete from all systems includeBackups: true, includeThirdParties: true, // Request deletion from third parties retainLegalRecords: true, // Keep consent records for compliance // Deletion verification verificationRequired: true, verificationMethod: 'email-confirmation' }); // Generate deletion certificate for parent const certificate = await this.accessControl.generateDeletionCertificate({ childId: childId, parentId: parentId, deletionDate: new Date().toISOString(), scope: deletionResult.deletedSystems, verificationHash: deletionResult.verificationHash }); // Send confirmation to parent await this.accessControl.notifyParent({ parentId: parentId, type: 'deletion_complete', certificate: certificate, reason: reason }); return { deleted: true, certificate: certificate, deletionId: deletionResult.id }; } // Allow parent to stop further data collection async revokeConsent(parentId, childId) { const verified = await this.accessControl.verifyRelationship({ parentId: parentId, childId: childId }); if (!verified.authorized) { throw new AccessError('Unauthorized consent revocation'); } // Revoke consent and stop collection await this.accessControl.revokeConsent({ childId: childId, effectiveImmediately: true, notifyAllSystems: true }); // Place account in limited mode or delete await this.accessControl.limitAccount({ childId: childId, allowedActivities: ['view-only'], // No new data collection displayNotice: 'Consent revoked - limited functionality' }); return { consentRevoked: true, effectiveDate: new Date().toISOString(), accountStatus: 'limited' }; } }

Data Security and Breach Response

COPPA requires operators to maintain "reasonable security procedures" to protect children's personal information. While COPPA doesn't prescribe specific security measures, best practices and recent enforcement actions provide clear guidance.

Required Security Measures

  • Encryption: All child data must be encrypted at rest (AES-256) and in transit (TLS 1.3+)
  • Access Controls: Role-based access control (RBAC) with principle of least privilege
  • Authentication: Multi-factor authentication for all systems accessing child data
  • Audit Logging: Comprehensive logging of all data access, modifications, and deletions
  • Security Audits: Annual third-party security audits and penetration testing
  • Incident Response: Documented incident response plan with breach notification procedures
  • Vendor Management: Security requirements for all third-party vendors with data access
  • Data Minimization: Regular purging of unnecessary data to reduce breach impact

Key Takeaways

  • COPPA applies broadly to any service collecting data from children under 13, including websites, apps, games, IoT devices, and connected services.
  • Verifiable parental consent is mandatory and must use FTC-approved methods such as credit card verification, government ID, or video conferencing.
  • Privacy policies must be comprehensive and prominent, clearly disclosing all data practices in language parents can understand.
  • Parents have extensive rights to review, modify, delete, and control their children's personal information with 30-day response timeframes.
  • Data security is non-negotiable requiring encryption, access controls, audit logging, and incident response planning.
  • Penalties are severe with fines up to $50,120 per violation, making compliance both a legal and financial imperative.
  • Conditional participation is prohibited - services cannot require children to provide more data than necessary to participate.
