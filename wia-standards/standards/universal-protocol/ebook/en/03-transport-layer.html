🚀Chapter 3: Transport Layer

3.1 Transport Abstraction

The transport layer is responsible for moving messages between endpoints. The Universal Protocol abstracts this layer so your application code doesn't need to know whether it's using HTTP, WebSocket, gRPC, or any other mechanism.

3.1.1 Transport Interface

All transports implement a common interface:

interface Transport {
  // Connection management
  connect(): Promise<void>;
  disconnect(): Promise<void>;
  isConnected(): boolean;

  // Message transmission
  send(message: Message): Promise<void>;
  receive(): AsyncIterableIterator<Message>;

  // Event handling
  on(event: string, handler: Function): void;
  off(event: string, handler: Function): void;

  // Configuration
  configure(options: TransportOptions): void;
}

3.2 HTTP Transport

HTTP is the most widely supported transport. The Universal Protocol uses HTTP for request-response patterns.

import { HTTPTransport } from '@wia/universal-protocol';

const transport = new HTTPTransport({
  baseURL: 'https://api.example.com',
  timeout: 30000,
  headers: {
    'User-Agent': 'UniversalProtocol/1.0',
    'Accept': 'application/json'
  },
  retryPolicy: {
    maxRetries: 3,
    retryDelay: 1000,
    retryOn: [408, 429, 500, 502, 503, 504]
  }
});

// RPC over HTTP
// Request: POST /rpc
// Body: {"method": "users.get", "params": {...}}
const result = await protocol.call('users.get', { id: '123' });

3.2.1 HTTP Streaming

Server-sent events (SSE) enable HTTP streaming:

const transport = new HTTPTransport({
  baseURL: 'https://api.example.com',
  streaming: {
    enabled: true,
    format: 'server-sent-events'
  }
});

// Server streams over HTTP using SSE
for await (const event of protocol.stream('notifications.subscribe')) {
  console.log('New notification:', event);
}

3.3 WebSocket Transport

WebSocket provides full-duplex communication over a single TCP connection.

import { WebSocketTransport } from '@wia/universal-protocol';

const transport = new WebSocketTransport({
  url: 'wss://api.example.com/ws',
  reconnect: {
    enabled: true,
    maxAttempts: 10,
    delay: 1000,
    maxDelay: 30000,
    backoff: 'exponential'
  },
  heartbeat: {
    enabled: true,
    interval: 30000,
    timeout: 5000
  },
  compression: true
});

const protocol = new UniversalProtocol({ transport });

3.3.1 WebSocket Features

  • Bidirectional: Client and server can send messages anytime
  • Low Latency: No HTTP overhead for each message
  • Persistent: Connection stays open for continuous communication
  • Compression: Built-in support for message compression
// Bidirectional streaming over WebSocket
const stream = protocol.createBidirectionalStream('chat');

// Send messages
stream.send({ message: 'Hello!' });

// Receive messages
stream.on('message', (data) => {
  console.log('Received:', data);
});

3.4 gRPC Transport

gRPC provides high-performance RPC with HTTP/2 and Protocol Buffers.

import { GRPCTransport } from '@wia/universal-protocol';

const transport = new GRPCTransport({
  host: 'api.example.com',
  port: 50051,
  credentials: {
    type: 'ssl',
    cert: fs.readFileSync('ca.pem')
  },
  keepalive: {
    time: 60000,
    timeout: 20000,
    permitWithoutCalls: true
  },
  compression: 'gzip'
});

const protocol = new UniversalProtocol({
  transport,
  encoding: 'protobuf' // gRPC works best with protobuf
});

3.4.1 gRPC Advantages

  • Performance: Binary protocol with efficient encoding
  • Streaming: Native support for all streaming patterns
  • Type Safety: Strong typing with Protocol Buffers
  • Code Generation: Automatic client/server code generation

3.5 MQTT Transport

MQTT is designed for IoT and constrained networks with low bandwidth.

import { MQTTTransport } from '@wia/universal-protocol';

const transport = new MQTTTransport({
  broker: 'mqtt://broker.hivemq.com',
  clientId: 'device_' + Math.random().toString(16).slice(2),
  qos: 1, // Quality of Service level
  clean: true,
  keepalive: 60,
  reconnectPeriod: 5000,
  topics: {
    request: 'devices/{deviceId}/request',
    response: 'devices/{deviceId}/response',
    events: 'devices/{deviceId}/events'
  }
});

// Publish-subscribe works naturally with MQTT
protocol.subscribe('sensor.temperature', (data) => {
  console.log('Temperature:', data.value);
});

protocol.publish('sensor.temperature', {
  deviceId: 'sensor_001',
  value: 23.5,
  unit: 'celsius'
});

3.5.1 MQTT QoS Levels

Level Name Guarantee
0 At most once Fire and forget, no acknowledgment
1 At least once Acknowledged delivery, possible duplicates
2 Exactly once Guaranteed delivery, no duplicates

3.6 Custom Transports

You can implement custom transports for specialized needs:

import { Transport } from '@wia/universal-protocol';

class CustomTCPTransport implements Transport {
  private socket: net.Socket;

  async connect(): Promise<void> {
    return new Promise((resolve, reject) => {
      this.socket = net.connect({
        host: this.config.host,
        port: this.config.port
      });

      this.socket.on('connect', () => {
        this.emit('connected');
        resolve();
      });

      this.socket.on('error', reject);
    });
  }

  async send(message: Message): Promise<void> {
    const buffer = this.serialize(message);
    const length = Buffer.alloc(4);
    length.writeUInt32BE(buffer.length, 0);

    this.socket.write(length);
    this.socket.write(buffer);
  }

  async* receive(): AsyncIterableIterator<Message> {
    for await (const chunk of this.socket) {
      const message = this.deserialize(chunk);
      yield message;
    }
  }
}

3.7 Transport Selection Guide

Transport Best For Latency Bandwidth
HTTP Web APIs, simple request-response Medium Medium
WebSocket Real-time web apps, gaming Low Low
gRPC Microservices, high-performance APIs Very Low Low
MQTT IoT, constrained networks Low Very Low
AMQP Enterprise messaging, reliability Medium Medium

3.8 Transport Multiplexing

Use multiple transports simultaneously for different purposes:

// HTTP for public API
const httpProtocol = new UniversalProtocol({
  transport: new HTTPTransport({ baseURL: 'https://api.example.com' })
});

// WebSocket for real-time features
const wsProtocol = new UniversalProtocol({
  transport: new WebSocketTransport({ url: 'wss://api.example.com/ws' })
});

// gRPC for internal microservices
const grpcProtocol = new UniversalProtocol({
  transport: new GRPCTransport({ host: 'internal.example.com', port: 50051 })
});

// Use the right protocol for each scenario
const userData = await httpProtocol.call('users.get', { id: '123' });
wsProtocol.subscribe('notifications', handleNotification);
const internalData = await grpcProtocol.call('internal.getData', params);

Transport Best Practices

  • Choose transport based on your specific requirements
  • Enable compression for large payloads
  • Implement reconnection logic for unstable networks
  • Use heartbeats to detect connection issues early
  • Monitor transport metrics (latency, throughput, errors)
  • Test your application with different transports
