WIA-COMM-015: Network Security Specification

Detecting and Preventing Network Intrusions

2.1 Introduction to IDS/IPS

Intrusion Detection Systems (IDS) and Intrusion Prevention Systems (IPS) are critical components of modern network security architecture. While traditional firewalls focus on blocking traffic based on ports and addresses, IDS/IPS solutions analyze the content and behavior of network traffic to detect and prevent sophisticated attacks that bypass conventional security controls.

An IDS operates in passive mode, monitoring network traffic and generating alerts when suspicious activity is detected. It serves as a vigilant observer, analyzing packets and flows to identify patterns that match known attack signatures or deviate from normal behavior. IDS systems provide valuable forensic data and early warning of potential security incidents.

An IPS extends IDS capabilities by operating inline within the network path, actively blocking detected threats in real-time. When malicious activity is identified, the IPS can drop packets, reset connections, or reconfigure firewall rules to prevent the attack from succeeding. This active defense capability makes IPS essential for protecting critical assets from zero-day exploits and advanced persistent threats.

IDS vs IPS: Key Differences
IDS: Passive monitoring, generates alerts, out-of-band deployment, no impact on network performance, cannot block attacks
IPS: Active prevention, blocks threats, inline deployment, potential performance impact, can stop attacks in real-time

Modern IDS/IPS solutions combine multiple detection techniques to achieve high accuracy while minimizing false positives. Signature-based detection identifies known attack patterns, anomaly-based detection discovers novel threats through behavioral analysis, and protocol analysis ensures RFC compliance and detects protocol-level attacks. By integrating these complementary approaches, contemporary IDS/IPS platforms can detect a wide spectrum of threats ranging from simple port scans to sophisticated APT campaigns.

2.2 Detection Methods

2.2.1 Signature-Based Detection

Signature-based detection is the foundation of IDS/IPS technology, operating similarly to antivirus software by matching network traffic against a database of known attack patterns. Each signature represents a specific attack technique, exploit, or malware communication pattern. When traffic matches a signature, the system generates an alert or blocks the connection.

Signatures are typically written in specialized rule languages such as Snort or Suricata syntax. These rules define the characteristics of malicious traffic including protocol types, header values, payload content, and packet sequences. Signature databases are continuously updated by security vendors and the research community as new vulnerabilities and exploits are discovered.

Example Snort Signature

alert tcp $EXTERNAL_NET any -> $HTTP_SERVERS 80 (
  msg:"SQL Injection Attempt";
  flow:to_server,established;
  content:"UNION"; nocase;
  content:"SELECT"; nocase; distance:0;
  pcre:"/(\%27)|(\')|(\-\-)|(\%23)|(#)/i";
  classtype:web-application-attack;
  sid:1000001;
  rev:1;
)

This signature detects SQL injection attempts by looking for the UNION and SELECT keywords (case-insensitive) followed by SQL comment characters in HTTP traffic. The flow keyword ensures the rule only applies to established server-bound connections, reducing false positives.

Signature Component Purpose Example
Action Defines what to do when matched alert, log, pass, drop, reject
Protocol Specifies protocol to analyze tcp, udp, icmp, ip
Source/Destination Defines traffic direction $EXTERNAL_NET any -> $HOME_NET 80
Content Matching Searches for specific patterns content:"malware"; nocase;
PCRE Advanced regex matching pcre:"/pattern/flags";
Metadata Classification and tracking sid, msg, classtype, reference

2.2.2 Anomaly-Based Detection

Anomaly-based detection identifies threats by establishing a baseline of normal network behavior and flagging deviations that exceed predefined thresholds. This approach can detect zero-day attacks and novel threat techniques that don't match known signatures. The system continuously learns from network traffic patterns to refine its understanding of normal behavior.

Statistical models track metrics such as traffic volume, connection rates, protocol distribution, and geographic patterns. Machine learning algorithms identify subtle correlations and patterns that might indicate malicious activity. For example, an unusual spike in outbound DNS queries might indicate a DNS tunneling data exfiltration attempt, while abnormal connection patterns could reveal botnet command-and-control communications.

Anomaly Detection Configuration Example

{
  "baseline": {
    "trafficVolume": {
      "mean": 1000000,
      "stdDev": 100000,
      "threshold": 3
    },
    "connectionRate": {
      "mean": 500,
      "stdDev": 50,
      "threshold": 3
    },
    "protocolDistribution": {
      "http": 0.40,
      "https": 0.45,
      "dns": 0.10,
      "other": 0.05
    },
    "geoDistribution": {
      "us": 0.50,
      "eu": 0.30,
      "asia": 0.15,
      "other": 0.05
    }
  },
  "anomalyDetected": {
    "type": "traffic-spike",
    "metric": "connectionRate",
    "current": 2500,
    "expected": 500,
    "deviation": 4.0,
    "severity": "high",
    "action": "alert",
    "timestamp": "2025-12-28T10:30:45Z"
  }
}

The challenge with anomaly-based detection is managing false positives. Legitimate business events like marketing campaigns, software updates, or seasonal traffic variations can trigger alerts. Effective tuning requires understanding business operations and continuously refining baseline models. Many organizations use anomaly detection as a complementary technique alongside signature-based detection rather than as a standalone solution.

2.2.3 Protocol Analysis

Protocol analysis, also known as stateful protocol inspection, validates that network traffic conforms to protocol specifications defined in RFCs. This technique detects attacks that exploit protocol weaknesses or use malformed packets to evade detection or crash vulnerable systems.

The IDS/IPS maintains state information about network sessions and validates that protocol exchanges follow the correct sequence. For example, HTTP protocol analysis verifies that requests use valid methods (GET, POST, etc.), headers conform to specifications, and responses match requests. DNS protocol analysis checks query and response formats, validates record types, and detects tunneling attempts.

Protocol Validation Checks Common Attacks Detected
HTTP/HTTPS Method validation, header structure, content-length SQL injection, XSS, directory traversal, HTTP smuggling
DNS Query/response format, record types, packet size DNS tunneling, cache poisoning, amplification attacks
SMTP Command sequence, RFC compliance, header validation Command injection, spam relay, email spoofing
SSL/TLS Handshake sequence, cipher suites, certificate validity Protocol downgrade, weak ciphers, certificate validation bypass
FTP Command syntax, bounce prevention, directory traversal Bounce attacks, anonymous access, command injection

2.3 IPS Response Actions

When an IPS detects malicious activity, it can execute various response actions to mitigate the threat. The appropriate action depends on the severity of the threat, confidence level of the detection, and business requirements. Organizations must carefully configure response policies to balance security effectiveness against the risk of disrupting legitimate traffic.

2.3.1 Action Types

  1. Alert: Generate a notification without blocking traffic. Used for low-confidence detections or monitoring-only scenarios. The alert is sent to SIEM systems, SOC dashboards, or email for investigation.
  2. Log: Record the event in detail for forensic analysis. Captures packet headers, payload samples, and contextual information. Logs feed into security analytics platforms for correlation and threat hunting.
  3. Drop: Silently discard the malicious packet without notifying the sender. This prevents the attack while avoiding information leakage about security controls. Dropped packets are logged for investigation.
  4. Reject: Actively terminate the connection by sending a TCP RST or ICMP unreachable message. This provides faster feedback to legitimate users experiencing false positives but reveals the presence of security controls to attackers.
  5. Quarantine: Temporarily isolate the source IP address or user account for a defined period. Useful for containing potential compromises while investigations proceed. Quarantined entities can be redirected to remediation portals.
  6. Block: Permanently add the source to a blacklist, blocking all future connections. Reserved for confirmed malicious sources like botnet controllers, known attack infrastructure, and repeat offenders.

2.3.2 Automated Response Playbooks

Modern IPS solutions integrate with Security Orchestration, Automation, and Response (SOAR) platforms to execute complex response workflows. When a high-severity threat is detected, the IPS can trigger automated playbooks that coordinate actions across multiple security systems.

  "playbook": "ransomware-detected",
  "trigger": {
    "event": "ips-alert",
    "severity": "critical",
    "category": "ransomware-activity"
  },
  "actions": [
    {
      "step": 1,
      "action": "ips-block-traffic",
      "target": "${source_ip}",
      "direction": "bidirectional",
      "duration": "permanent"
    },
    {
      "step": 2,
      "action": "firewall-quarantine",
      "target": "${source_ip}",
      "vlan": "quarantine-zone",
      "allowList": ["remediation-server"]
    },
    {
      "step": 3,
      "action": "edr-isolate-endpoint",
      "target": "${hostname}",
      "preserveForensics": true
    },
    {
      "step": 4,
      "action": "notify-incident-response",
      "channels": ["pagerduty", "slack-ir-channel"],
      "severity": "critical",
      "data": {
        "source": "${source_ip}",
        "hostname": "${hostname}",
        "user": "${username}",
        "indicators": "${iocs}",
        "timestamp": "${detection_time}"
      }
    },
    {
      "step": 5,
      "action": "threat-intel-share",
      "platforms": ["internal-tip", "isac"],
      "indicators": "${iocs}"
    }
  ]
}

2.4 Deployment Modes

2.4.1 Inline Mode (IPS)

In inline deployment, the IPS is positioned directly in the network path where all traffic must pass through it. This placement enables real-time threat blocking but introduces a potential single point of failure. Inline IPS devices typically include hardware bypass mechanisms that maintain network connectivity even if the IPS fails or is taken offline for maintenance.

Inline deployment is essential for protecting critical assets where automatic threat prevention is required. Common deployment points include internet edge, data center perimeter, and between network security zones. The IPS examines every packet and makes immediate allow/block decisions based on configured policies and threat signatures.

Inline Deployment Best Practices:
  • Deploy redundant IPS devices in high-availability pairs
  • Implement hardware bypass for network continuity during failures
  • Size IPS appropriately for peak traffic throughput
  • Monitor latency and packet loss metrics continuously
  • Test fail-open vs fail-closed behavior for your requirements
  • Plan maintenance windows for signature updates

2.4.2 Passive Mode (IDS)

Passive deployment places the IDS out-of-band, receiving a copy of network traffic via SPAN ports (port mirroring), network TAPs, or packet brokers. The IDS analyzes traffic and generates alerts but cannot block threats in real-time. This approach eliminates performance concerns and failure risks associated with inline deployment.

Passive IDS is ideal for monitoring-only scenarios, compliance requirements, and environments where inline blocking is not permitted. Security teams use IDS data for threat hunting, forensic investigations, and identifying attack trends. The detection information can trigger manual or automated responses through integration with firewalls and other security controls.

Aspect Inline IPS Passive IDS
Threat Prevention Real-time blocking Detection only
Network Impact Potential latency, single point of failure No impact on traffic flow
Response Time Immediate Delayed (requires manual/automated response)
False Positive Risk Can block legitimate traffic No service disruption
Deployment Complexity Higher (inline insertion, HA required) Lower (SPAN/TAP configuration)
Use Cases Critical asset protection, perimeter defense Monitoring, forensics, compliance, threat hunting

2.4.3 Hybrid Deployment

Many organizations implement hybrid architectures that combine inline IPS for critical traffic paths with passive IDS for comprehensive network visibility. For example, inline IPS might protect internet-facing servers and data center assets while passive IDS monitors internal network segments where blocking could disrupt operations.

This approach maximizes security effectiveness while managing risk. Critical applications receive active protection, while broader network monitoring identifies threats that require investigation or manual response. The IDS provides valuable context for security operations even in areas where automated blocking is not feasible.

2.5 Performance Optimization

IDS/IPS performance is critical for maintaining network throughput and minimizing latency. Modern threats use high-speed attack techniques that require IPS systems to analyze traffic at line speed without becoming a bottleneck. Performance optimization involves hardware acceleration, efficient signature matching algorithms, and intelligent traffic management.

Key Performance Metrics

  • Throughput: Maximum traffic rate the IPS can inspect (measured in Gbps)
  • Latency: Delay introduced by IPS processing (target: < 5ms for most applications)
  • Concurrent Connections: Number of simultaneous sessions the IPS can track
  • Packets Per Second (pps): Rate of packet processing (important for DDoS scenarios)
  • SSL Decryption Performance: Throughput when performing SSL/TLS inspection
  • Signature Loading Time: Time required to update and activate new signatures

Hardware acceleration technologies such as specialized ASICs, FPGAs, and multi-core processors enable high-performance packet processing. Pattern matching engines implement optimized algorithms like Aho-Corasick for efficient multi-pattern searching. Traffic bypass mechanisms send trusted or low-risk traffic around intensive inspection to preserve resources for high-risk analysis.

Key Takeaways

  • Complementary Detection Methods: Combining signature-based, anomaly-based, and protocol analysis detection provides comprehensive threat coverage. Signature-based detection catches known threats with high accuracy, while anomaly detection identifies novel attacks and zero-day exploits.
  • IDS vs IPS Trade-offs: IDS provides visibility without service disruption risk, while IPS offers active protection at the cost of potential performance impact and false positive consequences. Most enterprises deploy both in hybrid architectures tailored to specific network zones.
  • Signature Management: Effective IDS/IPS operation requires continuous signature updates, regular tuning to minimize false positives, and correlation with threat intelligence feeds. Outdated signatures leave systems vulnerable to new attack variants.
  • Response Action Strategy: Configure response actions based on threat severity, confidence level, and business impact. Critical threats warrant automatic blocking, while lower-severity detections may only trigger alerts for investigation.
  • Performance Considerations: IPS must operate at line speed without introducing unacceptable latency. Proper sizing, hardware acceleration, and traffic optimization are essential for maintaining network performance while providing comprehensive security.
  • Integration with Security Ecosystem: Modern IDS/IPS platforms integrate with SIEM, SOAR, threat intelligence platforms, and other security tools to enable coordinated threat response and comprehensive security analytics.
