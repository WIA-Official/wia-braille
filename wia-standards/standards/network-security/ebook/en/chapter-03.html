Chapter 3: Zero Trust Network Access

WIA-COMM-015: Network Security Specification

Never Trust, Always Verify

3.1 Zero Trust Fundamentals

Zero Trust is a security paradigm shift that eliminates the concept of trusted networks. Traditional security models assume that everything inside the corporate network is trustworthy, creating a hard perimeter with a soft interior. This approach fails in modern environments with cloud services, remote work, mobile devices, and sophisticated attackers who can breach the perimeter.

Zero Trust operates on the principle "never trust, always verify" - every access request must be authenticated, authorized, and encrypted regardless of where it originates. The model assumes breach and verifies every transaction. Users, devices, applications, and data are all treated as potentially untrusted until explicitly verified.

Core Zero Trust Principles:
1. Verify Explicitly: Always authenticate and authorize based on all available data points
2. Use Least Privilege Access: Limit access with just-in-time and just-enough-access (JIT/JEA)
3. Assume Breach: Minimize blast radius and segment access. Verify end-to-end encryption

Traditional vs Zero Trust Security Models

Aspect Traditional Perimeter Zero Trust
Trust Model Trust internal network Never trust, always verify
Verification Once at perimeter Continuous verification
Access Control Network-based (IP/Port) Identity-based + context
Segmentation Coarse-grained (VLANs) Micro-segmentation
Lateral Movement Easy once inside Severely restricted
Visibility Limited internal monitoring Comprehensive logging

The transition to Zero Trust represents a fundamental architectural change that requires rethinking network security from the ground up. Organizations must shift from network-centric to identity-centric security, implement comprehensive logging and monitoring, and embrace micro-segmentation to limit lateral movement. This transformation typically takes 18-36 months for large enterprises.

3.2 Identity Verification

3.2.1 Multi-Factor Authentication (MFA)

MFA is the cornerstone of Zero Trust identity verification. By requiring multiple independent authentication factors, MFA dramatically reduces the risk of credential compromise. Even if passwords are stolen through phishing or data breaches, attackers cannot access protected resources without additional factors.

Authentication Factors

  1. Something You Know: Passwords, PINs, security questions. Weakest factor due to vulnerability to phishing, social engineering, and database breaches. Should never be used alone in Zero Trust environments.
  2. Something You Have: Hardware security keys (YubiKey, Titan), smartphone apps (Google Authenticator, Microsoft Authenticator), SMS codes. More secure than passwords but SMS is vulnerable to SIM swapping attacks.
  3. Something You Are: Biometrics including fingerprints, facial recognition, iris scans, voice recognition. Difficult to steal but raises privacy concerns and requires specialized hardware.
  4. Somewhere You Are: Geolocation, IP address reputation, network location. Used as contextual factors to assess risk and trigger step-up authentication when unusual locations are detected.
  5. Something You Do: Behavioral biometrics including typing patterns, mouse movements, touchscreen interaction patterns. Continuous authentication that detects account takeover after initial login.

Remediation Workflows

When devices fail compliance checks, Zero Trust systems implement graduated response strategies. Minor violations may trigger warnings and require remediation within a specified timeframe, while serious violations result in immediate access denial or restriction to a quarantine network with remediation resources.

Violation Type Risk Level Response Action Remediation Required
Outdated OS patches (>7 days) Medium Limited access, warning Install updates within 24h
Antivirus disabled High Deny access Enable AV and verify running
No disk encryption High Deny access to sensitive data Enable BitLocker/FileVault
Jailbroken/Rooted device Critical Permanent block Use compliant device
MDM not enrolled High Quarantine network Complete MDM enrollment
Unknown device Critical Deny access Device registration required

3.4 Continuous Verification

Unlike traditional authentication that trusts users after initial login, Zero Trust continuously monitors sessions for anomalies. Risk scores are dynamically updated based on user behavior, location changes, resource access patterns, and threat intelligence. High-risk activities trigger step-up authentication or session termination.

3.4.1 Session Monitoring

Continuous monitoring analyzes multiple signals to detect account compromise or insider threats. Machine learning models establish behavioral baselines for each user and flag deviations. Real-time risk scoring combines these signals to make dynamic access control decisions.

Monitored Signals

  • Location Changes: Impossible travel detection (accessing from two distant locations within physically impossible timeframes)
  • Device Switching: Unusual device usage patterns or access from unrecognized devices
  • Access Patterns: Abnormal resource access, bulk data downloads, privilege escalation attempts
  • Behavioral Anomalies: Changes in typing speed, mouse movement patterns, application usage
  • Time-Based Anomalies: Access during unusual hours, weekend activity from typically weekday-only users
  • Threat Intelligence: Source IP appearing on threat feeds, malware detection, command-and-control traffic

3.4.2 Adaptive Access Policies

Zero Trust policies adapt dynamically based on risk assessment. Low-risk scenarios grant seamless access, while high-risk situations trigger additional verification. This balance maintains security without impeding legitimate user productivity.

Risk Level Access Decision Additional Controls
Low (0-30) Grant access Standard session duration (8h), normal privileges
Medium (31-60) Grant with enhanced monitoring Reduced session duration (4h), increased logging, DLP enforcement
High (61-80) Require step-up authentication MFA re-verification, limited privileges, short session (1h)
Critical (81-100) Deny or quarantine Access blocked, security team notification, investigation triggered

3.5 Least Privilege Access

Zero Trust implements the principle of least privilege, granting users the minimum permissions necessary to perform their job functions. Just-in-Time (JIT) access provides elevated privileges only when needed and only for the duration required. This approach minimizes the attack surface and limits the damage from compromised accounts.

Role-Based Access Control (RBAC) in Zero Trust

Zero Trust enhances traditional RBAC with attribute-based access control (ABAC) that considers user attributes, resource characteristics, environmental conditions, and real-time risk assessment. This dynamic approach ensures access decisions reflect current context rather than static role assignments.

Key Takeaways

  • Paradigm Shift: Zero Trust fundamentally changes security architecture from network-centric to identity-centric models. Organizations must abandon the concept of trusted internal networks and verify every access request regardless of origin.
  • Multi-Factor Authentication is Essential: MFA provides the foundation for strong identity verification in Zero Trust. Organizations should implement phishing-resistant MFA methods such as FIDO2 security keys and biometrics rather than SMS-based codes.
  • Device Security Matters: User identity alone is insufficient; device posture assessment ensures that only secure, compliant devices can access corporate resources. Compromised devices must be denied access even with valid user credentials.
  • Continuous Verification: Static authentication at login is inadequate. Zero Trust requires ongoing session monitoring and dynamic risk assessment that can trigger re-authentication or session termination when anomalies are detected.
  • Least Privilege Principle: Grant users minimal permissions necessary for their tasks. Implement just-in-time access for elevated privileges with automatic revocation after the specified duration.
  • Gradual Implementation: Zero Trust transformation is a journey, not a destination. Organizations should adopt phased approaches, starting with high-value assets and expanding coverage progressively while building expertise and refining policies.
