Digital Identity Systems

Exploring decentralized identifiers, verifiable credentials, blockchain-based solutions, and modern identity frameworks for privacy-preserving age verification.

Digital identity systems form the backbone of modern age verification infrastructure. As we move toward Web3 and decentralized technologies, traditional centralized identity systems are being replaced by user-controlled, privacy-preserving alternatives. This chapter explores how Decentralized Identifiers (DIDs), Verifiable Credentials (VCs), and blockchain-based identity solutions enable robust age verification while protecting user privacy and autonomy.

2.1 The Evolution of Digital Identity

Digital identity has evolved through several distinct phases, each addressing limitations of its predecessor while introducing new capabilities and challenges:

Generation Period Characteristics Limitations
Identity 1.0 1990s-2000s Siloed accounts per service, username/password Poor UX, password fatigue, no portability
Identity 2.0 2000s-2010s Federated identity (OAuth, SAML), social login Centralized control, tracking, vendor lock-in
Identity 3.0 2010s-present Self-sovereign identity, DIDs, verifiable credentials Adoption challenges, technical complexity
Identity 4.0 Emerging AI-enhanced, biometric, quantum-resistant Privacy concerns, regulatory uncertainty

2.2 Decentralized Identifiers (DIDs)

Decentralized Identifiers (DIDs) are a W3C standard for globally unique identifiers that enable verifiable, self-sovereign digital identity. Unlike traditional identifiers (email addresses, usernames), DIDs are owned and controlled by the subject, not by a centralized authority.

2.3 Verifiable Credentials (VCs)

Verifiable Credentials are tamper-evident credentials that can be cryptographically verified without contacting the issuing authority. For age verification, VCs enable users to prove they meet age requirements without revealing their actual date of birth or identity.

// Age Verification Credential Structure interface AgeVerificationCredential { '@context': string[]; type: string[]; issuer: { id: string; // DID of the issuing authority name: string; }; issuanceDate: string; expirationDate: string; credentialSubject: { id: string; // DID of the credential holder ageOver: number; // Minimum age attestation verificationMethod: string; verifiedAt: string; }; proof: { type: string; created: string; proofPurpose: string; verificationMethod: string; jws: string; // JSON Web Signature }; } // Example: 13+ Age Credential (COPPA compliant) const ageCredential: AgeVerificationCredential = { '@context': [ 'https://www.w3.org/2018/credentials/v1', 'https://wia-standards.org/credentials/age/v1' ], type: ['VerifiableCredential', 'AgeVerificationCredential'], issuer: { id: 'did:wia:child-002:issuer:gov-id-service', name: 'WIA Certified Age Verification Service' }, issuanceDate: '2025-01-15T10:30:00Z', expirationDate: '2026-01-15T10:30:00Z', credentialSubject: { id: 'did:wia:child-002:8zF3k9pQr2xY5tN7wM1vL6', ageOver: 13, // Only attests they are 13+ verificationMethod: 'government-id', verifiedAt: '2025-01-15T10:30:00Z' }, proof: { type: 'Ed25519Signature2020', created: '2025-01-15T10:30:00Z', proofPurpose: 'assertionMethod', verificationMethod: 'did:wia:child-002:issuer:gov-id-service#keys-1', jws: 'eyJhbGc...signature...' } }; // Age Credential Verification class AgeCredentialVerifier { async verifyAgeCredential( credential: AgeVerificationCredential, requiredAge: number ): Promise<VerificationResult> { // 1. Verify the cryptographic proof const proofValid = await this.verifyProof(credential.proof, credential.issuer.id); if (!proofValid) { return { verified: false, reason: 'Invalid cryptographic proof' }; } // 2. Check expiration const now = new Date(); const expiration = new Date(credential.expirationDate); if (now > expiration) { return { verified: false, reason: 'Credential expired' }; } // 3. Verify issuer is trusted const issuerTrusted = await this.verifyIssuerTrust(credential.issuer.id); if (!issuerTrusted) { return { verified: false, reason: 'Untrusted issuer' }; } // 4. Check age requirement if (credential.credentialSubject.ageOver < requiredAge) { return { verified: false, reason: 'Age requirement not met' }; } return { verified: true, ageVerified: credential.credentialSubject.ageOver }; } }

2.4 Self-Sovereign Identity (SSI) Principles

Self-Sovereign Identity represents a paradigm shift in digital identity, giving individuals complete control over their personal information. For children, SSI principles must be adapted to balance autonomy with protection:

  • Existence: Every user has the right to an independent digital existence
  • Control: Users control their identities (with parental oversight for minors)
  • Access: Users must have access to their own data
  • Transparency: Systems and algorithms must be transparent
  • Persistence: Identities must be long-lived
  • Portability: Identity information must be transportable
  • Interoperability: Identities should work across platforms
  • Consent: Users must consent to use of their identity
  • Minimization: Disclosure of claims must be minimized
  • Protection: Rights of users must be protected

2.5 Blockchain-Based Identity Solutions

Blockchain technology provides immutable, decentralized infrastructure for identity verification. Several approaches exist for age verification on blockchain:

// Smart Contract for Age Verification Registry pragma solidity ^0.8.0; contract AgeVerificationRegistry { // Mapping of DID hash to age verification status mapping(bytes32 => AgeVerification) private verifications; // Mapping of trusted verifier addresses mapping(address => bool) public trustedVerifiers; struct AgeVerification { uint8 ageThreshold; // e.g., 13, 16, 18 uint256 verifiedAt; // Timestamp uint256 expiresAt; // Expiration timestamp address verifier; // Who verified bool active; // Active status } event AgeVerified( bytes32 indexed didHash, uint8 ageThreshold, address indexed verifier ); event VerificationRevoked( bytes32 indexed didHash, address indexed revoker ); modifier onlyTrustedVerifier() { require(trustedVerifiers[msg.sender], "Not a trusted verifier"); _; } // Register age verification function registerAgeVerification( bytes32 didHash, uint8 ageThreshold, uint256 validityPeriod ) external onlyTrustedVerifier { require(ageThreshold > 0, "Invalid age threshold"); verifications[didHash] = AgeVerification({ ageThreshold: ageThreshold, verifiedAt: block.timestamp, expiresAt: block.timestamp + validityPeriod, verifier: msg.sender, active: true }); emit AgeVerified(didHash, ageThreshold, msg.sender); } // Check age verification (privacy-preserving) function checkAgeVerification( bytes32 didHash, uint8 requiredAge ) external view returns (bool verified) { AgeVerification memory verification = verifications[didHash]; if (!verification.active) return false; if (block.timestamp > verification.expiresAt) return false; if (verification.ageThreshold < requiredAge) return false; return true; } }

Privacy-First Blockchain Design

Notice how the smart contract stores only a hash of the DID (bytes32 didHash), not the DID itself. This ensures that even blockchain analytics cannot link age verification to specific individuals. The actual DID remains with the user, and they can prove they control the hashed DID through zero-knowledge proofs when needed.

2.6 Integration with Existing Identity Systems

Real-world deployment requires integration with existing identity infrastructure. The WIA-CHILD-002 standard provides adapters for major identity providers:

// Identity Provider Integration Layer class IdentityProviderBridge { // Convert OAuth/OIDC tokens to age verification claims async verifyViaOIDC( provider: 'google' | 'apple' | 'microsoft', idToken: string, requiredAge: number ): Promise<AgeVerificationResult> { // 1. Verify the ID token const claims = await this.verifyIDToken(provider, idToken); // 2. Extract birthdate if available if (claims.birthdate) { const age = this.calculateAge(claims.birthdate); return { verified: age >= requiredAge, ageVerified: age, method: 'oidc-birthdate', provider }; } // 3. Check for existing age verification from provider const providerVerification = await this.checkProviderAgeVerification( provider, claims.sub ); if (providerVerification) { return providerVerification; } // 4. Fall back to step-up verification return await this.initiateStepUpVerification(claims.sub, requiredAge); } }

COPPA Compliance Warning

When integrating with third-party identity providers, ensure that the provider's data handling practices comply with COPPA requirements for children under 13. Many OAuth providers collect extensive user data that may violate COPPA's minimization requirements. Always use age-specific scopes and consent flows for minor users.

Key Takeaways

  • DIDs enable self-sovereign age verification: Decentralized Identifiers give users control over their identity while enabling cryptographically verifiable age attestations without central authorities.
  • Verifiable Credentials protect privacy: VCs allow users to prove age thresholds (e.g., "over 13") without revealing exact birthdates or other personally identifiable information.
  • Blockchain provides immutable verification: Smart contracts can store hashed age verification records that are tamper-proof, transparent, and independently verifiable.
  • SSI principles must adapt for children: Self-sovereign identity empowers users but requires parental oversight mechanisms for minors to balance autonomy with protection.
  • Integration bridges legacy and modern systems: Real-world deployment requires adapters for OAuth/OIDC and other existing identity infrastructure while maintaining privacy standards.
  • Privacy-first design is critical: Store only hashed identifiers on public ledgers, minimize data collection, and implement zero-knowledge proofs to verify age without identity disclosure.
