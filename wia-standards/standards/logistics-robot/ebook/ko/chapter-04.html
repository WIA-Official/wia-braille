Chapter 4

Phase 1: Data Format & Telemetry

Establishing universal data schemas for robot telemetry, package tracking, warehouse maps, and SLAM data—the foundation of WIA interoperability.

4.1 Robot Telemetry Data Structures

Phase 1 of the WIA standard establishes JSON schemas for all robot operational data. This enables any system to parse, store, and analyze robot telemetry regardless of manufacturer. The core telemetry message includes position, orientation, velocity, battery status, operational state, and sensor readings transmitted 10-20 times per second.

Position and Pose Reporting

Robots report their position using a standardized coordinate system. The WIA standard supports multiple coordinate frames: global warehouse coordinates (meters from facility origin), local zone coordinates, and map-relative coordinates for SLAM-based systems.

{
  "robotId": "AMR-742",
  "timestamp": "2025-01-15T14:23:47.382Z",
  "position": {
    "x": 23.45,
    "y": 15.67,
    "z": 0.0,
    "frame": "warehouse_global",
    "confidence": 0.98
  },
  "orientation": {
    "yaw": 1.57,
    "pitch": 0.0,
    "roll": 0.0,
    "quaternion": [0, 0, 0.707, 0.707]
  },
  "velocity": {
    "linear": {"x": 0.5, "y": 0.0, "z": 0.0},
    "angular": {"x": 0.0, "y": 0.0, "z": 0.1}
  },
  "localizationQuality": "high"
}

4.2 Package Tracking and Inventory Data

Logistics robots transport packages, pallets, and inventory items. The WIA standard defines schemas for tracking these payloads throughout their journey from receiving to shipping.

Package Data Structure

Each package or inventory unit is identified by unique identifiers (barcodes, RFID tags, or QR codes). The robot tracks what it's carrying, destination locations, handling requirements, and priority levels.

4.4 SLAM Data Standardization

Simultaneous Localization and Mapping (SLAM) enables robots to build maps while localizing themselves. WIA standardizes SLAM data exchange, allowing robots to share map information and collaborative mapping across vendor boundaries.

Lidar Scan Data Format

Lidar sensors generate point cloud data used for navigation and obstacle detection. WIA defines standard formats compatible with common SLAM algorithms (GMapping, Cartographer, LOAM).

4.6 Task Status and Workflow State

Robots execute tasks (pick, transport, deliver) that transition through defined states. Standardized task state reporting enables fleet managers to track workflow progress and identify bottlenecks in real-time.

Task State Machine

WIA defines a standard task lifecycle: assigned → accepted → in_progress → completed/failed/cancelled. Each transition includes timestamps and optional metadata for analytics.

4.7 Error and Diagnostic Reporting

When robots encounter errors (navigation failures, obstacle detection, mechanical issues), standardized error codes and diagnostic data enable rapid troubleshooting across vendors. WIA defines error severity levels, standard error codes, and diagnostic data requirements.

4.8 Real-Time Metrics and KPIs

Fleet managers track Key Performance Indicators to optimize operations. WIA standardizes metrics calculation ensuring consistent definitions across vendors: robot utilization, task completion rate, average task duration, distance traveled, energy efficiency, and system availability.

Standard KPI Definitions

  • Robot Utilization: (Active time / Total operational time) × 100%
  • Task Completion Rate: (Completed tasks / Total assigned tasks) × 100%
  • Mean Time Between Failures (MTBF): Total operational hours / Number of failures
  • Throughput: Items moved per hour per robot
  • Energy Efficiency: Items moved per kWh consumed
  • Fleet Availability: (Available robots / Total robots) × 100%

4.9 Data Validation and Schema Evolution

WIA provides JSON Schema validators for all data formats, enabling automatic validation of messages before transmission or storage. This catches integration errors early and ensures data quality.

Schema Versioning Strategy

As WIA evolves, data schemas may require updates. The standard employs semantic versioning with backward compatibility guarantees: minor version updates add optional fields, major updates may restructure schemas with migration guides provided.

Schema Validation Example

Using JSON Schema validation in Python:

import jsonschema
from jsonschema import validate

wia_telemetry_schema = {
  "type": "object",
  "required": ["robotId", "timestamp", "position"],
  "properties": {
    "robotId": {"type": "string"},
    "timestamp": {"type": "string", "format": "date-time"},
    "position": {
      "type": "object",
      "required": ["x", "y", "frame"],
      "properties": {
        "x": {"type": "number"},
        "y": {"type": "number"},
        "z": {"type": "number"},
        "frame": {"type": "string"}
      }
    }
  }
}

# Validate telemetry message
validate(instance=robot_message, schema=wia_telemetry_schema)

🎯 Key Takeaways

  • Phase 1 establishes JSON schemas for all robot operational data—position, velocity, battery, task status, errors—enabling universal parsing and analytics across vendors
  • Standardized coordinate frames (warehouse global, zone local, map relative) with confidence metrics ensure robots accurately report location regardless of navigation technology used
  • Package tracking schemas link physical items (barcodes, RFID) with robot assignments, destinations, and handling requirements for complete supply chain visibility
  • Multiple map representations (occupancy grids, semantic maps, topological graphs) support different navigation and planning use cases from basic obstacle avoidance to complex multi-robot coordination
  • SLAM data standardization enables collaborative mapping where robots share sensor data and map information to build comprehensive facility models faster than individual robots could alone
  • Standardized error codes, diagnostic data, and KPI definitions ensure consistent troubleshooting and performance measurement across heterogeneous fleets
