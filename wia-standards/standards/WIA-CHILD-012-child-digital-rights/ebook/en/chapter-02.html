Chapter 02: Technical Architecture

WIA-CHILD-012 Child Digital Rights Standard | Implementation Architecture

Privacy-by-Design Architecture

Privacy-by-design is not a feature added to systems—it is a foundational architectural principle that embeds privacy protections into every layer of technology infrastructure. For children's digital rights, this means systems are built from the ground up to minimize data collection, maximize user control, and default to the most privacy-protective settings.

WIA-CHILD-012 mandates seven privacy-by-design principles for any system serving children: (1) proactive not reactive, (2) privacy as default setting, (3) privacy embedded in design, (4) full functionality with positive-sum, (5) end-to-end security, (6) visibility and transparency, and (7) respect for user privacy. These principles, established by Dr. Ann Cavoukian, form the technical foundation of child digital rights.

Seven Foundational Principles in Child Context

Principle General Interpretation Child-Specific Application Technical Implementation
1. Proactive not Reactive Anticipate privacy issues before they occur Design for developmental stages; prevent age-inappropriate exposure Age-gating, content filtering, parental controls built before launch
2. Privacy as Default Maximum privacy protection without user action Children's accounts private by default, minimal data collection Opt-in for data sharing, location services off, public profiles require explicit consent
3. Privacy Embedded in Design Privacy is core functionality, not add-on Child safety features are non-negotiable architecture elements Encryption mandatory, no backdoors, privacy settings irremovable
4. Full Functionality No false trade-offs between privacy and usability Children get full experience without sacrificing privacy Personalization without profiling; features work with minimal data
5. End-to-End Security Data protected throughout lifecycle Child data encrypted at rest, in transit, and in processing E2E encryption, secure deletion, no persistent logs of sensitive data
6. Visibility and Transparency Operations remain visible and understandable Child-appropriate explanations of data practices Privacy dashboards, simple language, visual explanations
7. Respect for User Privacy Keep user interests central Child's best interests over profit, engagement, or surveillance No dark patterns, no exploitation, best interests assessments required

Privacy-by-Design Reference Architecture

class ChildPrivacyArchitecture {
  // Layer 1: Data Minimization at Collection
  async collectData(dataRequest: DataRequest, child: ChildUser): Promise {
    // Assess necessity before collection
    const necessity = await this.assessDataNecessity(dataRequest);

    if (!necessity.required) {
      return { collected: false, reason: 'Data not necessary for service' };
    }

    // Check child's age and consent requirements
    const consentRequirement = this.determineConsentRequirement(child.age, dataRequest.dataType);

    if (consentRequirement === 'parental_required') {
      const parentalConsent = await this.obtainParentalConsent(child.parentId, dataRequest);
      if (!parentalConsent.granted) {
        return { collected: false, reason: 'Parental consent not obtained' };
      }
    }

    if (consentRequirement === 'child_and_parent') {
      const childConsent = await this.obtainChildConsent(child.id, dataRequest);
      const parentalConsent = await this.obtainParentalConsent(child.parentId, dataRequest);

      if (!childConsent.granted || !parentalConsent.granted) {
        return { collected: false, reason: 'Joint consent not obtained' };
      }
    }

    // Collect only what's necessary, pseudonymize where possible
    const collectedData = await this.minimizeAndPseudonymize(dataRequest, necessity.justification);

    // Set automatic deletion schedule
    await this.scheduleAutoDeletion(collectedData, this.calculateRetentionPeriod(child.age));

    return { collected: true, data: collectedData, expiresAt: collectedData.deletionDate };
  }

  // Layer 2: Privacy-Preserving Processing
  async processChildData(data: ChildData, purpose: ProcessingPurpose): Promise {
    // Verify purpose limitation
    if (!this.isPermittedPurpose(data.collectionPurpose, purpose)) {
      throw new Error('Purpose creep violation: cannot use data for unauthorized purpose');
    }

    // Use privacy-preserving techniques
    const processingMethod = this.selectPrivacyPreservingMethod(purpose);

    switch (processingMethod) {
      case 'differential_privacy':
        return await this.differentialPrivacyProcessing(data, purpose);

      case 'federated_learning':
        // Process on-device, never send raw data to servers
        return await this.federatedLearning(data, purpose);

      case 'homomorphic_encryption':
        // Process encrypted data without decryption
        return await this.homomorphicProcessing(data, purpose);

      case 'local_only':
        // Never leaves device
        return await this.localProcessing(data, purpose);
    }
  }

  // Layer 3: Default Privacy Settings
  getDefaultPrivacySettings(age: number): PrivacySettings {
    return {
      profileVisibility: age < 13 ? 'private' : 'friends_only',
      locationSharing: 'disabled', // Always off by default
      contactability: age < 13 ? 'parent_approved_only' : 'friends_only',
      dataSharing: {
        thirdParty: 'prohibited',
        advertising: 'prohibited',
        analytics: age >= 16 ? 'anonymous_only' : 'prohibited',
        research: 'opt_in_required'
      },
      contentVisibility: {
        posts: age < 13 ? 'private' : 'friends_only',
        photos: age < 16 ? 'friends_only' : 'friends_only', // Conservative default
        videos: age < 16 ? 'friends_only' : 'friends_only',
        liveStreaming: age < 16 ? 'disabled' : 'friends_only'
      },
      searchability: {
        findByEmail: false,
        findByPhone: false,
        searchEngineIndexing: false,
        peopleYouMayKnow: age >= 13
      },
      notifications: {
        marketing: 'disabled',
        socialUpdates: 'enabled',
        safetyAlerts: 'enabled'
      }
    };
  }

  // Layer 4: Transparency and Control
  async buildPrivacyDashboard(childId: string): Promise {
    const child = await this.getChild(childId);
    const collectedData = await this.getAllDataForChild(childId);

    return {
      dataInventory: {
        categories: this.categorizeData(collectedData),
        visualizations: this.createDataVisualizations(collectedData, child.age),
        explanations: this.generateAgeAppropriateExplanations(collectedData, child.age)
      },

      whoHasAccess: {
        platform: this.getPlatformAccess(childId),
        thirdParties: this.getThirdPartyAccess(childId), // Should usually be empty
        parents: child.age < 13 ? this.getParentalAccess(child.parentId) : null,
        lawEnforcement: this.getLawEnforcementRequests(childId)
      },

      controls: {
        downloadData: () => this.exportChildData(childId),
        deleteData: () => this.initiateDataDeletion(childId),
        restrictProcessing: (categories) => this.restrictProcessing(childId, categories),
        updateConsent: (newPreferences) => this.updateConsent(childId, newPreferences),
        revokeConsent: (dataType) => this.revokeConsent(childId, dataType)
      },

      activityLog: {
        dataAccesses: await this.getAccessLog(childId),
        dataModifications: await this.getModificationLog(childId),
        sharingEvents: await this.getSharingLog(childId),
        thirdPartyTransfers: await this.getTransferLog(childId) // Should be minimal
      }
    };
  }
}

Age-Appropriate Consent Mechanisms

Consent is not a one-time click—it is an ongoing process that must adapt to children's evolving capacities. Younger children may not fully comprehend privacy implications, requiring parental consent. Adolescents can provide meaningful consent but benefit from guardrails. WIA-CHILD-012 defines age-stratified consent mechanisms that respect developmental capabilities.

Consent Maturity Model

Age Range Consent Type Who Decides Verification Required Revocation Rights
Under 13 Parental Consent Only Parent/guardian Verifiable parental consent (VPC) per COPPA Parent can revoke anytime; child cannot override
13-15 Joint Consent Child + parent together Both parties acknowledge; email/SMS confirmation Either party can revoke; requires discussion to restore
16-17 Informed Child Consent Child (with parental notification) Child comprehension test; parent receives notice Child can revoke independently; parent can request review
18+ Adult Consent Individual Standard adult consent mechanisms Full independent control

Consent Interface Design

class AgeAppropriateConsent {
  async requestConsent(child: ChildUser, dataRequest: DataRequest): Promise {
    const consentFlow = this.designConsentFlow(child.age, dataRequest);

    // Step 1: Explain what we're asking for in age-appropriate language
    const explanation = this.generateExplanation(dataRequest, child.age);
    await this.presentExplanation(child, explanation);

    // Step 2: Comprehension check (for ages 13+)
    if (child.age >= 13) {
      const comprehension = await this.assessComprehension(child, dataRequest);
      if (!comprehension.passed) {
        // Re-explain and retry
        await this.reteachConcepts(child, comprehension.missedConcepts);
        const retryComprehension = await this.assessComprehension(child, dataRequest);
        if (!retryComprehension.passed) {
          return { granted: false, reason: 'Insufficient comprehension' };
        }
      }
    }

    // Step 3: Obtain appropriate consent based on age
    if (child.age < 13) {
      return await this.obtainParentalConsent(child.parentId, dataRequest, explanation);
    } else if (child.age >= 13 && child.age < 16) {
      return await this.obtainJointConsent(child, child.parentId, dataRequest, explanation);
    } else {
      return await this.obtainInformedChildConsent(child, dataRequest, explanation);
    }
  }

  generateExplanation(dataRequest: DataRequest, age: number): ConsentExplanation {
    // Age 6-9: Very simple, visual
    if (age < 10) {
      return {
        format: 'visual_story',
        content: `
          We want to remember your favorite color so we can make your page pretty!

          [Visual: Simple drawing of a profile page with favorite color]

          We'll keep this safe and only you and your parent can see it.
          Your parent needs to say it's okay before we remember this.
        `,
        metaphor: 'Like when you tell your teacher your favorite color for an art project'
      };
    }

    // Age 10-12: Concrete examples, clear consequences
    if (age < 13) {
      return {
        format: 'concrete_examples',
        content: `
          We'd like to use your location to show you local events near you.

          What this means:
          - We'll see what city you're in (but not your exact address)
          - We'll suggest activities happening nearby
          - We won't share your location with other users
          - You can turn this off anytime in Settings

          Why we need parent permission:
          - Location can be sensitive information
          - Your parent can help decide if this is safe
        `,
        consequences: 'If you say no: You can still use everything else, but event suggestions will be for your whole country instead of nearby'
      };
    }

    // Age 13-15: More detailed, with trade-offs
    if (age < 16) {
      return {
        format: 'detailed_with_tradeoffs',
        content: `
          Permission Request: Access to your photo library

          Why we're asking:
          We want to let you upload photos to your profile and posts. To do this, our app needs
          permission to access your photo library.

          What we'll do with this permission:
          ✓ Let you choose photos to upload
          ✓ Automatically detect if photos contain faces (for privacy warnings)

          What we WON'T do:
          ✗ Upload photos without you choosing them
          ✗ Access photos you don't explicitly select
          ✗ Scan your entire photo library

          Trade-offs:
          - If you grant: You can share photos easily
          - If you deny: You can still use the app, but can't post photos

          Privacy impact: Medium - We see photos you choose to upload, but not your entire library
        `,
        additionalInfo: 'You can revoke this permission anytime in your phone\'s Settings > [App] > Photos'
      };
    }

    // Age 16-17: Adult-level detail with developmental context
    return {
      format: 'comprehensive',
      content: `
        Data Processing Consent: Behavioral Analytics

        What we want to do:
        Analyze how you use our app (which features you use, when, for how long) to improve
        our service and suggest content you might like.

        Data collected:
        - Screen views and navigation patterns
        - Time spent on different features
        - Content interactions (likes, shares, saves)
        - Device type and OS version

        How we'll use it:
        - Improve app performance and fix bugs
        - Personalize your feed (show more of what you engage with)
        - Generate anonymous aggregate statistics

        Data retention: 90 days, then automatically deleted

        Third-party sharing: None - this data stays with us

        Your rights:
        - View all analytics data we've collected (Privacy Dashboard)
        - Download your data
        - Delete your data
        - Opt out of personalization while keeping basic analytics

        Important considerations:
        - This is OPTIONAL - core features work without this
        - You can change your mind anytime
        - Opting out means less personalized recommendations

        We're asking you (not your parent) because you're old enough to make this decision.
        However, we've notified your parent that you're being asked for this consent.
      `,
      legalBasis: 'Consent (GDPR Article 6(1)(a), Article 8)',
      parentalNotification: true
    };
  }

  async assessComprehension(child: ChildUser, dataRequest: DataRequest): Promise {
    const questions = this.generateComprehensionQuestions(dataRequest, child.age);

    const responses = await this.presentQuestions(child, questions);

    // Questions are designed to verify understanding, not trick users
    const correctAnswers = this.evaluateResponses(responses);

    if (correctAnswers / questions.length >= 0.75) {
      return { passed: true, score: correctAnswers / questions.length };
    } else {
      return {
        passed: false,
        score: correctAnswers / questions.length,
        missedConcepts: this.identifyMissedConcepts(responses)
      };
    }
  }

  generateComprehensionQuestions(dataRequest: DataRequest, age: number): Question[] {
    // Example for location sharing request (age 13-15)
    return [
      {
        question: "If you allow location access, who can see where you are?",
        options: [
          "Only me",
          "The app company only",
          "Anyone using the app",
          "My friends and the app company"
        ],
        correctAnswer: 1, // The app company only
        concept: "data_access_scope"
      },
      {
        question: "Can you change your mind later if you allow location access now?",
        options: [
          "Yes, I can turn it off anytime",
          "No, once I allow it, it's permanent",
          "Only my parent can turn it off",
          "I can turn it off but must wait 30 days"
        ],
        correctAnswer: 0, // Yes, anytime
        concept: "consent_revocability"
      },
      {
        question: "What happens if you DON'T allow location access?",
        options: [
          "I can't use the app at all",
          "I can use the app but won't get local event suggestions",
          "The app will track my location anyway",
          "I'll have to pay for the app"
        ],
        correctAnswer: 1, // Can use but no local suggestions
        concept: "consequences_of_denial"
      }
    ];
  }
}

Right to Deletion APIs

The right to deletion (also called "right to be forgotten" or "right to erasure") is fundamental to children's digital rights. Children and their parents must be able to delete personal data, close accounts, and remove digital footprints. WIA-CHILD-012 mandates comprehensive deletion APIs that honor these rights within strict timeframes.

Deletion Request Processing

interface DeletionAPI {
  // Initiate deletion request
  requestDeletion(childId: string, scope: DeletionScope, requestor: 'child' | 'parent'): Promise;

  // Check deletion status
  getDeletionStatus(requestId: string): Promise;

  // Cancel deletion (during grace period)
  cancelDeletion(requestId: string): Promise;

  // Export data before deletion
  exportBeforeDeletion(childId: string): Promise;
}

class ChildDataDeletion {
  async requestDeletion(
    childId: string,
    scope: DeletionScope,
    requestor: 'child' | 'parent'
  ): Promise {

    const child = await this.getChild(childId);

    // Verify requestor authorization
    if (!await this.authorizeRequestor(child, requestor)) {
      throw new Error('Unauthorized deletion request');
    }

    // Create deletion request with grace period
    const deletionRequest = {
      id: this.generateRequestId(),
      childId: childId,
      requestedBy: requestor,
      requestedAt: new Date(),
      scope: scope,
      status: 'pending',
      gracePeriodEnds: this.calculateGracePeriod(child.age), // 14-30 days
      estimatedCompleionDate: this.calculateCompletionDate(scope)
    };

    // Notify relevant parties
    if (requestor === 'child' && child.age < 18) {
      await this.notifyParent(child.parentId, deletionRequest);
    }
    if (requestor === 'parent') {
      await this.notifyChild(childId, deletionRequest);
    }

    // Immediately disable account (but don't delete yet)
    await this.disableAccount(childId);

    // Schedule deletion after grace period
    await this.scheduleDeletion(deletionRequest);

    return deletionRequest;
  }

  async executeDeletion(request: DeletionRequest): Promise {
    const child = await this.getChild(request.childId);

    // Multi-phase deletion process
    const phases = [
      { name: 'user_content', data: await this.identifyUserContent(child.id) },
      { name: 'profile_data', data: await this.identifyProfileData(child.id) },
      { name: 'activity_logs', data: await this.identifyActivityLogs(child.id) },
      { name: 'analytics_data', data: await this.identifyAnalyticsData(child.id) },
      { name: 'backup_copies', data: await this.identifyBackups(child.id) },
      { name: 'third_party_data', data: await this.identifyThirdPartyData(child.id) }
    ];

    const deletionResults = [];

    for (const phase of phases) {
      try {
        const result = await this.deletePhase(phase, request.scope);
        deletionResults.push(result);
      } catch (error) {
        // Log failure but continue
        deletionResults.push({
          phase: phase.name,
          status: 'failed',
          error: error.message,
          retryScheduled: true
        });
      }
    }

    // Generate deletion certificate
    const certificate = await this.generateDeletionCertificate(request, deletionResults);

    // Send confirmation to requestor
    await this.sendDeletionConfirmation(request, certificate);

    return {
      requestId: request.id,
      completedAt: new Date(),
      phasesDeleted: deletionResults,
      certificate: certificate
    };
  }

  async deletePhase(phase: DeletionPhase, scope: DeletionScope): Promise {
    switch (phase.name) {
      case 'user_content':
        // Posts, photos, videos, comments
        if (scope === 'full' || scope === 'content_only') {
          return await this.deleteUserContent(phase.data);
        }
        break;

      case 'profile_data':
        // Name, email, birthdate, profile photo
        if (scope === 'full' || scope === 'profile_only') {
          return await this.deleteProfileData(phase.data);
        }
        break;

      case 'activity_logs':
        // Browsing history, search queries, interaction logs
        if (scope === 'full' || scope === 'activity_only') {
          return await this.deleteActivityLogs(phase.data);
        }
        break;

      case 'analytics_data':
        // Aggregated usage statistics
        if (scope === 'full') {
          return await this.deleteAnalytics(phase.data);
        }
        break;

      case 'backup_copies':
        // All backup systems
        if (scope === 'full') {
          return await this.deleteBackups(phase.data);
        }
        break;

      case 'third_party_data':
        // Data shared with partners
        if (scope === 'full') {
          return await this.requestThirdPartyDeletion(phase.data);
        }
        break;
    }

    return { phase: phase.name, status: 'not_in_scope' };
  }

  calculateGracePeriod(age: number): Date {
    // Younger children get longer grace periods (prevent accidental deletions)
    const graceDays = age < 13 ? 30 : age < 16 ? 21 : 14;
    return new Date(Date.now() + graceDays * 24 * 60 * 60 * 1000);
  }

  async handleLegalHoldExceptions(childId: string): Promise {
    // Certain data may need to be retained for legal compliance
    const exceptions = [];

    // Check for active law enforcement holds
    const lawEnforcementHolds = await this.checkLawEnforcementHolds(childId);
    if (lawEnforcementHolds.length > 0) {
      exceptions.push({
        reason: 'law_enforcement_hold',
        data: lawEnforcementHolds,
        retainUntil: 'investigation_complete',
        notifyUser: true
      });
    }

    // Check for active child safety investigations
    const safetyInvestigations = await this.checkSafetyInvestigations(childId);
    if (safetyInvestigations.length > 0) {
      exceptions.push({
        reason: 'safety_investigation',
        data: safetyInvestigations,
        retainUntil: 'case_closed',
        notifyUser: true
      });
    }

    // Check for financial/tax retention requirements
    const financialData = await this.checkFinancialRetention(childId);
    if (financialData.length > 0) {
      exceptions.push({
        reason: 'tax_compliance',
        data: financialData,
        retainUntil: new Date(Date.now() + 7 * 365 * 24 * 60 * 60 * 1000), // 7 years
        notifyUser: true
      });
    }

    return exceptions;
  }
}

// Deletion Scope Types
type DeletionScope =
  | 'full'                    // Everything
  | 'content_only'            // Posts, photos, videos
  | 'profile_only'            // Identity data
  | 'activity_only'           // Logs and history
  | 'specific_data_category'; // User-specified categories

Encryption and Data Security

Children's data requires the highest levels of security. WIA-CHILD-012 mandates end-to-end encryption for sensitive communications, encryption at rest for stored data, and secure deletion protocols that prevent data recovery. These technical safeguards ensure that even if systems are compromised, children's data remains protected.

Data Type Encryption Standard Key Management Retention Policy
Messages (private) E2E encryption (Signal Protocol) User-controlled keys; no server access Deleted after delivery + 30 days
Personal information (name, DOB) AES-256 at rest Platform-managed with HSM Retained while account active + 90 days
Photos/videos AES-256 at rest; TLS 1.3 in transit Platform-managed encryption Retained per user settings; default 1 year
Location data E2E encryption for sharing; no server storage Ephemeral keys; auto-rotate hourly Not retained; processed in-memory only
Payment information PCI-DSS compliant tokenization Third-party payment processor (no platform access) Tokens only; no raw card data stored
Analytics/telemetry Anonymized before storage (no encryption needed) N/A (no PII) Aggregated data only; 90 days then anonymized

Key Takeaways

  • Privacy-by-design is architectural, not a feature: Seven foundational principles (proactive, default privacy, embedded design, full functionality, end-to-end security, transparency, user respect) must be built into systems from the ground up.
  • Age-appropriate consent mechanisms adapt to developmental stages: Under-13s require parental consent, 13-15-year-olds provide joint child-parent consent, 16-17-year-olds give informed consent with parental notification, recognizing evolving capacities.
  • Consent is not a checkbox—it requires comprehension assessment: Systems must explain requests in age-appropriate language (visual stories for young children, detailed trade-offs for teens), verify understanding through non-trick questions, and allow revocation anytime.
  • Right to deletion must be comprehensive and timely: Children/parents can request deletion with 14-30 day grace periods, systems must delete across all storage (primary, backups, third-parties), and provide deletion certificates as proof.
  • Data minimization is enforced at collection: Systems must assess necessity before collecting, pseudonymize where possible, set automatic deletion schedules, and justify every data point against clear service requirements.
  • End-to-end encryption protects sensitive communications: Private messages use Signal Protocol with user-controlled keys, location data is ephemeral and never stored, and personal information uses AES-256 with hardware security modules.
  • Privacy dashboards provide transparency and control: Children can see exactly what data is collected, who has access, how it's used, and exercise rights (download, delete, restrict processing) through simple interfaces with age-appropriate explanations.

  2. The consent maturity model requires "joint consent" for 13-15-year-olds. Walk through a scenario where the child and parent disagree about a data sharing request. How should the system resolve this conflict?
  3. Critique the comprehension assessment approach: Is it paternalistic to test whether users understand privacy requests? Could this prevent legitimate consent? How would you balance understanding verification with respect for autonomy?
  4. A platform uses differential privacy and federated learning to analyze child behavior without collecting raw data. Is this sufficient to protect privacy, or are there still concerns? Discuss the limits of privacy-preserving computation.
  5. The deletion API includes "legal hold exceptions" where data cannot be deleted due to law enforcement investigations. Debate whether this exception is justified or whether children's right to deletion should be absolute.
  6. Compare end-to-end encryption (E2E) for messages versus server-side encryption (AES-256) for profile data. Why might E2E be required for one but not the other? What are the trade-offs in terms of features, recovery, and safety?
  7. The default privacy settings make profiles "private" for under-13s and "friends only" for 13+. Should there be an option for children to have public profiles if they demonstrate understanding of the risks? Why or why not?
  8. Design a privacy dashboard for a 10-year-old. What visualizations, language, and controls would you include? How would this differ from a dashboard for a 16-year-old?

弘益人間 (Hongik Ingan)

"Benefit All Humanity"

Privacy is not just a technical specification—it is a manifestation of respect for human dignity. When we build privacy-by-design architectures, we declare that children are not data sources to be mined, but individuals whose autonomy and development deserve protection.

The philosophy of 弘益人間 reminds us that technology should serve humanity, not exploit it. By embedding privacy into the deepest layers of our systems, we ensure that every child—regardless of their technical knowledge, parental resources, or geographic location—experiences digital environments that respect their rights and support their flourishing.
