CHAPTER 06 · PHASE 3

Consent Protocol

Understanding consent propagation protocols, synchronization mechanisms, inter-system communication, and real-time consent verification across organizational boundaries.

Beyond Single Systems: The Protocol Layer

Phase 3 addresses a critical challenge: how does consent flow between systems, across organizational boundaries, and throughout complex technology ecosystems? While Phases 1 and 2 established data formats and APIs for individual systems, Phase 3 defines the communication protocols that enable consent to propagate, synchronize, and verify across the entire digital landscape.

The Consent Propagation Challenge

Modern organizations operate in complex ecosystems:

  • Multiple internal systems (CRM, marketing automation, analytics, support)
  • Cloud service providers (AWS, Azure, Google Cloud)
  • SaaS platforms (Salesforce, HubSpot, Zendesk)
  • Advertising networks and DSPs
  • Data brokers and third-party partners
  • Consent management platforms (OneTrust, TrustArc)

When a user updates their consent preferences, that change must propagate to every system processing their data—often in real-time to maintain compliance. Phase 3 protocols make this possible.

Core Protocol Components

1. Consent Synchronization Protocol

Ensures consent state remains consistent across distributed systems through event-driven synchronization:

X-WIA-Event-ID: evt-abc123 X-WIA-Timestamp: 2025-06-20T14:22:00Z { "event": "consent.updated", "consentId": "consent-550e8400...", "userId": "user-789012", "timestamp": "2025-06-20T14:22:00Z", "changes": { "purposes.marketing-email.granted": { "old": true, "new": false } }, "metadata": { "source": "preference-center", "ipAddress": "192.0.2.1" } } // Subscriber Response { "received": true, "processedAt": "2025-06-20T14:22:01Z", "affectedRecords": 3, "status": "success" }

2. Third-Party Consent Verification

Enables organizations to verify consent before processing data, even when the data originated from a third party:

POST https://consent-authority.example.com/api/v1/verify Authorization: Bearer {api_key} Content-Type: application/json { "userId": "user-789012", "purposeId": "marketing-email", "requestingParty": "partner-company-xyz", "context": { "dataSource": "shared-customer-list", "timestamp": "2025-06-20T14:30:00Z" } } Response: { "isValid": true, "consentId": "consent-550e8400...", "grantedAt": "2025-01-15T10:30:00Z", "expiresAt": "2026-01-15T10:30:00Z", "scope": ["marketing-email"], "thirdPartyAllowed": true, "verificationToken": "verify-xyz789...", "validUntil": "2025-06-20T15:30:00Z" }

3. Consent Delegation Protocol

Allows data controllers to delegate consent verification to processors while maintaining accountability:

{ "delegationId": "deleg-abc123", "delegator": "controller.example.com", "delegate": "processor.example.com", "purposes": ["analytics", "personalization"], "validFrom": "2025-01-15T00:00:00Z", "validUntil": "2026-01-15T00:00:00Z", "restrictions": { "jurisdictions": ["EU", "EEA"], "dataCategories": ["behavioral", "preferences"], "operations": ["read", "aggregate"] }, "auditRequired": true, "signature": "..." }

4. Consent Receipt Protocol

Provides users with cryptographically verifiable receipts of their consent decisions:

{ "receiptId": "receipt-xyz789", "consentId": "consent-550e8400...", "userId": "user-789012", "timestamp": "2025-01-15T10:30:00Z", "purposes": [ { "purposeId": "marketing-email", "granted": true, "description": "Receive promotional emails..." } ], "organization": { "name": "Example Corp", "jurisdiction": "EU", "privacyOfficer": "privacy@example.com" }, "userRights": [ "You may withdraw consent at any time", "You have the right to access your data", "You have the right to data portability" ], "signature": { "algorithm": "RS256", "value": "eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9...", "certificate": "-----BEGIN CERTIFICATE-----..." } }

Real-Time Consent Verification

For applications requiring immediate consent checks (e.g., before sending an email or displaying personalized content), the protocol supports low-latency verification:

// Distributed consent cache with TTL GET /api/v1/consents/verify/user-789012/marketing-email Authorization: Bearer {api_key} Cache-Control: max-age=300 Response: { "isValid": true, "cachedAt": "2025-06-20T14:20:00Z", "expiresAt": "2025-06-20T14:25:00Z" }

Cross-Organization Consent Exchange

When organizations merge, acquire, or partner, consent must be transferred with proper authorization:

{ "transferId": "xfer-abc123", "source": "company-a.example.com", "destination": "company-b.example.com", "timestamp": "2025-06-20T14:30:00Z", "legalBasis": "merger", "userNotification": { "required": true, "method": "email", "template": "merger-notification-v2" }, "consents": [ { "consentId": "consent-550e8400...", "userId": "user-789012", "transferAuthorization": "auth-xyz789..." } ], "auditTrail": true, "regulatoryApproval": "approval-ref-123" }

Consent Conflict Resolution

When multiple systems have conflicting consent states, the protocol defines resolution rules:

  • Most Restrictive Wins: If one system shows consent revoked, all systems treat it as revoked
  • Timestamp Priority: Most recent update takes precedence
  • User Intent Priority: Direct user actions override automated processes
  • Audit and Alert: All conflicts logged and investigated

Consent Status Broadcasting

For real-time applications, the protocol supports pub/sub broadcasting of consent status:

// WebSocket connection wss://consent-stream.example.com/subscribe Authorization: Bearer {api_key} Subscribe Message: { "action": "subscribe", "userIds": ["user-789012", "user-456789"], "purposes": ["marketing-email", "analytics"] } Broadcast Message: { "event": "consent.updated", "userId": "user-789012", "purposeId": "marketing-email", "granted": false, "timestamp": "2025-06-20T14:22:00Z" }

Security and Trust

Phase 3 protocols include robust security measures:

  • Mutual TLS: Both parties authenticate with certificates
  • Request Signing: HMAC-SHA256 signatures prevent tampering
  • Replay Prevention: Nonces and timestamps prevent replay attacks
  • Encryption: All data encrypted in transit and at rest
  • Audit Logging: Complete audit trail of all protocol interactions

Protocol Extensions

Organizations can extend the protocol for specialized use cases:

{ "event": "consent.custom.geofence-entered", "userId": "user-789012", "customData": { "location": "EU", "previousLocation": "US", "action": "apply-eu-consent-rules" } }

Implementation Checklist

  1. Identify all systems that process user data
  2. Map data flows and consent dependencies
  3. Implement consent synchronization endpoints
  4. Set up webhook listeners for consent events
  5. Configure consent verification caching
  6. Implement third-party verification flows
  7. Set up monitoring for synchronization failures
  8. Test cross-organization consent exchanges
  9. Implement conflict resolution logic
  10. Conduct end-to-end protocol testing

Chapter Summary

Phase 3 extends consent management beyond individual systems to enable true ecosystem-wide consent coordination. Through standardized protocols for synchronization, verification, delegation, and exchange, organizations can ensure consent is respected across all systems and partners.
