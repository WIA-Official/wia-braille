CHAPTER 05 · PHASE 2

Consent API Interface

Complete API reference for consent operations: creation, retrieval, updates, revocation, and verification with comprehensive code examples.

From Data to Action: The API Layer

Phase 1 established the consent data format—the "what" of consent management. Phase 2 defines the "how": standardized APIs that enable systems to create, read, update, delete, and verify consent records programmatically. These APIs form the operational backbone of WIA-CORE-002, enabling real-world consent management at scale.

API Design Principles

The WIA-CORE-002 API is designed around several key principles:

  • RESTful Architecture: Uses standard HTTP methods (GET, POST, PUT, PATCH, DELETE) with predictable URL patterns
  • GraphQL Support: Alternative query interface for efficient, flexible data retrieval
  • Idempotency: Safe retry behavior for operations
  • Versioning: API versioning through URL path for backward compatibility
  • Authentication: OAuth 2.0 and API key support
  • Rate Limiting: Protection against abuse with clear rate limit headers
  • Pagination: Cursor-based pagination for large result sets
  • Error Handling: Standardized error responses with detailed error codes

Core API Endpoints

1. Create Consent

POST /api/v1/consents Authorization: Bearer {access_token} Content-Type: application/json { "userId": "user-789012", "purposes": [ { "purposeId": "marketing-email", "granted": true } ], "jurisdiction": "EU", "metadata": { "source": "web-signup", "ipAddress": "192.0.2.1" } } Response 201 Created: { "consentId": "consent-550e8400...", "status": "active", "createdAt": "2025-01-15T10:30:00Z", ... }

2. Retrieve Consent

GET /api/v1/consents/{consentId} Authorization: Bearer {access_token} Response 200 OK: { "consentId": "consent-550e8400...", "userId": "user-789012", "status": "active", ... }

3. List User Consents

GET /api/v1/users/{userId}/consents?status=active&limit=50 Authorization: Bearer {access_token} Response 200 OK: { "data": [ { "consentId": "consent-1...", ... }, { "consentId": "consent-2...", ... } ], "pagination": { "cursor": "eyJpZCI6MTIzfQ==", "hasMore": true } }

4. Update Consent

PATCH /api/v1/consents/{consentId} Authorization: Bearer {access_token} Content-Type: application/json { "purposes": [ { "purposeId": "marketing-email", "granted": false } ] } Response 200 OK: { "consentId": "consent-550e8400...", "status": "active", "updatedAt": "2025-06-20T14:22:00Z", ... }

5. Revoke Consent

POST /api/v1/consents/{consentId}/revoke Authorization: Bearer {access_token} Content-Type: application/json { "reason": "User requested via preference center", "revokeAll": false } Response 200 OK: { "consentId": "consent-550e8400...", "status": "revoked", "revokedAt": "2025-12-01T09:15:00Z" }

6. Verify Consent

POST /api/v1/consents/verify Authorization: Bearer {access_token} Content-Type: application/json { "userId": "user-789012", "purposeId": "marketing-email" } Response 200 OK: { "isValid": true, "consentId": "consent-550e8400...", "grantedAt": "2025-01-15T10:30:00Z", "expiresAt": "2026-01-15T10:30:00Z" }

Batch Operations

For high-volume scenarios, batch endpoints enable processing multiple operations in a single request:

POST /api/v1/consents/batch Authorization: Bearer {access_token} Content-Type: application/json { "operations": [ { "operation": "create", "data": { "userId": "user-1", ... } }, { "operation": "update", "consentId": "consent-abc...", "data": { "purposes": [...] } } ] } Response 200 OK: { "results": [ { "success": true, "consentId": "consent-new..." }, { "success": true, "consentId": "consent-abc..." } ], "summary": { "total": 2, "successful": 2, "failed": 0 } }

GraphQL Interface

For applications requiring flexible queries, WIA-CORE-002 provides a GraphQL endpoint:

POST /api/v1/graphql Authorization: Bearer {access_token} Content-Type: application/json { "query": "query GetUserConsents($userId: ID!) { user(id: $userId) { consents(status: ACTIVE) { consentId purposes { purposeId purposeName granted } createdAt } } }", "variables": { "userId": "user-789012" } }

Webhooks and Event Streaming

Real-time consent change notifications via webhooks:

POST https://your-app.com/webhooks/consent Content-Type: application/json X-WIA-Signature: sha256=... { "eventId": "evt-123...", "eventType": "consent.updated", "timestamp": "2025-06-20T14:22:00Z", "data": { "consentId": "consent-550e8400...", "userId": "user-789012", "changes": { "purposes.marketing-email.granted": { "old": true, "new": false } } } }

Error Handling

Standardized error responses ensure consistent error handling across implementations:

Response 400 Bad Request: { "error": { "code": "INVALID_PURPOSE_ID", "message": "The purpose ID 'invalid-id' is not recognized", "details": { "field": "purposes[0].purposeId", "value": "invalid-id", "validValues": ["marketing-email", "analytics", ...] } } }

Security and Authentication

All API requests must be authenticated using OAuth 2.0 bearer tokens or API keys:

  • TLS 1.3 required for all connections
  • OAuth 2.0 with appropriate scopes (consents.read, consents.write, consents.admin)
  • API key authentication for server-to-server integrations
  • Request signing for webhook verification
  • IP whitelisting for sensitive operations
  • Rate limiting: 1000 requests/hour per API key (adjustable)

SDK Libraries

Official SDKs simplify integration:

// TypeScript/JavaScript import { WIAConsent } from '@wia/consent-sdk'; const client = new WIAConsent({ apiKey: process.env.WIA_API_KEY }); const consent = await client.consents.create({ userId: 'user-789012', purposes: [{ purposeId: 'marketing-email', granted: true }], jurisdiction: 'EU' }); console.log('Consent created:', consent.consentId);

SDKs available for: TypeScript/JavaScript, Python, Java, Go, Ruby, PHP, .NET
