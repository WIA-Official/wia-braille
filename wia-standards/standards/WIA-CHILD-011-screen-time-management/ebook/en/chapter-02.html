Multi-Platform Activity Tracking

Effective screen time management requires comprehensive tracking across all devices a child uses—smartphones, tablets, laptops, desktops, gaming consoles, smart TVs, and wearables. WIA-CHILD-011's architecture provides unified tracking through platform-specific APIs that feed into a central aggregation service, giving parents accurate, real-time visibility into their child's total screen time regardless of device.

The challenge is substantial: iOS, Android, Windows, macOS, ChromeOS, gaming consoles, and smart TVs all use different mechanisms for activity tracking. Some provide robust APIs (iOS Screen Time API, Android UsageStats), others require custom instrumentation. WIA-CHILD-011 provides abstraction layers that normalize data from all sources into a unified timeline.

Platform-Specific Tracking APIs

Platform Primary API Data Granularity Real-Time Availability Limitations
iOS Screen Time API (Family Sharing) Per-app, per-category, per-website Near real-time (1-5 min delay) Requires Family Sharing enrollment
Android UsageStatsManager + Digital Wellbeing API Per-app, foreground/background distinction Real-time with permissions Manufacturer variations, permissions required
Windows Family Safety API App usage, web browsing, gaming time Hourly aggregation Requires Microsoft family accounts
macOS Screen Time API (macOS 10.15+) Per-app, per-category, website tracking Near real-time Requires parental controls setup
ChromeOS Chrome OS Family Link App and web usage, supervised user accounts Real-time Limited to supervised accounts
PlayStation/Xbox Parental Controls API Total gaming time, per-game breakdown Daily summaries Console-specific, no cross-platform aggregation
Smart TV Custom integration (manufacturer-specific) Viewing time, app usage Varies by manufacturer No standard API, incomplete coverage

Unified Activity Tracking Architecture

interface ActivityTracker {
  trackSession(session: ScreenSession): Promise;
  getCurrentActivity(deviceId: string): Promise;
  getHistory(deviceId: string, timeRange: TimeRange): Promise;
  getAggregatedTime(childId: string, timeRange: TimeRange): Promise;
}

class UnifiedActivityTracker {
  private platformAdapters: Map;
  private sessionAggregator: SessionAggregator;
  private qualityAnalyzer: QualityAnalyzer;

  async trackAllDevices(childId: string): Promise {
    const child = await this.getChildProfile(childId);
    const devices = await this.getChildDevices(childId);

    // Start monitoring on all enrolled devices
    for (const device of devices) {
      const adapter = this.platformAdapters.get(device.platform);
      await adapter.startTracking(device.id, {
        reportingInterval: '5_minutes',
        includeBackground: false,
        trackWebBrowsing: true,
        categoryClassification: true
      });
    }
  }

  async aggregateActivity(childId: string, date: Date): Promise {
    const devices = await this.getChildDevices(childId);
    const allSessions: ScreenSession[] = [];

    // Collect from all devices
    for (const device of devices) {
      const adapter = this.platformAdapters.get(device.platform);
      const sessions = await adapter.getSessions(device.id, date);
      allSessions.push(...sessions);
    }

    // Merge overlapping sessions (child using multiple devices simultaneously)
    const mergedSessions = this.sessionAggregator.deduplicateSessions(allSessions);

    // Classify and score each session
    const classified = await Promise.all(
      mergedSessions.map(s => this.classifySession(s))
    );

    // Calculate quality-adjusted time
    const qualityAdjusted = classified.map(s => ({
      ...s,
      adjustedDuration: s.duration * (1.5 - s.qualityScore)
    }));

    return {
      date: date,
      totalScreenTime: this.sumDuration(mergedSessions),
      qualityAdjustedTime: this.sumDuration(qualityAdjusted),
      byDevice: this.groupByDevice(classified),
      byCategory: this.groupByCategory(classified),
      byApp: this.groupByApp(classified),
      sessions: classified
    };
  }
}

// iOS-specific adapter
class IOSScreenTimeAdapter implements PlatformAdapter {
  async getSessions(deviceId: string, date: Date): Promise {
    // Use Screen Time API through Family Sharing
    const screenTimeData = await this.familySharing.getScreenTime({
      deviceId: deviceId,
      date: date
    });

    return screenTimeData.intervals.map(interval => ({
      deviceId: deviceId,
      platform: 'iOS',
      startTime: interval.start,
      endTime: interval.end,
      duration: interval.duration,
      app: interval.bundleIdentifier,
      appName: interval.displayName,
      category: this.mapCategoryCode(interval.categoryIdentifier),
      webDomain: interval.webDomain || null,
      rawData: interval
    }));
  }

  mapCategoryCode(categoryId: string): ActivityCategory {
    const mapping = {
      'Entertainment': 'entertainment',
      'Social': 'social_media',
      'Productivity': 'productivity',
      'Education': 'education',
      'Games': 'gaming',
      'Reading & Reference': 'reading',
      'Creativity': 'creative',
      'Health & Fitness': 'health_fitness',
      'Other': 'other'
    };
    return mapping[categoryId] || 'other';
  }
}

// Android-specific adapter
class AndroidUsageStatsAdapter implements PlatformAdapter {
  async getSessions(deviceId: string, date: Date): Promise {
    const stats = await this.usageStats.queryUsageStats({
      deviceId: deviceId,
      intervalType: 'DAILY',
      beginTime: date.setHours(0, 0, 0, 0),
      endTime: date.setHours(23, 59, 59, 999)
    });

    // Android provides foreground time per app, need to reconstruct sessions
    return this.reconstructSessions(stats);
  }

  reconstructSessions(stats: UsageStats[]): ScreenSession[] {
    const sessions: ScreenSession[] = [];

    for (const app of stats) {
      // Get event timeline to build accurate sessions
      const events = app.events.sort((a, b) => a.timestamp - b.timestamp);

      let sessionStart = null;
      for (const event of events) {
        if (event.eventType === 'ACTIVITY_RESUMED') {
          sessionStart = event.timestamp;
        } else if (event.eventType === 'ACTIVITY_PAUSED' && sessionStart) {
          sessions.push({
            deviceId: app.deviceId,
            platform: 'Android',
            startTime: new Date(sessionStart),
            endTime: new Date(event.timestamp),
            duration: event.timestamp - sessionStart,
            app: app.packageName,
            appName: app.appName,
            category: this.inferCategory(app.packageName),
            rawData: app
          });
          sessionStart = null;
        }
      }
    }

    return sessions;
  }
}

Screen Time Classification Engine

Raw usage data (app name, duration) must be classified into meaningful categories and assigned quality scores. WIA-CHILD-011's classification engine uses multiple signals: app metadata, content analysis, behavioral patterns, and machine learning models trained on educational research.

Classification Method Input Signals Accuracy Use Case
App Store Metadata Category, age rating, description, educational tags ~75% Initial classification for known apps
Website Content Analysis Domain categorization, content scraping, SSL cert metadata ~80% Web browsing classification
Behavioral Pattern Analysis Session duration, time-of-day, frequency, multitasking ~70% Distinguishing productive vs. consumptive use
Machine Learning Classification App usage patterns, user demographics, educational outcomes ~85% Quality score prediction for novel apps
Parental Overrides Manual category assignment by parent 100% Corrections, family-specific customization
Crowdsourced Ratings Parent community ratings and reviews ~82% New apps, niche content, validation

Quality Scoring Algorithm

class ActivityClassifier {
  async classifyActivity(session: ScreenSession): Promise {
    // Multi-stage classification pipeline
    const appMetadata = await this.getAppMetadata(session.app);
    const contentSignals = await this.analyzeContent(session);
    const behaviorPattern = this.analyzeBehavior(session);
    const parentOverride = await this.getParentOverride(session.app);

    // Start with metadata-based classification
    let category = this.categoryFromMetadata(appMetadata);
    let qualityScore = this.baseQualityScore(category);

    // Adjust based on content analysis
    if (contentSignals.educationalKeywords > 5) {
      qualityScore += 0.15;
    }
    if (contentSignals.interactivityScore > 0.7) {
      qualityScore += 0.10;
    }
    if (contentSignals.socialConnectionScore > 0.6) {
      qualityScore += 0.08;
    }

    // Adjust based on behavioral patterns
    if (behaviorPattern.averageSessionLength < 15 && category === 'social_media') {
      // Short bursts suggest healthier usage
      qualityScore += 0.05;
    }
    if (behaviorPattern.averageSessionLength > 120 && category === 'gaming') {
      // Very long gaming sessions reduce quality
      qualityScore -= 0.10;
    }
    if (behaviorPattern.timeOfDay === 'late_night' && session.duration > 30) {
      // Late-night usage reduces quality due to sleep impact
      qualityScore -= 0.15;
    }

    // Apply ML model for refinement
    const mlPrediction = await this.mlModel.predictQuality({
      app: session.app,
      category: category,
      duration: session.duration,
      timeOfDay: session.startTime.getHours(),
      childAge: session.childAge,
      weekday: session.startTime.getDay() < 5
    });
    qualityScore = (qualityScore * 0.7) + (mlPrediction * 0.3);

    // Parent override takes precedence
    if (parentOverride) {
      category = parentOverride.category;
      qualityScore = parentOverride.qualityScore;
    }

    // Clamp to valid range
    qualityScore = Math.max(0, Math.min(1, qualityScore));

    return {
      ...session,
      category: category,
      qualityScore: qualityScore,
      educationalValue: contentSignals.educationalScore,
      activeEngagement: contentSignals.interactivityScore,
      socialConnection: contentSignals.socialConnectionScore,
      classificationConfidence: this.calculateConfidence(appMetadata, contentSignals, mlPrediction)
    };
  }

  baseQualityScore(category: ActivityCategory): number {
    const scores = {
      education: 0.85,
      creative: 0.75,
      productivity: 0.70,
      video_calling: 0.80,
      reading: 0.75,
      active_gaming: 0.60,
      social_media: 0.35,
      entertainment: 0.40,
      passive_gaming: 0.30,
      video_streaming: 0.35,
      other: 0.40
    };
    return scores[category] || 0.40;
  }
}

class ScreenTimeQualityModel {
  async predictQuality(features: ActivityFeatures): Promise {
    // This would be a trained ML model (e.g., gradient boosting, neural network)
    // For illustration, showing the feature engineering

    const encodedFeatures = {
      // Categorical encoding
      app_hash: this.hashApp(features.app),
      category_onehot: this.oneHotEncode(features.category),

      // Temporal features

      is_weekend: features.weekday ? 0 : 1,

      // User features
      child_age: features.childAge,

      // Usage patterns
      duration_minutes: features.duration / 60,
      duration_log: Math.log(features.duration / 60 + 1),

      // Interaction features
      age_category_interaction: features.childAge * this.categoryToNumeric(features.category),

Intelligent Limit Enforcement

Once screen time is tracked and classified, WIA-CHILD-011 enforces limits through platform-specific APIs. Enforcement must be reliable (children can't easily bypass), flexible (different limits for different activities), and family-friendly (gradual warnings before hard cutoffs).

Enforcement Mechanisms

Enforcement Level Technique Bypassability User Experience Impact
Soft Warnings Notifications at 75%, 90%, 100% of limit Easily ignored Minimal - educational nudges
App Blocking OS-level app blocking APIs Low - requires parent password Moderate - specific apps unavailable
Category Limits Block entire category (e.g., all games) Low - parent password protected Moderate - multiple apps affected
Device Downtime Entire device locked during scheduled times Very low - hardware-backed High - device fully unavailable
Network Filtering Router-level blocking for specific domains/apps Medium - VPN can bypass Moderate - affects all devices on network
Graduated Slowdown Progressively throttle app performance near limit Low - subconscious discouragement Low to moderate - app becomes less enjoyable

Smart Limit Enforcement

class LimitEnforcer {
  async checkLimits(childId: string, activity: Activity): Promise {
    const dailyUsage = await this.getDailyUsage(childId);
    const limits = await this.getLimits(childId);

    // Check multiple limit types
    const checks = {
      totalTime: this.checkTotalTimeLimit(dailyUsage, limits),
      categoryTime: this.checkCategoryLimit(activity.category, dailyUsage, limits),
      qualityAdjusted: this.checkQualityAdjustedLimit(dailyUsage, limits),
      timeOfDay: this.checkDowntime(activity.startTime, limits),
      consecutiveUsage: this.checkConsecutiveLimit(dailyUsage, limits)
    };

    // Determine appropriate action
    if (checks.timeOfDay.inDowntime) {
      return {
        action: 'block',
        reason: 'Device downtime',
        message: 'Devices are unavailable from 9 PM to 7 AM',
        allowExceptions: ['Phone calls', 'Emergency contacts'],
        gracePeriod: 0
      };
    }

    if (checks.totalTime.exceeded || checks.qualityAdjusted.exceeded) {
      return {
        action: 'warn_then_block',
        reason: 'Daily limit reached',
        message: `You've reached your ${checks.totalTime.limit} minute daily limit`,
        currentUsage: checks.totalTime.current,
        limit: checks.totalTime.limit,
        gracePeriod: 5  // 5 minutes to finish current activity
      };
    }

    if (checks.categoryTime.exceeded) {
      return {
        action: 'block_category',
        reason: 'Category limit reached',
        category: activity.category,
        message: `You've used your ${checks.categoryTime.limit} minutes of ${activity.category} for today`,
        alternative: this.suggestAlternativeActivity(activity.category, limits)
      };
    }

    if (checks.consecutiveUsage.exceeded) {
      return {
        action: 'force_break',
        reason: 'Consecutive usage too long',
        message: 'You've been on screens for 2 hours straight. Take a 15-minute break',
        breakDuration: 15,
        countdown: true
      };
    }

    // Approaching limits - send warnings
    if (checks.totalTime.remaining < 15) {
      return {
        action: 'warn',
        message: `${checks.totalTime.remaining} minutes of screen time remaining today`,
        priority: 'high'
      };
    }

    return { action: 'allow' };
  }

  async enforceAction(action: EnforcementAction, device: Device): Promise {
    switch (action.action) {
      case 'block':
        await this.blockDevice(device, action.reason);
        break;

      case 'block_category':
        await this.blockCategory(device, action.category, action.reason);
        break;

      case 'warn_then_block':
        await this.sendWarning(device, action.message);
        await this.scheduleBlock(device, action.gracePeriod);
        break;

      case 'force_break':
        await this.initiateBreak(device, action.breakDuration, action.message);
        break;

      case 'warn':
        await this.sendWarning(device, action.message);
        break;
    }
  }

  async initiateBreak(device: Device, duration: number, message: string): Promise {
    // Lock device with countdown timer
    await device.lockScreen({
      message: message,
      countdown: duration * 60,  // Convert to seconds
      allowEmergency: true,
      allowParentOverride: true,
      unlockAt: new Date(Date.now() + duration * 60 * 1000)
    });

    // Suggest offline activities
    await device.showNotification({
      title: 'Screen Break Time',
      body: 'Try: going outside, reading a book, drawing, or playing with friends!',
      actions: [
        { label: 'Set a timer', action: 'start_timer' },
        { label: 'Ask parent for more time', action: 'request_extension' }
      ]
    });
  }
}

Key Takeaways

  • WIA-CHILD-011 aggregates screen time across all devices (iOS, Android, Windows, macOS, gaming consoles, smart TVs) using platform-specific APIs that normalize into a unified timeline.
  • iOS Screen Time API, Android UsageStatsManager, and Windows Family Safety API provide different levels of granularity (per-app, per-category, web tracking) with varying real-time availability (1-5 min to hourly).
  • Activity classification uses multiple signals: app store metadata (~75% accuracy), website content analysis (~80%), behavioral patterns (~70%), and machine learning models (~85%) to assign quality scores.
  • Quality scoring considers educational value, active engagement, social connection, physical activity, and age-appropriateness, with parental overrides taking precedence over automated classification.
  • Enforcement mechanisms range from soft warnings (easily ignored) to device downtime (hardware-backed blocking) with different bypassability levels and user experience impacts.
  • Smart limit enforcement checks multiple limit types simultaneously: total time, category time, quality-adjusted time, time-of-day restrictions, and consecutive usage limits.
  • Graduated responses include warnings at 75%/90%/100% of limits, grace periods for finishing activities, forced breaks after extended use, and alternative activity suggestions.

"Benefit All Humanity"

Technology architecture should serve human wellbeing, not corporate interests or surveillance capitalism. WIA-CHILD-011's technical design prioritizes accuracy, privacy, and family autonomy over data collection or engagement maximization.

By providing parents with precise, actionable data about screen time quality and quantity, we empower families to make informed decisions. The system measures to inform, not to control or manipulate—embodying the principle of benefiting all humanity through technology that respects human agency.
