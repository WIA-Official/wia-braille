Chapter 2: IIoT Architecture & Communication

WIA-IND-027 Standard
Understanding the layered architecture and communication patterns that enable robust IIoT systems

2.1 Three-Layer IIoT Architecture

The WIA-IND-027 standard defines a three-layer architecture that separates concerns between device control, edge processing, and cloud analytics. This architecture provides scalability, fault tolerance, and optimal resource utilization across the IIoT ecosystem.

2.1.1 Layer Responsibilities

LayerPrimary FunctionsLatency RequirementsTypical Hardware
Device/FieldPhysical control, sensor reading, safety<1ms - 100msPLCs, Robots, Sensors
Edge ComputingProtocol translation, local analytics, buffering10ms - 1sIndustrial PCs, Gateways
Cloud/EnterpriseLong-term storage, ML, MES/ERP integration1s - minutesCloud VMs, Databases

2.1.2 Device/Field Layer Details

The field layer operates in real-time, controlling physical processes with deterministic timing. Key characteristics include:

  • Siemens S7-1500 PLCs: 1ms scan cycle, PROFINET IRT for motion control, integrated safety (Safety Integrated)
  • Allen-Bradley ControlLogix: EtherNet/IP communication, 5ms response time, hot-swappable modules
  • ABB Robots: Real-time path planning, 125μs servo cycle, RobotStudio simulation integration
  • Industrial Sensors: 4-20mA analog signals, HART protocol for diagnostics, IO-Link digital communication

Safety-critical operations at this layer follow SIL (Safety Integrity Level) ratings according to IEC 61508:

2.2 Network Topologies

2.2.1 Star Topology

All devices connect to a central gateway, simplifying network management but creating a single point of failure:

        ┌────────────────┐
        │  Edge Gateway  │
        │  10.0.1.1      │
        └────────────────┘
         ↙   ↓   ↓   ↓   ↘
    [PLC]  [Sensor][Robot][CNC] [AGV]
   .10     .20     .30    .40   .50
  • Advantages: Simple wiring, easy troubleshooting, centralized security policy
  • Disadvantages: Gateway failure stops all communication, cable length limited to 100m (Ethernet)
  • Use Cases: Small factories (10-50 devices), single production line, pilot IIoT projects

2.2.2 Hierarchical Topology

Multi-level structure with line gateways feeding into factory-level aggregators:

           ┌──────────────────┐
           │ Factory Gateway  │
           │ Cloud Sync       │
           └──────────────────┘
              ↙            ↘
    ┌──────────────┐      ┌──────────────┐
    │ Line A GW    │      │ Line B GW    │
    │ Local Analytics│    │ Local Analytics│
    └──────────────┘      └──────────────┘
       ↙    ↓    ↘            ↙    ↓    ↘
   [PLC] [Sensor] [Robot] [PLC] [CNC] [AGV]
  • Advantages: Scalable to 1000s of devices, fault isolation per line, distributed processing
  • Disadvantages: Higher cost, complex configuration, multiple failure points
  • Use Cases: Multi-line factories, campus-wide deployments, large-scale manufacturing

2.2.3 Mesh Topology

Peer-to-peer connectivity with redundant paths, common in WirelessHART and ISA100.11a networks:

    [Gateway] ←→ [Sensor A]
        ↕  ×    ×   ↕
    [Sensor B] ←→ [Sensor C]
        ↕           ↕
    [Actuator] ←→ [PLC]
  • Advantages: Self-healing, no single point of failure, extended range via multi-hop
  • Disadvantages: Complex routing, higher latency, difficult troubleshooting
  • Use Cases: Wireless sensor networks, large areas (oil fields, warehouses), high-reliability requirements

2.3 Communication Patterns

2.3.1 Request/Response (Client/Server)

Synchronous communication where client initiates requests and waits for server responses:

// OPC-UA Read Request Example (Python)
from opcua import Client

client = Client("opc.tcp://192.168.1.100:4840")
client.connect()

# Read temperature from PLC
node = client.get_node("ns=2;s=Machine_001.Temperature")
temperature = node.get_value()
print(f"Temperature: {temperature}°C")

# Write setpoint
setpoint_node = client.get_node("ns=2;s=Machine_001.Setpoint")
setpoint_node.set_value(75.0)

client.disconnect()

Performance Characteristics:

  • Latency: 10-100ms typical over Ethernet
  • Throughput: 100-1000 requests/sec per client
  • Use Cases: On-demand data retrieval, configuration changes, infrequent polling
  • Limitations: Scales poorly with many clients, creates network traffic spikes

2.3.2 Publish/Subscribe

Asynchronous event-driven communication through a broker intermediary:

// MQTT Publish/Subscribe Example (JavaScript)
const mqtt = require('mqtt');
const client = mqtt.connect('mqtt://broker.factory.com');

// Publisher (Sensor)
setInterval(() => {
  const data = {
    sensorId: 'temp-001',
    value: 45.2 + Math.random(),
    timestamp: Date.now(),
    unit: 'celsius'
  };

  client.publish('factory/line-A/temperature',
                 JSON.stringify(data),
                 { qos: 1 });  // At least once delivery
}, 1000);  // Publish every second

// Subscriber (Dashboard)
client.subscribe('factory/line-A/#');  // Wildcard: all topics under line-A

client.on('message', (topic, message) => {
  const data = JSON.parse(message.toString());
  console.log(`${topic}: ${data.value}${data.unit}`);

  if (data.value > 50) {
    sendAlert('Temperature threshold exceeded');
  }
});

Performance Characteristics:

  • Latency: 5-50ms end-to-end
  • Throughput: 100K+ messages/sec on modern brokers (HiveMQ, VerneMQ)
  • Use Cases: High-frequency telemetry, one-to-many distribution, event notifications
  • Advantages: Decoupled clients, bandwidth efficient, scales to millions of devices

2.3.3 Streaming

Continuous data flow for high-frequency sensors and video feeds:

// Apache Kafka Streaming Example (Java)
Properties props = new Properties();
props.put("bootstrap.servers", "kafka-broker:9092");
props.put("group.id", "vibration-analyzer");

KafkaConsumer<String, byte[]> consumer =
    new KafkaConsumer<>(props);

consumer.subscribe(Arrays.asList("vibration-sensors"));

while (true) {
  ConsumerRecords<String, byte[]> records =
      consumer.poll(Duration.ofMillis(100));

  for (ConsumerRecord<String, byte[]> record : records) {
    // Process 10kHz vibration data
    double[] samples = deserialize(record.value());
    double[] spectrum = fft(samples);

    // Detect bearing fault
    if (spectrum[bearingFreq] > threshold) {
      raiseAlert("Bearing fault detected");
    }
  }
}

Performance Characteristics:

  • Throughput: Millions of events/sec (Kafka: 1M+ msg/sec per broker)
  • Use Cases: Vibration monitoring (10-100 kHz), video analytics (30 fps), high-speed counting
  • Technologies: Apache Kafka, Apache Pulsar, AWS Kinesis, Azure Event Hubs

2.4 Data Flow Optimization

2.4.1 Dead-band Filtering

Transmit only significant changes, reducing bandwidth by 50-90%:

// Dead-band Filter Implementation
class DeadbandFilter {
  constructor(threshold) {
    this.threshold = threshold;
    this.lastTransmitted = null;
  }

  filter(value) {
    if (this.lastTransmitted === null) {
      this.lastTransmitted = value;
      return { transmit: true, value };
    }

    const change = Math.abs(value - this.lastTransmitted);

    if (change >= this.threshold) {
      this.lastTransmitted = value;
      return { transmit: true, value };
    }

    return { transmit: false };
  }
}

// Usage: Temperature with ±0.5°C deadband
const filter = new DeadbandFilter(0.5);

const temps = [45.1, 45.15, 45.12, 45.18, 45.6, 45.58, 45.55];

temps.forEach(temp => {
  const result = filter.filter(temp);
  if (result.transmit) {
    console.log(`Transmit: ${temp}°C`);
    mqtt.publish('sensors/temp-001', temp);
  } else {
    console.log(`Suppress: ${temp}°C`);
  }
});

// Output:
// Transmit: 45.1°C   (first value always transmitted)
// Suppress: 45.15°C  (change 0.05 < 0.5)
// Suppress: 45.12°C  (change 0.02 < 0.5)
// Suppress: 45.18°C  (change 0.08 < 0.5)
// Transmit: 45.6°C   (change 0.5 >= 0.5)
// Suppress: 45.58°C  (change 0.02 < 0.5)
// Suppress: 45.55°C  (change 0.05 < 0.5)

// Result: 71% reduction (2 transmissions vs 7 samples)

2.4.2 Statistical Sampling

Aggregate high-frequency data into statistical summaries:

// Statistical Aggregation (1-minute window)
class StatisticalSampler {
  constructor(windowMs) {
    this.windowMs = windowMs;
    this.samples = [];
    this.startTime = Date.now();
  }

  addSample(value) {
    this.samples.push(value);

    const elapsed = Date.now() - this.startTime;

    if (elapsed >= this.windowMs) {
      const stats = this.computeStats();
      this.samples = [];
      this.startTime = Date.now();
      return stats;
    }

    return null;
  }

  computeStats() {
    const n = this.samples.length;
    const mean = this.samples.reduce((a, b) => a + b) / n;
    const min = Math.min(...this.samples);
    const max = Math.max(...this.samples);

    const variance = this.samples
      .map(x => Math.pow(x - mean, 2))
      .reduce((a, b) => a + b) / n;
    const stddev = Math.sqrt(variance);

    return { mean, min, max, stddev, count: n };
  }
}

// Collect 1000 samples over 10 seconds, transmit 1 summary
const sampler = new StatisticalSampler(10000);

setInterval(() => {
  const value = readSensor();  // High-frequency sampling
  const stats = sampler.addSample(value);

  if (stats) {
    mqtt.publish('sensors/temp-001/stats', JSON.stringify(stats));
    console.log(`Mean: ${stats.mean.toFixed(2)}, StdDev: ${stats.stddev.toFixed(2)}`);
  }
}, 10);  // Sample every 10ms = 100 Hz

// Result: 99% data reduction (1 message vs 1000 samples)

Key Takeaways

  • Three-Layer Architecture: Device/Field (<1ms), Edge (10ms-1s), Cloud (1s+) layers optimize latency vs. scalability tradeoffs
  • Safety Integrity Levels: SIL 1-4 ratings define failure rates from 10⁻⁵ to <10⁻⁸ per hour for safety-critical systems
  • Edge Processing: Protocol translation, normalization, filtering, and local analytics reduce cloud bandwidth by 50-90%
  • Network Topologies: Star (simple, single point of failure), Hierarchical (scalable, distributed), Mesh (self-healing, complex)
  • Communication Patterns: Request/Response (10-100ms, 100-1000 req/s), Pub/Sub (5-50ms, 100K msg/s), Streaming (millions of events/s)
  • Data Optimization: Dead-band filtering (50-90% reduction), statistical sampling (99% reduction for high-frequency sensors)
