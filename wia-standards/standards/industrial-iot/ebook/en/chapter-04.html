4.1 MQTT - Message Queuing Telemetry Transport

MQTT is a lightweight publish/subscribe messaging protocol designed for constrained devices and unreliable networks. Originally developed by IBM in 1999 for oil pipeline SCADA systems, MQTT has become the de facto standard for IoT and IIoT telemetry.

4.1.1 MQTT Architecture

MQTT uses a broker-based architecture that decouples publishers from subscribers, enabling scalable one-to-many messaging:

ComponentRoleExamplesScalability
PublisherSends messages to topicsSensors, PLCs, gatewaysMillions of clients
BrokerRoutes messages to subscribersMosquitto, HiveMQ, EMQX100K-10M+ msg/sec
SubscriberReceives messages from topicsSCADA, analytics, historiansThousands of subscribers
TopicMessage routing pathfactory/line-A/tempMillions of topics

4.1.2 Quality of Service Levels

MQTT provides three QoS levels balancing reliability against performance:

QoSNameGuaranteeMessagesUse Cases
0At most onceFire and forget1 messageNon-critical telemetry, high-frequency data
1At least onceAcknowledged delivery≥1 (may duplicate)Important events, alarms
2Exactly onceNo duplicatesExactly 1Critical commands, billing, safety
 
// MQTT QoS Examples (JavaScript)
const mqtt = require('mqtt');
const client = mqtt.connect('mqtt://broker.factory.com');

// QoS 0: At most once (best effort)
client.publish('sensors/temp-001', '45.2', { qos: 0 });

// QoS 1: At least once (acknowledged)
client.publish('alarms/high-temp', 'Temperature exceeded 80C', { qos: 1 });

// QoS 2: Exactly once (critical)
client.publish('commands/stop-machine', 'EMERGENCY_STOP', { qos: 2 });

// Subscribe with QoS
client.subscribe('sensors/+/temperature', { qos: 1 });
client.subscribe('alarms/#', { qos: 2 });

4.1.3 Topic Design Best Practices

Hierarchical topic structure enables efficient filtering and wildcard subscriptions:

# Good: Hierarchical, specific
factory/001/line-A/machine-001/temperature
factory/001/line-A/machine-001/pressure
factory/001/line-A/machine-002/temperature
factory/001/line-B/robot-001/position

# Topic levels:
#   Level 1: Site/Factory ID
#   Level 2: Production line
#   Level 3: Equipment ID
#   Level 4: Measurement type

# Wildcard subscriptions
factory/001/line-A/+/temperature      # All temps on line A
factory/001/line-A/machine-001/#     # All data from machine-001
factory/+/+/+/temperature            # All temps in factory 001

4.1.4 Retained Messages and Last Will

// Retained messages - latest value persisted
client.publish('status/machine-001', 'running', {
  qos: 1,
  retain: true  // New subscribers get last value immediately
});

// Last Will and Testament - automatic notification on disconnect
client.connect('mqtt://broker.factory.com', {
  clientId: 'sensor-temp-001',
  clean: true,
  will: {
    topic: 'status/sensor-temp-001',
    payload: 'offline',
    qos: 1,
    retain: true
  }
});

// When sensor-temp-001 disconnects (network failure, power loss),
// broker automatically publishes "offline" to status/sensor-temp-001

4.3 Modbus Protocol

Modbus, developed by Modicon (now Schneider Electric) in 1979, remains the most widely deployed industrial protocol. Simple, open, and royalty-free, Modbus is supported by virtually every PLC, VFD, and industrial device.

4.3.2 Modbus Data Model

Modbus uses a register-based data model with four address spaces:

TypeAccessSizeAddress RangeUse Cases
Coils (0x)Read/Write1 bit00001-09999Digital outputs, relay control
Discrete Inputs (1x)Read-Only1 bit10001-19999Digital inputs, switches, limit sensors
Input Registers (3x)Read-Only16 bit30001-39999Analog inputs, sensor readings
Holding Registers (4x)Read/Write16 bit40001-49999Analog outputs, setpoints, config

4.3.3 Modbus Function Codes

# Common Modbus Function Codes

01 (0x01) - Read Coils
   Read 1-2000 contiguous coils
   Example: Read 10 coils starting at address 00001

02 (0x02) - Read Discrete Inputs
   Read 1-2000 discrete inputs
   Example: Read limit switch states

03 (0x03) - Read Holding Registers
   Read 1-125 holding registers (most common)
   Example: Read temperature setpoint

04 (0x04) - Read Input Registers
   Read 1-125 input registers
   Example: Read analog sensor values

05 (0x05) - Write Single Coil
   Write ON (0xFF00) or OFF (0x0000)
   Example: Activate relay

06 (0x06) - Write Single Register
   Write 16-bit value
   Example: Update setpoint

15 (0x0F) - Write Multiple Coils
   Write 1-1968 coils
   Example: Set multiple outputs

16 (0x10) - Write Multiple Registers
   Write 1-123 registers (most common for batch writes)
   Example: Update recipe parameters

4.3.4 Modbus TCP Example

// Python Modbus TCP Client (pymodbus)
from pymodbus.client import ModbusTcpClient
from pymodbus.payload import BinaryPayloadDecoder
from pymodbus.constants import Endian

# Connect to PLC
client = ModbusTcpClient('192.168.1.100', port=502)
client.connect()

# Read holding registers (Function Code 03)
# Address 40001 (temperature) = register 0
# Read 2 registers (32-bit float)
result = client.read_holding_registers(address=0, count=2, slave=1)

if not result.isError():
    # Decode as 32-bit float (IEEE 754)
    decoder = BinaryPayloadDecoder.fromRegisters(
        result.registers,
        byteorder=Endian.Big,
        wordorder=Endian.Big
    )
    temperature = decoder.decode_32bit_float()
    print(f"Temperature: {temperature}°C")

# Write single register (Function Code 06)
# Set setpoint to 75.0°C
client.write_register(address=10, value=750, slave=1)  # 75.0 * 10 = 750

# Write multiple registers (Function Code 16)
values = [750, 1500, 2000]  # Setpoint, Speed RPM, Pressure
client.write_registers(address=10, values=values, slave=1)

# Read coils (Function Code 01)
# Read 8 digital outputs
coils = client.read_coils(address=0, count=8, slave=1)
print(f"Outputs: {coils.bits[:8]}")

# Write single coil (Function Code 05)
client.write_coil(address=5, value=True, slave=1)  # Turn on output 5

client.close()

4.3.5 Modbus RTU over RS-485

// Node.js Modbus RTU Client
const ModbusRTU = require("modbus-serial");
const client = new ModbusRTU();

// Open serial port
client.connectRTUBuffered("/dev/ttyUSB0", {
  baudRate: 9600,
  dataBits: 8,
  stopBits: 1,
  parity: 'none'
});

// Set slave ID
client.setID(1);

// Read holding registers
client.readHoldingRegisters(0, 10)
  .then(data => {
    console.log("Registers:", data.data);
  })
  .catch(err => {
    console.error("Modbus error:", err);
  });

// Write multiple registers
const values = [100, 200, 300];
client.writeRegisters(10, values)
  .then(() => {
    console.log("Write successful");
  });

4.5 MQTT-Modbus Gateway

Edge gateways often bridge MQTT and Modbus to modernize legacy infrastructure:

// MQTT-Modbus Gateway (Node.js)
const mqtt = require('mqtt');
const ModbusRTU = require('modbus-serial');

// MQTT client
const mqttClient = mqtt.connect('mqtt://broker.factory.com');

// Modbus client
const modbusClient = new ModbusRTU();
modbusClient.connectRTUBuffered('/dev/ttyUSB0', { baudRate: 9600 });
modbusClient.setID(1);

// Poll Modbus every 1 second and publish to MQTT
setInterval(async () => {
  try {
    // Read temperature (register 0-1, 32-bit float)
    const tempData = await modbusClient.readHoldingRegisters(0, 2);
    const buffer = Buffer.from([
      tempData.data[0] >> 8, tempData.data[0] & 0xFF,
      tempData.data[1] >> 8, tempData.data[1] & 0xFF
    ]);
    const temperature = buffer.readFloatBE(0);

    // Publish to MQTT
    mqttClient.publish('factory/line-A/plc-001/temperature',
      JSON.stringify({
        value: temperature,
        unit: 'celsius',
        timestamp: Date.now()
      }),
      { qos: 1 }
    );

    console.log(`Published temperature: ${temperature}°C`);

  } catch (err) {
    console.error('Modbus read error:', err);
  }
}, 1000);

// Subscribe to MQTT commands and write to Modbus
mqttClient.subscribe('factory/line-A/plc-001/commands/#');

mqttClient.on('message', async (topic, message) => {
  if (topic.endsWith('/setpoint')) {
    const setpoint = parseFloat(message.toString());

    // Write to Modbus register 10
    await modbusClient.writeRegister(10, Math.round(setpoint * 10));
    console.log(`Set setpoint to ${setpoint}°C`);
  }
});

Key Takeaways

  • MQTT Architecture: Lightweight pub/sub protocol with 3 QoS levels (0: at most once, 1: at least once, 2: exactly once) scales to millions of devices
  • MQTT Features: Retained messages, Last Will Testament, hierarchical topics with wildcards (+, #), TLS encryption, username/password authentication
  • MQTT Performance: Modern brokers (HiveMQ, EMQX) handle 1M-5M msg/sec, support clustering for 100M+ concurrent clients
  • Modbus Variants: RTU (RS-485, 1200m, 247 devices), TCP (Ethernet, unlimited devices), ASCII (readable but inefficient)
  • Modbus Data Model: 4 address spaces - Coils (digital I/O), Discrete Inputs (read-only digital), Input/Holding Registers (analog, 16-bit)
  • MQTT vs Modbus: MQTT excels at scalable telemetry (5-50ms latency), Modbus best for direct PLC access (10-500ms depending on poll rate)
  • Gateway Pattern: MQTT-Modbus bridges enable modern cloud connectivity for legacy equipment, poll Modbus at 1-10Hz, publish events to MQTT
