3.1 OPC-UA Fundamentals

OPC Unified Architecture (OPC-UA) is the modern standard for industrial communication, developed by the OPC Foundation. Unlike its predecessor OPC Classic (based on Microsoft DCOM), OPC-UA is platform-independent, secure by design, and scales from embedded devices to enterprise cloud platforms.

3.1.1 OPC-UA Architecture Models

3.1.2 Information Model (Address Space)

OPC-UA uses an object-oriented information model where every data point, method, and event is represented as a node in an address space. Nodes are identified by NodeIds and connected via references.

[Server Root]
  └─ [Objects] (ObjectsFolder)
       ├─ [DeviceSet] (FolderType)
       │    ├─ [Machine_001] (ObjectType: CNCMachineType)
       │    │    ├─ [Temperature] (Variable, Double, CurrentRead)
       │    │    ├─ [Pressure] (Variable, Double, CurrentRead)
       │    │    ├─ [SpindleSpeed] (Variable, Int32, CurrentRead)
       │    │    ├─ [Status] (Variable, StatusEnum, CurrentRead)
       │    │    ├─ [Alarm] (ObjectType: AlarmConditionType)
       │    │    └─ [StartMachine] (Method, Input: none, Output: StatusCode)
       │    │
       │    └─ [Robot_001] (ObjectType: RobotType)
       │         ├─ [Position] (Variable, Vector3D, CurrentRead)
       │         ├─ [JointAngles] (Variable, Double[], CurrentRead)
       │         └─ [ExecuteProgram] (Method, Input: ProgramName, Output: Result)
       │
       └─ [Views] (ViewsFolder)
            └─ [ProductionLineView] (Custom view of selected machines)

3.1.3 NodeId Formats

NodeIds uniquely identify nodes across the OPC-UA ecosystem:

// Numeric NodeId (most efficient)
ns=2;i=1001              // Namespace 2, numeric identifier 1001

// String NodeId (human-readable)
ns=2;s=Machine_001.Temperature

// GUID NodeId (globally unique)
ns=2;g=09087e75-8e5e-499b-954f-f2a9603db28a

// Opaque (ByteString) NodeId
ns=2;b=M/RbKBsRVkePCePcx24oRA==

3.2 OPC-UA Services

3.2.1 Read Service

Synchronous data retrieval from one or more nodes:

// Python OPC-UA Client - Read Multiple Values
from opcua import Client
import time

client = Client("opc.tcp://plc.factory.com:4840")

try:
    client.connect()
    print("Connected to OPC-UA Server")

    # Get nodes
    temp_node = client.get_node("ns=2;s=Machine_001.Temperature")
    pressure_node = client.get_node("ns=2;s=Machine_001.Pressure")
    status_node = client.get_node("ns=2;s=Machine_001.Status")

    # Read values
    temp = temp_node.get_value()
    pressure = pressure_node.get_value()
    status = status_node.get_value()

    # Read with timestamp and quality
    temp_data = temp_node.get_data_value()
    print(f"Temperature: {temp_data.Value.Value}°C")
    print(f"Timestamp: {temp_data.SourceTimestamp}")
    print(f"Quality: {temp_data.StatusCode}")

    # Batch read for efficiency
    nodes_to_read = [temp_node, pressure_node, status_node]
    values = client.get_values(nodes_to_read)
    print(f"Batch read: Temp={values[0]}, Pressure={values[1]}, Status={values[2]}")

finally:
    client.disconnect()

3.2.2 Write Service

Modify variable values with access control and validation:

// C# OPC-UA Client - Write with Error Handling
using Opc.Ua;
using Opc.Ua.Client;

var endpoint = "opc.tcp://plc.factory.com:4840";
var session = Session.Create(...);

try {
    // Write single value
    var setpointNode = new NodeId("Machine_001.Setpoint", 2);
    var value = new DataValue(new Variant(75.0));

    StatusCode status = session.Write(
        null,  // requestHeader
        new WriteValueCollection {
            new WriteValue {
                NodeId = setpointNode,
                AttributeId = Attributes.Value,
                Value = value
            }
        },
        out var results,
        out var diagnosticInfos
    );

    if (StatusCode.IsGood(results[0])) {
        Console.WriteLine("Setpoint updated successfully");
    } else {
        Console.WriteLine($"Write failed: {results[0]}");
    }

    // Write multiple values atomically
    var writes = new WriteValueCollection {
        new WriteValue {
            NodeId = new NodeId("Machine_001.Mode", 2),
            AttributeId = Attributes.Value,
            Value = new DataValue(new Variant("AUTO"))
        },
        new WriteValue {
            NodeId = new NodeId("Machine_001.Speed", 2),
            AttributeId = Attributes.Value,
            Value = new DataValue(new Variant(1500))
        }
    };

    session.Write(null, writes, out results, out diagnosticInfos);

} finally {
    session.Close();
}

3.2.3 Subscription Service

Efficient data-change notifications with configurable sampling and publishing intervals:

// JavaScript OPC-UA Client - Subscription with Deadband
const opcua = require("node-opcua");

const client = opcua.OPCUAClient.create({
    endpointMustExist: false,
});

const endpointUrl = "opc.tcp://plc.factory.com:4840";

async function main() {
    await client.connect(endpointUrl);
    console.log("Connected");

    const session = await client.createSession();
    console.log("Session created");

    // Create subscription
    const subscription = opcua.ClientSubscription.create(session, {
        requestedPublishingInterval: 1000,  // 1 second
        requestedLifetimeCount: 100,
        requestedMaxKeepAliveCount: 10,
        maxNotificationsPerPublish: 100,
        publishingEnabled: true,
        priority: 10
    });

    subscription.on("started", () => {
        console.log("Subscription started - ID:", subscription.subscriptionId);
    });

    // Monitor temperature with deadband
    const tempMonitor = opcua.ClientMonitoredItem.create(
        subscription,
        {
            nodeId: "ns=2;s=Machine_001.Temperature",
            attributeId: opcua.AttributeIds.Value
        },
        {
            samplingInterval: 100,  // Sample every 100ms
            discardOldest: true,
            queueSize: 10,
            filter: new opcua.DataChangeFilter({
                trigger: opcua.DataChangeTrigger.StatusValue,
                deadbandType: opcua.DeadbandType.Absolute,
                deadbandValue: 0.5  // ±0.5°C deadband
            })
        },
        opcua.TimestampsToReturn.Both
    );

    tempMonitor.on("changed", (dataValue) => {
        console.log(`Temperature changed: ${dataValue.value.value}°C at ${dataValue.sourceTimestamp}`);

        if (dataValue.value.value > 80) {
            console.log("WARNING: High temperature!");
        }
    });

    // Keep subscription alive
    await new Promise(resolve => setTimeout(resolve, 60000)); // Run for 1 minute

    await subscription.terminate();
    await session.close();
    await client.disconnect();
}

main().catch(console.error);

3.2.4 Method Call Service

Execute server-side functions for complex operations:

// Python OPC-UA - Method Call
from opcua import Client, ua

client = Client("opc.tcp://plc.factory.com:4840")
client.connect()

# Get object and method nodes
machine = client.get_node("ns=2;s=Machine_001")
start_method = machine.get_child("StartMachine")

# Call method with input arguments
input_args = [
    ua.Variant(value="AUTO", varianttype=ua.VariantType.String),  # Mode
    ua.Variant(value=1500, varianttype=ua.VariantType.Int32)       # Speed RPM
]

result = machine.call_method(start_method, *input_args)
print(f"StartMachine returned: {result}")

# Advanced: Call with output parameters
execute_program = machine.get_child("ExecuteProgram")
program_name = ua.Variant("PROG_001", ua.VariantType.String)

output = machine.call_method(execute_program, program_name)
success = output[0]  # First output parameter
error_code = output[1]  # Second output parameter
print(f"Program execution: Success={success}, Error={error_code}")

client.disconnect()

3.3.2 Certificate-Based Authentication

OPC-UA uses X.509 certificates for server and client authentication:

// Generate self-signed certificate (OpenSSL)
// Server certificate
openssl req -x509 -newkey rsa:4096 -keyout server_key.pem \
  -out server_cert.pem -days 365 -nodes \
  -subj "/CN=plc.factory.com/O=Factory Inc/C=US" \
  -addext "subjectAltName=URI:urn:factory:plc:001,DNS:plc.factory.com"

// Client certificate
openssl req -x509 -newkey rsa:4096 -keyout client_key.pem \
  -out client_cert.pem -days 365 -nodes \
  -subj "/CN=scada-client/O=Factory Inc/C=US" \
  -addext "subjectAltName=URI:urn:factory:scada:client"

// Convert to DER format (required by some implementations)
openssl x509 -in server_cert.pem -outform DER -out server_cert.der
openssl rsa -in server_key.pem -outform DER -out server_key.der
// Python Secure OPC-UA Connection
from opcua import Client
from opcua.crypto import security_policies

client = Client("opc.tcp://plc.factory.com:4840")

# Configure security
client.set_security(
    security_policies.SecurityPolicyBasic256Sha256,
    certificate_path="client_cert.der",
    private_key_path="client_key.pem",
    server_certificate_path="server_cert.der"
)

client.connect()

# Authenticate with username/password
client.set_user("operator")
client.set_password("SecurePassword123!")

session = client.create_session("operator", "SecurePassword123!")
print("Secure connection established")

client.disconnect()

3.5 OPC-UA Performance Optimization

3.5.1 Subscription Tuning

ParameterRecommended ValueImpactTradeoff
Publishing Interval100-1000msNetwork bandwidth, CPU loadLower = more updates, higher load
Sampling Interval50-500msServer CPU, data freshnessLower = more accurate, higher server load
Queue Size10-100Memory, data loss during network issuesHigher = more buffering, more memory
Max Notifications100-1000Message size, latencyHigher = batch efficiency, larger packets

3.5.2 Batch Operations

// Efficient batch read (100 nodes)
const nodes = [];
for (let i = 1; i <= 100; i++) {
    nodes.push(client.get_node(`ns=2;s=Sensor_${i}.Value`));
}

// Inefficient: 100 individual reads (100 round-trips)
for (const node of nodes) {
    const value = await node.get_value();
    console.log(value);
}

// Efficient: Single batch read (1 round-trip)
const values = await client.get_values(nodes);
console.log(values);  // All 100 values in one call

// Performance improvement: ~100x faster

Key Takeaways

  • Unified Architecture: OPC-UA provides platform-independent, secure communication from embedded devices to enterprise systems
  • Information Model: Object-oriented address space with NodeIds, types, and references enables rich semantic data modeling
  • Security by Design: AES-256 encryption, X.509 certificates, and multiple authentication methods (anonymous, username, certificate, token)
  • Services: Read (10-50ms), Write (validation), Subscribe (deadband filtering), Method Call (server-side functions), Historical Access
  • Pub/Sub (Part 14): Broker-based, connectionless communication for high-performance (1-10ms) multicast scenarios
  • Performance: Batch operations, subscription tuning (publishing interval, sampling rate, queue size) optimize network and CPU usage
