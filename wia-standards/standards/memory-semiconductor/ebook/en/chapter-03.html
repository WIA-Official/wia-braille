Chapter 3: NAND Flash Memory Architecture

NAND Flash has revolutionized data storage, enabling everything from USB drives and SSDs to smartphones and data centers. Its unique properties—non-volatility, high density, and continuous scaling through 3D architecture—make it the dominant storage technology. This chapter explores NAND Flash fundamentals, 3D V-NAND technology, and the algorithms that manage its operation.

3.1 NAND Flash Cell Structure

NAND Flash stores data by trapping electrons in a floating gate transistor, a structure fundamentally different from DRAM's capacitive storage.

3.1.1 Floating Gate Transistor

The NAND Flash cell consists of:

  • Control Gate: Connected to the wordline, controls read/program operations
  • Floating Gate: Electrically isolated conductor that stores charge
  • Tunnel Oxide: Thin oxide layer allowing charge injection/removal
  • Channel: Silicon region where current flows during read operations

When electrons are trapped in the floating gate, they increase the threshold voltage (Vth) of the transistor. By sensing whether the cell conducts at a specific gate voltage, the stored data can be determined.

3.1.2 SLC, MLC, TLC, and QLC

NAND Flash density has increased through multi-level cell (MLC) technology, storing multiple bits per transistor:

Each additional bit per cell doubles capacity but requires tighter voltage control, reducing endurance and performance. Consumer SSDs typically use TLC for balanced cost/performance, while data centers may use MLC or even SLC for critical applications.

3.1.3 Program, Read, and Erase Operations

Program Operation (Write)

Programming injects electrons into the floating gate through Fowler-Nordheim tunneling:

  1. High Voltage Application: ~20V applied to control gate
  2. Tunneling: Electrons tunnel through oxide into floating gate
  3. Verify: Read cell to confirm correct threshold voltage
  4. Incremental Program: Repeat if needed with slightly higher voltage

Program operations are relatively slow (200-1500 μs) and can only change '1' to '0' (increase Vth). The incremental step pulse programming (ISPP) method applies progressively higher voltages until the target threshold is reached, enabling precise voltage control for MLC/TLC/QLC.

Read Operation

Reading applies intermediate voltages to determine the cell's threshold:

  1. Reference Voltage: Apply voltage between different Vth levels
  2. Sense Current: Measure if cell conducts (Vth below reference) or not (above)
  3. Multiple Reads: TLC requires 7 reference voltages, QLC requires 15
  4. Decode: Determine stored bits from read results

Read operations are fast (~25-50 μs) and non-destructive, allowing unlimited reads without wearing the cell.

Erase Operation

Erasing removes electrons from floating gate, resetting cells to '1' state:

  1. Block Selection: NAND erases entire blocks (64KB-4MB typically)
  2. High Voltage: ~20V applied to substrate, 0V to control gate
  3. Tunneling: Electrons tunnel from floating gate to substrate
  4. Verify: Confirm all cells in block are erased

Erase is the slowest operation (1.5-5 ms) and can only be performed on entire blocks. This block-erase limitation creates the "write amplification" problem that affects SSD performance and endurance.

3.2 3D NAND Architecture (V-NAND)

As 2D NAND scaling reached physical limits around the 15nm node, the industry transitioned to 3D vertical NAND (V-NAND), stacking memory cells vertically to increase density.

3.2.1 From 2D Planar to 3D Vertical

Traditional 2D NAND arranged cells horizontally on a silicon wafer. As feature sizes shrunk below 20nm, challenges emerged:

  • Cell-to-Cell Interference: Adjacent cells affecting each other's charge
  • Reduced Endurance: Thinner oxides and smaller geometries
  • Higher Error Rates: Requiring stronger ECC
  • Slower Performance: More conservative programming needed

3D NAND solves these issues by stacking cells vertically, allowing larger cell dimensions (improving reliability) while increasing density through vertical scaling.

3.2.2 3D NAND Structure

Modern 3D NAND uses a vertical channel architecture:

  • Vertical Channel: Silicon pillar etched through layers of wordlines
  • Charge Trap Layer: Replaces floating gate with insulating charge trap
  • Stacked Wordlines: 96-232+ layers of control gates
  • String Structure: Multiple cells connected vertically in series

The charge trap flash (CTF) design uses a silicon nitride layer to trap charge, avoiding the manufacturing complexity of creating isolated floating gates in 3D.

3.3 NAND Flash Organization

3.3.1 Page, Block, and Plane Structure

NAND Flash is organized hierarchically:

  • Page: Smallest read/write unit (4KB-16KB typical)
  • Block: Smallest erase unit (256KB-4MB typical, containing 64-256 pages)
  • Plane: Collection of blocks sharing peripheral circuitry
  • Die: One or more planes on a single silicon chip
  • Package: Multiple dies in a single package

A typical modern NAND die might have:

  • 2-4 planes per die
  • 2,000-4,000 blocks per plane
  • 256-512 pages per block
  • 16KB page size

This yields: 4 planes × 2,000 blocks × 256 pages × 16KB = 32 GB per die

3.3.2 ONFI and Toggle Mode Interfaces

NAND Flash communicates via standardized interfaces:

ONFI (Open NAND Flash Interface)

  • ONFI 1.0: 50 MT/s (2006)
  • ONFI 2.0-2.3: 200 MT/s, synchronous interface
  • ONFI 3.0-3.2: 400 MT/s
  • ONFI 4.0-4.2: 800-1200 MT/s, NV-DDR3 interface
  • ONFI 5.0: 1600 MT/s, NV-DDR4 interface (2022)

Toggle Mode (Toshiba/Samsung)

Alternative to ONFI, offering similar speeds through a different physical interface. Many controllers support both standards.

3.4 Flash Translation Layer (FTL)

The FTL bridges the gap between the block device interface expected by the OS and the reality of NAND Flash's erase-before-write limitation.

3.4.1 Logical to Physical Mapping

The FTL maintains a mapping table translating logical block addresses (LBAs) to physical pages:

  • Page-Level Mapping: Maximum flexibility, high RAM requirement (1GB RAM per 1TB NAND typical)
  • Block-Level Mapping: Lower overhead, less flexibility
  • Hybrid Mapping: Block mapping with page-level cache for frequently updated data

3.4.2 Garbage Collection

When pages are updated, the FTL writes new data to empty pages and marks old pages as invalid. Over time, blocks accumulate invalid pages:

  1. Select Block: Choose block with many invalid pages (victim selection)
  2. Copy Valid Data: Read remaining valid pages, copy to new block
  3. Erase Block: Erase the now-empty block
  4. Return to Pool: Block available for new writes

Garbage collection causes write amplification: writing 1GB of user data might require erasing and rewriting 1.5GB or more of flash data. Write amplification factor (WAF) is a key SSD performance metric.

3.4.3 Wear Leveling

Since NAND has limited endurance (1,000-100,000 P/E cycles), the FTL must distribute writes evenly:

Dynamic Wear Leveling

Distributes new writes across blocks with lowest erase counts. Simple but doesn't move static data.

Static Wear Leveling

Periodically moves static (rarely updated) data from low-erase-count blocks, making those blocks available for frequently updated data. This ensures all blocks wear evenly.

3.4.4 Error Correction Codes (ECC)

NAND Flash requires ECC to correct bit errors from charge leakage, program disturb, and read disturb:

ECC TypeCorrection CapabilityOverheadTypical Use
Hamming Code1-2 bit/512B~6-13 bitsLegacy NOR, simple NAND
BCH Code40-120 bit/1KB~14-20%Consumer TLC/QLC SSDs
LDPC Code80-200+ bit/1KB~18-25%Enterprise SSDs, advanced QLC

Modern SSDs use Low-Density Parity-Check (LDPC) codes, which provide strong correction capability with reasonable overhead. As NAND wears, error rates increase, eventually exceeding ECC capability and marking the block as bad.

3.5 SSD Architecture and Performance

3.5.1 SSD Controller

The SSD controller is a sophisticated processor managing:

  • Host Interface: SATA, SAS, NVMe over PCIe
  • FTL: Address mapping, garbage collection, wear leveling
  • ECC Engine: Hardware acceleration for encode/decode
  • NAND Interface: Controls 8-16+ NAND channels in parallel
  • Cache Management: DRAM buffering and SLC caching

3.5.2 NVMe Protocol

NVMe (Non-Volatile Memory Express) is optimized for flash storage over PCIe:

  • Low Latency: Direct PCIe connection, no SATA/SAS translation
  • High Queue Depth: 64K queues with 64K commands each
  • Parallel I/O: Multiple queues for different CPU cores
  • Reduced Overhead: Streamlined command set vs SCSI

NVMe over PCIe 4.0 x4 provides ~7 GB/s bandwidth, with PCIe 5.0 doubling that to ~14 GB/s.

Chapter Summary

  • NAND Flash stores data by trapping electrons in floating gates, with threshold voltage representing stored bits
  • Multi-level cell technology (MLC/TLC/QLC) stores multiple bits per cell, increasing density but reducing endurance
  • Program, read, and erase have asymmetric performance: reads are fast (~50μs), programs slower (~500μs), erases slowest (~3ms)
  • 3D V-NAND stacks cells vertically, enabling continued density scaling without the limitations of 2D planar NAND
  • Modern 3D NAND uses 176-232 layers with charge trap flash (CTF) architecture
  • NAND is organized into pages (read/write unit), blocks (erase unit), planes, and dies
  • The Flash Translation Layer (FTL) provides block-device interface through address mapping, garbage collection, and wear leveling
  • Garbage collection and write amplification are critical performance factors in SSDs
  • Strong ECC (typically LDPC) is required for reliable operation, especially with TLC/QLC
  • NVMe over PCIe provides much higher performance than SATA, with Gen4 SSDs reaching 7 GB/s sequential reads
