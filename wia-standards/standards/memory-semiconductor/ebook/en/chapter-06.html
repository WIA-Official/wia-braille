Chapter 6: Memory Protocols and Interfaces

Memory protocols define how processors communicate with memory devices, specifying command structures, timing requirements, and electrical characteristics. Understanding these protocols is essential for memory controller design, system optimization, and troubleshooting. This chapter covers JEDEC standards, DDR command protocols, NAND Flash interfaces, HBM protocols, and the emerging CXL memory standard.

6.1 JEDEC Standards Organization

JEDEC (Joint Electron Device Engineering Council) develops open standards for the microelectronics industry, ensuring interoperability across manufacturers. Founded in 1958, JEDEC has published hundreds of standards covering memory semiconductors, from basic specifications to advanced testing methodologies. These standards enable a competitive marketplace where memory from different manufacturers can work together seamlessly.

6.2 DDR Command Structure and Protocol

6.2.1 Basic Command Set

DDR SDRAM uses a set of commands encoded on control pins. Each command performs a specific function in the memory access sequence:

  • ACTIVATE: Opens a row for read/write access, loading row data into sense amplifiers
  • READ: Initiates read from activated row, data appears after CAS latency
  • WRITE: Initiates write to activated row, data must be provided at correct timing
  • PRECHARGE: Closes an open row, writing back any modified data
  • REFRESH: Refreshes DRAM cells to prevent data loss from capacitor leakage
  • MODE REGISTER SET (MRS): Configures operating parameters like CAS latency, burst length
  • NOP: No operation, used to meet timing requirements

6.2.2 Command Encoding

Commands are encoded using control signals: /CS (chip select), /RAS (row address strobe), /CAS (column address strobe), /WE (write enable). The combination of these signals determines which command is executed:

6.2.3 DDR Read Sequence Example

A typical read operation follows this sequence:

// Example DDR4 read operation sequence
1. ACTIVATE (Bank=2, Row=0x1234)
   - Opens row 0x1234 in bank 2
   - Must wait tRCD (14 cycles for DDR4-3200)

2. Wait 14 clock cycles (tRCD)

3. READ (Bank=2, Column=0x040, Auto-Precharge=1)
   - Issues read to column 0x040
   - Auto-precharge will close row after burst completes
   - Data appears after tCL cycles (14 cycles for DDR4-3200)

4. Wait 14 clock cycles (tCL)

5. Data Transfer
   - Burst of 8 transfers (BL8)
   - Data on both rising and falling clock edges
   - Total 4 clock cycles for burst

6. PRECHARGE automatic (due to auto-precharge flag)
   - Row closes, bank ready for next activate after tRP

6.3 DDR Timing Parameters

6.3.1 Critical Timing Constraints

DDR timing ensures data integrity and proper operation. Violating timing parameters can cause data corruption, system instability, or device damage. Memory controllers must carefully schedule commands to meet all constraints:

  • tCL (CAS Latency): Delay from READ command to data output. Higher frequencies require higher latency to allow signal propagation. DDR4 ranges from 14-22 cycles, DDR5 from 32-52 cycles.
  • tRCD (RAS to CAS Delay): Minimum time from ACTIVATE to READ/WRITE. Required to allow row data to stabilize in sense amplifiers before column access.
  • tRP (Row Precharge): Time to close a row before opening another. Ensures previous row data is properly written back to cells.
  • tRAS (Row Active Time): Minimum time a row must remain open. Prevents data loss from premature precharge.
  • tRC (Row Cycle Time): Minimum time between activations to same bank. Sum of tRAS + tRP plus overhead.
  • tRFC (Refresh Cycle Time): Time required to refresh all rows. Increases with capacity (350ns for 8Gb, 550ns for 16Gb DDR4).
  • tCCD (Column-to-Column Delay): Minimum time between column commands. Varies by bank group (tCCD_S for same group, tCCD_L for different groups).
  • tWR (Write Recovery): Time from end of write burst to PRECHARGE. Ensures write data is committed before row closes.

DDR4-3200 Timing Example

For DDR4-3200 with tCL=14, tRCD=14, tRP=14:

Total read latency = tRCD + tCL = 14 + 14 = 28 cycles = 17.5ns

This represents the time from ACTIVATE command to first data output. Page hits (accessing same row) avoid the tRCD delay and achieve much lower latency.

6.4 Signal Integrity and Electrical Characteristics

6.4.1 On-Die Termination (ODT)

DDR2 and later include on-die termination resistors to improve signal integrity at high frequencies. ODT provides controlled impedance matching to reduce reflections and ringing on signal lines. The termination resistance can be dynamically enabled/disabled and configured to different values:

  • RTT_NOM: Nominal termination when not actively driving (40Ω, 48Ω, 60Ω, 120Ω options)
  • RTT_WR: Write termination, active during writes (80Ω, 120Ω, 240Ω, or disabled)
  • RTT_PARK: Park termination for idle ranks in multi-rank systems

ODT is programmed through mode registers and can be adjusted based on system topology, frequency, and number of ranks.

6.4.2 Data Bus Inversion (DBI)

DBI reduces simultaneous switching noise and power consumption by inverting data patterns with more than 50% ones. An additional DBI pin indicates when data is inverted. The receiver inverts the data back to original form:

// DBI Algorithm
if (count_ones(data_byte) > 4) {
    data_byte = ~data_byte;  // Invert all bits
    DBI_pin = 1;             // Signal inversion
} else {
    DBI_pin = 0;             // No inversion
}

Benefits include reduced power consumption (fewer simultaneous transitions), lower electromagnetic interference (EMI), and improved signal integrity. DBI is optional in DDR4 but mandatory in DDR5.

6.4.3 Write Leveling and Read Training

At high data rates, clock skew between signals requires calibration. Modern memory systems perform extensive training sequences during initialization:

Write Leveling

Aligns DQS (data strobe) signals with clock at the DRAM device. The controller adjusts DQS delay until the DRAM samples it correctly aligned with the clock edge. This compensates for trace length differences and package delays.

Read Training

Optimizes the sampling point for incoming data at the controller. The controller sweeps receive delay across the data eye, finds the passing region, and sets the delay to the center of the valid window. This maximizes timing margins.

Command/Address Training

Ensures commands and addresses are sampled correctly by the DRAM. Critical at DDR5 speeds where setup/hold margins are tight.

Training must be performed at boot and may be repeated periodically during operation as voltage and temperature change. Modern controllers can perform online training without disrupting operation.

6.5 NAND Flash Interface (ONFI)

6.5.1 ONFI Standard Overview

The Open NAND Flash Interface (ONFI) standardizes communication between NAND Flash and controllers, enabling interoperability. ONFI specifications define command sets, timing modes, and feature sets:

ONFI 1.050 MT/sBasic asynchronous interface
ONFI 2.0200 MT/sNV-DDR synchronous mode
ONFI 3.0400 MT/sNV-DDR2, EZ-NAND features
ONFI 4.0800 MT/sNV-DDR3, multi-plane operations
ONFI 5.01600 MT/sNV-DDR4, enhanced performance

6.5.2 NAND Flash Commands

NAND Flash uses a simple command interface with opcode-based commands:

  • READ PAGE (00h, 30h): Reads page from array to internal buffer, then transfers to controller
  • PROGRAM PAGE (80h, 10h): Programs data from buffer to memory array
  • ERASE BLOCK (60h, D0h): Erases entire block (64-256 pages)
  • READ STATUS (70h): Returns device status (ready/busy, pass/fail)
  • RESET (FFh): Resets device to idle state
  • CACHE PROGRAM (15h): Pipelines program operations for higher throughput
  • MULTI-PLANE (11h): Operates on multiple planes in parallel

6.6 HBM Protocol

6.6.1 HBM Architecture

High Bandwidth Memory (HBM) uses a wide interface and 3D stacking to achieve extreme bandwidth. HBM2 provides 8 independent channels of 128 bits each (1024 bits total), while HBM3 reorganizes this into 16 channels of 64 bits for better flexibility:

  • HBM2: 8 channels × 128 bits = 1024 bits, 256-461 GB/s per stack
  • HBM3: 16 channels × 64 bits = 1024 bits, 665-819 GB/s per stack

Each channel operates independently with its own command/address bus, enabling high parallelism. The protocol is simplified compared to DDR, with fixed burst length and no multi-rank complications.

6.7 CXL Memory Protocol

6.7.1 Compute Express Link Overview

CXL provides cache-coherent memory connectivity over PCIe physical layer, enabling memory pooling and expansion in data centers. CXL defines three sub-protocols:

  • CXL.io: Standard PCIe I/O transactions for device discovery and configuration
  • CXL.cache: Device can cache host memory with coherency maintained
  • CXL.mem: Host can access device-attached memory as expanded main memory

6.7.2 CXL Memory Expansion

CXL enables memory pooling and expansion architectures:

  • Type 1: Accelerators with coherent cache (no device memory)
  • Type 2: Accelerators with coherent cache and local memory
  • Type 3: Memory expanders (memory-only devices for capacity expansion)

CXL Type 3 devices enable disaggregated memory architectures where memory resources are pooled and dynamically allocated to compute nodes, improving data center efficiency and flexibility.

Key Takeaways

  • JEDEC standards define memory interfaces, ensuring interoperability across manufacturers and enabling a competitive marketplace
  • DDR commands (ACTIVATE, READ, WRITE, PRECHARGE, REFRESH) are encoded using control signals and must follow strict timing constraints
  • Timing parameters like tCL, tRCD, tRP, and tRAS ensure proper operation and data integrity. Violations can cause corruption or system failure
  • Signal integrity techniques (ODT, DBI, write leveling, read training) are critical at high data rates to maintain reliable communication
  • NAND Flash uses ONFI protocol with opcode-based commands for page read/program and block erase operations
  • HBM provides 1024-bit wide interface through 3D stacking, achieving 256-819 GB/s per stack depending on generation
  • CXL enables cache-coherent memory expansion over PCIe, supporting disaggregated architectures in data centers
  • Modern memory controllers must perform extensive training (write leveling, read training, command/address training) to operate reliably at high speeds
