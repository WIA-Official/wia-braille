제05장: CXL과 차세대 메모리 인터커넥트

CXL(Compute Express Link)은 CPU와 가속기, 메모리 간의 고속 인터커넥트 표준입니다. 메모리 확장, 풀링, 일관성 유지 기능을 제공하여 차세대 데이터센터의 핵심 기술로 부상하고 있습니다. 이 장에서는 CXL 아키텍처, 메모리 타입, 그리고 실제 응용 사례를 다룹니다.

CXL 기본 개념

1. CXL의 필요성

전통적인 서버 아키텍처는 각 CPU 소켓에 메모리가 고정 연결되어 확장성과 활용률에 한계가 있습니다. CXL은 이러한 문제를 해결합니다.

전통 아키텍처의 한계

  • 메모리 고립: 각 CPU 소켓의 메모리를 다른 CPU가 직접 사용 불가
  • 불균형 워크로드: 일부 CPU는 메모리 부족, 다른 CPU는 유휴 메모리
  • 확장 제약: CPU당 메모리 채널 수 제한
  • 비용 비효율: 최대 용량으로 프로비저닝 필요

2. CXL의 주요 기능

기능 설명 효과
메모리 일관성 CPU와 가속기 간 캐시 일관성 유지 프로그래밍 모델 단순화
메모리 확장 CPU 소켓 너머 메모리 접근 용량 확장성
메모리 풀링 여러 호스트가 메모리 공유 활용률 향상
낮은 레이턴시 PCIe 기반으로 빠른 액세스 성능 유지

CXL 프로토콜 스택

1. 3가지 프로토콜

CXL은 PCIe 5.0+ 물리 계층 위에서 세 가지 프로토콜을 정의합니다.

CXL 프로토콜 계층

  • CXL.io: PCIe 5.0+ 기반 I/O 프로토콜. 디바이스 발견, 설정, 레지스터 액세스
  • CXL.cache: 디바이스가 호스트 메모리에 액세스할 때 캐시 일관성 유지
  • CXL.mem: 호스트가 디바이스 메모리에 액세스. 로드/스토어 시맨틱 제공
프로토콜 방향 용도 레이턴시
CXL.io 양방향 제어, 상태, 인터럽트 높음 (μs)
CXL.cache 디바이스→호스트 가속기의 호스트 메모리 액세스 낮음 (100ns)
CXL.mem 호스트→디바이스 호스트의 메모리 확장 중간 (200-500ns)
// CXL 디바이스 타입과 프로토콜 사용
class CXLDevice {
  constructor(type) {
    this.type = type;
    this.protocols = this.getProtocols(type);
  }

  getProtocols(type) {
    switch(type) {
      case 1: // Type 1: 가속기 with cache
        return ['CXL.io', 'CXL.cache'];
      case 2: // Type 2: 가속기 with cache & memory
        return ['CXL.io', 'CXL.cache', 'CXL.mem'];
      case 3: // Type 3: 메모리 확장 디바이스
        return ['CXL.io', 'CXL.mem'];
      default:
        return ['CXL.io'];
    }
  }
}

// 예시: CXL 메모리 확장 모듈 (Type 3)
const memExpander = new CXLDevice(3);
console.log(memExpander.protocols); // ['CXL.io', 'CXL.mem']

CXL 메모리 타입

1. CXL Type 3 메모리 디바이스

CXL Type 3는 순수 메모리 확장 디바이스로, 가장 널리 채택되고 있습니다.

Type 3 디바이스 특징

  • 휘발성: DRAM 기반 (DDR4/DDR5)
  • 비휘발성: Intel Optane, 3D XPoint
  • 하이브리드: DRAM + NAND 조합
  • 용량: 디바이스당 최대 512GB-1TB
메모리 타입 레이턴시 대역폭 용량 주요 용도
CXL DRAM 200-300 ns 높음 중간 메모리 확장
CXL PMem 500-1000 ns 중간 높음 대용량 메모리
로컬 DDR 80-100 ns 매우 높음 낮음 핫 데이터

2. CXL 메모리 풀링

CXL 2.0 이상은 메모리 풀링을 지원하여 여러 호스트가 동일한 메모리를 공유할 수 있습니다.

// CXL 메모리 풀 관리 예시
class CXLMemoryPool {
  constructor(totalCapacity, numHosts) {
    this.totalCapacity = totalCapacity; // GB
    this.numHosts = numHosts;
    this.allocations = new Map();
  }

  allocate(hostId, requestedGB) {
    const allocated = this.getAllocatedTotal();
    const available = this.totalCapacity - allocated;
    
    if (requestedGB <= available) {
      this.allocations.set(hostId, requestedGB);
      console.log(`Host ${hostId}: ${requestedGB}GB 할당`);
      return true;
    } else {
      console.log(`할당 실패: ${available}GB만 사용 가능`);
      return false;
    }
  }

  getAllocatedTotal() {
    let total = 0;
    for (const [host, size] of this.allocations) {
      total += size;
    }
    return total;
  }

  getUtilization() {
    return (this.getAllocatedTotal() / this.totalCapacity) * 100;
  }
}

// 예시: 1TB CXL 메모리 풀, 8개 호스트
const pool = new CXLMemoryPool(1024, 8);
pool.allocate('host1', 256);
pool.allocate('host2', 128);
console.log(`활용률: ${pool.getUtilization().toFixed(1)}%`);

CXL 스위칭과 패브릭

1. CXL 스위치

CXL 스위치는 여러 호스트와 메모리 디바이스를 연결하여 유연한 토폴로지를 구성합니다.

  • 포트 구성: 업링크 (호스트), 다운링크 (메모리 디바이스)
  • 메모리 인터리빙: 여러 디바이스에 데이터 분산
  • QoS: 호스트별 대역폭 및 레이턴시 보장
  • 핫플러그: 동적 메모리 추가/제거

2. CXL 패브릭

CXL 3.0은 멀티 레벨 스위칭과 패브릭을 도입하여 대규모 메모리 풀 구축을 가능하게 합니다.

토폴로지 스위치 레벨 최대 호스트 최대 메모리 복잡도
Direct Attach 0 1 제한적 낮음
Single Switch 1 8-16 수십 TB 중간
Multi-Level 2-3 수백 수백 TB 높음

CXL 소프트웨어 스택

1. OS 메모리 관리

CXL 메모리는 OS 레벨에서 투명하게 또는 명시적으로 관리될 수 있습니다.

CXL 메모리 관리 모드

  • 투명 모드: OS가 CXL 메모리를 일반 NUMA 노드로 취급. 애플리케이션 수정 불필요
  • 명시적 모드: 애플리케이션이 CXL 메모리를 직접 선택. 성능 최적화 가능
  • 하이브리드 모드: 핫 데이터는 로컬 DRAM, 콜드 데이터는 CXL 메모리
// NUMA 노드 기반 CXL 메모리 할당 (Linux)
#include <numa.h>
#include <numaif.h>

void* allocate_on_cxl_node(size_t size, int cxl_node) {
  // 특정 NUMA 노드(CXL)에 메모리 할당
  void* ptr = numa_alloc_onnode(size, cxl_node);
  
  if (ptr == NULL) {
    printf("CXL 노드 %d에 할당 실패\n", cxl_node);
    return NULL;
  }
  
  // 메모리 정책 설정: 이 노드에 바인딩
  unsigned long nodemask = 1UL << cxl_node;
  mbind(ptr, size, MPOL_BIND, &nodemask,
        sizeof(nodemask) * 8, 0);
  
  return ptr;
}

// 예시: 10GB를 CXL 노드 2에 할당
void* data = allocate_on_cxl_node(10UL * 1024 * 1024 * 1024, 2);

2. 메모리 티어링

Linux 6.0+은 메모리 티어링을 지원하여 로컬 DRAM과 CXL 메모리를 계층화합니다.

티어 메모리 타입 레이턴시 용도
Tier 0 로컬 DDR ~100 ns 핫 페이지
Tier 1 CXL DRAM ~300 ns 웜 페이지
Tier 2 CXL PMem ~1 μs 콜드 페이지

CXL 응용 사례

1. 클라우드 데이터센터

클라우드 서비스 제공자는 CXL을 통해 메모리 활용률을 극대화하고 비용을 절감합니다.

  • 메모리 풀링: 여러 VM이 공유 메모리 풀 사용, 활용률 30% 향상
  • 동적 할당: 워크로드에 따라 메모리 재분배
  • 비용 절감: 오버프로비저닝 불필요, TCO 20% 감소

2. AI/ML 워크로드

대형 모델 훈련 시 CXL 메모리로 용량 확장 및 체크포인트 저장을 가속화합니다.

// PyTorch에서 CXL 메모리 활용
import torch
import os

# NUMA 노드 설정 (CXL 메모리)
os.environ['CUDA_VISIBLE_DEVICES'] = '0'
cxl_node = 2 # CXL 메모리가 NUMA 노드 2

# 대형 텐서를 CXL 메모리에 배치
def create_tensor_on_cxl(shape):
  # CPU 텐서 생성 후 CXL 노드로 이동
  tensor = torch.randn(shape, device='cpu')
  
  # libnuma를 통해 메모리를 CXL 노드로 마이그레이션
  # (실제로는 ctypes로 mbind 호출 필요)
  migrate_to_cxl_node(tensor, cxl_node)
  
  return tensor

# 100억 파라미터 모델의 가중치를 CXL에 저장
weights = create_tensor_on_cxl((10_000_000_000,))
print(f"가중치 크기: {weights.element_size() * weights.nelement() / 1e9:.1f} GB")

시나리오 로컬 DRAM CXL 메모리 성능 영향

웜 데이터 (40%) - 2 TB -15%

CXL 성능 고려사항

1. 레이턴시 오버헤드

CXL 메모리는 로컬 DRAM보다 레이턴시가 높으므로, 워크로드 특성에 따라 영향이 다릅니다.

레이턴시 민감도별 워크로드

  • 높음: 랜덤 액세스, 작은 트랜잭션 (5-20% 성능 저하)
  • 중간: 순차 스캔, 중간 배치 (2-10% 성능 저하)
  • 낮음: 대용량 배치, 분석 쿼리 (0-5% 성능 저하)

2. 대역폭 활용

CXL은 PCIe 레인을 공유하므로, 다른 PCIe 디바이스(GPU, NIC)와 대역폭 경합이 발생할 수 있습니다.

  • 레인 할당: CXL 메모리에 충분한 PCIe 레인 할당 (x8 이상 권장)
  • 트래픽 분리: CXL과 GPU를 다른 PCIe 루트 컴플렉스에 배치
  • QoS 설정: CXL 스위치에서 대역폭 보장 정책 구성

차세대 메모리 기술 전망

1. CXL + HBM 통합

CXL과 HBM을 결합하여 용량과 대역폭을 동시에 극대화하는 솔루션이 개발 중입니다.

기술 용량 대역폭 레이턴시 예상 출시
CXL + DDR 수 TB 중간 200-500 ns 현재
CXL + HBM 수백 GB TB/s급 100-200 ns 2025-2026
CXL + 차세대 메모리 수십 TB 높음 가변 2027+

2. Optical CXL

광 인터커넥트를 사용한 CXL은 거리 제약을 극복하고 데이터센터 레벨 메모리 풀링을 가능하게 합니다.

  • 전송 거리: 구리 케이블 10m → 광섬유 수백 m
  • 랙 간 풀링: 여러 랙에 걸친 메모리 공유
  • 대역폭 확장: 파장 다중화로 수백 Gbps 달성

요약

CXL은 메모리 확장과 풀링을 위한 차세대 인터커넥트 표준으로, 데이터센터의 메모리 활용률과 확장성을 크게 개선합니다. PCIe 기반으로 낮은 레이턴시를 유지하면서도 유연한 메모리 구성을 가능하게 합니다.

핵심 요점

  • CXL은 메모리 일관성, 확장, 풀링을 지원하는 개방형 표준
  • Type 3 디바이스로 DRAM, PMem 등 다양한 메모리 활용
  • 메모리 티어링과 NUMA로 OS 레벨 투명한 지원
  • 클라우드, AI, 데이터베이스에서 비용과 성능 최적화
  • CXL 3.0+로 대규모 패브릭과 광 인터커넥트 지원
