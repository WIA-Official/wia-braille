제02장: SRAM과 캐시 메모리 시스템

SRAM(Static Random Access Memory)은 고속 메모리로, 주로 CPU 캐시에 사용됩니다. 리프레시가 필요 없어 DRAM보다 빠르지만, 셀 크기가 커서 용량 대비 비용이 높습니다. 이 장에서는 SRAM의 구조, 캐시 메모리 아키텍처, 그리고 성능 최적화 기법을 다룹니다.

SRAM 기본 구조

1. 6T SRAM 셀

가장 일반적인 SRAM 셀은 6개의 트랜지스터(6T)로 구성됩니다. 두 개의 교차 결합된 인버터가 비트를 저장하고, 두 개의 접근 트랜지스터가 읽기/쓰기를 제어합니다.

6T SRAM 셀 구성 요소

  • M1, M2 (풀업 트랜지스터): PMOS 트랜지스터로 구성된 첫 번째 인버터의 로드
  • M3, M4 (풀다운 트랜지스터): NMOS 트랜지스터로 구성된 드라이버
  • M5, M6 (접근 트랜지스터): 워드 라인에 의해 제어되는 NMOS 스위치
  • 비트 라인 쌍(BL, BLB): 차동 신호로 노이즈 내성 향상

2. SRAM vs DRAM 비교

특성 SRAM DRAM
셀 구조 6 트랜지스터 1 트랜지스터 + 1 캐패시터
액세스 시간 1-10 ns 10-100 ns
리프레시 불필요 필수 (64ms 주기)
전력 소비 높음 (대기 시) 중간 (리프레시 포함)
셀 크기 큼 (~100F²) 작음 (~6F²)
비용/비트 높음 낮음
주요 용도 CPU 캐시, 레지스터 메인 메모리

캐시 메모리 아키텍처

1. 캐시 계층 구조

현대 프로세서는 다층 캐시 계층 구조를 사용하여 성능과 비용을 최적화합니다. L1, L2, L3 캐시는 각각 다른 크기와 레이턴시 특성을 가집니다.

캐시 레벨 크기 레이턴시 위치 공유 범위
L1 Data 32-64 KB 3-4 사이클 코어 내부 코어 전용
L1 Instruction 32-64 KB 3-4 사이클 코어 내부 코어 전용
L2 Unified 256KB-1MB 10-12 사이클 코어 내부/근접 코어 전용
L3 Unified 8-64 MB 30-40 사이클 칩 내부 모든 코어 공유
// 캐시 히트율 계산 예시
class CacheSimulator {
  constructor(size_kb, associativity, line_size) {
    this.size = size_kb * 1024;
    this.associativity = associativity;
    this.line_size = line_size;
    this.num_sets = this.size / (associativity * line_size);
    this.hits = 0;
    this.misses = 0;
  }

  getHitRate() {
    const total = this.hits + this.misses;
    return total > 0 ? (this.hits / total) * 100 : 0;
  }

  calculateAMAT(hit_time, miss_penalty) {
    // AMAT = Hit Time + Miss Rate × Miss Penalty
    const miss_rate = 1 - (this.getHitRate() / 100);
    return hit_time + (miss_rate * miss_penalty);
  }
}

// 예시: L1 캐시 (32KB, 8-way, 64B 라인)
const l1_cache = new CacheSimulator(32, 8, 64);
console.log(`Sets: ${l1_cache.num_sets}`); // 64 세트

2. 캐시 매핑 방식

캐시는 메인 메모리의 데이터를 어떻게 배치할지 결정하는 매핑 방식에 따라 성능이 달라집니다.

캐시 매핑 방식 비교

  • 직접 매핑(Direct Mapped): 각 메모리 블록이 정확히 하나의 캐시 라인에만 매핑. 간단하지만 충돌 미스 발생 가능
  • 완전 연관(Fully Associative): 메모리 블록이 어떤 캐시 라인에도 매핑 가능. 유연하지만 하드웨어 복잡도 높음
  • 세트 연관(Set Associative): 직접 매핑과 완전 연관의 절충안. n-way 세트 연관이 가장 일반적 (n=4, 8, 16)

캐시 일관성 프로토콜

1. MESI 프로토콜

멀티코어 시스템에서 각 코어의 캐시 간 데이터 일관성을 유지하기 위해 MESI 프로토콜을 사용합니다.

상태 의미 특징
M (Modified) 수정됨 이 캐시만 유효한 복사본 보유, 메모리와 불일치
E (Exclusive) 배타적 이 캐시만 복사본 보유, 메모리와 일치
S (Shared) 공유됨 여러 캐시가 복사본 보유, 읽기만 가능
I (Invalid) 무효 캐시 라인이 유효하지 않음
// MESI 상태 전이 예시
class MESICache {
  constructor() {
    this.state = 'I'; // 초기 상태: Invalid
  }

  readHit() {
    // M, E, S 상태에서는 그대로 유지
    console.log(`Read hit in state ${this.state}`);
  }

  writeHit() {
    // 모든 상태에서 M으로 전이
    this.state = 'M';
    console.log('Write hit: transitioned to Modified');
  }

  readMiss() {
    // 다른 캐시에 있으면 S, 없으면 E
    const otherCacheHas = this.checkOtherCaches();
    this.state = otherCacheHas ? 'S' : 'E';
    console.log(`Read miss: loaded in ${this.state} state`);
  }

  writeMiss() {
    // 다른 모든 캐시를 무효화하고 M 상태로
    this.invalidateOtherCaches();
    this.state = 'M';
    console.log('Write miss: loaded in Modified state');
  }
}

2. 스누핑과 디렉터리 기반 일관성

캐시 일관성을 유지하는 두 가지 주요 방법이 있습니다.

  • 스누핑 기반: 모든 캐시가 버스를 모니터링하여 일관성 유지. 작은 시스템(2-16 코어)에 적합
  • 디렉터리 기반: 중앙 디렉터리가 각 캐시 라인의 상태 추적. 대규모 시스템(수십-수백 코어)에 적합

캐시 최적화 기법

1. 프리페칭(Prefetching)

프로그램이 데이터를 요청하기 전에 미리 캐시로 가져와 미스를 줄입니다.

프리페칭 전략

  • 하드웨어 프리페칭: 순차 액세스 패턴 감지 시 다음 라인 자동 로드
  • 스트라이드 프리페칭: 일정 간격의 메모리 액세스 패턴 감지
  • 소프트웨어 프리페칭: 컴파일러나 프로그래머가 명시적 프리페치 명령 삽입
// 소프트웨어 프리페칭 예시 (x86-64)
void processArray(int* data, size_t size) {
  for (size_t i = 0; i < size; i++) {
    // 16개 앞의 데이터를 프리페치
    if (i + 16 < size) {
      __builtin_prefetch(&data[i + 16], 0, 3);
    }
    
    // 현재 데이터 처리
    processData(data[i]);
  }
}

// ARM NEON 프리페치 예시
void prefetchLoop(float* src, size_t count) {
  for (size_t i = 0; i < count; i += 8) {
    __pld(src + i + 64); // 64바이트 앞 프리페치
    // SIMD 연산 수행
    float32x4_t v1 = vld1q_f32(src + i);
    float32x4_t v2 = vld1q_f32(src + i + 4);
  }
}

2. 논블로킹 캐시

캐시 미스 발생 시에도 다른 히트 요청을 계속 처리할 수 있는 구조입니다.

기법 설명 효과
히트 언더 미스 미스 처리 중에도 히트 처리 레이턴시 숨김
미스 언더 미스 여러 미스 동시 처리 메모리 레벨 병렬성 향상
MSHR (Miss Status Holding Registers) 진행 중인 미스 추적 중복 요청 방지

특수 목적 SRAM

1. CAM (Content Addressable Memory)

CAM은 데이터 내용으로 검색하는 특수 메모리로, TLB(Translation Lookaside Buffer)와 캐시 태그 검색에 사용됩니다.

  • TCAM (Ternary CAM): 0, 1, X(don't care) 세 가지 상태 지원. 네트워크 라우팅 테이블에 사용
  • BCAM (Binary CAM): 0, 1 두 가지 상태만 지원. 캐시 태그 매칭에 사용

2. 레지스터 파일

CPU 레지스터는 가장 빠른 SRAM 기반 저장소로, 다중 포트 구조를 가집니다.

아키텍처 레지스터 개수 포트 구성 액세스 시간
x86-64 16 범용 레지스터 3R2W (3읽기 2쓰기) <1 사이클
ARM64 31 범용 레지스터 3R2W <1 사이클
RISC-V 32 범용 레지스터 2R1W <1 사이클

저전력 SRAM 기술

1. 전압 스케일링

모바일 프로세서는 전력 절감을 위해 SRAM 전압을 동적으로 조절합니다.

// 동적 전압/주파수 조절 (DVFS) 예시
class PowerManager {
  setPowerMode(mode) {
    switch(mode) {
      case 'HIGH_PERFORMANCE':
        this.voltage = 1.0; // V
        this.frequency = 3.0; // GHz
        break;
      case 'BALANCED':
        this.voltage = 0.8; // V
        this.frequency = 2.0; // GHz
        break;
      case 'POWER_SAVE':
        this.voltage = 0.6; // V
        this.frequency = 1.0; // GHz
        break;
    }
    
    // 전력 = C × V² × f
    const power = this.capacitance * Math.pow(this.voltage, 2) * this.frequency;
    console.log(`Power: ${power.toFixed(2)}W`);
  }
}

2. 파워 게이팅

사용하지 않는 캐시 블록의 전원을 차단하여 누설 전력을 줄입니다.

  • 웨이 단위 게이팅: 세트 연관 캐시의 개별 웨이를 선택적으로 차단
  • 뱅크 단위 게이팅: 캐시를 여러 뱅크로 나누어 미사용 뱅크 차단
  • 상태 보존: 전원 재개 시 이전 상태 복원

SRAM 제조 및 공정

1. FinFET SRAM

최신 SRAM은 FinFET 트랜지스터를 사용하여 누설 전류를 크게 감소시켰습니다.

공정 노드 SRAM 셀 크기 누설 전력 동작 전압
28nm Planar 0.12 μm² 기준 0.9-1.2V
14nm FinFET 0.06 μm² -50% 0.7-1.0V
7nm FinFET 0.03 μm² -70% 0.6-0.9V
5nm FinFET 0.021 μm² -80% 0.55-0.85V

2. 안정성 향상 기법

미세 공정에서 SRAM 셀의 안정성을 유지하기 위한 다양한 기법이 사용됩니다.

SRAM 안정성 메트릭

  • SNM (Static Noise Margin): 읽기 안정성 지표. 외부 노이즈에 대한 내성
  • WM (Write Margin): 쓰기 능력 지표. 셀 값을 변경할 수 있는 능력
  • RSNM (Read Static Noise Margin): 읽기 동작 중 안정성
  • Hold SNM: 대기 상태에서의 안정성

요약

SRAM은 빠른 액세스 시간과 리프레시가 필요 없다는 장점으로 CPU 캐시의 핵심 기술입니다. 캐시 계층 구조, 일관성 프로토콜, 최적화 기법들이 종합적으로 작용하여 시스템 성능을 극대화합니다.

핵심 요점

  • 6T SRAM 셀은 빠르지만 DRAM보다 면적이 크고 비쌈
  • L1/L2/L3 캐시 계층 구조로 성능과 비용 균형 유지
  • MESI 프로토콜로 멀티코어 환경에서 캐시 일관성 보장
  • 프리페칭과 논블로킹 캐시로 성능 향상
  • FinFET 기술로 전력 효율성 크게 개선
