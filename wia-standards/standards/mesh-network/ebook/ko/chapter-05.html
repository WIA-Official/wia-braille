Phase 2: 라우팅 구현

멀티홉 라우팅 프로토콜을 구현하고 자가치유 메커니즘을 추가합니다.

Phase 2 개요

Phase 2에서는 메시 네트워크의 핵심인 라우팅 기능을 구현합니다. 노드 간의 직접 통신을 넘어 멀티홉 경로를 통한 데이터 전달, 동적 경로 탐색과 유지, 장애 발생 시 자동 복구를 구현합니다. AODV(Ad-hoc On-Demand Distance Vector) 프로토콜을 기반으로 WIA 표준에 맞는 라우팅 시스템을 구축합니다.

Phase 2 목표

  • AODV 라우팅 프로토콜 구현
  • 라우팅 테이블 관리 시스템 개발
  • 경로 탐색 및 유지 메커니즘 구현
  • 자가치유(Self-Healing) 기능 추가
  • 멀티홉 통신 테스트 및 검증
  • 경로 최적화 및 성능 튜닝

AODV 프로토콜 이해

AODV는 리액티브 라우팅 프로토콜로, 필요할 때만 경로를 탐색합니다. 이는 저트래픽 환경에서 오버헤드를 최소화하면서도 동적 토폴로지에 잘 적응합니다.

AODV의 핵심 메커니즘

메커니즘목적메시지 타입
경로 탐색 목적지까지 경로 발견 RREQ (Route Request)
경로 응답 발견된 경로 알림 RREP (Route Reply)
경로 오류 링크 단절 알림 RERR (Route Error)
경로 유지 경로 유효성 확인 HELLO 메시지

라우팅 테이블 구조

각 노드는 라우팅 테이블을 유지하여 알려진 목적지로의 경로 정보를 저장합니다. 테이블 항목은 목적지, 다음 홉, 홉 수, 시퀀스 번호, 수명 등의 정보를 포함합니다. 

// 라우팅 테이블 항목 구조
struct RouteEntry {
    uint16_t dest_addr;        // 목적지 주소
    uint16_t next_hop;         // 다음 홉 주소
    uint8_t  hop_count;        // 홉 수
    uint32_t dest_seq;         // 목적지 시퀀스 번호
    uint32_t lifetime;         // 경로 유효 시간
    uint8_t  flags;            // 상태 플래그
    int8_t   rssi;             // 링크 신호 강도
    time_t   last_used;        // 마지막 사용 시간
};

// 라우팅 테이블
#define MAX_ROUTES 100
struct RouteTable {
    RouteEntry routes[MAX_ROUTES];
    uint16_t num_routes;
    pthread_mutex_t lock;
};

라우팅 테이블 관리 함수

경로 추가/업데이트: 새로운 경로 정보를 테이블에 추가하거나 기존 경로를 더 좋은 정보로 갱신합니다.

경로 조회: 특정 목적지로의 경로를 빠르게 찾습니다. 해시 테이블 사용으로 O(1) 검색 가능합니다.

경로 삭제: 만료되거나 유효하지 않은 경로를 제거합니다. 주기적인 정리 작업으로 메모리 효율 유지합니다.

경로 정리: 수명이 다한 경로를 자동으로 삭제하는 백그라운드 작업을 실행합니다.

경로 탐색 프로세스

데이터를 전송하려는 노드가 목적지까지의 경로를 모를 때 경로 탐색을 시작합니다. RREQ 메시지를 브로드캐스트하여 전체 네트워크에 경로를 요청합니다.

RREQ 메시지 구조

struct RREQ {
    uint8_t  type;             // 메시지 타입 (RREQ)
    uint8_t  flags;            // 플래그 비트
    uint8_t  hop_count;        // 현재 홉 수
    uint32_t rreq_id;          // 요청 고유 ID
    uint16_t dest_addr;        // 목적지 주소
    uint32_t dest_seq;         // 목적지 시퀀스 번호
    uint16_t orig_addr;        // 발신자 주소
    uint32_t orig_seq;         // 발신자 시퀀스 번호
};

RREQ 처리 알고리즘

  1. RREQ 수신: 노드가 RREQ를 받으면 중복 확인을 수행합니다.
  2. 역방향 경로 생성: 발신자로의 경로를 라우팅 테이블에 추가합니다.
  3. 목적지 확인: 자신이 목적지이거나 유효한 경로를 가지고 있으면 RREP를 전송합니다.
  4. RREQ 전파: 그렇지 않으면 홉 카운트를 증가시켜 RREQ를 재브로드캐스트합니다.
  5. TTL 확인: 홉 카운트가 최대값에 도달하면 RREQ를 폐기합니다.

경로 응답 프로세스

목적지 노드 또는 유효한 경로를 가진 중간 노드가 RREP 메시지를 생성하여 발신자에게 유니캐스트로 전송합니다. 

// RREP 전송 함수
void send_rrep(uint16_t dest, uint16_t orig, uint32_t dest_seq, uint8_t hop_count) {
    RREP rrep;
    rrep.type = MSG_RREP;
    rrep.hop_count = hop_count;
    rrep.dest_addr = dest;
    rrep.dest_seq = dest_seq;
    rrep.orig_addr = orig;
    rrep.lifetime = ROUTE_LIFETIME;

    // 발신자로의 경로 조회
    RouteEntry* route = lookup_route(orig);
    if (route) {
        // 다음 홉으로 RREP 전송
        unicast(route->next_hop, &rrep, sizeof(rrep));
    }
}

RREP 전파

RREP를 수신한 중간 노드는 목적지로의 순방향 경로를 생성하고, RREP를 발신자 방향으로 계속 전달합니다. 이 과정에서 경로상의 모든 노드가 양방향 경로 정보를 얻게 됩니다.

경로 유지 메커니즘

설정된 경로가 계속 유효한지 확인하고, 링크 단절을 감지하여 대응합니다. HELLO 메시지와 MAC 계층 피드백을 활용합니다.

HELLO 메시지

각 노드는 주기적으로 HELLO 메시지를 브로드캐스트하여 이웃에게 자신의 활성 상태를 알립니다. 일정 시간 동안 HELLO 메시지를 받지 못하면 해당 이웃으로의 링크가 끊어진 것으로 판단합니다.

HELLO 간격: 1초마다 전송 (네트워크 부하에 따라 조정 가능)

타임아웃: 3번 연속 HELLO 미수신 시 링크 단절로 판단

링크 품질 모니터링: RSSI와 패킷 수신률(PRR)을 추적하여 링크 품질 평가

경로 오류 처리

링크 단절이 감지되면 RERR 메시지를 생성하여 영향받는 모든 노드에게 알립니다. 이를 통해 무효화된 경로를 사용하는 시도를 방지합니다. 

// 링크 단절 처리
void handle_link_failure(uint16_t next_hop) {
    // 영향받는 경로 찾기
    RouteEntry* affected[MAX_ROUTES];
    int count = find_affected_routes(next_hop, affected);

    if (count > 0) {
        // RERR 메시지 생성
        RERR rerr;
        rerr.type = MSG_RERR;
        rerr.dest_count = count;

        for (int i = 0; i < count; i++) {
            rerr.unreachable[i].addr = affected[i]->dest_addr;
            rerr.unreachable[i].seq = affected[i]->dest_seq;

            // 경로 무효화
            invalidate_route(affected[i]);
        }

        // 상위 노드들에게 RERR 전송
        send_rerr_to_precursors(&rerr);
    }
}

자가치유 메커니즘

메시 네트워크의 핵심 장점인 자가치유 능력을 구현합니다. 노드 장애나 링크 단절 시 자동으로 대체 경로를 찾아 통신을 복구합니다.

자가치유 전략

전략방법장점
로컬 복구 단절 지점 주변 노드가 대체 경로 탐색 빠른 복구, 낮은 오버헤드
백업 경로 미리 대체 경로를 유지 즉시 전환, 패킷 손실 최소
멀티패스 여러 경로로 동시 전송 높은 신뢰성, 부하 분산
프로액티브 감지 링크 품질 저하 조기 감지 예방적 대응, 안정성 향상

로컬 복구 구현

링크 단절을 감지한 노드가 직접 대체 경로를 찾습니다. 발신자에게 알리지 않고 로컬에서 문제를 해결하여 지연을 최소화합니다.

  1. 링크 단절 감지 시 로컬 RREQ 시작 (제한된 TTL)
  2. 짧은 시간 내에 대체 경로 발견 시 즉시 적용
  3. 실패 시 상위 노드로 RERR 전송하여 글로벌 재탐색
  4. 데이터 패킷을 버퍼링하여 경로 복구 후 전송 재개

경로 최적화

단순히 홉 수만 고려하지 않고 다양한 메트릭을 활용하여 최적의 경로를 선택합니다.

복합 메트릭

// 경로 품질 계산
float calculate_route_quality(RouteEntry* route) {
    float quality = 0.0;

    // 홉 수 (낮을수록 좋음)
    quality += (1.0 / (route->hop_count + 1)) * 0.3;

    // 링크 품질 (RSSI, 높을수록 좋음)
    quality += normalize_rssi(route->rssi) * 0.3;

    // 경로 안정성 (수명, 길수록 좋음)
    quality += (route->lifetime / MAX_LIFETIME) * 0.2;

    // 부하 (낮을수록 좋음)
    quality += (1.0 - route->load) * 0.2;

    return quality;
}

성능 최적화

라우팅 성능을 향상시키기 위한 다양한 최적화 기법을 적용합니다.

최적화 기법

  • 경로 캐싱: 최근 사용한 경로를 캐시에 저장하여 재탐색 빈도 감소
  • 점진적 RREQ: TTL을 점진적으로 증가시켜 불필요한 플러딩 방지
  • 경로 축약: 중간 노드가 더 짧은 경로를 알면 RREP에 반영
  • 선택적 HELLO: 활성 경로에 있는 노드만 HELLO 전송
  • 부하 인식 라우팅: 혼잡한 노드를 우회하는 경로 선택

라우팅 동작을 관찰하고 문제를 진단하기 위한 도구와 로깅을 구현합니다. 

// 라우팅 이벤트 로깅
void log_routing_event(const char* event, RouteEntry* route) {
    printf("[ROUTING] %s: dest=%04x next_hop=%04x hops=%d seq=%u\n",
           event, route->dest_addr, route->next_hop,
           route->hop_count, route->dest_seq);

    // 파일에도 기록
    write_to_log_file(event, route);
}

// 라우팅 테이블 덤프
void dump_routing_table() {
    printf("=== Routing Table ===\n");
    printf("Dest\tNext Hop\tHops\tSeq\tLifetime\n");
    for (int i = 0; i < route_table.num_routes; i++) {
        RouteEntry* r = &route_table.routes[i];
        printf("%04x\t%04x\t%d\t%u\t%u\n",
               r->dest_addr, r->next_hop, r->hop_count,
               r->dest_seq, r->lifetime);
    }
}
