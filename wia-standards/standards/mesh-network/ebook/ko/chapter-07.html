최적화의 중요성

메시 네트워크의 성공적인 배포 후에는 지속적인 최적화를 통해 성능을 극대화하고, 리소스 사용을 최소화하며, 사용자 경험을 향상시켜야 합니다. Phase 4에서는 네트워크 성능 튜닝, 알고리즘 개선, 에너지 효율성 향상, 확장성 강화 등 다양한 최적화 기법을 다룹니다.

WIA-MESH_NETWORK 표준은 측정 가능한 성능 지표, 벤치마킹 방법론, 모범 사례를 제공하여 조직이 메시 네트워크의 잠재력을 완전히 실현할 수 있도록 돕습니다. 최적화는 일회성 작업이 아니라 지속적인 프로세스이며, 네트워크 조건, 사용 패턴, 비즈니스 요구사항의 변화에 따라 지속적으로 조정되어야 합니다.

🎯 최적화 핵심 영역

  • 성능 최적화: 지연시간 감소, 처리량 증가, 응답 시간 개선

라우팅 알고리즘 최적화

라우팅 알고리즘은 메시 네트워크 성능의 핵심입니다. 최적의 경로 선택, 효율적인 부하 분산, 빠른 장애 복구는 모두 지능적인 라우팅 알고리즘에 의존합니다. 이 섹션에서는 고급 라우팅 최적화 기법을 탐구합니다.

1. 적응형 라우팅 메트릭

전통적인 홉 수 기반 라우팅을 넘어, 현대 메시 네트워크는 링크 품질, 노드 부하, 에너지 레벨, 대역폭 가용성 등 다양한 요소를 고려하는 복합 메트릭을 사용합니다.

복합 라우팅 메트릭 계산: 
interface RoutingMetric {
  hopCount: number;         // 홉 수
  linkQuality: number;      // 링크 품질 (0-1)
  nodeLoad: number;         // 노드 부하 (0-1)
  energyLevel: number;      // 에너지 레벨 (0-1)
  bandwidth: number;        // 가용 대역폭 (Mbps)
  reliability: number;      // 신뢰성 점수 (0-1)
}

function calculatePathCost(path: Node[]): number {
  let totalCost = 0;

  for (let i = 0; i < path.length - 1; i++) {
    const link = getLink(path[i], path[i + 1]);
    const metric = link.metric;

    // 가중 복합 메트릭 계산
    const cost = (
      metric.hopCount * 0.2 +                    // 홉 수 (20%)
      (1 - metric.linkQuality) * 0.25 +          // 링크 품질 (25%)
      metric.nodeLoad * 0.2 +                     // 노드 부하 (20%)
      (1 - metric.energyLevel) * 0.15 +          // 에너지 (15%)
      (1 - metric.bandwidth / 1000) * 0.1 +      // 대역폭 (10%)
      (1 - metric.reliability) * 0.1              // 신뢰성 (10%)
    );

    totalCost += cost;
  }

  return totalCost;
}

// 최적 경로 선택
function findOptimalPath(source: Node, destination: Node): Node[] {
  const allPaths = findAllPaths(source, destination);

  return allPaths.reduce((bestPath, currentPath) => {
    const currentCost = calculatePathCost(currentPath);
    const bestCost = calculatePathCost(bestPath);

    return currentCost < bestCost ? currentPath : bestPath;
  });
}

2. 다중 경로 라우팅 (Multipath Routing)

단일 최적 경로에만 의존하는 대신, 여러 경로를 동시에 활용하여 부하를 분산하고 장애 복원력을 높이는 다중 경로 라우팅은 대규모 메시 네트워크에서 필수적입니다.

다중 경로 라우팅의 이점

  • 부하 분산: 트래픽을 여러 경로로 분산하여 혼잡 방지
  • 대역폭 집계: 여러 경로의 대역폭을 결합하여 총 처리량 증가
  • 빠른 장애 복구: 주 경로 실패 시 즉시 대체 경로 사용
  • QoS 보장: 우선순위 트래픽을 최고 품질 경로로 전송
다중 경로 라우팅 구현: 
class MultipathRouter {
  private pathCache: Map = new Map();

  async routePacket(packet: Packet, source: Node, dest: Node) {
    const cacheKey = `${source.id}-${dest.id}`;

    // 다중 경로 조회 또는 계산
    let paths = this.pathCache.get(cacheKey);
    if (!paths || this.shouldRecalculate(paths)) {
      paths = await this.findMultiplePaths(source, dest, {
        maxPaths: 3,              // 최대 3개 경로
        minDisjointness: 0.5,     // 최소 50% 경로 분리도
        maxCostRatio: 1.5         // 최적 경로 대비 최대 1.5배 비용
      });
      this.pathCache.set(cacheKey, paths);
    }

    // 경로 선택 전략
    const path = this.selectPath(paths, packet);

    // 패킷 전송
    return await this.forwardPacket(packet, path);
  }

  private selectPath(paths: Path[], packet: Packet): Path {
    // 우선순위 트래픽: 최고 품질 경로
    if (packet.priority === 'high') {
      return paths[0]; // 최적 경로
    }

    // 일반 트래픽: 라운드 로빈 부하 분산
    const pathIndex = this.roundRobinCounter++ % paths.length;
    return paths[pathIndex];
  }

  private async findMultiplePaths(
    source: Node,
    dest: Node,
    options: MultipathOptions
  ): Promise {
    const paths: Path[] = [];
    const usedLinks = new Set();

    for (let i = 0; i < options.maxPaths; i++) {
      // 이미 사용된 링크를 회피하는 경로 탐색
      const path = await this.findDisjointPath(
        source,
        dest,
        usedLinks,
        options.minDisjointness
      );

      if (path && this.isAcceptablePath(path, paths[0], options.maxCostRatio)) {
        paths.push(path);
        path.links.forEach(link => usedLinks.add(link.id));
      } else {
        break; // 더 이상 적절한 경로 없음
      }
    }

    return paths;
  }
}

에너지 효율성 최적화

배터리 구동 노드가 많은 메시 네트워크에서 에너지 효율성은 네트워크 수명을 결정하는 핵심 요소입니다. 지능적인 전력 관리, 슬립 스케줄링, 에너지 인식 라우팅을 통해 배터리 수명을 극적으로 연장할 수 있습니다.

1. 동적 전력 관리

전력 절약 기법:
  • 적응형 송신 전력: 거리와 링크 품질에 따라 송신 전력 동적 조정
  • 슬립 스케줄링: 조율된 슬립/웨이크 사이클로 불필요한 대기 전력 제거
  • 듀티 사이클링: 주기적으로 라디오를 켜고 끄는 방식으로 전력 소비 감소
  • 데이터 집계: 여러 작은 패킷을 하나로 결합하여 전송 횟수 감소
에너지 인식 라우팅 알고리즘: 
class EnergyAwareRouter {
  async selectEnergyEfficientPath(
    source: Node,
    dest: Node,
    packet: Packet
  ): Promise {
    const allPaths = await this.findAllPaths(source, dest);

    return allPaths.reduce((bestPath, currentPath) => {
      const currentEnergy = this.calculatePathEnergy(currentPath, packet);
      const bestEnergy = this.calculatePathEnergy(bestPath, packet);

      // 에너지 균형과 총 에너지 소비를 모두 고려
      const currentScore = this.calculateEnergyScore(
        currentPath,
        currentEnergy
      );
      const bestScore = this.calculateEnergyScore(
        bestPath,
        bestEnergy
      );

      return currentScore < bestScore ? currentPath : bestPath;
    });
  }

  private calculatePathEnergy(path: Path, packet: Packet): number {
    let totalEnergy = 0;

    for (const node of path.nodes) {
      // 송신 에너지
      const txEnergy = this.calculateTxEnergy(
        packet.size,
        node.txPower,
        node.distance
      );

      // 수신 에너지
      const rxEnergy = this.calculateRxEnergy(packet.size);

      // 처리 에너지
      const processingEnergy = packet.size * node.energyPerBit;

      totalEnergy += txEnergy + rxEnergy + processingEnergy;
    }

    return totalEnergy;
  }

  private calculateEnergyScore(path: Path, pathEnergy: number): number {
    // 경로의 최소 잔여 에너지를 찾음
    const minRemainingEnergy = Math.min(
      ...path.nodes.map(n => n.remainingEnergy)
    );

    // 에너지 불균형 패널티
    const energyImbalance = path.nodes.reduce((sum, node) => {
      return sum + Math.abs(node.remainingEnergy - minRemainingEnergy);
    }, 0);

    // 총 점수 = 경로 에너지 + 불균형 패널티
    return pathEnergy + (energyImbalance * 0.3);
  }

  private calculateTxEnergy(
    packetSize: number,
    txPower: number,
    distance: number
  ): number {
    // 프리스 전송 방정식을 사용한 에너지 계산
    const pathLoss = Math.pow(distance, 2);
    return packetSize * txPower * pathLoss * 1e-9; // nJ
  }
}

2. 로드 밸런싱

트래픽을 네트워크 전체에 균등하게 분산시키는 로드 밸런싱은 병목 현상을 방지하고 전체 처리량을 극대화합니다. 동적 부하 인식, 게이트웨이 선택, 채널 할당 등 다양한 기법이 사용됩니다.

동적 로드 밸런싱 구현: 
class LoadBalancer {
  private nodeLoadMap: Map = new Map();
  private loadThreshold = 0.8; // 80% 부하 임계값

  async balanceLoad(packet: Packet, availablePaths: Path[]): Promise {
    // 각 경로의 현재 부하 계산
    const pathLoads = availablePaths.map(path => ({
      path,
      load: this.calculatePathLoad(path),
      bottleneck: this.findBottleneckNode(path)
    }));

    // 부하가 가장 낮은 경로 선택
    const selectedPath = pathLoads.reduce((best, current) => {
      return current.load < best.load ? current : best;
    });

    // 과부하 경로 회피
    if (selectedPath.load > this.loadThreshold) {
      await this.triggerLoadRebalancing(selectedPath.path);
    }

    return selectedPath.path;
  }

  private calculatePathLoad(path: Path): number {
    return path.nodes.reduce((maxLoad, node) => {
      const nodeLoad = this.getNodeLoad(node);
      return Math.max(maxLoad, nodeLoad);
    }, 0);
  }

  private async triggerLoadRebalancing(overloadedPath: Path) {
    // 1. 대체 경로 탐색
    const alternatePaths = await this.findAlternatePaths(overloadedPath);

    // 2. 트래픽 재분배
    const trafficToMigrate = this.calculateMigrationVolume(overloadedPath);

    for (const flow of trafficToMigrate) {
      const newPath = this.selectLightestPath(alternatePaths);
      await this.migrateFlow(flow, newPath);
    }

    // 3. 부하 모니터링 업데이트
    this.updateLoadMetrics();
  }
}

서비스 품질 (QoS) 최적화

다양한 유형의 트래픽이 공존하는 메시 네트워크에서 QoS 보장은 필수적입니다. 음성, 비디오, 센서 데이터, 제어 명령 등 각 트래픽 유형의 요구사항을 충족시키기 위한 차별화된 서비스가 필요합니다.

트래픽 분류 및 우선순위

QoS 클래스 정의

클래스 우선순위 지연 요구 대역폭 예시
실시간 제어 최고 < 10ms 낮음 산업 제어, 긴급 경보
실시간 스트리밍 높음 < 50ms 높음 음성, 비디오
우선 데이터 중간 < 200ms 중간 중요 센서 데이터
일반 데이터 보통 < 1초 가변 주기적 보고

class QoSScheduler {
  private queues: Map> = new Map([
    [QoSClass.REALTIME_CONTROL, new PriorityQueue()],
    [QoSClass.REALTIME_STREAMING, new PriorityQueue()],
    [QoSClass.PRIORITY_DATA, new PriorityQueue()],
    [QoSClass.NORMAL_DATA, new PriorityQueue()],
    [QoSClass.BACKGROUND, new PriorityQueue()]
  ]);

  enqueuePacket(packet: Packet) {
    const qosClass = this.classifyPacket(packet);
    this.queues.get(qosClass).enqueue(packet);
  }

  async scheduleTransmission(): Promise {
    // 엄격한 우선순위 스케줄링 + WFQ (Weighted Fair Queuing)

    // 1. 실시간 제어 패킷은 항상 우선
    if (!this.queues.get(QoSClass.REALTIME_CONTROL).isEmpty()) {
      return this.queues.get(QoSClass.REALTIME_CONTROL).dequeue();
    }

    // 2. 가중 라운드 로빈으로 나머지 클래스 처리
    const weights = {
      [QoSClass.REALTIME_STREAMING]: 40,
      [QoSClass.PRIORITY_DATA]: 30,
      [QoSClass.NORMAL_DATA]: 20,
      [QoSClass.BACKGROUND]: 10
    };

    return this.weightedFairQueuing(weights);
  }

  private classifyPacket(packet: Packet): QoSClass {
    // DSCP 마킹 기반 분류
    if (packet.dscp >= 46) return QoSClass.REALTIME_CONTROL;
    if (packet.dscp >= 34) return QoSClass.REALTIME_STREAMING;
    if (packet.dscp >= 18) return QoSClass.PRIORITY_DATA;
    if (packet.dscp >= 8) return QoSClass.NORMAL_DATA;
    return QoSClass.BACKGROUND;
  }

  private weightedFairQueuing(weights: Record): Packet | null {
    // 가중치에 따라 각 큐에서 패킷 선택
    for (const [qosClass, weight] of Object.entries(weights)) {
      const queue = this.queues.get(qosClass as QoSClass);

      if (!queue.isEmpty() && this.shouldServeQueue(qosClass, weight)) {
        return queue.dequeue();
      }
    }

    return null;
  }
}

장애 복구 및 자가 치유

메시 네트워크의 핵심 장점 중 하나는 장애 복원력입니다. 노드나 링크가 실패하더라도 네트워크가 자동으로 재구성하여 서비스를 유지합니다. 최적화된 장애 감지 및 복구 메커니즘은 다운타임을 최소화합니다.

빠른 장애 감지

장애 감지 메커니즘

  • 하트비트 모니터링: 주기적인 keep-alive 메시지로 이웃 노드 상태 확인
  • 링크 품질 모니터링: RSSI, SNR, 패킷 손실률 지속적 측정
  • 경로 프로빙: 능동적 경로 테스트로 장애 조기 감지
  • 예측적 장애 감지: ML 기반으로 장애 전조 증상 식별
자가 치유 메커니즘: 
class SelfHealingMesh {
  private healthMonitor: HealthMonitor;
  private failureDetector: FailureDetector;

  async monitorAndHeal() {
    setInterval(async () => {
      // 1. 네트워크 건강 상태 평가
      const healthStatus = await this.healthMonitor.assess();

      // 2. 장애 감지
      const failures = await this.failureDetector.detect();

      if (failures.length > 0) {
        await this.healFailures(failures);
      }

      // 3. 예방적 최적화
      if (healthStatus.score < 0.8) {
        await this.preventiveOptimization(healthStatus);
      }
    }, 5000); // 5초마다 체크
  }

  private async healFailures(failures: Failure[]) {
    for (const failure of failures) {
      console.log(`장애 감지: ${failure.type} at ${failure.location}`);

      switch (failure.type) {
        case 'NODE_FAILURE':
          await this.handleNodeFailure(failure);
          break;
        case 'LINK_FAILURE':
          await this.handleLinkFailure(failure);
          break;
        case 'PARTITION':
          await this.handleNetworkPartition(failure);
          break;
      }
    }
  }

  private async handleNodeFailure(failure: NodeFailure) {
    const failedNode = failure.node;

    // 1. 영향받는 경로 식별
    const affectedPaths = await this.findAffectedPaths(failedNode);

    // 2. 대체 경로 계산
    for (const path of affectedPaths) {
      const newPath = await this.findAlternatePath(
        path.source,
        path.destination,
        [failedNode] // 실패 노드 제외
      );

      if (newPath) {
        // 3. 트래픽 재라우팅
        await this.rerouteTraffic(path, newPath);
      } else {
        // 대체 경로 없음 - 상위 레이어에 알림
        await this.notifyPathUnavailable(path);
      }
    }

    // 4. 네트워크 토폴로지 업데이트
    await this.updateTopology(failedNode, 'REMOVE');

    // 5. 자동 복구 시도 (재부팅 등)
    await this.attemptNodeRecovery(failedNode);
  }

  private async preventiveOptimization(healthStatus: HealthStatus) {
    // 예방적 조치로 네트워크 상태 개선

    if (healthStatus.congestionLevel > 0.7) {
      // 혼잡 완화
      await this.relieveCongestion();
    }

    if (healthStatus.energyImbalance > 0.5) {
      // 에너지 균형 조정
      await this.rebalanceEnergy();
    }

    if (healthStatus.routingEfficiency < 0.8) {
      // 라우팅 최적화
      await this.optimizeRouting();
    }
  }
}

지속적인 모니터링 및 튜닝

최적화는 일회성 활동이 아니라 지속적인 프로세스입니다. 실시간 모니터링, 성능 분석, 점진적 튜닝을 통해 네트워크를 최상의 상태로 유지해야 합니다.

성능 대시보드

Grafana, Kibana와 같은 시각화 도구를 사용하여 실시간 성능 메트릭을 모니터링하고, 이상 징후를 조기에 발견하며, 데이터 기반 최적화 결정을 내릴 수 있습니다.

주요 모니터링 메트릭:
  • 노드별 처리량, 지연시간, 패킷 손실률
  • 링크별 품질 지표 (RSSI, SNR, BER)
  • 경로 최적성 및 홉 수 분포
  • 에너지 소비 및 잔여 배터리 레벨
  • 네트워크 토폴로지 변화 빈도
  • QoS 위반 및 SLA 준수율
