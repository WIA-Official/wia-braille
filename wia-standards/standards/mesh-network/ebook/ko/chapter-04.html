제4장

Phase 1: 기초 인프라 구축

메시 네트워크 구현의 첫 단계로 기본 인프라와 노드 설정을 다룹니다.

Phase 1 개요

Phase 1은 메시 네트워크 구현의 기초를 다지는 단계입니다. 하드웨어 선택, 초기 설정, 기본 통신 확립, 노드 발견 메커니즘 구현이 이 단계의 주요 목표입니다. 견고한 기초 없이는 상위 기능이 제대로 작동할 수 없으므로 이 단계가 매우 중요합니다.

Phase 1 목표

  • 적절한 하드웨어 플랫폼 선택
  • 물리 계층 및 MAC 계층 설정
  • 기본 노드간 통신 확립
  • 이웃 발견 프로토콜 구현
  • 초기 토폴로지 구축
  • 간단한 테스트 시나리오 검증

하드웨어 플랫폼 선택

메시 네트워크의 성능과 기능은 하드웨어 선택에 크게 영향을 받습니다. 응용의 요구사항, 예산, 확장성 계획을 고려하여 적절한 플랫폼을 선택해야 합니다.

주요 하드웨어 플랫폼

플랫폼프로세서무선적합 응용
ESP32 Dual-core 240MHz WiFi, BLE 스마트 홈, IoT 게이트웨이
nRF52840 ARM Cortex-M4 BLE, 802.15.4 저전력 센서, Thread
CC2652 ARM Cortex-M4 Zigbee, Thread Zigbee 메시, Matter
Raspberry Pi Quad-core ARM WiFi, 확장 가능 게이트웨이, 테스트
STM32WB Dual-core M4+M0 BLE, 802.15.4 저전력 메시, 의료

하드웨어 선택 기준

처리 능력: 라우팅 테이블 크기, 암호화 연산, 예상 트래픽을 고려합니다. 복잡한 라우팅 프로토콜은 더 강력한 프로세서가 필요합니다.

메모리: RAM은 라우팅 테이블과 버퍼에, Flash는 펌웨어와 설정에 사용됩니다. 최소 256KB RAM, 1MB Flash를 권장합니다.

무선 인터페이스: 주파수 대역, 전송 전력, 수신 감도가 통신 범위를 결정합니다. 2.4GHz는 속도가 빠르고 Sub-GHz는 범위가 넓습니다.

전력 소비: 배터리 기반 노드는 저전력 모드, 슬립 모드가 필수입니다. Active, Idle, Sleep 상태의 전류를 확인합니다.

확장성: GPIO, 센서 인터페이스, 확장 커넥터가 향후 기능 추가를 용이하게 합니다.

개발 환경 구축

효율적인 개발을 위해 적절한 도구와 프레임워크를 설정합니다. WIA 표준은 다양한 플랫폼과 개발 환경을 지원합니다.

필수 소프트웨어

  • IDE: Visual Studio Code, Eclipse, PlatformIO
  • 컴파일러: ARM GCC, ESP-IDF, Zephyr SDK
  • 디버거: JTAG/SWD 디버거, 시리얼 모니터
  • 프로토콜 분석기: Wireshark, nRF Sniffer
  • WIA SDK: WIA-MESH_NETWORK 참조 구현

WIA SDK 설치

WIA SDK는 표준 구현을 빠르게 시작할 수 있는 라이브러리와 예제를 제공합니다. 다음은 기본 설치 절차입니다. 

# Git 저장소 복제
git clone https://github.com/WIA-Official/wia-mesh-sdk.git
cd wia-mesh-sdk

# 의존성 설치
./install-deps.sh

# 예제 빌드
cd examples/basic-mesh
mkdir build && cd build
cmake ..
make

# 펌웨어 플래시
make flash

물리 계층 설정

물리 계층은 실제 무선 통신을 담당합니다. 주파수 채널, 전송 전력, 변조 방식 등을 적절히 설정해야 합니다.

채널 선택

대역채널장점단점
2.4 GHz 11-26 (802.15.4) 높은 속도, 작은 안테나 혼잡, WiFi 간섭
915 MHz 1-10 (북미) 긴 범위, 장애물 통과 낮은 속도, 지역 제한
868 MHz 0 (유럽) 긴 범위, 적은 간섭 단일 채널, 듀티 사이클

전송 전력 최적화

전송 전력은 통신 범위와 전력 소비 사이의 트레이드오프입니다. 너무 높으면 간섭을 유발하고 배터리를 소모하며, 너무 낮으면 연결이 불안정합니다.

권장 설정:

  • 실내 환경: 0 dBm ~ +4 dBm
  • 실외 환경: +8 dBm ~ +20 dBm
  • 장거리 통신: +20 dBm (규제 허용 범위 내)
  • 저전력 센서: -12 dBm ~ 0 dBm

적응형 전력 제어: 링크 품질을 모니터링하여 필요한 최소 전력을 사용합니다. RSSI 피드백으로 동적 조절이 가능합니다.

MAC 계층 설정

MAC 계층은 채널 접근을 조정하고 충돌을 방지합니다. IEEE 802.15.4 MAC을 기반으로 메시 네트워크에 최적화된 파라미터를 사용합니다.

주요 MAC 파라미터

파라미터설명권장값
macMinBE 최소 백오프 지수 3
macMaxBE 최대 백오프 지수 5
macMaxCSMABackoffs 최대 백오프 시도 4
macMaxFrameRetries 최대 재전송 횟수 3
macAckWaitDuration ACK 대기 시간 54 symbols

이웃 발견 프로토콜

각 노드는 주변의 다른 노드를 발견하고 이웃 테이블을 유지해야 합니다. WIA 표준은 주기적 비컨과 요청-응답 방식을 모두 지원합니다.

비컨 기반 발견

각 노드는 주기적으로 비컨을 브로드캐스트하여 자신의 존재를 알립니다. 비컨에는 노드 ID, 능력 정보, 네트워크 상태가 포함됩니다. 

// 비컨 구조
struct Beacon {
    uint16_t node_id;          // 노드 고유 ID
    uint8_t  hop_count;        // 게이트웨이까지 홉 수
    uint8_t  load;             // 현재 부하 (0-100)
    uint16_t sequence;         // 시퀀스 번호
    uint8_t  capabilities;     // 능력 플래그
};

// 비컨 전송 (30초 간격)
void send_beacon() {
    Beacon beacon;
    beacon.node_id = my_node_id;
    beacon.hop_count = distance_to_gateway;
    beacon.load = get_current_load();
    beacon.sequence = ++beacon_seq;
    beacon.capabilities = ROUTER | LOW_POWER;

    broadcast(&beacon, sizeof(beacon));
}

이웃 테이블 관리

수신한 비컨 정보를 기반으로 이웃 테이블을 구성합니다. 타임아웃을 설정하여 오래된 항목을 제거합니다.

이웃 항목 구조:

  • 노드 ID: 이웃 노드의 고유 식별자
  • RSSI: 수신 신호 강도, 링크 품질 지표
  • LQI: 링크 품질 지수
  • 마지막 수신 시간: 타임아웃 판단용
  • 홉 카운트: 라우팅 메트릭
  • 능력: 라우터, 엔드 디바이스 등

타임아웃: 비컨 간격의 3배 동안 비컨이 수신되지 않으면 해당 이웃을 테이블에서 제거합니다. (예: 90초)

초기 네트워크 형성

첫 번째 노드가 네트워크를 생성하고 다른 노드들이 순차적으로 참여합니다. PAN 코디네이터 역할을 하는 노드가 네트워크 ID를 할당합니다.

네트워크 시작 절차

  1. PAN ID 선택: 무작위 또는 사전 설정된 PAN ID 사용
  2. 채널 스캔: 간섭이 적은 채널 선택 (에너지 검출)
  3. 네트워크 생성: 선택한 채널에서 비컨 전송 시작
  4. 조인 허용: 새 노드의 참여 요청 승인
  5. 주소 할당: 참여 노드에 단축 주소 부여

노드 참여 절차

// 네트워크 참여 코드 예시
void join_network() {
    // 1. 비컨 스캔
    scan_beacons();

    // 2. 최적 네트워크 선택
    Network* best = select_best_network();

    // 3. 조인 요청 전송
    send_join_request(best->pan_id);

    // 4. 응답 대기
    JoinResponse* resp = wait_for_response(TIMEOUT);

    if (resp && resp->status == ACCEPTED) {
        // 5. 네트워크 파라미터 설정
        my_short_addr = resp->assigned_addr;
        network_key = resp->network_key;

        // 6. 네트워크 활동 시작
        start_routing();
        send_beacon();
    }
}

기본 통신 테스트

인프라 구축 후 기본 통신이 제대로 작동하는지 검증합니다. 단순한 핑-퐁 테스트부터 시작하여 점진적으로 복잡한 시나리오를 테스트합니다.

테스트 시나리오

1. 이웃 발견 테스트:

  • 각 노드의 이웃 테이블 확인
  • 양방향 링크 검증
  • RSSI 및 LQI 값 모니터링

2. 직접 통신 테스트:

  • 인접 노드 간 핑 메시지 교환
  • 응답 시간 측정
  • 패킷 손실률 확인

3. 브로드캐스트 테스트:

  • 브로드캐스트 메시지 전송
  • 모든 이웃이 수신하는지 확인
  • 브로드캐스트 스톰 방지 메커니즘 검증

문제 해결

Phase 1 구현 중 자주 발생하는 문제와 해결 방법입니다.

문제원인해결 방법
노드 발견 실패 채널 불일치, 전력 부족 채널 설정 확인, 전송 전력 증가
빈번한 연결 끊김 간섭, 약한 신호 채널 변경, 노드 위치 조정

비컨 수신 안됨 타이밍 문제, 슬립 모드 동기화 개선, 웨이크업 스케줄 조정

요약

Phase 1에서는 메시 네트워크의 기초를 구축했습니다. 하드웨어 선택, 물리/MAC 계층 설정, 이웃 발견, 초기 네트워크 형성을 완료했습니다. 이제 견고한 기반 위에 라우팅 기능을 구현할 준비가 되었습니다.

다음 Phase 2에서는 멀티홉 라우팅 프로토콜을 구현하고 네트워크 기능을 확장하겠습니다.
