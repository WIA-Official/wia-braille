LPWAN 기술 개요: LoRaWAN, NB-IoT, Sigfox를 통한 저전력 광역 네트워크의 이해

LPWAN의 등장 배경

사물인터넷(IoT) 시대의 도래와 함께 수십억 개의 센서와 기기가 네트워크에 연결되면서, 전통적인 무선 통신 기술로는 커버할 수 없는 새로운 요구사항이 등장했습니다. 스마트 시티, 스마트 농업, 산업 IoT, 자산 추적 등의 애플리케이션은 장거리 통신, 저전력 소비, 저비용 연결성을 동시에 요구합니다.

Wi-Fi는 높은 데이터 전송률을 제공하지만 통신 거리가 100m 이내로 제한되며, 전력 소비가 커서 배터리로 수년간 작동해야 하는 센서에는 부적합합니다. Bluetooth Low Energy(BLE)는 전력 효율적이지만 통신 거리가 더욱 짧아 10-50m에 불과합니다. 셀룰러 네트워크(2G/3G/4G)는 광역 커버리지를 제공하지만 모듈 비용이 높고, 데이터 요금이 비싸며, 배터리 수명이 일반적으로 며칠에서 몇 주에 불과합니다.

LPWAN(Low Power Wide Area Network)은 이러한 간극을 메우기 위해 설계된 무선 통신 기술로, 수 km에서 수십 km의 통신 거리, 배터리로 10년 이상의 작동 시간, 낮은 디바이스 비용과 통신 비용을 실현합니다. 대신 데이터 전송률은 낮아서 일반적으로 수백 bps에서 수십 kbps 수준이며, 이는 주기적인 센서 데이터 전송이나 간헐적인 제어 명령 전송에 충분합니다.

LPWAN 시장은 2015년경부터 본격적으로 성장하기 시작했으며, LoRaWAN, NB-IoT, Sigfox가 주요 기술로 자리잡았습니다. 각 기술은 고유한 장단점을 가지고 있어 애플리케이션 특성에 따라 선택됩니다. 글로벌 LPWAN 시장 규모는 2025년 약 650억 달러에 달할 것으로 전망되며, 연평균 45% 이상의 성장률을 보이고 있습니다.

LoRaWAN 기술 심층 분석

LoRaWAN(Long Range Wide Area Network)은 LoRa Alliance가 표준화하고 주도하는 개방형 LPWAN 프로토콜로, Semtech가 개발한 LoRa 물리 계층 기술을 기반으로 합니다. LoRa는 Chirp Spread Spectrum(CSS) 변조 방식을 사용하여 낮은 신호 대 잡음비(SNR) 환경에서도 신뢰할 수 있는 통신을 제공합니다. CSS는 시간에 따라 주파수가 변하는 chirp 신호를 사용하여 간섭과 페이딩에 강인한 특성을 갖습니다.

LoRaWAN은 비면허 주파수 대역을 사용하므로 통신사 계약 없이 독자적으로 네트워크를 구축할 수 있습니다. 지역별로 사용 가능한 주파수 대역이 다르며, 유럽은 868MHz, 북미는 915MHz, 아시아는 923MHz 또는 지역별 할당 대역을 사용합니다. 각 지역에서는 듀티 사이클 제한(유럽은 일반적으로 1%), 최대 전송 전력(유럽 14dBm, 북미 30dBm), 채널 대역폭 등의 규제를 준수해야 합니다.

LoRaWAN 네트워크 아키텍처는 star-of-stars 토폴로지를 채택합니다. 엔드 디바이스는 하나 이상의 게이트웨이와 직접 통신하며, 게이트웨이는 백홀 연결(이더넷, 3G/4G, Wi-Fi)을 통해 중앙 네트워크 서버로 메시지를 전달합니다. 네트워크 서버는 디바이스 인증, 중복 메시지 제거, Adaptive Data Rate(ADR) 제어, 메시지 라우팅을 담당합니다. 애플리케이션 서버는 네트워크 서버로부터 디코딩된 데이터를 받아 비즈니스 로직을 처리합니다.

LoRaWAN은 세 가지 디바이스 클래스를 정의합니다. Class A는 가장 전력 효율적이며, 업링크 전송 후 짧은 수신 창에서만 다운링크를 받을 수 있습니다. Class B는 주기적인 수신 창을 추가하여 지연 시간이 예측 가능한 다운링크를 제공하며, 게이트웨이로부터 비콘 신호를 받아 시간 동기화를 수행합니다. Class C는 수신을 항상 켜두어 최소 지연으로 다운링크를 받을 수 있지만 전력 소비가 가장 높습니다. 대부분의 센서 애플리케이션은 Class A를 사용하며, 액추에이터나 즉시 응답이 필요한 경우 Class C를 선택합니다.

LoRaWAN의 주요 특징 중 하나는 Spreading Factor(SF)입니다. SF는 7부터 12까지 설정 가능하며, SF가 높을수록 통신 거리가 길어지지만 데이터 전송률이 낮아지고 airtime이 증가합니다. SF7은 5.5kbps의 전송률과 약 2km의 도심 커버리지를, SF12는 250bps의 전송률과 15km 이상의 농촌 커버리지를 제공합니다. ADR 기능은 디바이스와 게이트웨이 간의 링크 품질을 모니터링하여 최적의 SF와 전송 전력을 자동으로 조정함으로써 배터리 수명을 연장하고 네트워크 용량을 향상시킵니다.

LoRaWAN의 보안은 AES-128 암호화를 기반으로 하며, 두 개의 세션 키를 사용합니다. Network Session Key(NwkSKey)는 네트워크 서버와의 통신을 암호화하고 메시지 무결성을 검증하며, Application Session Key(AppSKey)는 애플리케이션 페이로드를 암호화합니다. 디바이스 활성화는 OTAA(Over-The-Air Activation)와 ABP(Activation By Personalization) 두 가지 방식을 지원하며, OTAA가 보안성이 높고 권장됩니다.

NB-IoT 기술 상세 설명

NB-IoT(Narrowband IoT)는 3GPP Release 13에서 표준화된 셀룰러 LPWAN 기술로, 기존 LTE 네트워크 인프라를 활용하여 IoT 기기를 위한 저전력 광역 통신을 제공합니다. NB-IoT는 면허 주파수 대역을 사용하므로 간섭이 적고, 통신사가 관리하는 안정적인 네트워크 품질과 서비스 수준 계약(SLA)을 기대할 수 있습니다. 전 세계 100개 이상의 통신사가 NB-IoT 서비스를 제공하고 있으며, 로밍 협정을 통해 글로벌 커버리지도 가능합니다.

NB-IoT는 세 가지 배치 모드를 지원합니다. Standalone 모드는 기존 GSM 주파수 대역을 재사용하며, Guard Band 모드는 LTE 대역의 가드 밴드에 배치되고, In-Band 모드는 LTE carrier 내의 Physical Resource Block(PRB)을 사용합니다. In-Band 배치가 가장 유연하며 추가 주파수 할당 없이 기존 LTE 네트워크에 통합할 수 있습니다. 200kHz의 좁은 대역폭을 사용하여 하나의 PRB만으로도 운영이 가능하며, 이는 주파수 효율성이 매우 높은 것을 의미합니다.

NB-IoT의 핵심 특징은 Coverage Enhancement(CE)입니다. 일반 셀룰러 통신에서 도달하기 어려운 깊은 실내, 지하실, 지하 주차장 등의 환경에서도 통신이 가능하도록 설계되었습니다. 이는 메시지 반복 전송을 통해 달성되며, 최대 128회까지 반복할 수 있습니다. Maximum Coupling Loss(MCL) 164dB를 달성하여 기존 GPRS 대비 20dB 이상의 커버리지 향상을 제공합니다. CE는 세 가지 레벨로 분류되며, CE Level 0은 정상 커버리지, CE Level 1은 중간 커버리지 확장, CE Level 2는 최대 커버리지 확장을 제공합니다.

전력 절감을 위해 NB-IoT는 Power Saving Mode(PSM)와 extended Discontinuous Reception(eDRX)를 지원합니다. PSM에서 디바이스는 deep sleep 상태로 들어가 마이크로암페어 수준의 전류만 소비하며, 설정된 시간이 지나거나 전송할 데이터가 있을 때까지 네트워크와의 연결을 유지하지 않습니다. Active Timer와 TAU(Tracking Area Update) Timer를 조정하여 PSM 주기를 애플리케이션 요구사항에 맞게 최적화할 수 있습니다. eDRX는 paging 수신 주기를 확장하여 디바이스가 더 긴 시간 동안 sleep 상태를 유지하면서도 네트워크 도달성을 유지합니다. PSM과 eDRX를 적절히 조합하면 배터리 수명을 10년 이상으로 연장할 수 있습니다.

NB-IoT는 CoAP(Constrained Application Protocol), LwM2M(Lightweight M2M), MQTT 등 다양한 IoT 프로토콜을 지원합니다. LwM2M은 OMA(Open Mobile Alliance)에서 정의한 디바이스 관리 프로토콜로, 펌웨어 업데이트, 원격 설정, 진단 기능을 표준화된 방식으로 제공합니다. CoAP는 HTTP의 경량 버전으로, UDP 위에서 동작하며 REST 아키텍처를 따릅니다. DTLS(Datagram TLS)를 통해 end-to-end 암호화를 제공하여 애플리케이션 데이터를 보호합니다.

NB-IoT의 데이터 전송률은 업링크 최대 약 60-70kbps, 다운링크 최대 약 30-40kbps이며, 이는 대부분의 센서 데이터 전송에 충분합니다. 지연 시간은 일반적으로 1.6-10초 사이이며, CE 레벨이 높을수록 반복 전송으로 인해 지연이 증가합니다. Release 14에서는 positioning 기능이 추가되어 E-CID(Enhanced Cell ID), OTDOA(Observed Time Difference Of Arrival) 등의 기술을 통해 디바이스 위치를 추정할 수 있습니다.

Sigfox 플랫폼 기술 개요

Sigfox는 프랑스 기업 Sigfox SA가 개발하고 운영하는 독자적인 LPWAN 기술로, Ultra-Narrowband(UNB) 변조 방식을 채택합니다. LoRaWAN이나 NB-IoT와 달리 Sigfox는 단일 사업자가 네트워크를 소유하고 운영하는 중앙 집중식 모델을 따르며, 각 국가에서는 파트너 운영사가 Sigfox 기술을 라이선스하여 서비스를 제공합니다. 현재 70개 이상의 국가에서 Sigfox 네트워크가 운영되고 있으며, Sigfox Atlas를 통해 글로벌 커버리지 맵을 확인할 수 있습니다.

Sigfox의 UNB 변조는 100Hz의 매우 좁은 대역폭을 사용하여 간섭에 강하고 장거리 통신이 가능합니다. 전송 속도는 업링크 100bps, 다운링크 600bps로 매우 낮지만, 이를 통해 극도로 낮은 전력 소비와 뛰어난 수신 감도(-142dBm)를 달성합니다. 주파수 다이버시티를 위해 각 메시지는 서로 다른 주파수에서 세 번 전송되며, 이는 간섭이나 페이딩으로 인한 전송 실패 확률을 크게 낮춥니다.

Sigfox 네트워크는 메시지 제한이 있습니다. 디바이스당 하루 140개의 업링크 메시지(12바이트 페이로드)와 4개의 다운링크 메시지(8바이트 페이로드)로 제한되며, 메시지 간 최소 간격은 업링크 10초, 다운링크 20초입니다. 이러한 제약은 Sigfox가 대규모 디바이스 배포와 네트워크 확장성을 우선시하며, 주기적인 센서 데이터 보고나 알람 전송과 같은 low-throughput 애플리케이션에 최적화되어 있음을 의미합니다.

Sigfox의 페이로드는 12바이트로 제한되어 있어 효율적인 데이터 인코딩이 필수적입니다. 일반적으로 고정 소수점 표현, 비트 패킹, lookup table, 차분 인코딩 등의 기법을 사용하여 제한된 공간에 최대한 많은 정보를 담습니다. 예를 들어, 온도, 습도, 배터리 전압, 이벤트 플래그를 모두 12바이트 안에 인코딩할 수 있습니다. Sigfox Backend에서는 custom payload decoder를 설정하여 hexadecimal 데이터를 JSON, XML 등의 형식으로 자동 변환할 수 있습니다.

Sigfox의 보안은 디바이스 ID와 디바이스별 secret key를 사용하며, 각 메시지에는 Message Authentication Code(MAC)가 포함되어 메시지 무결성과 인증을 제공합니다. 페이로드 자체는 기본적으로 암호화되지 않지만, 애플리케이션 레벨에서 추가 암호화를 적용할 수 있습니다. 디바이스 provisioning은 Porting Authorization Code(PAC)를 통해 안전하게 수행됩니다.

Sigfox는 RSSI 기반의 geolocation 서비스를 제공하여 GPS 없이도 디바이스 위치를 추정할 수 있습니다. 여러 기지국에서 수신한 신호 강도를 분석하여 위치를 계산하며, 정확도는 환경에 따라 수백 미터에서 수 km까지 다양합니다. 이는 자산 추적, 분실물 찾기 등의 애플리케이션에 유용합니다. Sigfox Atlas Coverage API를 통해 특정 위치의 예상 커버리지 품질을 사전에 확인할 수 있어 배포 계획 수립에 도움이 됩니다.
