Chapter 3: Sigfox Technology

WIA-COMM-018 Standard | Low-Power Wide Area Networks

Focus: Ultra-narrowband modulation, extreme simplicity, and 20-year battery life

3.1 Introduction to Sigfox

Sigfox represents the minimalist philosophy of LPWAN technologies—extreme simplicity in exchange for extreme efficiency. Founded in 2009 in France, Sigfox took a radically different approach from other IoT networks: instead of maximizing data rate or flexibility, it optimized for three goals:

  • Ultra-low cost: Module costs as low as $2-5, making billion-device deployments economically viable
  • Maximum battery life: 15-20 years on a single AA battery
  • Global coverage: Single network operator per country, seamless international roaming

The tradeoff? Severe constraints: only 140 messages per day uplink (12 bytes each) and 4 messages per day downlink (8 bytes each). For many IoT applications—temperature sensors, asset trackers, utility meters—this is more than sufficient.

The Ultra-Narrowband Revolution

Sigfox's secret weapon is Ultra-Narrowband (UNB) modulation with a bandwidth of just 100 Hz—narrower than a single OFDM subcarrier in LTE (15 kHz) and 1,250 times narrower than a LoRa channel (125 kHz). This extreme narrowness provides:

  • Exceptional sensitivity: -126 dBm to -142 dBm (depending on configuration), enabling 30-50 km range in rural areas
  • Interference immunity: Narrowband interference affects only a tiny fraction of the spectrum
  • Spectral efficiency: Thousands of devices can share the same frequency band
  • Low power consumption: Simpler modulation = lower DSP complexity = less energy

3.2 Physical Layer: DBPSK Modulation

Sigfox uses Differential Binary Phase Shift Keying (DBPSK) for uplink and GFSK (Gaussian Frequency Shift Keying) for downlink. Let's examine the uplink modulation in detail:

DBPSK Encoding

DBPSK encodes bits by changing (or not changing) the phase of the carrier wave:

Bit Sequence: 1 0 1 1 0 1 Phase Changes: ┌────┐ ┌────┬────┐ ┌────┐ Carrier: ─────┘ └────┘ │ └────┘ └──── ↑ ↑ ↑ ↑ ↑ ↑ 180° 0° 180° 180° 0° 180° Bit 1 = Phase change (180° shift) Bit 0 = No phase change (0° shift) Differential encoding advantages: - No need for absolute phase reference - Resilient to Doppler shift - Simple receiver design

3.3 Message Transmission: Triple Redundancy

Every Sigfox uplink message is transmitted three times on three different frequencies with slight time offsets. This spatial and temporal diversity ensures exceptional reliability even in challenging RF environments.

┌───────────────────────────────────────────────────────────┐ │ Sigfox Triple Transmission Pattern │ ├───────────────────────────────────────────────────────────┤ │ │ │ Transmission 1: Freq A ──▶ [████████] │ │ Time offset: 0s │ │ │ │ ~500ms random │ │ Transmission 2: Freq B ──────────▶ [████████] │ │ Time offset: ~500ms │ │ │ │ ~500ms │ │ Transmission 3: Freq C ────────────────────▶ [████████] │ │ Time offset: ~1s │ │ │ │ Total transmission time: ~2 seconds │ │ │ │ Frequencies selected pseudo-randomly from: │ │ Europe: 868.130 MHz, 868.180 MHz, 868.230 MHz │ │ (400 frequency channels across 192 kHz) │ │ │ │ Benefits: │ │ • Overcome frequency-selective fading │ │ • Avoid interference on specific frequencies │ │ • Improve coverage in challenging locations │ │ • Achieve 99.9%+ delivery reliability │ │ │ └───────────────────────────────────────────────────────────┘

Why Triple Transmission Works:

  • If one frequency has interference, the other two likely succeed
  • If device is in a null (multipath cancellation) at one frequency, other frequencies work
  • Multiple base stations can receive different transmissions and forward to cloud
  • Sigfox cloud combines all received frames to extract message with highest confidence

3.4 Message Format and Constraints

Uplink Frame Structure

Sigfox Uplink Frame (23 bytes total over-the-air): ┌─────────┬──────────┬─────────────┬─────────┬──────────┐ │Preamble │ Sync Word│ Payload │ CRC │ Auth │ │ (5 B) │ (2 B) │ (12 B) │ (2 B) │ (2 B) │ └─────────┴──────────┴─────────────┴─────────┴──────────┘ Preamble: Alternating 0/1 pattern for receiver sync Sync Word: 0xB227 (fixed pattern marking frame start) Payload: 0-12 bytes of application data CRC: 16-bit checksum for error detection Auth: Message authentication code (MAC) Important Constraints: - Maximum 140 messages per day (1 message every 10 minutes average) - Payload limited to 12 bytes (must encode efficiently!) - No fragmentation support (message must fit in 12 bytes) - Transmission time: ~2 seconds (including 3 repetitions)

Downlink Frame Structure

Sigfox Downlink Frame (15 bytes total over-the-air): ┌─────────┬──────────┬─────────────┬─────────┐ │Preamble │ Sync Word│ Payload │ CRC │ │ (5 B) │ (2 B) │ (8 B) │ (2 B) │ └─────────┴──────────┴─────────────┴─────────┘ Downlink Constraints: - Maximum 4 messages per day - Payload: 8 bytes only - Must be requested by uplink (device opens RX window after TX) - RX window: 20-25 seconds after uplink transmission - Success rate: ~80-90% (lower than uplink due to downlink sensitivity)

3.5 Device Authentication and Security

Sigfox implements device-level authentication to prevent unauthorized devices from using the network:

Sigfox Security Model: 1. Device Identifiers (pre-provisioned in factory): Device ID: 0x0123ABCD (32-bit unique ID, like MAC address) PAC: Provisioning Authentication Code (8 ASCII chars) NAK: Network Authentication Key (128-bit secret key) 2. Message Authentication (every uplink): Payload: 0x1A2B3C4D... (up to 12 bytes) Sequence: 0x0042 (16-bit counter, increments each message) MAC = AES-128-CMAC(NAK, DeviceID || Sequence || Payload) MAC truncated to 16 bits and appended to frame 3. Replay Protection: - Backend tracks sequence number per device - Messages with Sequence ≤ last_seen are rejected - Prevents replay attacks 4. Device Cloning Prevention: - NAK is unique per device and secret - Cannot be extracted from over-the-air messages - Cloning requires physical access to extract NAK from chip Security Limitations: - Payload is NOT encrypted (sent in plaintext) - Only MAC provides authentication, not confidentiality - Suitable for non-sensitive data (temperature, counters) - Sensitive data should use application-layer encryption

3.6 Battery Life: The 20-Year Promise

Sigfox's simplicity enables the longest battery life in the LPWAN space:

Sigfox Battery Life Calculation: function calculateSigfoxBatteryLife( batteryCapacity_mAh, // Battery capacity messagesPerDay, // Uplink frequency downlinksPerDay = 0 // Downlinks requested ) { // Current consumption (typical Sigfox module) const sleepCurrent_uA = 1.0; // Ultra-low sleep const txCurrent_mA = 50.0; // TX current const rxCurrent_mA = 15.0; // RX current (if downlink) // Timing const txDuration_s = 2.0; // ~2s for 3 transmissions const rxDuration_s = 25.0; // 25s RX window for downlink // Daily energy consumption const sleepTime_s = 86400 - (messagesPerDay * txDuration_s) - (downlinksPerDay * rxDuration_s); const energySleep_mAh = (sleepCurrent_uA / 1000) * (sleepTime_s / 3600); const energyTx_mAh = txCurrent_mA * messagesPerDay * (txDuration_s / 3600); const energyRx_mAh = rxCurrent_mA * downlinksPerDay * (rxDuration_s / 3600); const dailyConsumption_mAh = energySleep_mAh + energyTx_mAh + energyRx_mAh; const batteryLife_days = batteryCapacity_mAh / dailyConsumption_mAh; const batteryLife_years = batteryLife_days / 365.25; return { dailyConsumption_mAh, batteryLife_years, breakdown: { sleep: energySleep_mAh, tx: energyTx_mAh, rx: energyRx_mAh } }; } // Example 1: Temperature sensor (4 messages/day, no downlink) result1 = calculateSigfoxBatteryLife(2500, 4, 0); // Result: 18.7 years on 1× AA battery // Example 2: Water meter (1 message/day, no downlink) result2 = calculateSigfoxBatteryLife(5000, 1, 0); // Result: 46.2 years on 2× AA batteries // (Limited by battery shelf life ~20 years) // Example 3: Tracker with downlinks (12 msg/day, 2 downlinks/day) result3 = calculateSigfoxBatteryLife(5000, 12, 2); // Result: 9.8 years

3.8 Practical Implementation Example

// Byte 5-8: Uptime since install uint8_t reserved[3]; // Byte 9-11: Reserved } __attribute__((packed)) ParkingReport; void setup() { Sigfox.begin(); // Configure low power Sigfox.setPowerMode(SIGFOX_POWER_SAVING); // Determine occupancy (threshold: 200 cm) if (report.distance_cm < 200) { report.status = 1; // Occupied } else { report.status = 0; // Free } // Read battery voltage report.battery_mv = readBatteryVoltage(); // Calculate uptime report.uptime_hours = millis() / 3600000; // Send via Sigfox Sigfox.beginPacket(); Sigfox.write((uint8_t*)&report, sizeof(report)); int result = Sigfox.endPacket(); if (result == 0) { // Success Serial.println("Message sent"); } else { // Failed (will retry next interval) Serial.println("Send failed"); } // Deep sleep for 5 minutes Sigfox.end(); // Power down module deepSleep(SLEEP_INTERVAL); } uint16_t measureDistance() { // Send ultrasonic pulse digitalWrite(ULTRASONIC_TRIG, LOW); delayMicroseconds(2); digitalWrite(ULTRASONIC_TRIG, HIGH); delayMicroseconds(10); digitalWrite(ULTRASONIC_TRIG, LOW); // Measure echo time long duration = pulseIn(ULTRASONIC_ECHO, HIGH, 30000); // Calculate distance (speed of sound: 343 m/s) uint16_t distance_cm = duration * 0.0343 / 2; return distance_cm; } Backend Processing (Node.js): const express = require('express'); const app = express(); // Sigfox callback endpoint app.post('/sigfox/callback', (req, res) => { const deviceId = req.body.device; Key Takeaways

  • Sigfox uses ultra-narrowband (100 Hz) modulation, achieving exceptional sensitivity (-126 to -142 dBm) for 30-50 km range
  • Every message is transmitted 3 times on different frequencies, providing 99.9%+ reliability through spatial/temporal diversity
  • Severe constraints (140 msg/day, 12 bytes uplink, 4 msg/day, 8 bytes downlink) traded for simplicity and 15-20 year battery life
  • Device-level authentication using AES-MAC prevents unauthorized network access, but payloads are not encrypted by default
  • Global network model (one operator per country) enables seamless international roaming for asset tracking
  • Ideal for infrequent, small-data applications: smart metering, environmental monitoring, asset tracking
  • Lower module cost ($2-5) than other LPWAN technologies makes billion-device deployments economically viable
