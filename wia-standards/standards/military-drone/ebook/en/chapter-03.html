Chapter 3

API and Interfaces

Comprehensive specifications for sensor payloads, communication protocols, and system integration interfaces.

Sensor Payload APIs

The WIA-DEF-002 standard defines comprehensive APIs for integrating diverse sensor payloads into military drone platforms. These APIs provide standardized interfaces that enable different sensor types to communicate with flight control systems, ground control stations, and data processing pipelines. By establishing common interface specifications, the standard enables mix-and-match sensor configurations and facilitates integration of sensors from multiple manufacturers.

Each sensor category has specific interface requirements tailored to its operational characteristics. Electro-optical cameras require different data rates, control commands, and metadata formats compared to synthetic aperture radar systems. The API specifications accommodate these differences while maintaining a consistent high-level interface structure that simplifies integration and reduces development time.

Electro-Optical Camera Interface

Electro-optical cameras represent the most common sensor type on military drones, providing daylight visual imaging capabilities essential for target identification and reconnaissance. The EO camera API defines interfaces for camera control, image capture, zoom/focus adjustment, and video streaming. 

interface EOCamera {
  // Camera identification and capabilities
  model: string;
  serialNumber: string;
  resolution: '720p' | '1080p' | '4K' | '8K';
  sensor: 'CMOS' | 'CCD';

  // Optical capabilities
  zoom: {
    optical: number;      // Maximum optical zoom (e.g., 30x)
    digital: number;      // Maximum digital zoom (e.g., 4x)
    current: number;      // Current zoom level
  };

  // Field of view settings
  fieldOfView: {
    wide: number;         // Wide FOV in degrees
    narrow: number;       // Narrow FOV in degrees
    current: number;      // Current FOV
  };

  // Frame rate control
  frameRate: number;      // Current fps
  maxFrameRate: number;   // Maximum supported fps

  // Stabilization system
  stabilization: {
    type: 'mechanical' | 'electronic' | 'hybrid';
    enabled: boolean;
    performance: number;  // Stabilization effectiveness (0-100%)
  };

  // Control methods
  setZoom(level: number): Promise<void>;
  setFOV(degrees: number): Promise<void>;
  setFrameRate(fps: number): Promise<void>;
  autofocus(): Promise<void>;
  manualFocus(distance: number): Promise<void>;

  // Image capture
  captureStill(): Promise<ImageData>;
  startVideoStream(): ReadableStream<VideoFrame>;
  stopVideoStream(): Promise<void>;

  // Geo-registration
  getImageCoordinates(pixelX: number, pixelY: number): Promise<{
    latitude: number;
    longitude: number;
    altitude: number;
    accuracy: number;
  }>;
}

This interface provides comprehensive control over all aspects of EO camera operation. The setZoom and setFOV methods allow operators to adjust the camera's viewing characteristics in real-time, balancing wide-area surveillance against detailed observation of specific targets. Frame rate control enables optimization for bandwidth constraints or specific operational requirements.

The getImageCoordinates method is particularly important for intelligence applications, enabling automatic extraction of geographic coordinates for objects in the camera's field of view. This geo-registration capability allows analysts to determine precise locations of observed features, facilities, or activities without manual map correlation.

Infrared Camera Interface

Infrared cameras provide night vision and thermal imaging capabilities essential for 24-hour operations. The IR camera API extends the basic camera interface with thermal-specific capabilities including temperature measurement, false color palettes, and detector cooling control. 

interface IRCamera {
  // Camera type and specifications
  type: 'MWIR' | 'LWIR' | 'SWIR';
  resolution: string;            // e.g., '640x480', '1280x1024'
  detector: 'cooled' | 'uncooled';
  thermalSensitivity: number;    // mK (milliKelvin)
  spectralRange: [number, number];  // μm (micrometers)
  frameRate: number;

  // Temperature measurement
  measureTemperature(x: number, y: number): Promise<{
    celsius: number;
    fahrenheit: number;
    kelvin: number;
    accuracy: number;
  }>;

  // Image enhancement
  palette: 'white-hot' | 'black-hot' | 'ironbow' | 'rainbow';
  setPalette(palette: string): Promise<void>;

  // Automatic gain control
  agc: {
    enabled: boolean;
    mode: 'linear' | 'plateau' | 'auto';
  };

  // Cooling system (for cooled detectors)
  coolingSystem?: {
    temperature: number;      // Current detector temperature (K)
    targetTemperature: number;  // Target operating temperature
    powerConsumption: number;   // Watts
    timeToOperational: number;  // Seconds until ready
  };

  // Video streaming
  startStream(): ReadableStream<ThermalFrame>;
  stopStream(): Promise<void>;

  // Calibration
  performNUC(): Promise<void>;  // Non-uniformity correction
}

The infrared camera interface accommodates the unique characteristics of thermal imaging systems. The measureTemperature method enables quantitative temperature measurement, useful for detecting heat signatures of vehicles, equipment, or even human body heat in search and rescue operations. The cooling system interface is essential for managing mid-wave infrared (MWIR) cameras that require cryogenic cooling for optimal performance.

Non-uniformity correction (NUC) calibration addresses the fact that individual detector pixels may have different sensitivity characteristics. The performNUC method triggers an automated calibration process that improves image uniformity and quality. This is typically performed periodically or when significant temperature changes affect the sensor.

Synthetic Aperture Radar Interface

Synthetic aperture radar provides all-weather, day/night imaging capability by using radio frequency energy rather than visible or infrared light. SAR systems are more complex than optical sensors and require specialized interfaces for mode selection, processing parameter configuration, and interpretation of radar returns. 

interface SARSystem {
  // System specifications
  frequency: 'X-band' | 'Ku-band' | 'Ka-band';  // GHz
  resolution: number;          // meters
  swathWidth: number;          // meters

  // Operating modes
  mode: 'stripmap' | 'spotlight' | 'scanSAR' | 'ISAR';
  setMode(mode: string): Promise<void>;

  // Polarization configuration
  polarization: {
    transmit: 'H' | 'V';
    receive: 'H' | 'V';
    configuration: 'single' | 'dual' | 'quad';
  };

  // Imaging parameters
  lookAngle: number;           // degrees from nadir
  squintAngle: number;         // degrees from perpendicular

  // Ground moving target indicator
  gmti: {
    enabled: boolean;
    minVelocity: number;       // m/s minimum detectable velocity
    maxTargets: number;        // Maximum tracked targets
  };

  // Image acquisition
  acquireImage(params: {
    center: { lat: number; lon: number };
    size: { width: number; height: number };  // meters
    resolution: number;
  }): Promise<SARImage>;

  // Change detection
  compareImages(image1: SARImage, image2: SARImage): Promise<{
    changes: Array<{
      location: { lat: number; lon: number };
      confidence: number;
      changeType: 'new' | 'removed' | 'modified';
    }>;
  }>;

  // Motion tracking
  trackMovingTargets(): ReadableStream<{
    targets: Array<{
      id: string;
      location: { lat: number; lon: number };
      velocity: { speed: number; heading: number };
      rcs: number;  // Radar cross-section (dBsm)
    }>;
  }>;
}

The SAR interface provides control over complex radar imaging parameters that significantly affect image quality and interpretation. Different imaging modes serve different purposes: stripmap mode provides wide-area coverage, spotlight mode concentrates radar energy for maximum resolution of a specific area, scanSAR extends coverage at reduced resolution, and inverse SAR (ISAR) creates images of moving targets.

Ground moving target indicator (GMTI) is a particularly valuable SAR capability that detects and tracks moving vehicles even when hidden under foliage or camouflage. The trackMovingTargets method provides a stream of target detections with estimated velocities, enabling monitoring of vehicle movements across large areas.

Communication Link APIs

Reliable communication between drones and ground control stations is fundamental to safe and effective operations. The WIA-DEF-002 standard defines comprehensive APIs for both line-of-sight and beyond-line-of-sight communication links, with provisions for link management, encryption, and failover.

Data Link Interface

The data link interface abstracts the underlying physical communication medium (RF, satellite, etc.) to provide a unified API for command/control and data transmission. This abstraction enables applications to operate independently of the specific communication technology in use. 

interface DataLink {
  // Link identification and type
  linkID: string;
  type: 'LOS-RF' | 'BLOS-Satellite' | 'Cellular' | 'Mesh';

  // Link status
  status: {
    connected: boolean;
    signalStrength: number;     // dBm
    signalQuality: number;      // 0-100%
    latency: number;            // milliseconds
    jitter: number;             // milliseconds
    packetLoss: number;         // percentage
  };

  // Bandwidth management
  bandwidth: {
    uplink: number;             // kbps available
    downlink: number;           // kbps available
    uplinkUsed: number;         // kbps in use
    downlinkUsed: number;       // kbps in use
  };

  // Security configuration
  security: {
    encryption: 'AES-256' | 'ChaCha20';
    authenticated: boolean;
    keyRotationInterval: number;  // seconds
  };

  // Send command to drone
  sendCommand(command: DroneCommand): Promise<CommandAck>;

  // Receive telemetry
  getTelemetry(): ReadableStream<TelemetryData>;

  // Video streaming
  getVideoStream(channelID: string): ReadableStream<VideoFrame>;

  // Link management
  getAvailableLinks(): Promise<DataLink[]>;
  switchLink(linkID: string): Promise<void>;

  // Events
  onDisconnect(callback: () => void): void;
  onReconnect(callback: () => void): void;
  onDegraded(callback: (status: LinkStatus) => void): void;
}

The data link interface provides comprehensive monitoring of link health through the status object, which reports signal strength, quality metrics, latency, jitter, and packet loss. These metrics are essential for operators to assess whether the link is adequate for current mission requirements or if alternative communication paths should be activated.

The switchLink method enables failover to backup communication links when the primary link becomes degraded or unavailable. This is particularly important for beyond-line-of-sight operations where satellite link interruptions can occur due to atmospheric conditions, satellite handoffs, or electronic interference.

Secure Communication Interface

Military drone communications must be protected against interception, jamming, and spoofing. The secure communication interface provides cryptographic protection, anti-jamming capabilities, and authentication mechanisms to ensure communication integrity. 

interface SecureDataLink extends DataLink {
  // Encryption configuration
  encryption: {
    algorithm: 'AES-256-GCM' | 'ChaCha20-Poly1305';
    keyLength: number;          // bits
    keyExchange: 'ECDH-P256' | 'RSA-4096';
    authentication: 'HMAC-SHA256' | 'Ed25519';
  };

  // Anti-jamming measures
  antiJam: {
    frequencyHopping: {
      enabled: boolean;
      hoppingRate: number;      // hops per second
      hopSet: number[];         // Available frequencies (MHz)
    };
    spreadSpectrum: {
      type: 'DSSS' | 'FHSS';
      processingGain: number;   // dB
    };
    adaptivePower: {
      enabled: boolean;
      currentPower: number;     // dBm
      maxPower: number;         // dBm
    };
  };

  // Intrusion detection
  intrusion: {
    detectionEnabled: boolean;
    anomalies: Array<{
      timestamp: Date;
      type: 'unauthorized-command' | 'replay-attack' | 'protocol-violation';
      severity: 'low' | 'medium' | 'high' | 'critical';
    }>;
  };

  // Key management
  rotateKeys(): Promise<void>;
  getKeyStatus(): Promise<{
    currentKeyID: string;
    expiresIn: number;          // seconds
    nextKeyID: string;
  }>;

  // Authentication
  authenticate(credentials: DroneCredentials): Promise<AuthToken>;
  verifyAuthentication(): Promise<boolean>;
}

The secure communication interface implements multiple layers of protection. Encryption protects against eavesdropping, authentication prevents unauthorized command injection, and anti-jamming measures maintain communications in contested electromagnetic environments. Frequency hopping is particularly effective against narrowband jammers, as the communication signal rapidly moves between hundreds or thousands of frequencies per second, making it extremely difficult to jam all frequencies simultaneously.

Intrusion detection monitors communication patterns for anomalies that might indicate attempted attacks. Replay attacks, where an adversary captures and retransmits legitimate commands, are detected through sequence number validation and timestamp verification. Protocol violations that deviate from expected communication patterns trigger alerts for investigation.

Mission Planning Interface

Mission planning APIs enable automated generation and optimization of flight plans, waypoint navigation, and sensor tasking. These interfaces support both pre-mission planning and dynamic re-planning during flight operations. 

interface MissionPlan {
  // Mission identification
  missionID: string;
  missionName: string;
  missionType: 'ISR' | 'Reconnaissance' | 'Surveillance' | 'Logistics' | 'CSAR';

  // Mission area
  area: {
    center: { latitude: number; longitude: number };
    radius?: number;            // meters (for circular areas)
    polygon?: Array<{ lat: number; lon: number }>;  // for irregular areas
  };

  // Flight parameters
  flightParameters: {
    altitude: number;           // feet MSL
    speed: number;              // knots
    estimatedDuration: number;  // hours
    takeoffTime: Date;
    estimatedLandingTime: Date;
  };

  // Waypoint sequence
  waypoints: Array<{
    id: string;
    sequence: number;
    position: { lat: number; lon: number; alt: number };
    action: 'flyby' | 'loiter' | 'orbit' | 'hover' | 'land';
    loiterTime?: number;        // seconds (for loiter)
    orbitRadius?: number;       // meters (for orbit)
    orbitDirection?: 'CW' | 'CCW';
    sensorTasking?: {
      sensors: string[];        // Sensor IDs to activate
      priority: 'low' | 'medium' | 'high';
    };
  }>;

  // Sensor tasking
  sensorPlan: Array<{
    sensorID: string;
    activationTime: Date;
    deactivationTime?: Date;
    targetArea?: { lat: number; lon: number; radius: number };
    parameters: Record<string, any>;
  }>;

  // Contingency planning
  contingencies: {
    lostLink: {
      action: 'RTB' | 'loiter' | 'land-nearest' | 'continue-mission';
      loiterDuration?: number;  // seconds before RTB
    };
    lowFuel: {
      action: 'RTB' | 'land-nearest';
      threshold: number;        // percentage remaining
    };
    weatherDivert: Array<{ lat: number; lon: number; name: string }>;
    emergencyLanding: Array<{ lat: number; lon: number; name: string }>;
  };

  // Validation and optimization
  validate(): Promise<ValidationResult>;
  optimize(criteria: 'time' | 'fuel' | 'coverage'): Promise<MissionPlan>;
  estimateFuelConsumption(): Promise<number>;
  checkAirspaceRestrictions(): Promise<Array<AirspaceViolation>>;
}

The mission planning interface provides comprehensive tools for defining all aspects of a drone mission. The waypoint structure allows specification of complex flight patterns including straight-line transit, loitering at points of interest, orbits around targets, and precision landing procedures. Each waypoint can have associated sensor tasking commands that automatically activate specific sensors when the drone reaches that location.

Mission validation is crucial before executing a flight plan. The validate method checks for potential problems including impossible turns given the aircraft's performance limits, conflicts with airspace restrictions, insufficient fuel for the planned route, and hazardous terrain along the flight path. Identifying these issues during planning prevents mission failures and potential platform losses.

Summary: Key Takeaways

  • Sensor API Standardization: TypeScript interfaces define consistent APIs for EO cameras, IR cameras, SAR systems, LIDAR, and other sensors, enabling multi-vendor interoperability and reducing integration costs.
  • Thermal Imaging Capabilities: IR camera interfaces support temperature measurement, false color palettes, and cooled detector management for sophisticated thermal imaging applications.
  • Radar Complexity: SAR interfaces accommodate multiple imaging modes (stripmap, spotlight, scanSAR, ISAR) and provide GMTI for detecting and tracking moving targets.
  • Communication Abstraction: Data link APIs abstract physical communication media to provide unified interfaces for LOS, BLOS, and cellular links with automatic failover capabilities.
  • Security Integration: Secure communication interfaces embed encryption, authentication, anti-jamming, and intrusion detection directly into the API layer rather than treating security as an add-on.
  • Mission Planning Tools: Comprehensive mission planning APIs support waypoint navigation, sensor tasking, contingency planning, and automated validation/optimization.
  • Geo-Registration: Camera APIs provide automatic coordinate extraction from imagery, enabling precise geolocation of observed features without manual processing.
