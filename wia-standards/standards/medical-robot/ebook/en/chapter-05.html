Phase 2: API Interface Standards

Implementing secure RESTful APIs for medical robot control, sensor data access, and EHR integration using OpenAPI 3.0, OAuth 2.0, and FHIR standards.

RESTful API Design Principles

Phase 2 establishes standardized RESTful HTTP APIs for medical robot integration. REST (Representational State Transfer) provides architectural constraints ensuring scalability, reliability, and interoperability. WIA-ROB-005 APIs follow these principles:

  • Resource-Based URLs: Endpoints represent resources (e.g., /robots/{id}/pose, /patients/{id}/vitals) rather than actions
  • HTTP Methods: GET (retrieve), POST (create), PUT (update), PATCH (partial update), DELETE (remove)
  • Stateless Communication: Each request contains all necessary information; no server-side session state
  • Standard Status Codes: 200 OK, 201 Created, 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found, 500 Server Error
  • JSON Payloads: Request/response bodies use JSON for universal parsing and human readability
  • Versioning: API versions in URL path (/v1/, /v2/) or Accept header for backward compatibility

OpenAPI 3.0 Specification

OpenAPI (formerly Swagger) provides machine-readable API definitions enabling automatic documentation generation, client library creation, and validation testing. WIA-ROB-005 mandates complete OpenAPI 3.0 specifications for all robot APIs.

OAuth 2.0 Authentication and Authorization

Medical robot APIs require robust authentication ensuring only authorized personnel can access or control devices. OAuth 2.0 provides industry-standard authorization framework with role-based access control (RBAC).

OAuth 2.0 Authorization Code Flow

  1. User Authorization: Application redirects user to hospital authorization server
  2. Consent: User authenticates (badge + PIN, biometric) and grants application requested scopes
  3. Authorization Code: Server redirects back to application with short-lived authorization code
  4. Token Exchange: Application exchanges code for access token and refresh token
  5. API Access: Application includes access token in Authorization header for all API requests
  6. Token Refresh: When access token expires (typically 1 hour), use refresh token to obtain new access token without re-authentication

Real-Time Sensor Data APIs

High-frequency sensor data (force/torque, position, velocity) requires efficient streaming APIs beyond traditional REST. WIA-ROB-005 specifies WebSocket and Server-Sent Events (SSE) for real-time data.

WebSocket Telemetry Streaming

// Client establishes WebSocket connection
const ws = new WebSocket('wss://api.hospital.org/robots/v1/telemetry');

ws.onopen = () => {
  // Subscribe to specific robot telemetry
  ws.send(JSON.stringify({
    action: 'subscribe',
    robotId: 'davinci-01',
    streams: ['pose', 'force', 'vitals'],
    frequency: 100  // Hz
  }));
};

ws.onmessage = (event) => {
  const data = JSON.parse(event.data);
