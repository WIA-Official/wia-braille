Chapter 4

Phase 1: Data Format Standardization

Mastering standardized data formats for patient demographics, vital signs, medical imaging, robot telemetry, and surgical procedures using HL7 FHIR, DICOM, LOINC, and SNOMED CT.

HL7 FHIR R4 Resources

Fast Healthcare Interoperability Resources (FHIR) provides a modern standard for healthcare data exchange. FHIR R4 (Release 4), published in December 2018 and achieving Normative status for core resources in 2019, defines over 140 resource types covering clinical, financial, workflow, and infrastructure use cases. WIA-ROB-005 Phase 1 mandates FHIR compliance for all clinical data elements.

Patient Demographics - FHIR Patient Resource

The Patient resource represents demographic and administrative information about an individual receiving healthcare services. Essential elements include:

  • Identifiers: Medical record number (MRN), national ID, passport, driver's license with system URIs and values
  • Name: Official name, maiden name, nicknames with use indicators (official, usual, nickname, old)
  • Demographics: Gender (male, female, other, unknown), birthdate (full date or partial for privacy), deceased indicator
  • Contact: Phone, email, address with use type (home, work, temp, old) and period validity
  • Communication: Preferred language with ISO 639-1 codes (en, es, zh, ko, etc.)
  • Emergency Contact: Name, relationship, phone, address

Vital Signs - FHIR Observation Resource with LOINC

The Observation resource captures measurements and simple assertions about a patient. Vital signs use standardized LOINC (Logical Observation Identifiers Names and Codes) for consistent coding across systems. WIA-ROB-005 mandates LOINC codes for all vital signs:

Vital Sign LOINC Code Unit (UCUM) Normal Range
Heart Rate 8867-4 /min (beats per minute) 60-100 /min
Respiratory Rate 9279-1 /min (breaths per minute) 12-20 /min
Blood Pressure Systolic 8480-6 mm[Hg] 90-120 mmHg
Blood Pressure Diastolic 8462-4 mm[Hg] 60-80 mmHg
Oxygen Saturation (SpO2) 59408-5 % (percentage) 95-100 %
Body Temperature 8310-5 Cel (degrees Celsius) 36.5-37.5 °C

Medical Imaging - DICOM Standards

Digital Imaging and Communications in Medicine (DICOM) defines formats and protocols for medical imaging. DICOM PS3.10 specifies file format, PS3.3 defines information object definitions, and PS3.6 contains the data dictionary. WIA-ROB-005 requires DICOM compliance for all medical imaging data and DICOM Web for network imaging access.

DICOM Core Tags for Surgical Robots

Surgical robots must extract and utilize DICOM metadata including patient demographics, study information, series details, and image parameters:

DICOM Tag Tag Number Description Example Value
Patient Name (0010,0010) Patient's full name Kim^Jin^Soo
Patient ID (0010,0020) Primary patient identifier MRN-12345678
Study Instance UID (0020,000D) Unique study identifier 1.2.840.113619...
Series Instance UID (0020,000E) Unique series identifier 1.2.840.113619...
Modality (0008,0060) Imaging modality CT, MR, CR, DX
Image Position (0020,0032) 3D position (x,y,z mm) [-125.0, -125.0, 100.0]
Image Orientation (0020,0037) Direction cosines [1,0,0,0,1,0]
Pixel Spacing (0028,0030) Row/column spacing (mm) [0.5, 0.5]

DICOM Web - RESTful Medical Imaging

DICOM Web provides RESTful access to DICOM objects using standard HTTP methods. Three services enable complete imaging workflows:

  • WADO-RS (Web Access to DICOM Objects): Retrieve studies, series, instances, metadata, or rendered images via HTTP GET. Example: GET /studies/{studyUID}/series/{seriesUID}/instances/{instanceUID}
  • STOW-RS (Store Over Web): Upload DICOM instances via HTTP POST with multipart/related content type
  • QIDO-RS (Query based on ID for DICOM Objects): Search for studies, series, instances using query parameters. Example: GET /studies?PatientID=MRN-12345678&Modality=CT

Surgical Procedures - FHIR Procedure with SNOMED CT

The Procedure resource describes activities performed on or for a patient. SNOMED CT (Systematized Nomenclature of Medicine Clinical Terms) provides standardized procedure codes. ICD-10-PCS (Procedure Coding System) serves billing purposes in the US.

Robot Telemetry Data Formats

Medical robots generate continuous telemetry data including pose (position + orientation), joint angles, velocities, forces/torques, and operational status. WIA-ROB-005 defines JSON schemas for robot telemetry ensuring consistent data structure across manufacturers.

Robot Pose and Kinematics

Robot pose combines position (x, y, z coordinates in millimeters) and orientation (quaternion or Euler angles). WIA-ROB-005 mandates quaternions to avoid gimbal lock:

JSON Schema Validation

WIA-ROB-005 provides comprehensive JSON Schema definitions for all data types, enabling automated validation. TypeScript interfaces, Python Pydantic models, and C++ structs are generated from schemas ensuring type safety across programming languages.

Key Takeaways

  • HL7 FHIR R4: Patient demographics, vital signs (LOINC codes), procedures (SNOMED CT), medications (RxNorm)
  • DICOM: Medical imaging file format (PS3.10), metadata tags, SOP Classes for modalities (CT, MRI, CR, DX)
  • DICOM Web: RESTful imaging access via WADO-RS (retrieve), STOW-RS (store), QIDO-RS (query)
  • Robot Telemetry: JSON schemas for pose, kinematics, force/torque, operational status
  • Standardized Coding: LOINC (observations), SNOMED CT (procedures), ICD-10 (diagnoses), CPT (billing)
