CHAPTER 2

Error Code Architecture

2.1 The Anatomy of a WIA Error Code

Every WIA error code follows a precise structure: WIA-{DOMAIN}-{CATEGORY}-{NUMBER}. This four-part format is designed to be instantly readable by both humans and machines, while providing maximum information density.

WIA-AUTH-INVALID-001
│   │    │       └── Unique identifier (001-999)
│   │    └────────── Category (INVALID, TIMEOUT, NOTFOUND, etc.)
│   └─────────────── Domain (AUTH, DB, NET, FILE, etc.)
└─────────────────── Standard prefix (WIA)

2.1.1 Component Breakdown

1. Standard Prefix (WIA): Identifies this as a WIA standard error. This prefix enables:

  • Easy filtering in logs and monitoring systems
  • Disambiguation from application-specific error codes
  • Future extensibility for other standard families
  • Global uniqueness across all systems

2. Domain: The high-level system area where the error occurred. Domains are technology-agnostic and represent universal computing concepts.

Standard Domains

Domain Description Examples
AUTH Authentication & Authorization Login failures, token validation, permissions
DB Database Operations Query failures, connection issues, constraints
NET Network Operations Timeouts, connection failures, DNS errors
FILE File System Operations File not found, permission denied, disk full
API API Operations Rate limiting, invalid requests, service unavailable
VALIDATE Data Validation Invalid format, missing fields, constraint violations
CRYPTO Cryptographic Operations Encryption failures, signature verification, key errors
CACHE Caching Operations Cache misses, eviction, invalidation
QUEUE Message Queue Operations Queue full, message expired, delivery failure
STORAGE Storage Operations Upload failures, quota exceeded, corruption

3. Category: The specific error type within the domain. Categories are standardized verbs or conditions.

Category When to Use Example
INVALID Input doesn't meet requirements WIA-AUTH-INVALID-001
NOTFOUND Requested resource doesn't exist WIA-FILE-NOTFOUND-003
TIMEOUT Operation exceeded time limit WIA-NET-TIMEOUT-015
CONNECTION Failed to establish connection WIA-DB-CONNECTION-008
PERMISSION Insufficient permissions WIA-FILE-PERMISSION-012
CONFLICT Resource state conflict WIA-DB-CONFLICT-005
RATE_LIMIT Too many requests WIA-API-RATE_LIMIT-007
INTERNAL Unexpected internal error WIA-API-INTERNAL-999

4. Number (001-999): A unique identifier for this specific error variant within the domain-category combination. Numbers allow for:

  • Differentiation between similar errors
  • Version tracking as error definitions evolve
  • Up to 999 distinct errors per category
  • Easy lookup in documentation and knowledge bases

2.2 Error Code Design Principles

2.2.1 Self-Documenting

A well-designed error code tells you immediately what went wrong, even without documentation:

✅ GOOD: WIA-AUTH-INVALID-001
   - Clearly authentication domain
   - Invalid credentials/input
   - Can infer the problem from the code alone

❌ BAD: E_AUTH_001
   - What kind of auth error?
   - Need to look up documentation
   - Not self-documenting

2.2.2 Hierarchical

Error codes form a natural hierarchy that enables powerful filtering and aggregation:

WIA-*                 // All WIA errors
WIA-AUTH-*            // All authentication errors
WIA-AUTH-INVALID-*    // All invalid credential errors
WIA-AUTH-INVALID-001  // Specific: username/password mismatch
WIA-AUTH-INVALID-002  // Specific: expired token
WIA-AUTH-INVALID-003  // Specific: malformed JWT

This hierarchy enables queries like:

  • "Show me all authentication errors in the last hour"
  • "What percentage of API errors are timeouts vs rate limits?"
  • "Which specific database connection error is most common?"

2.2.3 Language Agnostic

Error codes must work identically across all 99 supported programming languages. The same error code represents the same condition whether thrown in JavaScript, returned in Go, or wrapped in a Result type in Rust.

// JavaScript
throw new WIAError({ code: 'WIA-DB-TIMEOUT-015' });

// Go
return &wia.Error{ Code: wia.DBTimeout015 }

// Rust
Err(WIAError::new("WIA-DB-TIMEOUT-015"))

// Python
raise WIAError(code="WIA-DB-TIMEOUT-015")

// Java
throw new WIAError("WIA-DB-TIMEOUT-015");

// All represent the EXACT SAME ERROR

2.4 Creating Custom Error Codes

While WIA-CORE-010 provides 500+ standard error codes, you can create custom codes for domain-specific scenarios:

Custom Error Code Guidelines

  1. Use WIA prefix: Maintain compatibility with tooling
  2. Choose appropriate domain: Use existing domains when possible
  3. Start at 100: Reserve 001-099 for standard errors
  4. Document thoroughly: Add to your error catalog
  5. Review regularly: Consolidate similar custom errors
// Custom error code example
WIA-PAYMENT-DECLINED-101  // Custom payment domain
WIA-INVENTORY-OUTOFSTOCK-102  // Custom inventory category
WIA-SHIPPING-DELAYED-103  // Business-specific error

// These follow WIA standards but extend with domain-specific knowledge

2.5 Error Code Versioning

Error codes evolve over time. WIA-CORE-010 uses semantic versioning at the catalog level, but individual error codes are immutable once published.

Rules:

  • Never change the meaning of an existing error code
  • Deprecated codes remain in catalog with deprecation notice
  • New codes use next available number in sequence
  • Major catalog versions can reorganize code space
