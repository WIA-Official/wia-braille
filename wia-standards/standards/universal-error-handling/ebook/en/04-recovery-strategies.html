CHAPTER 4

Recovery Strategies and Patterns

4.1 Introduction to Error Recovery

The most powerful feature of WIA-CORE-010 is embedded recovery strategies. Every error includes explicit guidance on how to recover, transforming errors from dead-ends into actionable pathways.

Traditional error handling forces developers to figure out recovery logic for every error. Should we retry? How long should we wait? Should we use fallback data? Circuit break? WIA-CORE-010 standardizes these decisions.

4.2 The Six Recovery Strategies

1. RETRY_WITH_BACKOFF - Exponential Backoff Retry

When to use: Temporary failures that are likely to resolve quickly (network timeouts, database connection issues, rate limits).

How it works: Retry the operation with exponentially increasing delays between attempts (1s, 2s, 4s, 8s, etc.). Include jitter to prevent thundering herd.

async function retryWithBackoff(operation, maxAttempts = 5) {
  for (let attempt = 1; attempt <= maxAttempts; attempt++) {
    try {
      return await operation();
    } catch (error) {
      if (error.recovery !== 'RETRY_WITH_BACKOFF' || attempt === maxAttempts) {
        throw error;
      }

      // Exponential backoff: 2^attempt * 1000ms + random jitter
      const delay = Math.pow(2, attempt) * 1000 + Math.random() * 1000;
      console.log(`Retry ${attempt}/${maxAttempts} after ${delay}ms`);
      await sleep(delay);
    }
  }
}

// Usage
try {
  const data = await retryWithBackoff(() => fetchFromAPI());
} catch (error) {
  // All retries exhausted
  handleFinalFailure(error);
}

Best practices:

  • Maximum 5-10 retry attempts
  • Cap maximum delay at 30-60 seconds
  • Add random jitter (10-20% of delay)
  • Log each retry attempt with correlation ID
  • Respect retry-after headers from APIs

2. FALLBACK - Use Alternative Method

When to use: Primary method failed but alternative exists (cached data, backup service, degraded functionality).

How it works: Attempt primary operation, if it fails, immediately switch to fallback without retry.

class UserService {
  async getUser(userId) {
    try {
      // Try primary database
      return await this.primaryDB.query('SELECT * FROM users WHERE id = ?', [userId]);
    } catch (error) {
      if (error.recovery === 'FALLBACK') {
        console.log('Primary DB failed, using cache fallback');

        // Fallback to cache
        const cached = await this.cache.get(`user:${userId}`);
        if (cached) {
          return { ...cached, _source: 'cache', _stale: true };
        }

        // Fallback to read replica
        try {
          return await this.replicaDB.query('SELECT * FROM users WHERE id = ?', [userId]);
        } catch (replicaError) {
          // All fallbacks exhausted
          throw error;
        }
      }
      throw error;
    }
  }
}

Fallback hierarchy:

  1. In-memory cache (fastest)
  2. Distributed cache (Redis, Memcached)
  3. Read replica database
  4. Backup service/region
  5. Static fallback data
  6. Degraded mode (limited functionality)

3. CIRCUIT_BREAKER - Stop Requesting Failing Service

When to use: Service is consistently failing, continued requests will make it worse. Prevent cascading failures.

How it works: After threshold of failures, "open" the circuit - stop sending requests. After timeout, try again ("half-open"). If successful, "close" circuit.

class CircuitBreaker {
  constructor({ failureThreshold = 5, timeout = 60000, resetTimeout = 30000 }) {
    this.failureCount = 0;
    this.failureThreshold = failureThreshold;
    this.timeout = timeout;
    this.resetTimeout = resetTimeout;
    this.state = 'CLOSED'; // CLOSED, OPEN, HALF_OPEN
    this.nextAttempt = Date.now();
  }

  async execute(operation) {
    if (this.state === 'OPEN') {
      if (Date.now() < this.nextAttempt) {
        throw new WIAError({
          code: 'WIA-CIRCUIT-BREAKER-001',
          message: 'Circuit breaker is OPEN',
          severity: 'WARNING',
          recovery: 'FALLBACK'
        });
      }
      this.state = 'HALF_OPEN';
    }

    try {
      const result = await operation();
      this.onSuccess();
      return result;
    } catch (error) {
      this.onFailure();
      throw error;
    }
  }

  onSuccess() {
    this.failureCount = 0;
    this.state = 'CLOSED';
  }

  onFailure() {
    this.failureCount++;
    if (this.failureCount >= this.failureThreshold) {
      this.state = 'OPEN';
      this.nextAttempt = Date.now() + this.timeout;
      console.log(`Circuit breaker OPEN for ${this.timeout}ms`);
    }
  }
}

// Usage
const breaker = new CircuitBreaker({ failureThreshold: 5, timeout: 60000 });

async function callExternalAPI(data) {
  try {
    return await breaker.execute(() => api.call(data));
  } catch (error) {
    if (error.code === 'WIA-CIRCUIT-BREAKER-001') {
      // Circuit is open, use fallback
      return useCachedData();
    }
    throw error;
  }
}

4. GRACEFUL_DEGRADATION - Continue with Reduced Functionality

When to use: Non-critical feature failed but core functionality can continue.

How it works: Disable failing feature, continue with core service. Inform users of degraded state.

class EcommerceService {
  async checkout(cart, userId) {
    const order = { items: cart, userId, features: {} };

    // Core: Process payment (required)
    try {
      order.payment = await this.paymentService.process(cart.total);
    } catch (error) {
      // Payment is critical - cannot degrade
      throw error;
    }

    // Enhancement: Apply recommendations (optional)
    try {
      order.features.recommendations = await this.recommendationService.get(userId);
    } catch (error) {
      if (error.recovery === 'GRACEFUL_DEGRADATION') {
        console.warn('Recommendations unavailable, proceeding without them');
        order.features.recommendations = [];
        order._degraded = true;
      }
    }

    // Enhancement: Send email confirmation (optional)
    try {
      await this.emailService.send(order);
    } catch (error) {
      if (error.recovery === 'GRACEFUL_DEGRADATION') {
        console.warn('Email service down, queueing for later');
        await this.queue.add('email', order);
        order._emailQueued = true;
      }
    }

    return order;
  }
}

Degradation levels:

  • Level 1: Disable analytics and tracking
  • Level 2: Disable recommendations and personalization
  • Level 3: Disable images and media
  • Level 4: Text-only mode
  • Level 5: Core transaction processing only

5. FAIL_FAST - Immediate Failure, No Recovery

When to use: Error cannot be recovered (invalid input, authorization failure, logical error). Retrying will not help.

How it works: Immediately return error to caller. Do not retry, do not use fallback.

class AuthService {
  async authenticate(username, password) {
    // Validate input
    if (!username || !password) {
      throw new WIAError({
        code: 'WIA-VALIDATE-INVALID-001',
        message: 'Username and password required',
        severity: 'ERROR',
        recovery: 'FAIL_FAST' // Don't retry invalid input
      });
    }

    // Check credentials
    const user = await this.db.findUser(username);
    if (!user || !await this.verifyPassword(password, user.passwordHash)) {
      throw new WIAError({
        code: 'WIA-AUTH-INVALID-001',
        message: 'Invalid credentials',
        severity: 'ERROR',
        recovery: 'FAIL_FAST' // Don't retry bad credentials
      });
    }

    return this.generateToken(user);
  }
}

// Usage
try {
  const token = await auth.authenticate(username, password);
} catch (error) {
  if (error.recovery === 'FAIL_FAST') {
    // Show error to user immediately, don't retry
    return res.status(401).json({ error: error.message });
  }
}

6. MANUAL - Requires Human Intervention

When to use: Automated recovery is not possible or not safe. Requires investigation and manual action.

How it works: Log error with full context, alert on-call engineer, create ticket, wait for manual resolution.

class DataIntegrityService {
  async verifyChecksum(fileId) {
    const file = await this.storage.get(fileId);
    const computedChecksum = await this.computeChecksum(file.data);

    if (computedChecksum !== file.expectedChecksum) {
      // Data corruption detected - cannot auto-recover
      const error = new WIAError({
        code: 'WIA-STORAGE-CORRUPTION-001',
        message: 'File checksum mismatch - possible corruption',
        severity: 'CRITICAL',
        recovery: 'MANUAL',
        context: {
          fileId,
          expectedChecksum: file.expectedChecksum,
          computedChecksum,
          fileSize: file.data.length,
          lastModified: file.lastModified
        }
      });

      // Alert operations team
      await this.alerting.page({
        severity: 'CRITICAL',
        title: 'Data corruption detected',
        error,
        runbook: 'https://wiki.company.com/data-corruption'
      });

      // Create ticket
      await this.ticketing.create({
        priority: 'P0',
        title: `Data corruption: ${fileId}`,
        description: error.toString(),
        assignee: 'data-integrity-team'
      });

      throw error;
    }
  }
}

4.3 Combining Recovery Strategies

Complex systems often combine multiple recovery strategies in sequence:

async function robustAPICall(operation, options = {}) {
  const {
    maxRetries = 3,
    circuitBreaker,
    fallback,
    degradedMode
  } = options;

  try {
    // Strategy 1: Circuit Breaker
    if (circuitBreaker && circuitBreaker.isOpen()) {
      throw new Error('Circuit breaker open');
    }

    // Strategy 2: Retry with backoff
    return await retryWithBackoff(operation, maxRetries);

  } catch (error) {
    // Strategy 3: Fallback
    if (fallback) {
      console.log('Primary failed, using fallback');
      try {
        return await fallback();
      } catch (fallbackError) {
        // Fallback also failed
      }
    }

    // Strategy 4: Graceful Degradation
    if (degradedMode) {
      console.log('Entering degraded mode');
      return degradedMode.response;
    }

    // Strategy 5: Fail Fast
    throw error;
  }
}

// Usage
const result = await robustAPICall(
  () => api.fetchUserData(userId),
  {
    maxRetries: 3,
    circuitBreaker: userServiceBreaker,
    fallback: () => cache.get(`user:${userId}`),
    degradedMode: {
      response: { id: userId, name: 'Unknown User', _degraded: true }
    }
  }
);

4.4 Recovery Strategy Best Practices

  1. Match Strategy to Error Type: Network timeouts → RETRY. Invalid input → FAIL_FAST. Service down → CIRCUIT_BREAKER.
  2. Implement Timeouts: Every recovery strategy needs maximum time limit.
  3. Add Observability: Log every retry, fallback, and degradation with correlation IDs.
  4. Test Recovery Paths: Use chaos engineering to verify recovery strategies work under failure.
  5. Monitor Recovery Metrics: Track success rates for each recovery strategy.
  6. Document Runbooks: MANUAL errors need clear runbooks for on-call engineers.
  7. Avoid Infinite Loops: Cap retries, circuit breakers must eventually give up.
  8. Respect User Intent: Don't retry user-initiated cancellations.
