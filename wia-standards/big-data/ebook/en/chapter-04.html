Chapter 4: Phase 1 - Data Format Specification

Hongik Ingan (弘益人間)

Standardized data formats are the foundation of interoperability. Phase 1 ensures that data can be reliably exchanged across all systems.

4.1 Schema Definition Language (SDL)

The WIA Schema Definition Language provides a standardized way to describe data structures.

4.1.1 Basic Schema Structure

{
  "namespace": "com.example",
  "name": "DataRecord",
  "type": "record",
  "doc": "Example data record",
  "fields": [
    {
      "name": "id",
      "type": "string",
      "doc": "Unique identifier"
    },
    {
      "name": "timestamp",
      "type": "long",
      "logicalType": "timestamp-millis"
    },
    {
      "name": "value",
      "type": "double"
    }
  ]
}

4.1.2 Complex Types

Type Description Example
Array Ordered collection of items {"type": "array", "items": "string"}
Map Key-value pairs {"type": "map", "values": "int"}
Record Structured object with named fields {"type": "record", "fields": [...]}
Union One of several types ["null", "string", "int"]

4.2 WIA Binary Format (WBF)

WBF is the primary serialization format, optimized for big data workloads.

4.2.1 Design Principles

  • Compact: Minimal overhead, efficient encoding
  • Fast: Quick serialization/deserialization
  • Schema-aware: Embedded schema information
  • Streaming-friendly: Can process incrementally

4.2.2 Encoding Rules

Type Encoding Size (bytes)
boolean 1 byte (0 or 1) 1
int Variable-length zigzag encoding 1-5
long Variable-length zigzag encoding 1-10
float IEEE 754 single-precision 4
double IEEE 754 double-precision 8
string UTF-8 with length prefix Variable

4.3 Alternative Formats

4.3.1 JSON Format

For human readability and debugging:

{
  "id": "user-12345",
  "timestamp": 1704067200000,
  "value": 42.5
}

4.3.2 Parquet Format

For columnar storage and analytics:

  • Optimized for read-heavy workloads
  • Excellent compression ratios
  • Predicate pushdown support
  • Compatible with Spark, Hive, Impala

4.3.3 Avro Format

For schema evolution and compatibility:

  • Self-describing data format
  • Rich schema resolution rules
  • Widely adopted in Hadoop ecosystem
  • Full compatibility with WIA schemas

4.4 Schema Registry

4.4.1 Purpose and Benefits

Centralized schema management provides:

  • Version control: Track schema evolution over time
  • Compatibility checking: Prevent breaking changes
  • Schema reuse: Share schemas across teams
  • Documentation: Auto-generated API docs

4.4.2 Schema Evolution Rules

Change Type Backward Compatible Forward Compatible
Add optional field ✅ Yes ✅ Yes
Remove optional field ✅ Yes ✅ Yes
Add required field ❌ No ✅ Yes
Remove required field ✅ Yes ❌ No
Change field type ❌ No ❌ No

4.5 Data Partitioning

4.5.1 Partitioning Strategies

WIA-DATA-001 supports multiple partitioning schemes:

  • Time-based: Daily, hourly, or custom time windows
  • Hash-based: Distribute by key hash
  • Range-based: Continuous value ranges
  • List-based: Explicit value lists

4.5.2 Partition Metadata

{
  "partition_spec": {
    "type": "time",
    "field": "event_timestamp",
    "granularity": "day",
    "format": "yyyy-MM-dd"
  }
}

4.6 Compression

4.6.1 Supported Codecs

Codec Compression Ratio Speed Use Case
Snappy Medium (2-3x) Very Fast General purpose, real-time
LZ4 Medium (2-3x) Extremely Fast Low latency requirements
Gzip High (3-5x) Slow Archival, storage optimization
Zstd Very High (3-6x) Medium Balanced performance

4.7 Implementation Examples

4.7.1 Python Example

from wia.data import Schema, WBFWriter

schema = Schema.from_file("user_event.wsd")
writer = WBFWriter("events.wbf", schema)

for event in events:
    writer.write({
        "user_id": event["user"],
        "timestamp": event["ts"],
        "event_type": event["type"]
    })

writer.close()

4.7.2 Java Example

import com.wia.data.*;

Schema schema = new Schema.Parser().parse(
    new File("user_event.wsd"));
WBFWriter writer = new WBFWriter(
    new File("events.wbf"), schema);

GenericRecord record = new GenericData.Record(schema);
record.put("user_id", "user-123");
record.put("timestamp", System.currentTimeMillis());
record.put("event_type", "click");

writer.append(record);
writer.close();
