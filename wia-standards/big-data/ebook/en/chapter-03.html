Chapter 3: WIA-DATA-001 Standard Overview

Hongik Ingan (弘益人間)

"Benefit All Humanity"

WIA-DATA-001 provides a unified framework for big data systems, ensuring interoperability, scalability, and accessibility for all.

3.1 Standard Objectives

The WIA-DATA-001 Big Data Standard was created with the following core objectives:

  1. Interoperability: Enable seamless data exchange between different systems and platforms
  2. Scalability: Support systems from gigabytes to exabytes
  3. Vendor Neutrality: Work with any big data technology or cloud provider
  4. Simplicity: Reduce complexity and lower the barrier to entry
  5. Performance: Maintain high throughput and low latency
  6. Security: Ensure data protection and privacy by design

3.2 Standard Architecture

WIA-DATA-001 is organized into four progressive implementation phases:

Phase Focus Area Key Components Deliverables
Phase 1 Data Format Schema definition, serialization formats Data format specifications, schema registry
Phase 2 API Interface REST APIs, client libraries, SDKs API documentation, reference implementations
Phase 3 Protocol Communication protocols, data pipelines Protocol specs, pipeline templates
Phase 4 Integration System connectors, tool integration Integration guides, connector libraries

3.3 Core Principles

3.3.1 Open and Vendor-Neutral

WIA-DATA-001 is completely open and free to implement:

  • No licensing fees or royalties
  • Open-source reference implementations
  • Community-driven development
  • Works with all major big data platforms

3.3.2 Backward Compatible

The standard integrates with existing systems:

  • Supports legacy data formats through adapters
  • Compatible with Hadoop, Spark, Kafka, and other tools
  • Gradual migration paths
  • Non-breaking version updates

3.3.3 Performance-Oriented

Designed for high-performance scenarios:

  • Efficient binary serialization formats
  • Minimal overhead in processing pipelines
  • Optimized for distributed systems
  • Support for both batch and streaming workloads

3.4 Data Format Specification (Phase 1)

3.4.1 Schema Definition Language

WIA-DATA-001 uses a JSON-based schema definition language (SDL):

{
  "namespace": "com.wia.data",
  "name": "UserEvent",
  "type": "record",
  "fields": [
    {"name": "user_id", "type": "string"},
    {"name": "event_type", "type": "string"},
    {"name": "timestamp", "type": "long"},
    {"name": "properties", "type": "map", "values": "string"}
  ]
}

3.4.2 Supported Data Types

Type Description Examples
Primitive Basic data types string, int, long, float, double, boolean
Complex Structured types array, map, record, union
Temporal Time-based types timestamp, date, time, duration
Binary Raw data bytes, fixed

3.4.3 Serialization Formats

The standard supports multiple serialization formats:

  • WIA Binary Format (WBF): Optimized binary format (primary)
  • JSON: Human-readable, debugging-friendly
  • Avro: Compatibility with Apache Avro
  • Parquet: Columnar storage format

3.5 API Interface (Phase 2)

3.5.1 RESTful API Design

Standard HTTP endpoints for data operations:

GET    /api/v1/datasets
POST   /api/v1/datasets
GET    /api/v1/datasets/{id}
PUT    /api/v1/datasets/{id}
DELETE /api/v1/datasets/{id}
GET    /api/v1/datasets/{id}/data
POST   /api/v1/datasets/{id}/query

3.5.2 Client SDKs

Official SDKs available for:

  • Python (PyWIA)
  • Java (WIA4J)
  • JavaScript/TypeScript (wia-js)
  • Go (wia-go)
  • Scala (wia-scala)

3.6 Protocol Specification (Phase 3)

3.6.1 Data Pipeline Protocol

Defines how data flows through systems:

Stage Purpose Operations
Ingestion Data collection Validate, transform, route
Processing Data transformation Map, reduce, aggregate, join
Storage Data persistence Write, partition, replicate
Query Data access Read, filter, project

3.6.2 Messaging Protocol

For real-time data streaming:

  • Producer-consumer patterns
  • Exactly-once delivery semantics
  • Backpressure handling
  • Schema evolution support

3.7 Integration Framework (Phase 4)

3.7.1 Connector Architecture

Standard connectors for popular systems:

  • Databases: MySQL, PostgreSQL, Oracle, MongoDB
  • Cloud Storage: S3, GCS, Azure Blob
  • Message Queues: Kafka, RabbitMQ, Pulsar
  • Data Warehouses: Redshift, BigQuery, Snowflake

3.7.2 Tool Integration

Works seamlessly with:

  • Apache Spark
  • Apache Flink
  • Apache Beam
  • Airflow
  • Databricks

3.8 Certification Program

3.8.1 Individual Certification

Three certification levels:

  1. Associate: Basic understanding of WIA-DATA-001
  2. Professional: Ability to implement compliant systems
  3. Expert: Advanced design and troubleshooting

3.8.2 System Certification

Organizations can certify their implementations:

  • Compliance testing
  • Performance benchmarks
  • Security audits
  • Interoperability verification
