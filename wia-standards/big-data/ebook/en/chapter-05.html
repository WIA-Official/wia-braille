Chapter 5: Phase 2 - API Interface

Standardized APIs enable developers to build interoperable big data applications that work across any platform.

5.1 RESTful API Design

5.1.1 Core Endpoints

Method Endpoint Description
GET /api/v1/datasets List all datasets
POST /api/v1/datasets Create new dataset
GET /api/v1/datasets/{id} Get dataset metadata
PUT /api/v1/datasets/{id} Update dataset
DELETE /api/v1/datasets/{id} Delete dataset
POST /api/v1/datasets/{id}/query Query dataset

5.1.2 Request/Response Format

Example dataset creation:

POST /api/v1/datasets
{
  "name": "user_events",
  "schema": {...},
  "partitioning": {
    "type": "time",
    "field": "timestamp"
  }
}

Response:
{
  "id": "ds-12345",
  "name": "user_events",
  "created_at": "2025-01-01T00:00:00Z",
  "status": "active"
}

5.2 Query Language

5.2.1 WIA Query Syntax

POST /api/v1/datasets/{id}/query
{
  "select": ["user_id", "COUNT(*) as event_count"],
  "where": {
    "timestamp": {
      "gte": "2025-01-01",
      "lt": "2025-02-01"
    },
    "event_type": "click"
  },
  "groupBy": ["user_id"],
  "orderBy": ["event_count DESC"],
  "limit": 100
}

5.2.2 Query Operations

Operation Description Example
Filter Select rows matching conditions {"age": {"gt": 18}}
Project Select specific columns ["id", "name", "email"]
Aggregate Compute summary statistics ["SUM(amount)", "AVG(score)"]
Join Combine multiple datasets {"type": "inner", "on": "user_id"}

5.3 Batch Operations

5.3.1 Bulk Insert

POST /api/v1/datasets/{id}/batch
{
  "records": [
    {"user_id": "u1", "value": 10},
    {"user_id": "u2", "value": 20},
    ...
  ],
  "format": "wbf"

POST /api/v1/datasets/{id}/export
{
  "format": "parquet",

  "destination": "s3://bucket/path/"
}

5.4 Client SDKs

5.4.1 Python SDK (PyWIA)

from wia.data import WIAClient

client = WIAClient(api_key="your-key")

# Create dataset
dataset = client.create_dataset(
    name="user_events",
    schema=schema
)

# Insert data
dataset.insert([
    {"user_id": "u1", "timestamp": 1704067200},
    {"user_id": "u2", "timestamp": 1704067300}
])

# Query data
results = dataset.query()
    .select("user_id", "COUNT(*)")
    .where(timestamp__gte="2025-01-01")
    .groupby("user_id")
    .execute()

5.4.2 Java SDK

import com.wia.data.*;

WIAClient client = new WIAClient("your-key");

Dataset dataset = client.createDataset(
    DatasetConfig.builder()
        .name("user_events")
        .schema(schema)
        .build()
);

dataset.insert(records);

QueryResult results = dataset.query()
    .select("user_id", "COUNT(*)")
    .where(Where.gte("timestamp", "2025-01-01"))
    .groupBy("user_id")
    .execute();

5.5 Authentication and Security

5.5.1 API Key Authentication

curl -H "Authorization: Bearer YOUR_API_KEY" \
     https://api.wia-data.com/v1/datasets

5.5.2 OAuth 2.0 Support

  • Authorization code flow for user authentication
  • Client credentials for service-to-service
  • Token refresh and expiration handling

5.5.3 Encryption

  • In transit: TLS 1.3 required for all API calls
  • At rest: AES-256 encryption for stored data
  • Key management: Integration with HSM and KMS

5.6 Rate Limiting and Quotas

Tier Requests/min Data Transfer (GB/day) Storage (TB)
Free 60 1 0.1
Standard 600 100 10
Professional 6000 1000 100
Enterprise Unlimited Unlimited Unlimited

5.7 Error Handling

5.7.1 Standard Error Codes

Code Status Meaning
400 Bad Request Invalid parameters or malformed request
401 Unauthorized Invalid or missing authentication
403 Forbidden Insufficient permissions
404 Not Found Resource does not exist
429 Too Many Requests Rate limit exceeded
500 Internal Server Error Server-side error

5.7.2 Error Response Format

{
  "error": {
    "code": "INVALID_SCHEMA",
    "message": "Schema validation failed",
    "details": {
      "field": "user_id",
      "reason": "Required field missing"
    }
  }
}
