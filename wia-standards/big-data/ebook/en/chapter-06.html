Chapter 6: Phase 3 - Protocol Design

Hongik Ingan (弘益人間)

Robust protocols ensure reliable data movement across distributed systems, forming the backbone of big data infrastructure.

6.1 Data Pipeline Architecture

6.1.1 Pipeline Stages

Stage Purpose Key Operations
Ingestion Data collection from sources Validate, parse, route
Transformation Data processing and enrichment Map, filter, aggregate, join
Storage Persist processed data Write, partition, replicate
Access Query and retrieve data Read, filter, project

6.1.2 ETL vs ELT

Extract-Transform-Load (ETL):

  • Transform before loading into warehouse
  • Better for structured, smaller datasets
  • Protects warehouse from raw data complexity

Extract-Load-Transform (ELT):

  • Load raw data first, transform in warehouse
  • Leverages warehouse processing power
  • Better for big data and ad-hoc queries

6.2.2 Delivery Semantics

Semantic Guarantee Use Case
At-most-once Message may be lost, never duplicated Metrics, logs (lossy acceptable)
At-least-once Message delivered, may duplicate Event tracking (idempotent processing)
Exactly-once Message delivered exactly once Financial transactions, critical data

6.3 Stream Processing Protocol

6.3.1 Windowing Operations

Tumbling Windows:

  • Fixed-size, non-overlapping time windows
  • Example: Aggregate every 5 minutes
  • Use: Periodic reports, regular summaries

Sliding Windows:

  • Fixed-size, overlapping windows
  • Example: Moving average over last hour
  • Use: Continuous metrics, trend analysis

Session Windows:

  • Variable-size based on activity gaps
  • Example: User sessions with 30min timeout
  • Use: Behavior analysis, engagement tracking

6.4 Batch Processing Protocol

6.4.1 Job Specification

{
  "job": {
    "name": "daily_aggregation",
    "type": "batch",
    "schedule": "0 2 * * *",
    "input": {
      "dataset": "raw_events",
      "partition": "date=2025-01-01"
    },
    "transformations": [
      {"op": "filter", "condition": "status='active'"},
      {"op": "groupby", "keys": ["user_id"]},
      {"op": "aggregate", "functions": ["COUNT", "SUM(amount)"]}
    ],
    "output": {
      "dataset": "daily_summary",
      "format": "parquet",
      "compression": "snappy"
    }
  }
}

6.5 Data Transfer Protocol

6.5.1 Chunked Transfer

For large file transfers:

POST /api/v1/transfer/init
{
  "file_size": 10737418240,
  "chunk_size": 10485760,
  "checksum": "sha256:abc123..."
}

Response:
{
  "transfer_id": "txf-67890",
  "num_chunks": 1024,
  "upload_urls": [...]
}

6.5.2 Resumable Uploads

  • Support for interrupted transfers
  • Chunk-level checksums
  • Retry logic with exponential backoff
  • Concurrent chunk uploads

6.6 State Management

6.6.1 Checkpoint Protocol

{
  "checkpoint": {
    "job_id": "job-123",
    "checkpoint_id": "cp-456",
    "timestamp": 1704067200000,
    "offsets": {
      "topic1-partition0": 1000,
      "topic1-partition1": 2000
    },
    "state": {
      "counters": {...},
      "aggregates": {...}
    }
  }
}

6.6.2 Failure Recovery

Failure Type Recovery Action Data Loss Risk
Task failure Restart from last checkpoint None (if checkpointed)
Node failure Reschedule tasks on healthy nodes None (replicated state)
Network partition Wait for partition to heal None (buffered data)
Corrupted data Skip or quarantine bad records Minimal (bad records only)

Chapter Summary

Key Takeaways:

  1. Data pipelines follow a structured flow: ingestion, transformation, storage, access
  2. Message delivery semantics (at-most-once, at-least-once, exactly-once) suit different use cases
  3. Stream processing uses windowing operations for time-based aggregations
  4. Batch processing enables large-scale transformations on historical data
  5. Checkpointing and state management ensure fault tolerance
