제2장: 기술 아키텍처

"좋은 아키텍처는 보이지 않습니다. 학습자는 기술이 아닌 언어에 집중해야 합니다."

2.1 시스템 개요

WIA-EDU-022 아키텍처는 4계층 구조로 설계되어 확장성과 유연성을 제공합니다:

┌─────────────────────────────────────────┐
│  Layer 4: 사용자 인터페이스 계층         │  ← 학습자 상호작용
│  (Web, Mobile, Desktop, AR/VR)          │
└─────────────────────────────────────────┘
              ↕ (REST API / GraphQL)
┌─────────────────────────────────────────┐
│  Layer 3: 애플리케이션 계층              │  ← 비즈니스 로직
│  (학습 관리, 평가, 개인화 엔진)          │
└─────────────────────────────────────────┘
              ↕ (내부 API)
┌─────────────────────────────────────────┐
│  Layer 2: AI/ML 서비스 계층              │  ← 지능형 기능
│  (STT, TTS, NLP, 추천 시스템)           │
└─────────────────────────────────────────┘
              ↕ (데이터 액세스)
┌─────────────────────────────────────────┐
│  Layer 1: 데이터 계층                    │  ← 영구 저장
│  (학습자 프로필, 콘텐츠, 진도 기록)      │
└─────────────────────────────────────────┘

2.2 핵심 컴포넌트

🎯 2.2.1 학습 관리 시스템 (LMS Core)

중앙 조정 컴포넌트로 모든 학습 활동을 관리합니다.

기능 설명 기술
세션 관리 학습 세션 생성, 추적, 종료 Redis, WebSocket
진도 추적 실시간 학습 진행 상황 기록 TimescaleDB
콘텐츠 전달 적절한 학습 자료 제공 CDN, GraphQL
성취도 평가 학습 결과 측정 및 분석 PostgreSQL, Analytics

🧠 2.2.2 AI 개인화 엔진

각 학습자에게 최적화된 경험을 제공하는 머신러닝 시스템입니다.

  • 학습자 모델링 — 능력 수준, 학습 속도, 선호도 파악
  • 적응형 난이도 — 실시간으로 문제 난이도 조절
  • 콘텐츠 추천 — 협업 필터링 기반 맞춤형 추천
  • 학습 경로 최적화 — 강화학습으로 최적 커리큘럼 생성
개인화 파이프라인:

입력 데이터
├─ 과거 학습 이력
├─ 평가 결과
├─ 상호작용 패턴
└─ 명시적 선호도

    ↓ (특징 추출)

ML 모델
├─ 학습자 클러스터링 (K-Means)
├─ 능력 추정 (IRT 모델)
├─ 추천 시스템 (Transformer)
└─ 난이도 예측 (XGBoost)

    ↓ (추론)

출력
├─ 다음 학습 항목 (Top-K)
├─ 난이도 조정 (±2 레벨)
├─ 복습 일정 (간격 반복)
└─ 동기 부여 메시지

🎤 2.2.3 음성 처리 모듈

발음 학습과 평가를 위한 핵심 컴포넌트입니다.

모듈 역할 정확도
STT (Speech-to-Text) 학습자 발화를 텍스트로 변환 95%+
발음 평가 음소 단위 정확도 측정 92%+
TTS (Text-to-Speech) 원어민 발음 모델 제공 MOS 4.5+
억양 분석 피치, 리듬, 강세 평가 88%+

📝 2.2.4 자연어 처리 엔진

텍스트 기반 학습과 평가를 담당합니다.

  • 문법 검사 — 규칙 기반 + 통계적 접근
  • 작문 평가 — 자동 채점 시스템 (AES)
  • 대화 시뮬레이션 — Chatbot 기반 회화 연습
  • 번역 품질 — 신경망 번역 (NMT) + 품질 추정
  • 어휘 확장 — 문맥 기반 유의어/반의어 제안

2.3 데이터 흐름

시스템 내 데이터 이동 경로를 이해하는 것이 중요합니다.

📊 학습 세션 흐름

1. 세션 시작
   학습자 인증 → 프로필 로드 → 진도 조회

2. 콘텐츠 선택
   AI 엔진 추천 → 학습자 선택 → 콘텐츠 전달

3. 학습 활동
   학습자 입력 (음성/텍스트)
   → AI 평가 (STT/NLP)
   → 피드백 생성
   → UI 표시

4. 진도 기록
   활동 로그 → 성취도 계산 → DB 저장

5. 세션 종료
   통계 업데이트 → 다음 추천 생성 → 로그아웃

🔄 실시간 피드백 루프

단계 처리 시간 품질 기준
입력 수집 ~10ms 16kHz 샘플링
AI 처리 ~200ms 95% 정확도
피드백 생성 ~50ms 맞춤형 메시지
UI 렌더링 ~40ms 60 FPS
전체 지연시간 ~300ms 즉각적 경험

2.4 확장성 설계

수백만 동시 학습자를 지원하기 위한 아키텍처 전략:

☁️ 클라우드 네이티브 구조

  • 마이크로서비스 — 독립적으로 확장 가능한 서비스
  • 컨테이너화 — Docker + Kubernetes 오케스트레이션
  • 로드 밸런싱 — 자동 트래픽 분산
  • CDN 통합 — 전 세계 저지연 콘텐츠 전달
  • Auto-scaling — 수요에 따른 자동 리소스 조절

💾 데이터베이스 전략

데이터 유형 저장소 전략
사용자 프로필 PostgreSQL 샤딩 by user_id
학습 콘텐츠 MongoDB 레플리카 세트
진도 이벤트 TimescaleDB 시계열 압축
세션 상태 Redis 클러스터 모드
미디어 파일 S3/CloudStorage 지역별 버킷

2.5 보안 아키텍처

학습자 데이터를 보호하는 다층 보안 체계:

보안 계층:

L1: 네트워크 보안
    ├─ DDoS 방어 (Cloudflare)
    ├─ WAF (Web Application Firewall)
    └─ TLS 1.3 암호화

L2: 애플리케이션 보안
    ├─ OAuth 2.0 / OIDC 인증
    ├─ JWT 토큰 관리
    ├─ RBAC 권한 제어
    └─ Rate Limiting

L3: 데이터 보안
    ├─ 저장 데이터 암호화 (AES-256)
    ├─ 전송 데이터 암호화 (TLS)
    ├─ 필드 수준 암호화 (PII)
    └─ 정기 백업 (3-2-1 규칙)

L4: 모니터링 & 감사
    ├─ 침입 탐지 시스템 (IDS)
    ├─ 로그 분석 (SIEM)
    ├─ 이상 탐지 (ML 기반)
    └─ 규정 준수 감사
