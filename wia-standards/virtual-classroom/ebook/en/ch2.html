Core Concepts and Terminology

Establishing a common vocabulary is essential for effective communication about virtual classroom systems. This chapter defines the key terms, concepts, and architectural patterns that form the foundation of the WIA-EDU-006 standard. Whether you're a developer, educator, or administrator, understanding these concepts will enable you to work more effectively with virtual classroom technologies.

2.1 Fundamental Concepts

2.1.1 Virtual Classroom

Virtual Classroom
A digital environment that replicates and extends the capabilities of a traditional physical classroom through technology. A virtual classroom enables synchronous and/or asynchronous interaction between instructors and learners, providing tools for content delivery, communication, collaboration, assessment, and learning management.

Key characteristics of a virtual classroom include:

  • Presence: Participants can see, hear, and interact with each other in real-time
  • Content Delivery: Multiple formats for presenting information (video, audio, text, images)
  • Interaction Tools: Mechanisms for questions, discussions, and collaborative work
  • Assessment: Capabilities for evaluating learner understanding and progress
  • Persistence: Session recordings and materials remain accessible after live sessions

2.1.2 Synchronous vs. Asynchronous Learning

Synchronous Learning:

Real-time instruction where all participants are online simultaneously. Examples include live video lectures, interactive discussions, and collaborative activities. Synchronous learning provides immediate feedback and social interaction but requires scheduling coordination.

Asynchronous Learning:

Self-paced instruction where learners access content and complete activities on their own schedule. Examples include recorded lectures, discussion forums, and independent assignments. Asynchronous learning offers flexibility but may reduce social connection and immediate support.

Most effective virtual classrooms employ a blended approach, combining synchronous sessions for high-interaction activities with asynchronous content for flexible, self-paced learning.

2.1.3 Learning Management System (LMS)

Learning Management System (LMS)
A software application that administers, documents, tracks, reports, and delivers educational courses and training programs. An LMS typically handles course enrollment, content organization, assignment submission, grading, and progress tracking. Virtual classrooms often integrate with LMS platforms to provide a comprehensive learning ecosystem.

Common LMS platforms include Moodle, Canvas, Blackboard, and Google Classroom. WIA-EDU-006 specifies integration standards to ensure virtual classrooms can exchange data seamlessly with these systems.

2.2 Architectural Components

2.2.1 Client-Server Architecture

Virtual classroom systems typically follow a client-server architecture where:

Component Role Examples
Client User interface running on participant devices Web browsers, mobile apps, desktop applications
Server Backend systems handling data, logic, and communication Application servers, database servers, media servers
Media Infrastructure Specialized servers for real-time video and audio WebRTC servers, streaming servers, CDNs

2.2.2 Session Management

Session
A bounded period during which a virtual classroom is active. A session has a defined start time, end time, roster of participants, and associated content. Sessions may be recurring (e.g., weekly class meetings) or one-time events (e.g., guest lectures, webinars).

Session management encompasses:

  • Scheduling and calendar integration
  • Access control and authentication
  • Participant admission (waiting rooms, approval workflows)
  • Recording and archiving
  • Analytics and attendance tracking

2.2.3 User Roles and Permissions

WIA-EDU-006 defines standard user roles with specific capabilities:

Standard User Roles:

Instructor/Host:

  • Full control over session settings and content
  • Can admit/remove participants
  • Manages breakout rooms and activities
  • Controls recording and streaming
  • Assigns roles and permissions to others

Teaching Assistant/Co-Host:

  • Assists with session management
  • Can moderate chat and Q&A
  • Manages breakout rooms
  • Limited control over recordings

Student/Participant:

  • Can view content and participate in discussions
  • May share audio/video with permission
  • Can use chat and reaction features
  • Limited or no administrative capabilities

Observer/Auditor:

  • View-only access to sessions
  • Cannot interact or appear to other participants
  • Used for quality assurance and evaluation

Administrator:

  • System-level configuration and management
  • User account administration
  • Analytics and reporting access
  • Integration and API management

2.3 Communication Protocols

2.3.1 WebRTC (Web Real-Time Communication)

WebRTC
An open-source project providing web browsers and mobile applications with real-time communication capabilities via simple APIs. WebRTC enables peer-to-peer audio, video, and data sharing without requiring plugins or third-party software.

WebRTC is the foundation of most modern virtual classroom video conferencing. Key features include:

  • Low-latency audio and video streaming
  • Adaptive bitrate based on network conditions
  • Built-in encryption (DTLS/SRTP)
  • NAT traversal (STUN/TURN servers)
  • Screen sharing and data channels

2.3.2 WebSocket

WebSocket
A communication protocol providing full-duplex communication channels over a single TCP connection. WebSockets enable real-time, bidirectional data exchange between clients and servers, ideal for chat, notifications, and live updates.

In virtual classrooms, WebSockets power:

  • Live chat and messaging
  • Presence indicators (who's online/active)
  • Real-time whiteboard collaboration
  • Polling and Q&A updates
  • Notification delivery

2.3.3 HTTP/HTTPS and REST APIs

Traditional HTTP(S) requests and RESTful APIs handle non-real-time operations:

  • Content upload and download
  • Authentication and authorization
  • Session creation and management
  • Analytics and reporting
  • Integration with external systems

2.4 Data Formats and Standards

2.4.1 SCORM (Sharable Content Object Reference Model)

SCORM
A set of technical standards for eLearning software products. SCORM defines how content communicates with learning management systems, enabling content portability and interoperability across platforms.

WIA-EDU-006 recommends SCORM 2004 4th Edition support for:

  • Content packaging and distribution
  • Learner progress tracking
  • Completion and scoring data
  • Content sequencing and navigation

2.4.2 xAPI (Experience API / Tin Can API)

xAPI (Experience API)
A modern eLearning specification that captures learning experiences in a consistent format. xAPI uses simple statements in the form "Actor + Verb + Object" to record learning activities, providing more flexibility than SCORM.

Example xAPI statement: "John Doe (actor) completed (verb) Advanced Physics Module 3 (object)."

xAPI advantages for virtual classrooms:

  • Tracks learning beyond the LMS (mobile apps, simulations, real-world activities)
  • Works offline with later synchronization
  • Supports rich contextual data
  • Enables comprehensive learning analytics

2.4.3 LTI (Learning Tools Interoperability)

LTI (Learning Tools Interoperability)
A standard developed by IMS Global for integrating remote tools and content into learning platforms. LTI enables seamless single sign-on and grade passback between virtual classrooms and LMS systems.

WIA-EDU-006 mandates LTI 1.3 (LTI Advantage) support for:

  • Secure authentication and authorization
  • Deep linking to specific content
  • Assignment and grade synchronization
  • Names and roles provisioning

2.5 Quality of Service (QoS) Metrics

2.5.1 Latency

Latency
The time delay between a signal being sent and received. In virtual classrooms, latency affects the responsiveness of real-time communication. WIA-EDU-006 specifies maximum latency thresholds for acceptable user experience.
Metric Acceptable Range Impact
Audio Latency < 150ms Natural conversation flow
Video Latency < 200ms Synchronized audio-visual experience
Chat Latency < 500ms Responsive text communication
Whiteboard Latency < 100ms Smooth collaborative drawing

2.5.2 Bandwidth Requirements

Minimum bandwidth recommendations for quality virtual classroom experiences:

Per-Participant Bandwidth:
  • Audio only: 50-100 kbps (send/receive)
  • Standard Definition video: 1-2 Mbps (send/receive)
  • High Definition video: 3-5 Mbps (send/receive)
  • Screen sharing: 500 kbps - 2 Mbps

Note: These are per-stream requirements. A participant receiving video from 20 others needs bandwidth proportional to the number of streams.

2.5.3 Packet Loss and Jitter

Packet Loss
The percentage of data packets that fail to reach their destination. Acceptable packet loss for virtual classrooms is < 1% for audio/video streams.
Jitter
Variation in packet arrival times. High jitter causes choppy audio/video. Target jitter should be < 30ms for quality real-time communication.

2.6 Accessibility Terminology

2.6.1 WCAG (Web Content Accessibility Guidelines)

WCAG 2.1 AA
The international standard for web accessibility, defining how to make web content more accessible to people with disabilities. WIA-EDU-006 mandates WCAG 2.1 Level AA compliance for all virtual classroom interfaces and content.

WCAG is organized around four principles (POUR):

  • Perceivable: Information must be presentable to users in ways they can perceive
  • Operable: User interface components must be operable by all users
  • Understandable: Information and operation must be understandable
  • Robust: Content must be robust enough to work with current and future technologies

2.6.2 Screen Reader

Screen Reader
Assistive technology that reads on-screen content aloud for users with visual impairments. Virtual classroom interfaces must be compatible with popular screen readers like JAWS, NVDA, and VoiceOver.

2.6.3 Captions and Transcripts

Essential accessibility features for virtual classrooms:

  • Closed Captions: Text synchronized with audio/video content, can be toggled on/off
  • Live Captions: Real-time transcription of spoken content during live sessions
  • Transcripts: Complete text versions of audio/video content for reference and search

WIA-EDU-006 requires automatic caption generation capabilities with manual editing tools for accuracy.

2.7 Security and Privacy Concepts

2.7.1 End-to-End Encryption (E2EE)

End-to-End Encryption
A security method where data is encrypted on the sender's device and only decrypted on the recipient's device. In virtual classrooms, E2EE ensures that audio, video, and messages cannot be intercepted or viewed by intermediaries, including the platform provider.

2.7.2 OAuth 2.0 and SAML 2.0

Industry-standard protocols for authentication and authorization:

OAuth 2.0:

An authorization framework enabling third-party applications to access user resources without exposing credentials. Widely used for "Sign in with Google/Microsoft" functionality.

SAML 2.0:

Security Assertion Markup Language, an XML-based standard for exchanging authentication and authorization data between identity providers and service providers. Common in enterprise single sign-on (SSO) implementations.

2.7.3 FERPA and GDPR Compliance

FERPA (Family Educational Rights and Privacy Act)
U.S. federal law protecting the privacy of student education records. Virtual classroom platforms handling U.S. student data must comply with FERPA requirements.
GDPR (General Data Protection Regulation)
European Union regulation governing data protection and privacy. Any virtual classroom serving EU users must comply with GDPR requirements for data collection, processing, storage, and user rights.

2.8 Performance and Scalability Terms

2.8.1 Concurrent Users

Concurrent Users
The number of participants actively connected to the system simultaneously. WIA-EDU-006 compliant systems must support at least 1000 concurrent users per session with graceful degradation beyond that threshold.

2.8.2 Horizontal and Vertical Scaling

Scaling Type Approach Use Case
Vertical Scaling Adding resources (CPU, RAM) to existing servers Quick capacity increase for predictable growth
Horizontal Scaling Adding more servers to distribute load Handling unpredictable demand spikes, fault tolerance

WIA-EDU-006 recommends architectures that support both scaling strategies for maximum flexibility.

2.9 Summary

This chapter has established the fundamental vocabulary for discussing virtual classroom systems. From architectural concepts like client-server models and session management, to communication protocols like WebRTC and WebSocket, to data standards like SCORM and xAPI, these terms form the foundation for understanding the WIA-EDU-006 specification.

Key Takeaways:
  • Virtual classrooms combine synchronous and asynchronous learning capabilities
  • Standard user roles (Instructor, Student, TA, etc.) ensure consistent permissions
  • WebRTC, WebSocket, and HTTPS work together to enable real-time and asynchronous features
  • SCORM, xAPI, and LTI ensure interoperability with learning management systems
  • WCAG 2.1 AA compliance guarantees accessibility for all learners
  • Quality of Service metrics define acceptable performance thresholds
