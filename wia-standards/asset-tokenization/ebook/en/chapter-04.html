The Foundation: Why Data Format Matters

In traditional finance, data standards like ISO 20022 (financial messaging), FIGI (instrument identification), and LEI (legal entity identification) enable global interoperability. Without these standards, cross-border payments, securities trading, and regulatory reporting would be impossible.

Asset tokenization faces the same challenge. If every platform uses proprietary formats for token metadata, ownership records, and compliance attributes, the ecosystem fragments. Tokens from Platform A can't be listed on Exchange B. Custody providers require custom integrations for each issuer. Investors need separate wallets for every tokenized asset.

Phase 1 of WIA-FIN-008 solves this by defining standardized JSON schemas that any system can adopt—whether you're building on Ethereum, Polygon, or a private blockchain. These schemas cover:

  • Token Metadata: Name, symbol, total supply, asset class, issuer information
  • Asset Descriptors: Physical/digital attributes specific to the asset type (real estate, art, commodity)
  • Ownership Records: Investor addresses, token balances, acquisition dates, cost basis
  • Valuation Data: Initial appraisal, current NAV, historical valuations, third-party audits
  • Compliance Attributes: KYC status, accreditation level, jurisdiction, transfer restrictions
  • Distribution Events: Dividend payments, rental income, interest distributions

Core Schema: Token Metadata

Every tokenized asset begins with a base metadata structure that identifies the token, its issuer, and fundamental characteristics:

Field Descriptions

Field Type Description
@context URL JSON-LD context defining vocabulary (enables semantic interoperability)
tokenId string Unique identifier across all WIA tokens (format: TOK-YYYY-CLASS-###)
assetClass enum REAL_ESTATE, ART, COMMODITY, PRIVATE_EQUITY, DEBT_INSTRUMENT, INTELLECTUAL_PROPERTY
totalSupply integer Total number of tokens issued (must match smart contract supply)
decimals integer Number of decimal places (0 for whole shares, 18 for fractional)
lei string Legal Entity Identifier (ISO 17442 standard)
lockupPeriod duration ISO 8601 duration (P6M = 6 months, P1Y = 1 year)

Putting It All Together: Complete Token Package

A fully compliant tokenized asset combines all these schemas into a comprehensive data package:

  • ✅ Token Metadata: Basic identification and regulatory framework
  • ✅ Asset Descriptors: Detailed physical/financial attributes
  • ✅ Ownership Records: Complete investor registry with KYC/AML status
  • ✅ Valuation History: Periodic appraisals with third-party certification
  • ✅ Compliance Rules: Transfer restrictions enforced by smart contracts
  • ✅ Distribution Events: Automated cash flow payments
  • ✅ Document Registry: Immutable legal/financial documents

Validation & Schema Evolution

WIA-FIN-008 provides JSON Schema validation files that ensure data integrity:

  • Schema Validators: Automated validation via Ajv, jsonschema libraries
  • Versioning: Semantic versioning (v1.0.0, v1.1.0) for backward compatibility
  • Extensions: Custom fields allowed via x-custom- prefix
  • Deprecation: Advance notice before removing/changing fields
