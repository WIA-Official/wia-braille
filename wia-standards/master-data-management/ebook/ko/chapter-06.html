6장: 마스터 데이터 동기화

마스터 데이터와 소스 시스템 간의 일관성을 유지하는 것은 MDM의 핵심 과제입니다. 이 장에서는 실시간 동기화 패턴, CDC(Change Data Capture), 이벤트 기반 아키텍처, 충돌 해결 전략을 상세히 다룹니다.

1. 데이터 동기화 개요

동기화는 마스터 데이터 허브와 소스 시스템 간의 데이터 일관성을 보장하는 프로세스입니다.

동기화 방향 설명 사용 사례 복잡도
단방향 (One-Way) 소스 → MDM 또는 MDM → 소스 데이터 웨어하우스, 분석 낮음
양방향 (Bi-Directional) MDM ↔ 소스 상호 동기화 Coexistence 아키텍처 높음
멀티소스 (Multi-Source) 여러 소스 → MDM → 여러 타겟 엔터프라이즈 MDM 매우 높음
체인 (Chained) 시스템 A → MDM → 시스템 B → 시스템 C 프로세스 자동화 중간

2. 실시간 동기화 패턴

실시간 또는 거의 실시간으로 데이터 변경을 전파하는 다양한 패턴들을 살펴봅니다.

동기화 패턴 비교

패턴 지연시간 복잡도 데이터 일관성 적용 사례
Polling 초~분 낮음 최종 일관성 레거시 시스템
Webhooks 초 중간 최종 일관성 SaaS 통합
Message Queue 밀리초~초 중간 최종 일관성 비동기 처리
Event Streaming 밀리초 높음 최종 일관성 실시간 분석
Database Triggers 밀리초 중간 강한 일관성 트랜잭션 무결성
CDC (Change Data Capture) 초~분 중간 최종 일관성 데이터 복제

Webhook 기반 동기화 구현

from flask import Flask, request, jsonify
from typing import Dict, List
import requests
import hashlib
import hmac
import json

app = Flask(__name__)

class WebhookSyncService:
    """Webhook 기반 데이터 동기화 서비스"""

    def __init__(self, secret_key: str):
        self.secret_key = secret_key
        self.subscribers = []  # 구독자 목록

    def verify_signature(self, payload: str, signature: str) -> bool:
        """
        Webhook 요청 서명 검증

        Args:
            payload: 요청 본문
            signature: 서명 해시

        Returns:
            검증 성공 여부
        """
        expected_signature = hmac.new(
            self.secret_key.encode(),
            payload.encode(),
            hashlib.sha256
        ).hexdigest()

        return hmac.compare_digest(expected_signature, signature)

    def register_webhook(self, url: str, events: List[str]):
        """
        Webhook 구독 등록

        Args:
            url: Webhook 엔드포인트 URL
            events: 구독할 이벤트 타입 리스트
        """
        self.subscribers.append({
            'url': url,
            'events': events
        })

    def trigger_webhook(self, event_type: str, data: Dict):
        """
        Webhook 트리거 (구독자에게 전송)

        Args:
            event_type: 이벤트 타입
            data: 전송할 데이터
        """
        payload = {
            'event': event_type,
            'timestamp': datetime.now().isoformat(),
            'data': data
        }

        for subscriber in self.subscribers:
            if event_type in subscriber['events']:
                self._send_webhook(subscriber['url'], payload)

    def _send_webhook(self, url: str, payload: Dict):
        """Webhook 전송 (재시도 로직 포함)"""
        max_retries = 3
        retry_delay = [1, 2, 4]  # 지수 백오프

        payload_json = json.dumps(payload)

        # 서명 생성
        signature = hmac.new(
            self.secret_key.encode(),
            payload_json.encode(),
            hashlib.sha256
        ).hexdigest()

        headers = {
            'Content-Type': 'application/json',
            'X-Webhook-Signature': signature
        }

        for attempt in range(max_retries):
            try:
                response = requests.post(
                    url,
                    data=payload_json,
                    headers=headers,
                    timeout=10
                )

                if response.status_code == 200:
                    print(f"Webhook sent successfully to {url}")
                    return
                else:
                    print(f"Webhook failed: {response.status_code}")

            except requests.exceptions.RequestException as e:
                print(f"Webhook error (attempt {attempt + 1}): {e}")

            if attempt < max_retries - 1:
                time.sleep(retry_delay[attempt])

        print(f"Webhook failed after {max_retries} attempts")

3. CDC (Change Data Capture)

데이터베이스 트랜잭션 로그를 읽어 변경 사항을 실시간으로 캡처하는 기술입니다.

CDC 구현 방법

방법 원리 장점 단점
Trigger-based DB 트리거로 변경 기록 간단한 구현 성능 오버헤드
Timestamp-based 업데이트 타임스탬프 확인 낮은 복잡도 삭제 추적 불가
Log-based 트랜잭션 로그 읽기 낮은 오버헤드, 완전한 추적 DB별 구현 필요
Query-based 주기적 쿼리 실행 DB 독립적 높은 지연시간

from kafka import KafkaConsumer
import json

class CDCEventProcessor:
    """CDC 이벤트를 처리하여 MDM에 동기화"""

    def __init__(self, kafka_bootstrap_servers: str):
        self.consumer = KafkaConsumer(
            'mdm.customers',
            'mdm.products',
            bootstrap_servers=kafka_bootstrap_servers,
            value_deserializer=lambda m: json.loads(m.decode('utf-8')),
            group_id='mdm-sync-group',
            enable_auto_commit=True
        )

    def process_events(self):
        """CDC 이벤트 소비 및 처리"""
        for message in self.consumer:
            topic = message.topic
            event = message.value

            # 이벤트 타입 확인
            operation = event.get('__op')  # c=create, u=update, d=delete

            if operation == 'c':
                self.handle_create(topic, event)
            elif operation == 'u':
                self.handle_update(topic, event)
            elif operation == 'd':
                self.handle_delete(topic, event)

    def handle_create(self, topic: str, event: Dict):
        """새 레코드 생성 이벤트 처리"""
        entity_type = topic.split('.')[-1]
        data = event.get('after')

        print(f"Creating new {entity_type}: {data}")
        # MDM에 새 레코드 추가 로직

4. 이벤트 기반 동기화

이벤트 소싱과 CQRS 패턴을 활용한 확장 가능한 동기화 아키텍처입니다.

이벤트 기반 아키텍처 구성요소

  • Event Producer: 데이터 변경 이벤트 생성
  • Event Bus: 이벤트 라우팅 및 배포 (Kafka, RabbitMQ)
  • Event Store: 모든 이벤트 영구 저장
  • Event Consumer: 이벤트 구독 및 처리
  • Projection: 이벤트로부터 읽기 모델 생성

이벤트 소싱 구현

from dataclasses import dataclass, field
from datetime import datetime
from typing import List, Dict, Any
from uuid import uuid4
import json

@dataclass
class DomainEvent:
    """도메인 이벤트 기본 클래스"""
    event_id: str = field(default_factory=lambda: str(uuid4()))
    event_type: str = ""
    aggregate_id: str = ""
    aggregate_type: str = ""
    timestamp: datetime = field(default_factory=datetime.now)
    version: int = 1
    data: Dict[str, Any] = field(default_factory=dict)
    metadata: Dict[str, Any] = field(default_factory=dict)

@dataclass
class CustomerCreatedEvent(DomainEvent):
    """고객 생성 이벤트"""
    event_type: str = "CustomerCreated"

@dataclass
class CustomerUpdatedEvent(DomainEvent):
    """고객 업데이트 이벤트"""
    event_type: str = "CustomerUpdated"

@dataclass
class CustomerMergedEvent(DomainEvent):
    """고객 병합 이벤트"""
    event_type: str = "CustomerMerged"


class EventStore:
    """이벤트 저장소"""

    def __init__(self):
        self.events = []  # 실제로는 DB 사용

    def append(self, event: DomainEvent):
        """이벤트 추가"""
        self.events.append(event)

    def get_events(self, aggregate_id: str) -> List[DomainEvent]:
        """특정 Aggregate의 모든 이벤트 조회"""
        return [e for e in self.events if e.aggregate_id == aggregate_id]

    def get_all_events(self, from_version: int = 0) -> List[DomainEvent]:
        """모든 이벤트 조회 (버전 필터링)"""
        return [e for e in self.events if e.version > from_version]


class CustomerAggregate:
    """고객 Aggregate - 이벤트 소싱"""

    def __init__(self, customer_id: str):
        self.customer_id = customer_id
        self.version = 0
        self.state = {}
        self.uncommitted_events = []

    def create(self, data: Dict):
        """고객 생성"""
        event = CustomerCreatedEvent(
            aggregate_id=self.customer_id,
            aggregate_type="Customer",
            version=self.version + 1,
            data=data
        )
        self._apply_event(event)
        self.uncommitted_events.append(event)

    def update(self, changes: Dict):
        """고객 정보 업데이트"""
        event = CustomerUpdatedEvent(
            aggregate_id=self.customer_id,
            aggregate_type="Customer",
            version=self.version + 1,
            data={
                'changes': changes,
                'previous_state': self.state.copy()
            }
        )
        self._apply_event(event)
        self.uncommitted_events.append(event)

    def merge_with(self, other_customer_id: str, merged_data: Dict):
        """다른 고객과 병합"""
        event = CustomerMergedEvent(
            aggregate_id=self.customer_id,
            aggregate_type="Customer",
            version=self.version + 1,
            data={
                'merged_from': other_customer_id,
                'merged_data': merged_data
            }
        )
        self._apply_event(event)
        self.uncommitted_events.append(event)

    def _apply_event(self, event: DomainEvent):
        """이벤트 적용 (상태 변경)"""
        if isinstance(event, CustomerCreatedEvent):
            self.state = event.data.copy()
        elif isinstance(event, CustomerUpdatedEvent):
            self.state.update(event.data['changes'])
        elif isinstance(event, CustomerMergedEvent):
            self.state.update(event.data['merged_data'])

        self.version = event.version

    def load_from_history(self, events: List[DomainEvent]):
        """이벤트 히스토리로부터 상태 재구성"""
        for event in sorted(events, key=lambda e: e.version):
            self._apply_event(event)

    def commit(self, event_store: EventStore):
        """Uncommitted 이벤트를 Event Store에 저장"""
        for event in self.uncommitted_events:
            event_store.append(event)
        self.uncommitted_events = []

5. 충돌 해결 전략

양방향 동기화에서 불가피하게 발생하는 데이터 충돌을 해결하는 전략들입니다.

충돌 해결 방법

전략 설명 장점 단점 적용 사례
Last Write Wins (LWW) 타임스탬프 기준 최신 변경 채택 간단함 데이터 손실 가능 로그, 메트릭
Master Wins 마스터 시스템 변경 우선 예측 가능 유연성 부족 중앙집중 MDM
Manual Resolution 사용자가 수동 해결 정확성 높음 확장성 낮음 중요 비즈니스 데이터
Field-Level Merge 필드별로 최적 값 선택 데이터 손실 최소화 복잡한 로직 고객 프로필
Version Vector 벡터 시계로 인과관계 추적 정교한 충돌 감지 높은 복잡도 분산 시스템
CRDT 충돌 없는 복제 데이터 타입 자동 병합 제한된 데이터 타입 협업 편집

충돌 해결 엔진 구현

from enum import Enum
from typing import Any, Dict, Optional, Tuple
from datetime import datetime

class ConflictResolutionStrategy(Enum):
    LAST_WRITE_WINS = "last_write_wins"
    MASTER_WINS = "master_wins"
    MANUAL = "manual"
    FIELD_LEVEL_MERGE = "field_level_merge"
    SOURCE_PRIORITY = "source_priority"

class ConflictResolver:
    """데이터 충돌 해결 엔진"""

    def __init__(self):
        self.source_priorities = {}  # 소스별 우선순위
        self.field_strategies = {}   # 필드별 해결 전략
        self.pending_conflicts = []  # 수동 해결 대기 충돌

    def set_source_priority(self, source: str, priority: int):
        """소스 시스템의 우선순위 설정 (높을수록 우선)"""
        self.source_priorities[source] = priority

    def set_field_strategy(self, field: str, strategy: ConflictResolutionStrategy):
        """필드별 충돌 해결 전략 설정"""
        self.field_strategies[field] = strategy

    def resolve_conflict(
        self,
        field: str,
        value1: Any, source1: str, timestamp1: datetime,
        value2: Any, source2: str, timestamp2: datetime
    ) -> Tuple[Any, str]:
        """
        두 값 간 충돌 해결

        Returns:
            (선택된 값, 선택 이유)
        """
        # 값이 같으면 충돌 아님
        if value1 == value2:
            return value1, "values_identical"

        # 필드별 전략 확인
        strategy = self.field_strategies.get(
            field,
            ConflictResolutionStrategy.LAST_WRITE_WINS  # 기본 전략
        )

        if strategy == ConflictResolutionStrategy.LAST_WRITE_WINS:
            return self._last_write_wins(
                value1, timestamp1, value2, timestamp2
            )

        elif strategy == ConflictResolutionStrategy.MASTER_WINS:
            return self._master_wins(
                value1, source1, value2, source2
            )

        elif strategy == ConflictResolutionStrategy.SOURCE_PRIORITY:
            return self._source_priority(
                value1, source1, value2, source2
            )

        elif strategy == ConflictResolutionStrategy.MANUAL:
            return self._manual_resolution(
                field, value1, source1, value2, source2
            )

        elif strategy == ConflictResolutionStrategy.FIELD_LEVEL_MERGE:
            return self._field_level_merge(
                value1, value2
            )

    def _last_write_wins(
        self, value1: Any, timestamp1: datetime,
        value2: Any, timestamp2: datetime
    ) -> Tuple[Any, str]:
        """최신 타임스탬프의 값 선택"""
        if timestamp1 > timestamp2:
            return value1, f"last_write_wins (t1={timestamp1})"
        else:
            return value2, f"last_write_wins (t2={timestamp2})"

    def _master_wins(
        self, value1: Any, source1: str,
        value2: Any, source2: str
    ) -> Tuple[Any, str]:
        """'master' 소스의 값 선택"""
        if source1.lower() == 'master' or source1.lower() == 'mdm':
            return value1, f"master_wins (source={source1})"
        else:
            return value2, f"master_wins (source={source2})"

    def _source_priority(
        self, value1: Any, source1: str,
        value2: Any, source2: str
    ) -> Tuple[Any, str]:
        """소스 우선순위 기준 선택"""
        priority1 = self.source_priorities.get(source1, 0)
        priority2 = self.source_priorities.get(source2, 0)

        if priority1 >= priority2:
            return value1, f"source_priority ({source1}={priority1})"
        else:
            return value2, f"source_priority ({source2}={priority2})"

    def _manual_resolution(
        self, field: str,
        value1: Any, source1: str,
        value2: Any, source2: str
    ) -> Tuple[Any, str]:
        """수동 해결 큐에 추가"""
        conflict = {
            'field': field,
            'value1': value1,
            'source1': source1,
            'value2': value2,
            'source2': source2,
            'timestamp': datetime.now()
        }
        self.pending_conflicts.append(conflict)

        # 임시로 value1 반환 (나중에 수동 해결)
        return value1, "manual_resolution_pending"

    def _field_level_merge(
        self, value1: Any, value2: Any
    ) -> Tuple[Any, str]:
        """필드 수준 병합 (더 완전한 값 선택)"""
        # 문자열의 경우 더 긴 값 선택
        if isinstance(value1, str) and isinstance(value2, str):
            if len(value1) >= len(value2):
                return value1, "field_merge (longer)"
            else:
                return value2, "field_merge (longer)"

        # 리스트/딕셔너리의 경우 병합
        if isinstance(value1, list) and isinstance(value2, list):
            merged = list(set(value1 + value2))
            return merged, "field_merge (union)"

        if isinstance(value1, dict) and isinstance(value2, dict):
            merged = {**value1, **value2}
            return merged, "field_merge (dict_merge)"

        # 기본: value1 반환
        return value1, "field_merge (default)"

    def resolve_record_conflict(
        self,
        record1: Dict, source1: str, timestamp1: datetime,
        record2: Dict, source2: str, timestamp2: datetime
    ) -> Dict:
        """
        레코드 수준 충돌 해결 (모든 필드)

        Returns:
            충돌 해결된 병합 레코드
        """
        merged = {}
        all_fields = set(record1.keys()) | set(record2.keys())

        for field in all_fields:
            value1 = record1.get(field)
            value2 = record2.get(field)

            if value1 is None:
                merged[field] = value2
            elif value2 is None:
                merged[field] = value1
            else:
                resolved_value, reason = self.resolve_conflict(
                    field, value1, source1, timestamp1,
                    value2, source2, timestamp2
                )
                merged[field] = resolved_value
                merged[f"_{field}_resolution"] = reason  # 메타데이터

        return merged


# 사용 예시
resolver = ConflictResolver()

# 소스 우선순위 설정
resolver.set_source_priority('CRM', 10)
resolver.set_source_priority('ERP', 8)
resolver.set_source_priority('Website', 5)

# 필드별 전략 설정
resolver.set_field_strategy('email', ConflictResolutionStrategy.SOURCE_PRIORITY)
resolver.set_field_strategy('phone', ConflictResolutionStrategy.LAST_WRITE_WINS)
resolver.set_field_strategy('address', ConflictResolutionStrategy.FIELD_LEVEL_MERGE)

# 충돌 해결
record_crm = {
    'name': 'John Doe',
    'email': 'john@company.com',
    'phone': '555-1111',
    'address': '123 Main St'
}

record_web = {
    'name': 'John Doe',
    'email': 'john@gmail.com',
    'phone': '555-2222',
    'address': '123 Main Street, Apt 5'
}

merged = resolver.resolve_record_conflict(
    record_crm, 'CRM', datetime(2025, 1, 10),
    record_web, 'Website', datetime(2025, 1, 15)
)

print("Merged Record:")
for key, value in merged.items():
    print(f"  {key}: {value}")

6. 글로벌 데이터 동기화

지리적으로 분산된 데이터센터 간 마스터 데이터 동기화 전략입니다.

글로벌 동기화 패턴

패턴 설명 일관성 지연시간
Multi-Master 모든 리전에서 쓰기 가능 최종 일관성 낮음
Primary-Secondary 하나의 Primary, 여러 Read Replica 강한 일관성 중간
Active-Active 모든 리전 활성화 최종 일관성 낮음
Hub-and-Spoke (Global) 중앙 글로벌 허브 강한 일관성 높음
글로벌 동기화 고려사항:
  • 데이터 주권: GDPR 등 지역별 데이터 규제 준수
  • 네트워크 지연: 리전 간 레이턴시 최소화
  • 장애 복구: 리전 장애 시 자동 페일오버
  • 대역폭 비용: 리전 간 데이터 전송 비용 최적화
  • 시차 문제: 타임스탬프 동기화 및 UTC 사용

7. 동기화 모니터링 및 관찰성

동기화 프로세스의 건강 상태와 성능을 모니터링하는 방법입니다.

주요 모니터링 지표

지표 설명 목표 값 알람 조건
Sync Lag 소스 변경과 MDM 반영 시간 차이 < 1분 > 5분
Success Rate 동기화 성공률 > 99% < 95%
Throughput 초당 동기화 레코드 수 시스템 의존 급격한 감소
Error Count 동기화 오류 건수 0 > 10/시간
Conflict Rate 충돌 발생 비율 < 1% > 5%
Queue Depth 대기 중인 동기화 작업 수 < 1000 > 10000

모니터링 대시보드 구현 (Prometheus + Grafana)

# Prometheus 메트릭 수집
from prometheus_client import Counter, Gauge, Histogram, start_http_server
import time

# 메트릭 정의
sync_records_total = Counter(
    'mdm_sync_records_total',
    'Total number of records synced',
    ['source', 'status']
)

sync_lag_seconds = Gauge(
    'mdm_sync_lag_seconds',
    'Lag between source change and MDM sync',
    ['source']
)

sync_duration_seconds = Histogram(
    'mdm_sync_duration_seconds',
    'Time taken to sync a batch',
    ['source'],
    buckets=[0.1, 0.5, 1.0, 2.5, 5.0, 10.0]
)

conflict_count = Counter(
    'mdm_conflict_count_total',
    'Total number of conflicts detected',
    ['resolution_strategy']
)

# 메트릭 기록
def record_sync_metrics(source: str, records_count: int, duration: float,
                        lag: float, conflicts: int = 0):
    """동기화 메트릭 기록"""
    sync_records_total.labels(source=source, status='success').inc(records_count)
    sync_lag_seconds.labels(source=source).set(lag)
    sync_duration_seconds.labels(source=source).observe(duration)

    if conflicts > 0:
        conflict_count.labels(resolution_strategy='auto').inc(conflicts)

# Prometheus 서버 시작
start_http_server(8000)

CREATE TABLE sync_status (

    source_system VARCHAR(50) NOT NULL,
    last_sync_timestamp TIMESTAMP WITH TIME ZONE,

    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

CREATE TABLE sync_history (
    id SERIAL PRIMARY KEY,
    source_system VARCHAR(50) NOT NULL,
    sync_started_at TIMESTAMP WITH TIME ZONE,
    sync_completed_at TIMESTAMP WITH TIME ZONE,
    records_processed INTEGER,
    records_succeeded INTEGER,
    records_failed INTEGER,
    conflicts_detected INTEGER,
    average_lag_seconds FLOAT,
    error_messages TEXT[],
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()

-- 동기화 모니터링 쿼리
SELECT
    source_system,
    last_sync_timestamp,
    EXTRACT(EPOCH FROM (NOW() - last_sync_timestamp)) AS seconds_since_last_sync,
    status,
    errors_count
FROM sync_status
WHERE status != 'success' OR last_sync_timestamp < NOW() - INTERVAL '10 minutes';

8. 요약 및 핵심 포인트

효과적인 데이터 동기화는 MDM의 성공을 좌우하는 핵심 요소입니다.

핵심 요약:
  • 실시간 동기화는 Webhook, CDC, 이벤트 스트리밍 등 다양한 패턴 활용
  • CDC는 트랜잭션 로그 기반으로 낮은 오버헤드와 완전한 변경 추적
  • 이벤트 소싱은 모든 변경을 이벤트로 저장하여 완전한 감사 추적
  • 충돌 해결 전략은 비즈니스 요구사항에 맞게 필드별로 설정
  • 글로벌 동기화는 데이터 주권과 네트워크 지연을 고려
  • 모니터링은 Sync Lag, Success Rate, Conflict Rate 등 핵심 지표 추적
