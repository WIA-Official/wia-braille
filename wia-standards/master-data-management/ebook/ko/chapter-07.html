7장: 산업별 마스터 데이터 사례

각 산업은 고유한 비즈니스 요구사항과 규제 환경을 가지고 있어 MDM 구현 방식도 다릅니다. 이 장에서는 금융, 유통, 제조, 헬스케어, 공공 부문의 실제 MDM 사례와 산업별 데이터 모델을 심층 분석합니다.

1. 산업별 MDM 특성 비교

각 산업의 MDM 요구사항과 핵심 과제를 비교합니다.

산업 주요 마스터 데이터 핵심 과제 규제 요구사항
금융 고객, 계좌, 상품, 거래상대방 고객 360도 뷰, KYC, AML 바젤III, GDPR, FATCA
유통/리테일 상품, 고객, 공급업체, 매장 옴니채널 일관성, 재고 정확성 PCI-DSS, 소비자보호법
제조 부품, 자재, 공급업체, BOM 공급망 가시성, 품질 추적성 ISO 9001, RoHS, REACH
헬스케어 환자, 의료진, 약품, 장비 환자 안전, 정보 상호운용성 HIPAA, FDA, 의료법
공공 시민, 자산, 인허가, 사업 데이터 공개, 투명성 정보공개법, 개인정보보호법

2. 금융 서비스: 고객 360도 뷰

금융기관은 고객 중심 데이터 통합으로 리스크 관리와 고객 경험을 개선합니다.

사례: 글로벌 투자은행 - 고객 MDM

배경: 전 세계 30개국 지점에서 고객 데이터 중복과 불일치 문제

솔루션:

  • Hub-and-Spoke 아키텍처로 글로벌 고객 MDM 구축
  • 법인 고객 25만 건, 개인 고객 500만 건 통합
  • 실시간 KYC/AML 스크리닝 통합
  • 고객 계층 관리 (Parent-Child Relationships)

성과:

  • 고객 중복 70% 감소
  • KYC 프로세스 시간 60% 단축
  • 규제 보고 정확도 95% → 99.5%
  • 크로스셀 기회 35% 증가

금융 고객 데이터 모델

-- 금융 고객 마스터 스키마
CREATE TABLE customer_master (
    customer_id VARCHAR(50) PRIMARY KEY,
    customer_type VARCHAR(20) NOT NULL,  -- 'INDIVIDUAL', 'CORPORATE'
    legal_name VARCHAR(200) NOT NULL,
    trading_name VARCHAR(200),
    tax_id VARCHAR(50),
    lei_code VARCHAR(20),  -- Legal Entity Identifier

    -- 고객 분류
    customer_segment VARCHAR(50),  -- 'RETAIL', 'WEALTH', 'CORPORATE', 'INSTITUTIONAL'
    risk_rating VARCHAR(20),  -- 'LOW', 'MEDIUM', 'HIGH'
    credit_score INTEGER,

    -- KYC/AML
    kyc_status VARCHAR(20),
    kyc_review_date DATE,
    kyc_next_review_date DATE,
    pep_flag BOOLEAN DEFAULT FALSE,  -- Politically Exposed Person
    sanctions_screening_status VARCHAR(20),
    sanctions_screening_date TIMESTAMP,

    -- 계층 관계
    parent_customer_id VARCHAR(50),
    ultimate_parent_id VARCHAR(50),
    ownership_percentage DECIMAL(5,2),

    -- 감사
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW(),
    created_by VARCHAR(100),
    updated_by VARCHAR(100),
    version INTEGER DEFAULT 1
);

-- 고객 계좌 연결
CREATE TABLE customer_accounts (
    customer_id VARCHAR(50),
    account_id VARCHAR(50),
    account_type VARCHAR(50),  -- 'CHECKING', 'SAVINGS', 'LOAN', 'INVESTMENT'
    account_status VARCHAR(20),
    relationship_type VARCHAR(50),  -- 'PRIMARY', 'JOINT', 'BENEFICIARY'
    opened_date DATE,
    closed_date DATE,
    PRIMARY KEY (customer_id, account_id),
    FOREIGN KEY (customer_id) REFERENCES customer_master(customer_id)
);

-- 고객 관계 (법인 구조)
CREATE TABLE customer_relationships (
    parent_customer_id VARCHAR(50),
    child_customer_id VARCHAR(50),
    relationship_type VARCHAR(50),  -- 'SUBSIDIARY', 'AFFILIATE', 'BRANCH'
    ownership_percentage DECIMAL(5,2),
    effective_from DATE,
    effective_to DATE,
    PRIMARY KEY (parent_customer_id, child_customer_id)
);

금융권 MDM 모범 사례

  • 단일 고객 뷰: 모든 채널의 고객 정보 통합
  • 실시간 스크리닝: 거래 시점에 제재 리스트 확인
  • 계층 관리: 복잡한 기업 구조 추적
  • 데이터 계보: 규제 감사를 위한 완전한 이력
  • 글로벌 표준: LEI, BIC 등 국제 표준 활용

3. 유통/리테일: 상품 마스터 데이터

옴니채널 환경에서 일관된 상품 정보 제공이 핵심입니다.

사례: 글로벌 리테일 체인 - 상품 정보 관리(PIM)

배경: 온라인/오프라인 250개 매장, 10만 개 SKU 관리

솔루션:

  • 클라우드 기반 Product MDM 구축 (AWS)
  • 다국어 상품 설명 관리 (15개 언어)
  • 디지털 자산 관리(DAM) 통합
  • 실시간 재고 동기화
  • 공급업체 포털 연동

성과:

  • 상품 데이터 정확도 78% → 95%
  • 신상품 출시 시간 50% 단축
  • 온라인 반품률 30% 감소
  • 검색 정확도 40% 향상

상품 마스터 데이터 모델

-- 상품 마스터 스키마
CREATE TABLE product_master (
    product_id VARCHAR(50) PRIMARY KEY,
    sku VARCHAR(50) UNIQUE NOT NULL,
    gtin VARCHAR(14),  -- Global Trade Item Number (바코드)
    upc VARCHAR(12),   -- Universal Product Code

    -- 기본 정보
    product_name VARCHAR(200) NOT NULL,
    brand_id VARCHAR(50),
    manufacturer_id VARCHAR(50),
    category_id VARCHAR(50),

    -- 분류 및 속성
    product_type VARCHAR(50),  -- 'FINISHED_GOOD', 'RAW_MATERIAL', 'SERVICE'
    product_status VARCHAR(20),  -- 'ACTIVE', 'DISCONTINUED', 'SEASONAL'

    -- 물리적 속성
    weight_kg DECIMAL(10,3),
    length_cm DECIMAL(10,2),
    width_cm DECIMAL(10,2),
    height_cm DECIMAL(10,2),
    color VARCHAR(50),
    size VARCHAR(20),

    -- 가격 및 세금
    base_price DECIMAL(12,2),
    currency VARCHAR(3),
    tax_class VARCHAR(50),

    -- 재고
    reorder_point INTEGER,
    reorder_quantity INTEGER,
    minimum_stock_level INTEGER,

    -- 공급망
    lead_time_days INTEGER,
    shelf_life_days INTEGER,

    -- 감사
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW(),
    version INTEGER DEFAULT 1
);

-- 상품 다국어 설명
CREATE TABLE product_i18n (

CREATE TABLE product_suppliers (

4. 제조: 부품 및 자재 마스터

제조업은 복잡한 BOM(Bill of Materials)과 공급망 추적성이 핵심입니다.

사례: 자동차 제조사 - 부품 마스터 관리

배경: 200만 개 부품, 글로벌 500개 공급업체 관리

솔루션:

  • SAP MDG (Master Data Governance) 구현
  • 부품 번호 표준화 (PSCM 기준)
  • 공급업체 포털 통합
  • 블록체인 기반 원산지 추적
  • 품질 이력 관리 시스템 연동

성과:

  • 부품 중복 40% 제거
  • 조달 비용 12% 절감
  • 리콜 대응 시간 70% 단축
  • 공급망 가시성 100% 확보

제조 부품 데이터 모델

-- 부품 마스터 스키마
CREATE TABLE part_master (
    part_number VARCHAR(50) PRIMARY KEY,
    part_name VARCHAR(200) NOT NULL,
    part_description TEXT,

    -- 분류
    part_type VARCHAR(50),  -- 'RAW', 'COMPONENT', 'ASSEMBLY', 'FINISHED'
    commodity_code VARCHAR(50),
    hs_code VARCHAR(10),  -- Harmonized System Code (관세)

    -- 기술 사양
    revision VARCHAR(10),
    specification_document VARCHAR(200),
    drawing_number VARCHAR(100),
    unit_of_measure VARCHAR(20),  -- 'EA', 'KG', 'M', 'L'

    -- 물리적 속성
    weight DECIMAL(15,6),
    volume DECIMAL(15,6),
    material VARCHAR(100),
    color VARCHAR(50),
    finish VARCHAR(50),

    -- 공급 정보
    preferred_supplier_id VARCHAR(50),
    make_buy_code CHAR(1),  -- 'M' (Make), 'B' (Buy)
    procurement_type VARCHAR(20),  -- 'STANDARD', 'SPECIAL_ORDER'

    -- 품질 및 규제
    critical_part BOOLEAN DEFAULT FALSE,
    requires_certification BOOLEAN DEFAULT FALSE,
    rohs_compliant BOOLEAN,
    reach_compliant BOOLEAN,
    conflict_minerals_free BOOLEAN,

    -- 비용
    standard_cost DECIMAL(15,2),
    cost_currency VARCHAR(3),

    -- 상태
    lifecycle_status VARCHAR(20),  -- 'PROTOTYPE', 'ACTIVE', 'OBSOLETE'
    phase_in_date DATE,
    phase_out_date DATE,

    -- 감사
    created_at TIMESTAMP DEFAULT NOW(),
    created_by VARCHAR(100),
    updated_at TIMESTAMP DEFAULT NOW(),
    updated_by VARCHAR(100)
);

-- BOM (Bill of Materials)
CREATE TABLE bom (
    parent_part_number VARCHAR(50),
    child_part_number VARCHAR(50),
    sequence_number INTEGER,
    quantity DECIMAL(15,6),
    unit_of_measure VARCHAR(20),
    reference_designator VARCHAR(50),
    find_number INTEGER,
    is_phantom BOOLEAN DEFAULT FALSE,  -- 가상 부품 여부
    effective_from DATE,
    effective_to DATE,
    PRIMARY KEY (parent_part_number, child_part_number, sequence_number)
);

-- 부품-공급업체 관계
CREATE TABLE part_suppliers (
    part_number VARCHAR(50),
    supplier_id VARCHAR(50),
    supplier_part_number VARCHAR(50),
    is_approved BOOLEAN DEFAULT FALSE,
    approval_date DATE,
    unit_price DECIMAL(15,2),
    currency VARCHAR(3),
    lead_time_days INTEGER,
    minimum_order_quantity DECIMAL(15,2),
    quality_rating DECIMAL(3,2),  -- 0.00 ~ 1.00
    PRIMARY KEY (part_number, supplier_id)
);

-- 부품 변경 이력 (ECO - Engineering Change Order)
CREATE TABLE part_change_history (
    eco_number VARCHAR(50) PRIMARY KEY,
    part_number VARCHAR(50),
    change_type VARCHAR(50),  -- 'REVISION', 'OBSOLETE', 'NEW'
    change_description TEXT,
    change_reason TEXT,
    requested_by VARCHAR(100),
    approved_by VARCHAR(100),
    approval_date DATE,
    effective_date DATE,
    old_revision VARCHAR(10),
    new_revision VARCHAR(10)
);

제조 MDM 핵심 요구사항

  • BOM 관리: 다층 부품 구조 추적
  • 변경 관리: ECO/ECN 프로세스 통합
  • 규제 준수: RoHS, REACH, Conflict Minerals
  • 추적성: 로트/시리얼 번호 추적
  • PLM 통합: Product Lifecycle Management 연동

5. 헬스케어: 환자 마스터 인덱스(MPI)

환자 안전과 의료 품질 향상을 위한 정확한 환자 식별이 필수입니다.

사례: 대형 병원 네트워크 - 통합 MPI

배경: 5개 병원, 300만 환자 기록 중복 및 불일치

솔루션:

  • EMPI (Enterprise Master Patient Index) 구축
  • HL7 FHIR 표준 기반 상호운용성
  • 확률적 매칭 알고리즘 (환자명, 생년월일, 주소)
  • 중복 환자 레코드 자동 병합
  • EHR(전자건강기록) 시스템 통합

성과:

  • 환자 식별 정확도 92% → 99.2%
  • 중복 환자 레코드 65% 감소
  • 약물 오류 40% 감소
  • 환자 대기 시간 25% 단축

환자 마스터 데이터 모델

-- 환자 마스터 인덱스 (MPI)
CREATE TABLE patient_master (

    -- 인적 사항
    last_name VARCHAR(100) NOT NULL,

    -- 식별 정보
    ssn VARCHAR(11),  -- 암호화 필요
    drivers_license VARCHAR(50),
    passport_number VARCHAR(50),
    national_id VARCHAR(50),

    -- 인구 통계
    date_of_birth DATE NOT NULL,
    gender VARCHAR(20),  -- 'MALE', 'FEMALE', 'OTHER', 'UNKNOWN'
    ethnicity VARCHAR(50),
    race VARCHAR(50),
    preferred_language VARCHAR(50),
    marital_status VARCHAR(20),

    -- 연락처
    primary_phone VARCHAR(20),
    mobile_phone VARCHAR(20),
    email VARCHAR(100),

    -- 주소
    address_line1 VARCHAR(200),
    address_line2 VARCHAR(200),
    city VARCHAR(100),
    state VARCHAR(50),
    postal_code VARCHAR(20),
    country VARCHAR(50),

    -- 보험 정보
    primary_insurance_id VARCHAR(50),
    secondary_insurance_id VARCHAR(50),

    -- 의료 정보
    primary_care_physician_id VARCHAR(50),
    blood_type VARCHAR(5),
    organ_donor BOOLEAN,

    -- 상태
    patient_status VARCHAR(20),  -- 'ACTIVE', 'INACTIVE', 'DECEASED'

    consent_to_research BOOLEAN DEFAULT FALSE,
    consent_to_marketing BOOLEAN DEFAULT FALSE,
    data_sharing_consent BOOLEAN DEFAULT FALSE,

    -- 감사
    created_at TIMESTAMP DEFAULT NOW(),

6. 공공 부문: 시민 마스터 데이터

공공 서비스의 효율성과 투명성 향상을 위한 시민 데이터 통합입니다.

사례: 광역시 스마트시티 - 시민 통합 데이터

배경: 15개 부서, 300만 시민 정보 분산 관리

솔루션:

  • 클라우드 기반 시민 MDM 플랫폼 구축
  • 주민등록번호 기반 고유 식별
  • 복지, 세무, 민원 시스템 통합
  • 블록체인 기반 인증서 관리
  • 개인정보 자기결정권 포털

성과:

  • 민원 처리 시간 40% 단축
  • 중복 복지 지급 98% 방지
  • 시민 만족도 75% → 88%
  • 행정 비용 연 50억원 절감

시민 마스터 데이터 모델

-- 시민 마스터 레코드
CREATE TABLE citizen_master (
    citizen_id VARCHAR(50) PRIMARY KEY,
    national_id VARCHAR(20) UNIQUE,  -- 주민등록번호 (암호화)

    -- 기본 정보
    last_name VARCHAR(100),
    first_name VARCHAR(100),
    name_hanja VARCHAR(100),  -- 한자 이름
    gender VARCHAR(10),
    date_of_birth DATE,
    place_of_birth VARCHAR(100),
    nationality VARCHAR(50),

    -- 주소 정보 (행정구역 코드)

8. 교훈 및 모범 사례

산업별 MDM 구현 사례에서 얻은 핵심 교훈입니다.

공통 성공 요인:
  • 경영진 후원: C-레벨의 강력한 지원과 예산 확보
  • 단계적 접근: 작게 시작하여 점진적 확대
  • 데이터 거버넌스: 명확한 책임과 권한 정의
  • 사용자 교육: 지속적인 교육과 변화 관리
  • 품질 모니터링: KPI 추적 및 개선 피드백 루프
  • 표준 준수: 산업 표준 및 규제 요구사항 준수
흔한 실패 요인:
  • Big Bang 접근: 전사 동시 구현으로 리스크 증가
  • 기술 중심: 비즈니스 요구사항 무시
  • 데이터 품질 경시: 초기 데이터 정제 소홀
  • 변화 관리 부재: 사용자 저항 대응 미흡
  • ROI 측정 실패: 명확한 가치 입증 부족

9. 요약 및 핵심 포인트

산업별로 MDM 요구사항과 구현 방식이 다르지만, 공통된 원칙과 모범 사례가 존재합니다.

핵심 요약:
  • 금융은 규제 준수와 리스크 관리에 중점
  • 유통은 옴니채널 일관성과 상품 정보 풍부성이 핵심
  • 제조는 BOM 관리와 공급망 추적성이 필수
  • 헬스케어는 환자 안전과 상호운용성이 최우선
  • 공공 부문은 시민 서비스 향상과 투명성이 목표
  • 모든 산업에서 데이터 거버넌스와 품질이 성공의 열쇠
