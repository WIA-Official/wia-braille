제2장: 기술 아키텍처

"좋은 아키텍처는 보이지 않습니다. 학생은 기술이 아닌 학습에 집중합니다."

2.1 WIA 스트리밍 아키텍처 개요

WIA 스트리밍 표준은 4계층 아키텍처를 정의합니다:

┌─────────────────────────────────────────────┐
│  Layer 4: 애플리케이션 계층            │
│  (학습 플랫폼, 플레이어, UI)             │
├─────────────────────────────────────────────┤
│  Layer 3: 전송 계층                    │
│  (HLS, DASH, WebRTC 프로토콜)            │
├─────────────────────────────────────────────┤
│  Layer 2: 처리 계층                    │
│  (인코딩, 트랜스코딩, 패키징)            │
├─────────────────────────────────────────────┤
│  Layer 1: 인프라 계층                  │
│  (CDN, 스토리지, 네트워크)               │
└─────────────────────────────────────────────┘

2.2 Layer 1: 인프라 계층

2.2.1 CDN (Content Delivery Network)

CDN은 전 세계에 분산된 서버 네트워크로, 사용자에게 가장 가까운 서버에서 콘텐츠를 제공합니다.

CDN 구성요소 역할 WIA 요구사항
Origin Server 원본 콘텐츠 저장 99.99% 가용성
Edge Server 캐시된 콘텐츠 제공 50ms 미만 지연
PoP (Point of Presence) 지역별 서버 클러스터 100+ 글로벌 PoP

2.2.2 스토리지 아키텍처

스토리지 계층 구조:

1. Hot Storage (자주 접근)
   💾 SSD 기반
   📍 원본 + 최근 30일 콘텐츠
   ⚡ 1ms 미만 읽기 지연

2. Warm Storage (보통 접근)
   💿 HDD 기반
   📍 최근 1년 콘텐츠
   ⚡ 10ms 미만 읽기 지연

3. Cold Storage (드물게 접근)
   📦 객체 스토리지 (S3, Azure Blob)
   📍 아카이브 콘텐츠
   ⚡ 100ms+ 읽기 지연

2.2.3 네트워크 최적화

  • HTTP/2 — 멀티플렉싱, 헤더 압축
  • HTTP/3 (QUIC) — 저지연, 패킷 손실 복구
  • TCP BBR — 혼잡 제어 알고리즘
  • IPv6 — 확장성, 라우팅 효율성

2.3 Layer 2: 처리 계층

2.3.1 비디오 인코딩 파이프라인

입력 → 인코딩 → 출력

📹 원본 입력:
   - 해상도: 3840×2160 (4K)
   - 프레임율: 60 fps
   - 비트레이트: 50 Mbps
   - 코덱: 원본 (ProRes, DNxHR)

🔄 트랜스코딩 (Adaptive Bitrate Ladder):

   4K:    3840×2160 @ 15 Mbps (H.265)
   1080p: 1920×1080 @ 5 Mbps  (H.264)
   720p:  1280×720  @ 2.5 Mbps (H.264)
   480p:  854×480   @ 1 Mbps   (H.264)
   360p:  640×360   @ 0.5 Mbps (H.264)
   240p:  426×240   @ 0.25 Mbps (H.264)

📦 패키징:
   - HLS: .m3u8 플레이리스트 + .ts 세그먼트
   - DASH: .mpd 매니페스트 + .m4s 세그먼트
   - 세그먼트 길이: 4초 (권장)

2.3.2 코덱 선택 가이드

코덱 장점 단점 권장 용도
H.264 (AVC) 보편적 지원 낮은 압축률 기본 선택
H.265 (HEVC) 50% 대역폭 절감 라이선스 비용 4K 콘텐츠
VP9 무료, 좋은 압축 하드웨어 지원 제한 YouTube, 웹
AV1 최고 압축률 인코딩 느림 미래 준비

2.3.3 적응형 비트레이트 (ABR) 알고리즘

ABR은 네트워크 조건에 따라 자동으로 비디오 품질을 조정합니다.

ABR 결정 프로세스:

1. 대역폭 측정
   ⏱️ 세그먼트 다운로드 시간 추적
   📊 이동 평균 계산 (10초 윈도우)

   측정 대역폭 = 세그먼트 크기 / 다운로드 시간

2. 버퍼 상태 확인
   📦 현재 버퍼: 12초
   🎯 목표 버퍼: 30초
   ⚠️ 임계값: 5초

3. 품질 선택
   IF 버퍼 < 5초:
      → 품질 낮춤 (360p)
   ELSE IF 버퍼 > 30초 AND 대역폭 > 5 Mbps:
      → 품질 높임 (1080p)
   ELSE:
      → 현재 품질 유지 (720p)

4. 부드러운 전환
   🔄 점진적 품질 변경 (한 번에 1단계)
   ⏰ 최소 전환 간격: 10초

2.4 Layer 3: 전송 계층

2.4.1 HLS (HTTP Live Streaming)

Apple이 개발한 HTTP 기반 스트리밍 프로토콜입니다.

속성 값
매니페스트 .m3u8 (UTF-8 텍스트)
세그먼트 .ts (MPEG-2 TS)
지연시간 6-30초 (일반), 2-6초 (LL-HLS)
브라우저 지원 Safari 네이티브, 기타는 hls.js
DRM FairPlay (iOS/Safari)

HLS 매니페스트 예시:

#EXTM3U
#EXT-X-VERSION:3
#EXT-X-STREAM-INF:BANDWIDTH=5000000,RESOLUTION=1920x1080
1080p.m3u8
#EXT-X-STREAM-INF:BANDWIDTH=2500000,RESOLUTION=1280x720
720p.m3u8
#EXT-X-STREAM-INF:BANDWIDTH=1000000,RESOLUTION=854x480
480p.m3u8

2.4.2 DASH (Dynamic Adaptive Streaming over HTTP)

MPEG에서 표준화한 국제 표준 스트리밍 프로토콜입니다.

속성 값
매니페스트 .mpd (XML)
세그먼트 .m4s (fMP4)
표준화 ISO/IEC 23009-1
브라우저 지원 dash.js 라이브러리 사용
DRM Widevine, PlayReady

2.4.3 WebRTC (Web Real-Time Communication)

초저지연 실시간 스트리밍을 위한 P2P 기반 프로토콜입니다.

  • 지연시간 — 0.5초 미만
  • 프로토콜 — UDP, SRTP, DTLS
  • 코덱 — VP8, VP9, H.264
  • 용도 — 화상회의, 실시간 강의
  • 단점 — 확장성 제한 (100명+ 어려움)

2.5 Layer 4: 애플리케이션 계층

2.5.1 비디오 플레이어 아키텍처

플레이어 구성요소:

│  UI 컨트롤 (재생, 일시정지, 볼륨)  │
├─────────────────────────────────────┤
│  자막/캡션 렌더러                   │
├─────────────────────────────────────┤
│  ABR 엔진 (품질 선택)               │
├─────────────────────────────────────┤
│  버퍼 관리                          │
├─────────────────────────────────────┤
│  DRM 모듈                           │
├─────────────────────────────────────┤
│  네트워크 레이어                    │
├─────────────────────────────────────┤
│  미디어 디코더 (하드웨어 가속)     │
└─────────────────────────────────────┘

2.5.2 추천 플레이어 라이브러리

라이브러리 프로토콜 특징
hls.js HLS MSE 기반, 브라우저 광범위 지원
dash.js DASH MPEG 공식, 고급 기능
Video.js HLS, DASH 플러그인 생태계, 커스터마이징
Shaka Player HLS, DASH Google, 강력한 DRM 지원

2.6 확장성 및 성능

2.6.1 동시 접속자 처리

확장 전략:

소규모 (< 100명):
   🖥️ 단일 서버
   💾 로컬 스토리지
   📊 비용: $50-200/월

중규모 (100-10,000명):
   ⚖️ 로드 밸런서
   🌐 CDN (Cloudflare, CloudFront)
   💾 객체 스토리지 (S3)
   📊 비용: $500-5,000/월

대규모 (10,000-100만명+):
   🌍 글로벌 CDN (Akamai, Fastly)
   ⚙️ 자동 확장 (Auto-scaling)
   🔄 멀티-리전 복제
   📊 비용: $10,000-100,000+/월

2.6.2 성능 메트릭

메트릭 우수 양호 개선 필요
시작 시간 < 2초 2-5초 > 5초
버퍼링 비율 < 0.5% 0.5-2% > 2%
비트레이트 안정적 가끔 변동 자주 변동
에러율 < 0.1% 0.1-1% > 1%
