Chapter 6

Security and Privacy

Agricultural data is valuable and sensitive. This chapter covers encryption, authentication, access control, GDPR compliance, and best practices for protecting agricultural data throughout its lifecycle.

The Importance of Agricultural Data Security

Agricultural data has real economic value. Yield data reveals farm productivity. Sensor data shows soil quality. Financial records contain sensitive business information. This data must be protected from unauthorized access, theft, and misuse while remaining accessible to legitimate users.

Threat Landscape

  • Data Theft: Competitors may seek yield data, planting strategies, or supplier relationships.
  • Ransomware: Attackers encrypt farm data and demand payment for decryption keys.
  • Supply Chain Attacks: Compromised sensors or software can inject false data.
  • Privacy Violations: Unauthorized sharing of farm data with third parties.
  • Regulatory Penalties: GDPR and similar regulations impose fines for data breaches.

Encryption

Data in Transit

All WIA-AGRI-020 communications must use encryption to protect data while it travels across networks.

TLS 1.3 for HTTPS:

tls:
  version: 1.3
  ciphers:
    - TLS_AES_256_GCM_SHA384
    - TLS_CHACHA20_POLY1305_SHA256
  verifyPeer: true
  verifyHostname: true
  minimumVersion: 1.2

MQTT with TLS:

client.tls_set(
    ca_certs="/path/to/ca-cert.pem",
    certfile="/path/to/client-cert.pem",
    keyfile="/path/to/client-key.pem",
    tls_version=ssl.PROTOCOL_TLSv1_2
)
client.connect("mqtt.wia-agri.org", 8883, 60)

Data at Rest

Encrypt stored data to protect against server breaches and stolen hardware.

Database Encryption:

  • Transparent Data Encryption (TDE) for SQL databases
  • Encrypted storage volumes for NoSQL databases
  • Application-level encryption for sensitive fields
  • Encrypted backups stored in separate locations

Field-Level Encryption:

const crypto = require('crypto');

class FieldEncryption {
  constructor(key) {
    this.algorithm = 'aes-256-gcm';
    this.key = Buffer.from(key, 'hex');
  }

  encrypt(plaintext) {
    const iv = crypto.randomBytes(16);
    const cipher = crypto.createCipheriv(
      this.algorithm,
      this.key,
      iv
    );

    let encrypted = cipher.update(plaintext, 'utf8', 'hex');
    encrypted += cipher.final('hex');

    const authTag = cipher.getAuthTag();

    return {
      encrypted,
      iv: iv.toString('hex'),
      authTag: authTag.toString('hex')
    };
  }

  decrypt(encrypted, iv, authTag) {
    const decipher = crypto.createDecipheriv(
      this.algorithm,
      this.key,
      Buffer.from(iv, 'hex')
    );

    decipher.setAuthTag(Buffer.from(authTag, 'hex'));

    let decrypted = decipher.update(encrypted, 'hex', 'utf8');
    decrypted += decipher.final('utf8');

    return decrypted;
  }
}

Authentication

API Key Management

API keys must be treated like passwords - never committed to version control, rotated regularly, and revoked when compromised.

Best Practices:

  • Store keys in environment variables or secret management systems
  • Use different keys for development, staging, and production
  • Rotate keys every 90 days
  • Monitor key usage for anomalies
  • Immediately revoke compromised keys

OAuth 2.0

For applications accessing data on behalf of farmers, OAuth 2.0 provides secure delegated access without sharing passwords.

# OAuth Flow
1. Application redirects farmer to authorization server
2. Farmer logs in and grants permissions
3. Authorization server redirects back with authorization code
4. Application exchanges code for access token
5. Application uses token to access WIA-AGRI-020 API

Certificate-Based Authentication

IoT devices use client certificates for mutual TLS authentication:

client.tls_set(
    ca_certs="ca-cert.pem",
    certfile="device-cert.pem",
    keyfile="device-key.pem",
    cert_reqs=ssl.CERT_REQUIRED
)

Authorization and Access Control

Role-Based Access Control (RBAC)

RolePermissionsTypical Users
OwnerFull access, user managementFarm owner
ManagerRead/write data, no adminFarm manager
OperatorSubmit data, limited readEquipment operators
AnalystRead-only accessAgronomists, consultants
AuditorRead audit logsCompliance officers

Attribute-Based Access Control (ABAC)

More granular control based on attributes like data type, field location, or time range:

policy:
  - subject: role=analyst
    resource: dataType=SOIL_SENSOR
    action: read
    conditions:
      - fieldId in ['FIELD-NORTH-01', 'FIELD-SOUTH-02']
      - timestamp > '2025-01-01'
    effect: allow

GDPR and Privacy Compliance

Data Subject Rights

Under GDPR, farmers have specific rights regarding their data:

  • Right to Access: Farmers can request copies of all their data
  • Right to Rectification: Farmers can correct inaccurate data
  • Right to Erasure: Farmers can request data deletion ("right to be forgotten")
  • Right to Portability: Farmers can receive data in machine-readable format
  • Right to Restrict Processing: Farmers can limit how data is used

Data Anonymization

For research and benchmarking, personally identifiable information must be removed:

function anonymize(data) {
  return {
    ...data,
    farmId: hashFarmId(data.farmId),
    location: {
      // Reduce precision to 1km grid
      latitude: Math.round(data.location.latitude * 100) / 100,
      longitude: Math.round(data.location.longitude * 100) / 100
    },
    // Remove all personal identifiers
    owner: undefined,
    contact: undefined
  };
}

Audit Logging

What to Log

  • All data access (read, write, delete)
  • Authentication attempts (success and failure)
  • Permission changes
  • API key creation and revocation
  • Configuration changes
  • Export and sharing operations

Secure Development Practices

Input Validation

Never trust user input. Validate all data before processing:

const Joi = require('joi');

const schema = Joi.object({
  farmId: Joi.string().pattern(/^FARM-\d{4}-\d{3}$/),
  dataType: Joi.string().valid('SOIL_SENSOR', 'WEATHER', 'CROP_HEALTH'),
  readings: Joi.object({
    soilMoisture: Joi.object({
      value: Joi.number().min(0).max(100)
    })
  })
});

const {error, value} = schema.validate(inputData);
if (error) {
  throw new ValidationError(error.details);
}

Dependency Management

  • Regularly update dependencies to patch security vulnerabilities
  • Use automated tools like Dependabot or Snyk
  • Monitor security advisories for libraries you use
  • Pin dependency versions for reproducible builds

  • ✅ All inputs validated and sanitized

  • ✅ Regular security audits conducted

Chapter Summary

Securing agricultural data requires a multi-layered approach: encryption in transit and at rest, strong authentication, granular access control, comprehensive audit logging, and compliance with privacy regulations like GDPR. By following security best practices and implementing defense-in-depth strategies, you can protect valuable agricultural data while enabling authorized access for legitimate use cases.
