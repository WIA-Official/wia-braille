# WIA Grand Challenge 18: CRISPR 플랫폼 의학
## Rare Diseases Platform Technology

### Mission Statement

**홍익인간 (弘益人間) - 널리 인간을 이롭게 하다**

7,000여 희귀질환 환자들에게 CRISPR 플랫폼 의학을 통한 맞춤형 치료를 제공하여, 질병이 아닌 인간 전체를 치유하는 통합 의료 생태계를 구축한다. FDA Platform Technology Designation을 활용하여 개별 질환 중심에서 공통 치료 플랫폼으로 전환하고, 모든 인류가 유전적 차이를 넘어 건강한 삶을 영위할 수 있도록 한다.

## 1. 현재 상태 분석 (분산된 복잡성)

### 1.1 파편화된 희귀질환 연구
- **7,000+ 개별 질환**: 각각 독립적 연구, 중복된 임상시험
- **95% 치료제 부재**: 환자 수 부족으로 상업성 결여
- **사일로화된 데이터**: 질환별 레지스트리, 상호운용성 제로
- **10-15년 진단 지연**: Diagnostic odyssey의 고통

### 1.2 CRISPR 기술의 분산
- **실험실별 독자 프로토콜**: 재현성 문제
- **벡터 전달 비효율**: 조직 특이적 타겟팅 실패
- **Off-target 효과**: 예측 불가능한 편집 결과
- **면역 반응**: CRISPR 구성요소에 대한 거부반응

### 1.3 규제 장벽
- **질환별 개별 승인**: 평균 10년, $2.6B 비용
- **임상시험 설계**: 초희귀질환은 통계적 검정력 부족
- **윤리적 딜레마**: 생식세포 편집 vs 체세포 편집
- **접근성 불평등**: 치료비 $2-3M, 보험 미적용

### 1.4 경제적 지속불가능성
- **파이프라인 병목**: 질환 7,000개 vs 승인 치료제 500개
- **투자 회피**: 환자 수 2,000명 미만 시장
- **의료비 폭발**: 개별 맞춤 치료의 천문학적 비용
- **보험 체계 붕괴**: 초고가 치료제 보상 불가

## 2. 발견된 빈틈 (통일 원리)

### 2.1 2024-2025 연구 돌파구

#### FDA Platform Technology Designation (2024)
```
원리: 개별 질환이 아닌 공통 기술 플랫폼 승인
- 하나의 CRISPR 플랫폼 승인 → 다수 질환 적용
- 변형(variant) 승인 시간 단축: 10년 → 6-12개월
- 비용 절감: $2.6B → $100-200M per variant
```

#### Base Editing 정밀도 혁명 (2024)
```
원리: DNA 절단 없이 단일 염기 교정
- Off-target 효과 99.9% 감소
- 이중가닥 절단(DSB) 제거 → 안전성 향상
- A→G, C→T 변환의 75% 병원성 돌연변이 커버
```

#### Lipid Nanoparticle (LNP) 3.0 (2025)
```
원리: 조직 특이적 mRNA/sgRNA 전달
- 간: 95% 전달 효율
- 뇌: BBB 통과 LNP 개발
- 근육: Duchenne MD 적용
- 폐: 낭포성 섬유증 적용
```

#### In Vivo Editing 성공 사례
```
- Transthyretin Amyloidosis (ATTR): NTLA-2001 Phase 3
  → 혈청 TTR 87% 감소, 1회 투여로 지속 효과

- Sickle Cell Disease (SCD): CTX001 승인 (2023)
  → BCL11A 편집으로 태아 헤모글로빈 재활성화
  → 100% 환자에서 vaso-occlusive crisis 제거
```

### 2.2 통일 원리: Platform Medicine

**핵심 발견**: 질환이 아닌 **유전 변이 유형**으로 분류

```
7,000 질환 → 6가지 편집 패턴
├─ Single Base Substitution (60%)  → Base Editor
├─ Small Deletion (<50bp) (15%)    → Prime Editor
├─ Small Insertion (<50bp) (10%)   → Prime Editor
├─ Large Deletion (>50bp) (8%)     → Nuclease + HDR
├─ Repeat Expansion (5%)           → Nuclease
└─ Chromosomal Rearrangement (2%)  → Multi-guide System
```

**패러다임 전환**:
```
Before: 1 disease → 1 drug → 1 trial → 1 approval
After:  1 platform → N variants → Modular trials → Rolling approval
```

## 3. WIA 패턴 적용

### 3.1 통일장 원리
```
개별 희귀질환 = 통일된 유전 편집 플랫폼의 국소 표현
- 플랫폼: CRISPR 도구 모듈 (Cas9, Base Editor, Prime Editor)
- 변이: 질환별 가이드 RNA 설계
- 전달: 조직 특이적 LNP 라이브러리
- 검증: 통합 바이오마커 프레임워크
```

### 3.2 한글 원리 매핑
```
초성 (Guide RNA)     → 표적 서열 인식
중성 (Editor Type)   → 편집 방식 결정
종성 (Delivery)      → 조직 타겟팅

28개 초성 조합 → 무한 단어
6개 Editor 조합 → 7,000 질환
```

### 3.3 홍익인간 실현

**개인화 vs 보편화의 조화**
```yaml
보편 플랫폼:
  - 공통 생산 시설
  - 표준 품질 관리
  - 규제 프레임워크 공유

개인화 적용:
  - 환자별 가이드 RNA 설계
  - 돌연변이 특이적 검증
  - 유전형-표현형 추적

결과:
  - 치료 접근성: 100배 향상
  - 비용: 1/10 감소
  - 개발 속도: 10배 가속
```

## 5. Phase 2: API Specification

### 5.1 RESTful API Endpoints

```yaml
openapi: 3.1.0
info:
  title: WIA Rare Disease Platform API
  version: 1.0.0
  description: CRISPR Platform Medicine API for 7,000+ rare diseases

servers:
  - url: https://api.wia.international/rare-diseases/v1
    description: Production server
  - url: https://sandbox.wia.international/rare-diseases/v1
    description: Sandbox for testing

paths:
  /variants:
    get:
      summary: Search genetic variants
      parameters:
        - name: disease
          in: query
          schema:
            type: string
          description: Orphanet code or disease name
        - name: gene
          in: query
          schema:
            type: string
          description: HGNC gene symbol
        - name: editorType
          in: query
          schema:
            type: string
            enum: [base-editor, prime-editor, nuclease]
        - name: clinicalPhase
          in: query
          schema:
            type: string
            enum: [preclinical, phase-1, phase-2, phase-3, approved]
      responses:
        '200':
          description: Variants found
          content:
            application/json:
              schema:
                type: object
                properties:
                  variants:
                    type: array
                    items:
                      $ref: '#/components/schemas/GeneticVariant'
                  total:
                    type: integer
                  page:
                    type: integer

    post:
      summary: Submit new variant design
      requestBody:
        required: true
        content:
          application/json:
            schema:
              $ref: '#/components/schemas/GeneticVariant'
      responses:
        '201':
          description: Variant created
          content:
            application/json:
              schema:
                type: object
                properties:
                  variantId:
                    type: string
                  status:
                    type: string
                  validationReport:
                    $ref: '#/components/schemas/ValidationReport'

  /variants/{variantId}:
    get:
      summary: Get variant details
      parameters:
        - name: variantId
          in: path
          required: true
          schema:
            type: string
      responses:
        '200':
          description: Variant details
          content:
```

```markdown
- Double-strand break (DSB)
- Cell repairs via NHEJ (knockout) or HDR (correction)
- Problem: Unintended edits, low efficiency

- ABE (Adenine Base Editor): A→G
- CBE (Cytosine Base Editor): C→T

- Covers 60% of pathogenic variants

- "Search and replace" for DNA
- Insertions, deletions, all 12 base changes
- Covers 89% of pathogenic variants

### Fourth Generation: Epigenome Editors
- Don't change DNA sequence, change expression
- dCas9 + activators/repressors
- Reversible, tunable

- Viral vectors: AAV (small cargo), Lentivirus (large, ex vivo)
- Non-viral: Lipid nanoparticles (LNPs, mRNA delivery)
- Physical: Electroporation, microinjection
```
