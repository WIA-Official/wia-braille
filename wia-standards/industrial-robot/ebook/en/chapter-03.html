⚙️ Chapter 3: Control Systems and Programming

"A robot without programming is just metal and motors. Programming breathes life into the machine."

Mastering robot programming languages and control systems is essential for unlocking the full potential of industrial automation.

3.1 Motion Control Fundamentals

Motion control is the heart of industrial robot operation, determining how the robot moves from one position to another while ensuring safety, efficiency, and precision.

3.1.1 Point-to-Point (PTP) Motion

Point-to-Point (Joint Interpolation) is the fastest motion type where each joint moves independently to reach the target position.

Characteristics:

  • Path: Not controlled (unpredictable in Cartesian space)
  • Speed: Fastest motion type (each joint at maximum safe speed)
  • Accuracy: Only position matters, path does not
  • Typical Use: Moving between widely spaced points without obstacles

Mathematical Model:

For each joint i:
  θᵢ(t) = θᵢ₀ + (θᵢf - θᵢ₀) × s(t)

where s(t) is a smooth profile function (trapezoidal or S-curve)

Velocity Profile Phases:
  1. Acceleration: a(t) = aₘₐₓ
  2. Constant velocity: v(t) = vₘₐₓ
  3. Deceleration: a(t) = -aₘₐₓ

WIA-ROB-003 PTP Command Format:

{
  "command": "MOVE_PTP",
  "target_joint": [45.0, -30.0, 60.0, 0.0, 90.0, 0.0],
  "speed_override": 75,  // percentage of maximum
  "acceleration": 50,    // percentage of maximum
  "blend_radius": 0,     // mm (0 = exact stop)
  "motion_type": "joint_interpolation"
}

3.1.2 Linear Motion

Linear Interpolation (LIN) moves the TCP in a straight line from start to end position.

Characteristics:

  • Path: Straight line in Cartesian space
  • Speed: Constant TCP velocity (joint velocities vary)
  • Accuracy: Path deviation typically <0.1 mm
  • Typical Use: Welding, gluing, precise material handling

Implementation:

1. Divide path into small segments (1-10 mm)
2. For each segment:
   - Compute desired TCP position
   - Solve inverse kinematics
   - Move joints to required positions
3. Interpolation cycle: 1-8 ms (125-1000 Hz)

Speed Specification:

Application Typical Speed Accuracy Required
Arc Welding 5-15 mm/s ±0.5 mm
Gluing/Sealing 50-200 mm/s ±0.2 mm
Material Handling 500-2000 mm/s ±2 mm
Deburring 20-100 mm/s ±0.1 mm

3.1.3 Circular Motion

Circular Interpolation (CIRC) moves the TCP along a circular arc defined by a via point.

Definition:

Circle defined by three points:
  - Start point (current TCP position)
  - Via point (on the arc)
  - End point (final TCP position)

Plane: Determined by these three points
Radius: Calculated automatically

Applications:

  • Rounded corners in material handling
  • Circular welding patterns
  • Painting curved surfaces
  • Polishing circular parts

3.1.4 Trajectory Generation

Velocity Profiles:

Modern robots use smooth acceleration profiles to minimize jerk (rate of change of acceleration), reducing mechanical stress and improving accuracy.

Profile Type Jerk Smoothness Complexity Use Case
Trapezoidal Infinite (steps) Low Simple Non-critical paths
S-Curve (7-segment) Limited High Moderate Standard industrial
Polynomial (5th order) Zero at endpoints Very high High Precision tasks
B-Spline Continuous Highest Very high Complex 3D paths

3.1.5 Blending and Rounding

Zone Blending allows the robot to smoothly transition between path segments without stopping.

Without Blending:
  Point A → [Decel] → [Stop] → [Accel] → Point B
  Time: High | Smoothness: Low | Cycle time: +15-30%

With Blending (CNT/Rounding):
  Point A → [Blend Zone] → Point B
  Time: Low | Smoothness: High | Cycle time: Optimized

Blend Radius Specification:

  • Zone Fine (z0): Exact positioning (0 mm tolerance)
  • Zone 1-10: Small blending (1-10 mm)
  • Zone 20-100: Standard blending (20-100 mm)
  • Zone 200+: Large blending for high-speed paths

Safety Consideration: Blending must ensure the TCP never violates safety zones or collides with obstacles.

3.2.2 WIA Robot Language (WRL)

WIA-ROB-003 defines a vendor-neutral robot programming language to promote interoperability.

WRL Example Program:

// WIA Robot Language (WRL) v1.0
// Pick and Place Application

PROGRAM PickAndPlace

// Variable Declarations
VAR
    homePos: JOINT_POSITION := [0, 0, 0, 0, 0, 0];
    pickPos: CARTESIAN_POSITION := [500, 200, 300, 0, 180, 0];
    placePos: CARTESIAN_POSITION := [500, -200, 300, 0, 180, 0];
    approachOffset: REAL := 100.0;  // mm
    cycleCount: INTEGER := 0;
    maxCycles: INTEGER := 1000;
END_VAR

// Main Program
BEGIN
    // Initialize
    DIGITAL_OUT(1, FALSE);  // Gripper open
    MOVE_JOINT(homePos, speed:=100, accel:=80);
    
    // Main Loop
    WHILE (cycleCount < maxCycles) DO
        // Approach pick position
        MOVE_LINEAR(pickPos + [0, 0, approachOffset, 0, 0, 0], 
                   speed:=500, blend:=10);
        
        // Move to pick position
        MOVE_LINEAR(pickPos, speed:=100, blend:=0);
        
        // Close gripper
        DIGITAL_OUT(1, TRUE);
        WAIT(0.5);  // seconds
        
        // Check grip
        IF (DIGITAL_IN(1) == FALSE) THEN
            ERROR("Grip failed at cycle " + STR(cycleCount));
            GOTO ErrorHandler;
        END_IF;
        
        // Lift part
        MOVE_LINEAR(pickPos + [0, 0, approachOffset, 0, 0, 0], 
                   speed:=300, blend:=20);
        
        // Move to place position
        MOVE_LINEAR(placePos + [0, 0, approachOffset, 0, 0, 0], 
                   speed:=800, blend:=50);
        MOVE_LINEAR(placePos, speed:=100, blend:=0);
        
        // Open gripper
        DIGITAL_OUT(1, FALSE);
        WAIT(0.3);
        
        // Retract
        MOVE_LINEAR(placePos + [0, 0, approachOffset, 0, 0, 0], 
                   speed:=500, blend:=20);
        
        cycleCount := cycleCount + 1;
    END_WHILE;
    
    // Return home
    MOVE_JOINT(homePos, speed:=100, accel:=50);
    
    EXIT;

ErrorHandler:
    // Emergency stop and alarm
    STOP_MOTION();
    ALARM("Pick and place error");
    DIGITAL_OUT(1, FALSE);  // Open gripper
    
END_PROGRAM

Industrial automation standard programming language, widely used for PLC integration.

    Robot.MoveLinear(PickPosition, Speed := 500);

3.3 Path Planning

3.3.1 Collision Avoidance

Static Obstacle Avoidance:

Methods to avoid fixed obstacles in the workspace:

  1. Manual Programming: Programmer defines via points to avoid obstacles
  2. Workspace Zones: Define prohibited regions in Cartesian space
  3. Joint Limits: Software limits restrict certain joint ranges
  4. Geometric Modeling: 3D model of cell checks for collisions

Dynamic Obstacle Avoidance:

  • Vision-Based: Camera systems detect moving objects
  • Sensor-Based: Proximity sensors trigger speed reduction or stop
  • Predictive: Path planning algorithms recalculate paths in real-time

3.3.2 Optimization Algorithms

Rapidly-exploring Random Trees (RRT):

Used for complex path planning in cluttered environments
Advantages: Probabilistically complete, handles high-DOF robots
Disadvantages: Paths not optimal, requires post-processing

Algorithm:
1. Start with initial configuration
2. Sample random configuration in workspace
3. Find nearest node in tree
4. Extend tree towards sample (if collision-free)
5. Repeat until goal reached or max iterations
6. Extract path from tree
7. Smooth path using optimization

A* (A-Star) Planning:

Graph-based search algorithm, guarantees optimal path
Cost function: f(n) = g(n) + h(n)
  g(n) = cost from start to node n
  h(n) = estimated cost from n to goal (heuristic)

Suitable for: Discrete configuration spaces, grid-based maps

3.3.3 Time-Optimal Path Planning

Finding the fastest path given velocity and acceleration limits.

Time Scaling Method:

  1. Define geometric path (independent of time)
  2. Compute maximum velocity along path considering:
    • Joint velocity limits
    • Joint acceleration limits
    • Jerk limits
    • Path curvature
  3. Generate time-optimal velocity profile
  4. Execute path with computed timing

Typical Cycle Time Improvements:

  • Manual programming: Baseline (100%)
  • Basic optimization: 15-20% reduction
  • Advanced time-optimal: 25-35% reduction
  • Dynamic blending: 30-40% reduction

3.4 Teach Pendant and Offline Programming

3.4.1 Teach Pendant Programming

Hand-Held Teach Pendant (HMI):

Traditional method where the programmer manually jogs the robot to desired positions and records them.

Typical Features:

  • 6-axis joystick or directional buttons
  • Touchscreen display (5-12 inches)
  • Program editor with syntax highlighting
  • Variable monitor and debugger
  • I/O status display
  • Emergency stop button
  • Deadman switch (3-position enable device)

Programming Steps:

  1. Enter teach mode (robot at reduced speed, typically 250 mm/s max)
  2. Jog robot to position 1
  3. Record position (creates program instruction)
  4. Repeat for all positions
  5. Add motion commands, I/O operations, logic
  6. Test program at reduced speed
  7. Optimize and run at production speed

Advantages:

  • Intuitive for operators
  • Exact position teaching
  • No offline tools required
  • Easy for simple programs

Disadvantages:

  • Production downtime during programming
  • Safety risks (human in robot workspace)
  • Time-consuming for complex programs
  • Difficult for precise speed/acceleration tuning

3.4.2 Offline Programming (OLP)

3D Simulation Environment:

Programs are created on a PC using CAD data and virtual robot models, then downloaded to the real robot.

Major OLP Software:

Software Vendor Key Features Supported Robots
RobotStudio ABB Virtual controller, realistic simulation ABB (native), others via import
RoboGuide FANUC Integrated vision, welding simulation FANUC (native), others limited
KUKA.Sim KUKA Physics simulation, PLC integration KUKA (native), others via import
Process Simulate Siemens Factory simulation, ergonomics Multi-vendor support
RoboDK RoboDK Inc. Multi-robot, affordable, Python API 50+ robot brands
Visual Components Visual Components Material flow, logistics simulation Multi-vendor, library-based

OLP Workflow:

  1. Import CAD Data: Load part and fixture geometry
  2. Place Robot: Position robot in virtual cell
  3. Define Targets: Create TCP positions from CAD features
  4. Generate Path: Automatic or manual path creation
  5. Optimize: Collision checking, cycle time optimization
  6. Simulate: Virtual execution with timing analysis
  7. Post-Process: Convert to robot-specific language
  8. Download: Transfer program to real robot
  9. Touch-Up: Minor adjustments on real robot (typically <5% of positions)

Benefits:

  • 70-90% reduction in programming time for complex cells
  • No production downtime
  • Collision detection before execution
  • Cycle time optimization
  • Documentation and visualization
  • Reachability analysis before robot purchase

3.4.3 Lead-Through Programming

Modern collaborative robots offer intuitive lead-through (hand-guiding) programming.

Process:

  1. Activate lead-through mode
  2. Physically guide robot arm to positions
  3. Press button to record waypoints
  4. Add logic via graphical interface
  5. Test and run program

Requirements:

  • Force-torque sensors on all joints
  • Gravity compensation algorithms
  • Low-inertia mechanical design
  • Collision detection

Typical for: Universal Robots, Techman, ABB YuMi, FANUC CRX series

3.5 Advanced Control Techniques

3.5.1 Force Control

Impedance Control:

Robot acts as a mechanical impedance (mass-spring-damper) in response to external forces.

Impedance Equation:
F = M(ẍ - ẍd) + D(ẋ - ẋd) + K(x - xd)

where:
  F = external force
  M = virtual mass
  D = virtual damping
  K = virtual stiffness
  x = actual position
  xd = desired position

Applications:

  • Assembly with compliance (peg-in-hole)
  • Polishing and grinding (constant force)
  • Deburring (force-controlled edge following)
  • Human-robot collaboration (safety compliance)

3.5.2 Vision-Guided Control

2D Vision:

  • Part location and orientation
  • Quality inspection
  • Barcode/QR code reading
  • Pick-from-bin with 2D pattern matching

3D Vision:

  • Bin picking with arbitrary orientations
  • Volumetric inspection
  • Palletizing optimization
  • Welding seam tracking

Eye-in-Hand vs. Eye-to-Hand:

Configuration Advantages Disadvantages
Eye-in-Hand (camera on robot) Moves with robot, flexible viewing angles Limited field of view, payload reduction
Eye-to-Hand (fixed camera) Large field of view, no payload penalty Fixed perspective, occlusion issues

3.5.3 Adaptive Control

Machine Learning Integration:

  • Reinforcement Learning: Robot learns optimal picking strategies
  • Neural Networks: Pattern recognition for quality control
  • Predictive Maintenance: Anomaly detection in joint currents/vibrations
  • Process Optimization: Automatic tuning of welding/painting parameters
