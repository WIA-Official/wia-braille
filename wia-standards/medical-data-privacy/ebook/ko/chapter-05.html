데이터 암호화

← 이전 장 목차 다음 장 →
장 개요: 이 장에서는 저장 데이터(data at rest)와 전송 데이터(data in transit) 암호화, 키 관리 전략, 암호화 알고리즘 선택, 그리고 의료 환경에서의 실무 적용 방법을 다룹니다.

암호화의 중요성

암호화는 의료 데이터 보호의 마지막 방어선입니다. 다른 모든 보안 조치가 실패하더라도 암호화된 데이터는 키 없이 읽을 수 없습니다. HIPAA Security Rule과 GDPR 모두 암호화를 강력히 권장하며, 많은 규정에서 사실상 필수 요구사항으로 간주됩니다.

저장 데이터 암호화 (Encryption at Rest)

저장 데이터 암호화는 데이터베이스, 파일 시스템, 백업, 이동식 매체에 저장된 데이터를 보호합니다.

AES (Advanced Encryption Standard)

AES는 의료 데이터 암호화의 사실상 표준입니다:

키 크기 보안 수준 권장 용도
AES-128 높음 일반 PHI
AES-192 매우 높음 민감 PHI
AES-256 최고 고도 민감 데이터, 장기 보관

암호화 모드

  • CBC (Cipher Block Chaining): 널리 사용되나 패딩 오라클 공격에 취약
  • GCM (Galois/Counter Mode): 인증 암호화 제공, 권장
  • XTS: 디스크 전체 암호화에 최적화
AES-256-GCM 암호화 예시 (Python)
from cryptography.hazmat.primitives.ciphers.aead import AESGCM
import os

class MedicalDataEncryption:
    def __init__(self, key: bytes):
        """
        key: 32바이트 (256비트) AES 키
        """
        self.aesgcm = AESGCM(key)

    @staticmethod
    def generate_key() -> bytes:
        """안전한 랜덤 키 생성"""
        return AESGCM.generate_key(bit_length=256)

    def encrypt(self, plaintext: bytes, associated_data: bytes = None) -> tuple:
        """
        데이터 암호화
        
        Args:
            plaintext: 암호화할 데이터
            associated_data: 인증할 추가 데이터 (환자 ID 등)
        
        Returns:
            (nonce, ciphertext) 튜플
        """
        nonce = os.urandom(12)  # 96비트 nonce
        ciphertext = self.aesgcm.encrypt(nonce, plaintext, associated_data)
        return (nonce, ciphertext)

    def decrypt(self, nonce: bytes, ciphertext: bytes, 
                associated_data: bytes = None) -> bytes:
        """데이터 복호화"""
        return self.aesgcm.decrypt(nonce, ciphertext, associated_data)

# 사용 예시
key = MedicalDataEncryption.generate_key()
encryptor = MedicalDataEncryption(key)

# 환자 데이터 암호화
patient_data = b"Patient: John Doe, Diagnosis: Diabetes, HbA1c: 7.2%"
patient_id = b"P-2024-001234"

nonce, ciphertext = encryptor.encrypt(patient_data, associated_data=patient_id)

print(f"Nonce: {nonce.hex()}")
print(f"Ciphertext: {ciphertext.hex()}")

# 복호화
decrypted = encryptor.decrypt(nonce, ciphertext, associated_data=patient_id)
print(f"Decrypted: {decrypted.decode()}")

전송 데이터 암호화 (Encryption in Transit)

네트워크를 통해 전송되는 모든 PHI는 암호화되어야 합니다.

TLS (Transport Layer Security)

TLS는 웹 통신, API 호출, 데이터베이스 연결 등을 보호하는 표준 프로토콜입니다:

버전 상태 권장사항
SSL 2.0/3.0 폐기 사용 금지
TLS 1.0/1.1 폐기 사용 금지 (2020년 이후)
TLS 1.2 허용 최소 요구사항
TLS 1.3 권장 새 시스템에 사용

TLS 1.3의 장점

  • 향상된 보안: 취약한 암호 스위트 제거
  • 빠른 핸드셰이크: 1-RTT, 0-RTT 지원
  • 전방향 보안: 모든 핸드셰이크에서 강제
  • 간소화: 복잡성 감소로 구현 오류 최소화
실무 적용: 웹 서버, 로드 밸런서, API 게이트웨이, 데이터베이스 연결, 내부 마이크로서비스 통신 등 모든 네트워크 통신에 TLS 1.2 이상 적용하세요.

키 관리 전략

암호화 키 관리는 암호화 시스템의 가장 중요하고 어려운 부분입니다. 키가 유출되면 암호화가 무의미해집니다.

키 생명주기

  1. 생성 (Generation):
    • 암호학적으로 안전한 난수 생성기 사용 (CSPRNG)
    • 충분한 엔트로피 확보
    • 키 생성 이벤트 로깅
  2. 배포 (Distribution):
    • 안전한 채널을 통한 키 전송
    • 키 래핑 (Key Wrapping) 사용
    • 대역 외(out-of-band) 검증
  3. 저장 (Storage):
    • HSM (Hardware Security Module) 또는 KMS (Key Management Service) 사용
    • 키는 절대 평문으로 저장하지 않음
    • 마스터 키와 데이터 암호화 키 분리
  4. 사용 (Usage):
    • 최소 권한 원칙
    • 키 사용 감사 로깅
    • 키 분리 (암호화/복호화 키 분리 가능 시)
  5. 순환 (Rotation):
    • 정기적 키 교체 (90-180일)
    • 키 유출 의심 시 즉시 순환
    • 자동화된 순환 프로세스
  6. 폐기 (Destruction):
    • 안전한 키 삭제 프로토콜
    • 복구 불가능한 방식으로 삭제
    • 폐기 기록 유지

키 계층 구조

키 계층 구조 (Envelope Encryption)

                 │ 암호화
                 ▼

데이터베이스 암호화

암호화 수준 선택

수준 장점 단점 적용 예
디스크 암호화 구현 간단, 성능 영향 적음 메모리에서는 평문, DB 관리자 접근 가능 물리적 도난 방지
파일 암호화 개별 파일 보호 파일 시스템 수준 공격 취약 백업 파일
TDE (Transparent Data Encryption) 애플리케이션 변경 불필요, DB 전체 보호 DB 관리자 접근 가능, 세분화 어려움 규정 준수
컬럼 암호화 세분화된 보호, 선택적 암호화 애플리케이션 변경 필요, 성능 영향 민감 필드 (SSN, 진단명)
애플리케이션 암호화 최고 보안, DB 관리자도 접근 불가 복잡한 구현, 큰 성능 영향 고도 민감 데이터

클라우드 환경 암호화

클라우드 서비스 사용 시 암호화는 더욱 중요합니다:

클라우드 암호화 모델

  • 서버측 암호화 (CSP 관리 키):
    • 간편한 구현
    • CSP가 키 관리
    • 규정 준수 제한적
  • 서버측 암호화 (고객 관리 키):
    • 고객이 키 제어
    • KMS 통합 필요
    • 권장 방식
  • 클라이언트측 암호화:
    • 클라우드 업로드 전 암호화
    • 최고 보안
    • 복잡한 구현

AWS KMS 예시

AWS KMS를 사용한 암호화
import boto3
import base64

class AWSKMSEncryption:
    def __init__(self, key_id: str, region: str = 'us-east-1'):
        self.kms_client = boto3.client('kms', region_name=region)
        self.key_id = key_id

    def encrypt(self, plaintext: str, context: dict = None) -> str:
        """
        KMS를 사용하여 데이터 암호화
        
        Args:
            plaintext: 암호화할 데이터
            context: 암호화 컨텍스트 (환자 ID 등)
        
        Returns:
            Base64 인코딩된 암호문
        """
        params = {
            'KeyId': self.key_id,
            'Plaintext': plaintext.encode()
        }
        if context:
            params['EncryptionContext'] = context

        response = self.kms_client.encrypt(**params)
        ciphertext = response['CiphertextBlob']
        return base64.b64encode(ciphertext).decode()

    def decrypt(self, ciphertext_b64: str, context: dict = None) -> str:
        """KMS를 사용하여 데이터 복호화"""
        ciphertext = base64.b64decode(ciphertext_b64)
        
        params = {'CiphertextBlob': ciphertext}
        if context:
            params['EncryptionContext'] = context

        response = self.kms_client.decrypt(**params)
        return response['Plaintext'].decode()

# 사용 예시
kms_enc = AWSKMSEncryption(key_id='arn:aws:kms:us-east-1:123456789:key/...')

patient_data = "Patient: Jane Doe, Blood Type: O+, Allergies: Penicillin"
encryption_context = {
    'PatientID': 'P-2024-567890',
    'Department': 'Cardiology'
}

# 암호화
encrypted = kms_enc.encrypt(patient_data, context=encryption_context)
print(f"Encrypted: {encrypted}")

# 복호화 (동일한 컨텍스트 필요)
decrypted = kms_enc.decrypt(encrypted, context=encryption_context)
print(f"Decrypted: {decrypted}")

암호화 모범 사례

  1. 심층 방어: 여러 계층에서 암호화 적용 (디스크, 파일, 컬럼, 전송)
  2. 강력한 알고리즘: AES-256, RSA-2048 이상 사용
  3. 키 분리: 암호화 키와 데이터를 다른 위치에 저장
  4. 정기 순환: 암호화 키 정기적 교체
  5. HSM/KMS 사용: 전문 키 관리 솔루션 활용
  6. 전송 암호화: 모든 네트워크 통신에 TLS 1.2+ 적용
  7. 백업 암호화: 백업 데이터도 암호화
  8. 이동식 매체: USB, 노트북 등 전체 디스크 암호화
  9. 폐기 프로토콜: 하드웨어 폐기 시 암호학적 삭제
  10. 성능 테스트: 암호화로 인한 성능 영향 평가 및 최적화

암호화 성능 최적화

  • 하드웨어 가속: AES-NI 등 CPU 암호화 명령어 활용
  • 비동기 처리: 암호화 작업을 백그라운드 스레드에서 수행
  • 캐싱: 복호화된 데이터를 메모리에 일시 캐싱 (보안 고려)
  • 배치 처리: 대량 데이터 암호화 시 배치로 처리
  • 선택적 암호화: 모든 데이터가 아닌 민감 데이터만 암호화

결론

암호화는 의료 데이터 보호의 필수 요소입니다. 적절한 암호화 알고리즘 선택, 안전한 키 관리, 그리고 저장 및 전송 데이터 모두에 대한 암호화 적용이 중요합니다. 클라우드 환경에서는 고객 관리 키를 사용하여 데이터 통제권을 유지하세요.
