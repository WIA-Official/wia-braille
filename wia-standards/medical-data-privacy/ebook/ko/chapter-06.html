장 개요: 이 장에서는 역할 기반 접근 제어(RBAC), 속성 기반 접근 제어(ABAC), 다중 인증(MFA), 최소 권한 원칙, 그리고 의료 환경에 적합한 인증 메커니즘을 다룹니다.

접근 제어의 중요성

접근 제어(Access Control)는 누가 무엇에 접근할 수 있는지를 결정하는 보안의 핵심 요소입니다. 의료 환경에서는 환자 프라이버시 보호와 업무 효율성 사이의 균형을 맞추는 것이 중요합니다.

접근 제어 모델

1. 역할 기반 접근 제어 (RBAC)

RBAC는 사용자의 역할에 따라 권한을 부여하는 가장 일반적인 접근 제어 모델입니다. 의료 기관의 조직 구조와 잘 맞아 널리 사용됩니다.

역할 권한 접근 범위
의사 읽기, 쓰기, 수정 담당 환자 전체 기록
간호사 읽기, 제한적 쓰기 담당 병동 환자 간호 기록
약사 읽기 (처방, 알레르기) 처방전 관련 정보만
방사선 기사 읽기, 영상 업로드 영상 검사 관련 정보
청구 담당자 읽기 (진단, 시술 코드) 청구 관련 정보만
환자 읽기 (자신의 기록) 본인 의료 기록 전체
연구원 읽기 (비식별화 데이터) IRB 승인 프로젝트 데이터
RBAC 구현 예시 (TypeScript)
interface Permission {
  resource: string;
  actions: ('read' | 'write' | 'update' | 'delete')[];
}

interface Role {
  name: string;
  permissions: Permission[];
}

class RBACService {
  private roles: Map = new Map();

  defineRole(role: Role): void {
    this.roles.set(role.name, role);
  }

  hasPermission(
    roleName: string,
    resource: string,
    action: string
  ): boolean {
    const role = this.roles.get(roleName);
    if (!role) return false;

    return role.permissions.some(
      p => p.resource === resource && p.actions.includes(action as any)
    );
  }
}

// 역할 정의
const rbac = new RBACService();

rbac.defineRole({
  name: 'physician',
  permissions: [
    { resource: 'patient_records', actions: ['read', 'write', 'update'] },
    { resource: 'prescriptions', actions: ['read', 'write', 'update', 'delete'] },
    { resource: 'lab_results', actions: ['read'] },
    { resource: 'imaging', actions: ['read'] }
  ]
});

rbac.defineRole({
  name: 'nurse',
  permissions: [
    { resource: 'patient_records', actions: ['read', 'update'] },
    { resource: 'vital_signs', actions: ['read', 'write', 'update'] },
    { resource: 'nursing_notes', actions: ['read', 'write', 'update'] }
  ]
});

rbac.defineRole({
  name: 'pharmacist',
  permissions: [
    { resource: 'prescriptions', actions: ['read', 'update'] },
    { resource: 'patient_allergies', actions: ['read'] },
    { resource: 'medication_history', actions: ['read'] }
  ]
});

// 권한 확인
console.log(rbac.hasPermission('physician', 'prescriptions', 'write'));  // true
console.log(rbac.hasPermission('nurse', 'prescriptions', 'write'));      // false
console.log(rbac.hasPermission('pharmacist', 'prescriptions', 'read'));  // true

2. 속성 기반 접근 제어 (ABAC)

ABAC는 사용자, 리소스, 환경의 속성을 기반으로 동적으로 접근 권한을 결정합니다. RBAC보다 더 세밀한 제어가 가능합니다.

ABAC 속성 예시

  • 사용자 속성: 역할, 부서, 자격증, 근무 시간
  • 리소스 속성: 데이터 민감도, 환자 ID, 생성일
  • 환경 속성: 시간, 위치, IP 주소, 디바이스 유형
  • 관계 속성: 담당 의사 여부, 진료 팀 소속
ABAC 정책 예시 (XACML 스타일)
{
  "policy": "EmergencyAccess",
  "description": "응급 상황에서 의사는 모든 환자 기록 접근 가능",
  "target": {
    "subject": { "role": "physician" },
    "resource": { "type": "patient_record" },
    "environment": { "emergencyMode": true }
  },
  "rule": {
    "effect": "permit",
    "condition": "true"
  }
}

{
  "policy": "PrimaryCareAccess",
  "description": "주치의는 담당 환자의 전체 기록 접근 가능",
  "target": {
    "subject": { "role": "physician" },
    "resource": { "type": "patient_record" }
  },
  "rule": {
    "effect": "permit",
    "condition": "subject.id === resource.primaryPhysicianId"
  }
}

{
  "policy": "BusinessHoursOnly",
  "description": "청구 담당자는 업무 시간에만 접근 가능",
  "target": {
    "subject": { "role": "billing_staff" },
    "resource": { "type": "patient_record" }
  },
  "rule": {
    "effect": "permit",
    "condition": "environment.time >= '08:00' AND environment.time <= '18:00' AND environment.weekday IN ['Mon','Tue','Wed','Thu','Fri']"
  }
}

{
  "policy": "MentalHealthRestriction",
  "description": "정신건강 기록은 해당 전문의만 접근 가능",
  "target": {
    "subject": { "role": "physician" },
    "resource": { 
      "type": "patient_record",
      "category": "mental_health"
    }
  },
  "rule": {
    "effect": "permit",
    "condition": "subject.specialty === 'psychiatry' OR subject.specialty === 'psychology'"
  }
}

인증 메커니즘

다중 인증 (MFA)

MFA는 두 가지 이상의 인증 요소를 요구하여 보안을 크게 강화합니다. HIPAA와 GDPR 모두 MFA를 강력히 권장합니다.

인증 요소 3가지 유형

  1. 알고 있는 것 (Knowledge): 비밀번호, PIN, 보안 질문
  2. 가지고 있는 것 (Possession): 스마트폰, 하드웨어 토큰, 스마트카드
  3. 본인 자체 (Inherence): 지문, 얼굴, 홍채, 음성
MFA 방법 보안 수준 사용자 편의성 비용 권장 용도
SMS OTP 중간 높음 낮음 환자 포털
인증 앱 (TOTP) 높음 중간 낮음 의료진, 직원
하드웨어 토큰 매우 높음 중간 높음 관리자, 특권 계정
생체 인식 높음 매우 높음 높음 빠른 접근이 필요한 환경
푸시 알림 높음 매우 높음 낮음 모바일 워크플로
FIDO2/WebAuthn 매우 높음 높음 중간 차세대 표준

싱글 사인온 (SSO)

SSO는 하나의 인증으로 여러 시스템에 접근할 수 있게 하여 사용자 편의성을 높이고 보안을 강화합니다.

SSO 프로토콜

  • SAML 2.0: 엔터프라이즈 환경에서 가장 널리 사용
  • OAuth 2.0: API 인증 및 권한 부여에 적합
  • OpenID Connect: OAuth 2.0 위에 구축된 ID 계층

최소 권한 원칙

최소 권한 원칙(Principle of Least Privilege)은 사용자에게 업무 수행에 필요한 최소한의 권한만 부여하는 것입니다.

구현 전략

  1. 기본 거부: 명시적으로 허용하지 않은 모든 접근 차단
  2. 역할 최소화: 필요한 최소 권한만 포함하는 세분화된 역할
  3. 임시 권한: 특정 작업을 위한 일시적 권한 상승
  4. 정기 검토: 분기별 권한 재검토 및 조정
  5. 자동 철회: 미사용 권한 자동 제거
Break-glass 메커니즘: 응급 상황에서 일시적으로 모든 접근 권한을 부여하되, 모든 활동을 상세히 기록하고 사후 검토하는 시스템을 구현하세요.

접근 제어 정책 예시

종합 접근 제어 정책
# 의료 정보 시스템 접근 제어 정책

## 1. 인증 요구사항

### 1.1 비밀번호 정책
- 최소 12자 이상
- 대소문자, 숫자, 특수문자 포함
- 과거 12개 비밀번호 재사용 금지
- 90일마다 변경
- 5회 실패 시 계정 잠금 (30분)

### 1.2 다중 인증 (MFA)
- 모든 의료진: TOTP 앱 또는 하드웨어 토큰
- 관리자: 하드웨어 토큰 필수
- 원격 접속: MFA 필수
- 환자 포털: SMS OTP 또는 인증 앱

### 1.3 세션 관리
- 업무용 워크스테이션: 15분 비활동 시 자동 잠금
- 환자 포털: 30분 세션 타임아웃
- 관리자 콘솔: 10분 세션 타임아웃
- 원격 접속: 세션당 재인증

## 2. 역할 기반 접근 제어

### 2.1 의사
- 담당 환자 전체 기록: 읽기, 쓰기, 수정
- 타 환자 기록: 진료 의뢰 시만 읽기
- 처방: 생성, 수정, 취소
- 검사 오더: 생성, 수정

### 2.2 간호사
- 담당 병동 환자: 읽기, 간호 기록 작성
- 바이탈 사인: 입력, 수정
- 투약 기록: 입력, 확인
- 처방: 읽기 전용

### 2.3 약사
- 처방전: 읽기, 조제 확인
- 환자 알레르기: 읽기, 업데이트
- 약물 이력: 읽기, 상호작용 확인
- 진단명: 읽기 전용

### 2.4 환자
- 본인 의료 기록: 읽기
- 검사 결과: 읽기 (의사 승인 후)
- 처방 내역: 읽기
- 예약: 읽기, 수정, 취소

## 3. 특수 데이터 보호

### 3.1 정신 건강 기록
- 정신과 전문의만 접근
- 명시적 환자 동의 필요
- 별도 감사 로그

### 3.2 약물 중독 치료 기록
- 치료 팀만 접근
- 연방법 준수 (42 CFR Part 2)
- 공개 시 법적 승인 필요

### 3.3 HIV/AIDS 관련 정보
- 감염내과 전문의 및 담당 의사
- 주법에 따른 추가 보호
- 환자 명시적 서면 동의

### 3.4 유전 정보
- 유전 상담사 및 해당 전문의
- GINA 규정 준수
- 보험사 접근 금지

## 4. 환경 기반 제어

### 4.1 위치 기반
- 병원 내부: 전체 접근
- VPN 연결: 읽기 전용
- 공용 네트워크: 차단

### 4.2 시간 기반
- 청구 담당자: 08:00-18:00, 평일
- 시스템 관리자: 24/7
- 연구원: 승인된 시간대

### 4.3 디바이스 기반
- 병원 워크스테이션: 전체 접근
- 개인 모바일: 제한적 접근
- 미등록 디바이스: 차단

## 5. 감사 및 모니터링

### 5.1 로깅 필수 이벤트
- 모든 PHI 접근 (읽기 포함)
- 인증 성공/실패
- 권한 변경
- 시스템 설정 수정
- 데이터 다운로드/출력

### 5.2 실시간 경고
- 비정상 접근 패턴
- 대량 데이터 다운로드
- 근무 시간 외 접근
- 타 부서 환자 기록 접근
- 반복 인증 실패

### 5.3 정기 검토
- 일간: 고위험 활동 검토
- 주간: 접근 패턴 분석
- 월간: 권한 검토
- 분기별: 종합 감사

## 6. 예외 처리

### 6.1 Break-glass (응급 접근)
- 승인자: 당직 책임자
- 사유: 생명 위협 상황
- 기록: 모든 활동 상세 로그
- 사후 검토: 24시간 이내

### 6.2 임시 권한 상승
- 요청 프로세스: 티켓 시스템
- 승인자: 직속 상사 + 보안 담당자
- 기간: 최대 24시간
- 자동 철회: 기간 만료 시

## 7. 벌칙

### 7.1 위반 수준
- Level 1 (경미): 경고
- Level 2 (중간): 30일 접근 정지
- Level 3 (심각): 해고, 법적 조치

### 7.2 위반 예시
- Level 1: 세션 잠금 미이행, 비밀번호 공유
- Level 2: 불필요한 환자 기록 조회, 권한 오용
- Level 3: PHI 무단 다운로드/유출, 악의적 접근

접근 제어 모범 사례

  1. 계층화된 방어: 네트워크, 애플리케이션, 데이터 수준에서 모두 접근 제어 적용
  2. 동적 접근 제어: 컨텍스트(위치, 시간, 디바이스)를 고려한 적응형 제어
  3. 정기 감사: 권한 및 접근 로그 정기 검토
  4. 자동화: 입사/이동/퇴사 시 권한 자동 부여/변경/철회
  5. 교육: 접근 제어 정책 및 중요성에 대한 정기 교육
  6. 테스트: 침투 테스트로 접근 제어 취약점 발견
  7. Zero Trust: 모든 접근 요청을 검증하는 Zero Trust 모델 도입

결론

효과적인 접근 제어는 의료 데이터 보호의 핵심입니다. RBAC와 ABAC를 조합하고, 강력한 인증(MFA), 최소 권한 원칙, 그리고 지속적인 모니터링을 통해 환자 프라이버시를 보호하면서도 의료진의 업무 효율성을 유지할 수 있습니다.
