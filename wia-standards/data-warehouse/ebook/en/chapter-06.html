Chapter 6

Slowly Changing Dimensions (SCD)

6.1 The Challenge of Changing Dimensions

Dimension attributes change over time. A customer moves to a new city, a product changes categories, or an employee gets promoted. How should we handle these changes while preserving analytical accuracy?

6.2 SCD Type 0: Retain Original

The simplest approach: never change dimension values. Once set, attributes remain fixed forever.

  • Use case: Immutable attributes like birth date
  • Pros: Simple, no historical tracking needed
  • Cons: Cannot reflect reality when changes occur

6.3 SCD Type 1: Overwrite

Replace old values with new ones, maintaining no history. 

-- Before
customer_id | name | city
123        | John | Boston

-- After update
customer_id | name | city
123        | John | Seattle
  • Use case: Correcting errors, unimportant changes
  • Pros: Simple, no storage overhead
  • Cons: Historical data lost forever

6.4 SCD Type 2: Add New Row

The most common approach. Create a new row for each change, preserving full history. 

customer_key | customer_id | name | city    | effective_date | expiration_date | is_current
1           | 123        | John | Boston  | 2023-01-01    | 2024-12-31     | false
2           | 123        | John | Seattle | 2025-01-01    | 9999-12-31     | true
  • Use case: Tracking important historical changes
  • Pros: Complete history, accurate point-in-time analysis
  • Cons: Storage overhead, more complex queries

6.5 SCD Type 3: Add New Column

Track limited history by adding columns for previous values. 

customer_id | name | current_city | previous_city | city_change_date
123        | John | Seattle     | Boston       | 2025-01-01
  • Use case: Tracking one or two previous values
  • Pros: No new rows, simpler queries
  • Cons: Limited history, schema changes needed

6.6 SCD Type 4: History Table

Maintain current data in the main table and historical data in a separate history table.

6.7 SCD Type 6: Hybrid (1+2+3)

Combines Types 1, 2, and 3 to track both current and historical values.

6.8 Implementation Best Practices

💡 SCD Guidelines

  • Use Type 2 for most business-critical dimensions
  • Use Type 1 for error corrections and insignificant changes
  • Always include effective_date and is_current flag for Type 2
  • Use surrogate keys to handle Type 2 properly
  • Consider performance impact of large Type 2 dimensions
