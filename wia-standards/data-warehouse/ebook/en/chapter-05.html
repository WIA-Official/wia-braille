Chapter 5

Fact Tables and Dimension Tables

5.1 Understanding Fact Tables

Fact tables store the measurable, quantitative data about business events. They are typically tall and narrow, containing millions or billions of rows with relatively few columns.

Fact Table Characteristics

  • Large volume: Most rows in the warehouse
  • Foreign keys: References to dimension tables
  • Measures: Numeric, additive facts
  • Grain: Defines the level of detail

Types of Facts

Type Description Example
Additive Can be summed across all dimensions Sales amount, quantity sold
Semi-Additive Can be summed across some dimensions Account balance, inventory level
Non-Additive Cannot be summed Ratios, percentages, averages

5.2 Understanding Dimension Tables

Dimension tables provide descriptive context for facts. They are typically wide with many columns and relatively few rows compared to fact tables.

Dimension Table Characteristics

  • Descriptive attributes: Rich textual information
  • Primary key: Surrogate key (typically integer)
  • Natural key: Business identifier
  • Hierarchies: Roll-up paths for aggregation

5.3 Common Dimension Types

Date/Time Dimension

The most universal dimension, providing temporal context for all facts. 

CREATE TABLE dim_date (
    date_key INT PRIMARY KEY,
    full_date DATE,
    day_of_week VARCHAR(10),
    day_of_month INT,
    month INT,
    month_name VARCHAR(10),
    quarter INT,
    year INT,
    is_weekend BOOLEAN,
    is_holiday BOOLEAN,
    fiscal_year INT,
    fiscal_quarter INT
);

Customer Dimension

Contains demographic and geographic information about customers.

Product Dimension

Describes products with categories, brands, and hierarchies.

5.4 Fact Table Design Patterns

Transaction Fact Table

Records individual business events at their atomic grain.

Periodic Snapshot Fact Table

Captures the state of things at regular intervals (daily, weekly, monthly).

Accumulating Snapshot Fact Table

Tracks the progress of events through defined stages with multiple dates.

5.5 Best Practices

💡 Design Guidelines

  • Use surrogate keys for all dimensions
  • Keep fact tables narrow with only necessary measures
  • Add descriptive attributes to dimensions, not facts
  • Define grain carefully and consistently
  • Create degenerate dimensions when needed
  • Use role-playing dimensions to avoid duplication
