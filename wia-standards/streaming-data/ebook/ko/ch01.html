제1장: 스트리밍 데이터 개요 및 특성

1.1 스트리밍 데이터의 정의와 중요성

스트리밍 데이터는 다양한 소스에서 연속적으로 생성되는 데이터를 의미하며, 센서, 애플리케이션, 디바이스, 시스템 등에서 끊임없이 발생합니다. 전통적인 배치 처리와 달리, 스트리밍 데이터는 데이터가 도착하는 즉시 증분적으로 처리되어 즉각적인 인사이트와 행동을 가능하게 합니다.

핵심 원칙: 데이터를 저장하고 나중에 처리하는 것이 아니라, 이동 중인 데이터를 처리합니다. 배치 처리 윈도우를 기다리지 않고 이벤트가 발생할 때 분석하여 실시간 의사결정을 가능하게 합니다.

1.2 데이터 처리의 진화

컴퓨팅 초기에는 데이터 처리가 주로 배치 지향적이었습니다. 조직은 하루, 주, 월 단위로 데이터를 누적한 후 사용량이 적은 시간에 대량으로 처리했습니다. 이 방식은 과거 보고와 분석에는 효과적이었지만 실시간 인사이트가 필요한 경우에는 부족했습니다.

디지털 트랜스포메이션, 연결된 디바이스의 확산, 소셜 미디어, IoT 센서의 등장으로 지속적으로 생성되는 데이터가 폭발적으로 증가했습니다. 이러한 변화는 데이터를 처리하고 생각하는 방식의 근본적인 변화를 요구했습니다.

1.3 스트리밍 데이터의 5V 특성

특성 정의 스트리밍 데이터에서의 의미 실제 예시
속도 (Velocity) 데이터 생성 속도 초당 수천~수백만 이벤트 처리 증권 거래소: 초당 10,000+ 거래
볼륨 (Volume) 데이터 양 확장 가능한 처리 인프라 필요 IoT 센서: 일일 테라바이트급
다양성 (Variety) 데이터 타입 다양한 형식과 스키마 JSON, Avro, Protobuf, 바이너리
변동성 (Volatility) 유효 기간 빠른 처리 필요 플래시 세일: 분, 센서: 초
정확성 (Veracity) 데이터 품질 실시간 검증 및 정제 누락값, 이상치 처리

1.4 배치 처리 vs 스트림 처리 상세 비교

측면 배치 처리 스트림 처리 하이브리드 접근
데이터 범위 전체 또는 대부분의 데이터 시간 윈도우 내 데이터 두 방식 결합 (Lambda)
지연시간 분~시간 밀리초~초 실시간 + 배치 조정
복잡도 낮음 높음 (상태, 윈도우) 매우 높음
리소스 사용 주기적 피크 지속적 소비 두 패턴 모두
정확성 높음 (완전한 데이터) 근사값 (윈도우 내) 최종 일관성

1.5 스트리밍 데이터 파이프라인 구조

1.5.1 데이터 생성 계층

다양한 소스에서 이벤트를 지속적으로 생성:

  • 웹 애플리케이션: 사용자 클릭, 페이지 뷰, 세션 데이터
  • 모바일 앱: 앱 이벤트, 위치 데이터, 푸시 알림
  • IoT 디바이스: 센서 측정값, 상태 변경, 경고
  • 마이크로서비스: API 호출, 비즈니스 이벤트, 상태 변경
  • 데이터베이스: CDC (Change Data Capture) 이벤트

// Kafka Producer 설정 예제
import { Kafka } from 'kafkajs';

const kafka = new Kafka({
    clientId: 'event-producer',
    brokers: ['kafka1:9092', 'kafka2:9092', 'kafka3:9092'],
    retry: {
        retries: 5,
        initialRetryTime: 300
    }
});

const producer = kafka.producer({
    allowAutoTopicCreation: true,
    transactionalId: 'event-producer-1',
    maxInFlightRequests: 5,
    idempotent: true  // 정확히 한 번 전송 보장
});

async function sendEvent(eventType, data) {
    await producer.connect();
    
    const message = {
        key: data.userId,
        value: JSON.stringify({
            eventType,
            data,
            timestamp: new Date().toISOString(),
            version: '1.0'
        }),
        headers: {
            'correlation-id': generateCorrelationId(),
            'source': 'web-app',
            'content-type': 'application/json'
        }
    };

    await producer.send({
        topic: 'user-events',
        messages: [message],
        compression: 1  // GZIP 압축
    });
}

// 사용 예
await sendEvent('page_view', {
    userId: 'user-123',
    page: '/products',
    sessionId: 'session-456'
});

1.5.4 스트림 처리 계층

// Kafka Streams를 사용한 처리 예제
const { KafkaStreams } = require('kafka-streams');

const config = {
    kafkaHost: 'localhost:9092',
    groupId: 'stream-processor',
    workerPerPartition: 1,
    options: {
        sessionTimeout: 10000
    }
};

const kafkaStreams = new KafkaStreams(config);

const stream = kafkaStreams.getKStream('user-events');

stream
    // 필터링: 금액이 1000 이상인 거래만
    .filter(event => event.amount > 1000)
    
    // 변환: 사용자 데이터로 보강
    .map(event => {
        return {
            ...event,
            userData: getUserData(event.userId),
            processedAt: new Date().toISOString()
        };
    })
    
    // 키별 그룹화
    .keyBy(event => event.userId)
    
    // 5분 윈도우 집계
    .window({
        windowType: 'tumbling',
        windowSize: 300000  // 5분
    })
    .aggregate((acc, event) => {
        return {
            userId: event.userId,
            count: (acc.count || 0) + 1,
            totalAmount: (acc.totalAmount || 0) + event.amount,
            avgAmount: ((acc.totalAmount || 0) + event.amount) / ((acc.count || 0) + 1)
        };
    })
    
    // 이상 거래 탐지
    .filter(agg => agg.count > 10)
    
    // 알림 전송
    .forEach(agg => {
        sendAlert({
            userId: agg.userId,
            message: `의심스러운 활동 탐지: ${agg.count}건의 거래`,
            totalAmount: agg.totalAmount
        });
    });

stream.start();

1.6.2 사기 탐지 시스템

// 실시간 사기 탐지 예제
class FraudDetector {
    constructor() {
        this.riskScorer = new RiskScorer();
        this.alertService = new AlertService();
    }

    async detectFraud(transaction) {
        // 여러 규칙 기반 검사
        const checks = {
            amountAnomaly: this.checkAmountAnomaly(transaction),
            locationAnomaly: this.checkLocationAnomaly(transaction),
            velocityCheck: this.checkTransactionVelocity(transaction),
            deviceFingerprint: this.checkDeviceFingerprint(transaction),
            merchantRisk: this.checkMerchantRisk(transaction)
        };

        // 위험 점수 계산
        const riskScore = this.riskScorer.calculate(checks);

        // 임계값 기반 조치
        if (riskScore > 0.9) {
            // 높은 위험: 즉시 차단
            await this.blockTransaction(transaction);
            await this.alertService.sendUrgent(transaction, riskScore);
        } else if (riskScore > 0.7) {
            // 중간 위험: 추가 검증 요청
            await this.requestAdditionalVerification(transaction);
        } else if (riskScore > 0.5) {
            // 낮은 위험: 모니터링
            await this.flagForReview(transaction);
        }

        return { riskScore, checks };
    }

    checkTransactionVelocity(transaction) {
        // 최근 5분간 거래 횟수 확인
        const recentTransactions = this.getRecentTransactions(
            transaction.userId,
            Date.now() - 300000
        );

        return recentTransactions.length > 10 ? 0.8 : 0.2;
    }
}
