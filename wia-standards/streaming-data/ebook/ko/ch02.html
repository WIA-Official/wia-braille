제2장: 스트리밍 아키텍처 패턴

개요

스트리밍 데이터 처리 시스템을 설계할 때는 비즈니스 요구사항, 데이터 특성, 확장성 요구사항을 고려한 적절한 아키텍처 패턴 선택이 중요합니다. 이 장에서는 Lambda, Kappa, 하이브리드 아키텍처를 포함한 검증된 스트리밍 아키텍처 패턴들을 심층적으로 분석하고, 각 패턴의 장단점, 적용 시나리오, 구현 전략을 다룹니다.

Lambda 아키텍처

Lambda 아키텍처는 Nathan Marz가 제안한 빅데이터 처리 아키텍처로, 배치 처리와 스트림 처리를 결합하여 정확성과 저지연을 동시에 달성합니다.

Lambda 아키텍처 구조

// Lambda 아키텍처 전체 구조
데이터 소스 (API, IoT, 로그)
    ↓
메시지 큐 / 이벤트 버스 (Kafka)
    ↓
    ├────────────────────┬────────────────────┐
    ↓                    ↓                    ↓
배치 레이어          스피드 레이어         서빙 레이어
(Hadoop/Spark)      (Flink/Storm)        (HBase/Cassandra)
    ↓                    ↓                    ↓
마스터 데이터셋      실시간 뷰            통합 뷰 제공
(HDFS/S3)           (최근 데이터)         (쿼리 API)
    ↓                    ↓                    ↓
배치 뷰 ─────────────→ 서빙 레이어 ←───────  실시간 뷰
(사전 계산된 뷰)                         (최신 데이터)
                         ↓
                    애플리케이션
                (대시보드, API, 분석)

// 특징:
// - 배치 레이어: 완전하고 정확한 데이터 처리
// - 스피드 레이어: 최근 데이터의 빠른 처리
// - 서빙 레이어: 두 결과를 통합하여 제공

Lambda 아키텍처의 세 가지 레이어

레이어역할기술 스택처리 시간정확도
배치 레이어마스터 데이터셋 저장 및 배치 뷰 생성Hadoop, Spark, Hive시간~일매우 높음
스피드 레이어실시간 증분 처리Flink, Storm, Kafka Streams초~분높음
서빙 레이어쿼리 응답 및 뷰 통합HBase, Cassandra, Druid밀리초높음

Lambda 아키텍처 구현 예제

// 배치 레이어: Spark 배치 처리
import org.apache.spark.sql.SparkSession;
import org.apache.spark.sql.Dataset;
import org.apache.spark.sql.Row;

public class BatchLayer {
    public static void main(String[] args) {
        SparkSession spark = SparkSession.builder()
            .appName("Lambda Batch Layer")
            .master("yarn")
            .getOrCreate();

        // 마스터 데이터셋 읽기 (HDFS)
        Dataset masterData = spark.read()
            .parquet("hdfs://namenode:9000/master_dataset/*");

        // 배치 뷰 계산 (일일 집계)
        Dataset batchView = masterData
            .groupBy("user_id", "date")
            .agg(
                count("*").as("transaction_count"),
                sum("amount").as("total_amount"),
                avg("amount").as("avg_amount")
            );

        // 서빙 레이어에 저장 (HBase)
        batchView.write()
            .format("org.apache.hadoop.hbase.spark")
            .option("hbase.table", "batch_views")
            .save();

        spark.stop();
    }
}

// 스피드 레이어: Flink 스트림 처리
import org.apache.flink.streaming.api.environment.StreamExecutionEnvironment;
import org.apache.flink.streaming.api.windowing.time.Time;

public class SpeedLayer {
    public static void main(String[] args) throws Exception {
        StreamExecutionEnvironment env =
            StreamExecutionEnvironment.getExecutionEnvironment();

        // Kafka에서 실시간 데이터 읽기
        DataStream stream = env
            .addSource(new FlinkKafkaConsumer<>("transactions",
                new TransactionSchema(), properties));

        // 실시간 뷰 계산 (최근 1시간)
        DataStream realtimeView = stream
            .keyBy(Transaction::getUserId)
            .timeWindow(Time.hours(1))
            .aggregate(new RealtimeAggregator());

        // 서빙 레이어에 저장 (Redis)
        realtimeView.addSink(new RedisSink<>());

        env.execute("Lambda Speed Layer");
    }
}

// 서빙 레이어: 통합 쿼리 API
import org.springframework.web.bind.annotation.*;

@RestController
@RequestMapping("/api/stats")
public class ServingLayer {

    @Autowired
    private HBaseTemplate batchViewStore;

    @Autowired
    private RedisTemplate realtimeViewStore;

    @GetMapping("/user/{userId}")
    public UserStats getUserStats(@PathVariable String userId) {
        // 배치 뷰에서 과거 데이터 조회
        UserStats batchStats = batchViewStore.get(
            "batch_views", userId, UserStats.class);

        // 실시간 뷰에서 최근 데이터 조회
        UserStats realtimeStats = realtimeViewStore.opsForValue()
            .get("realtime:" + userId);

        // 두 뷰를 병합하여 반환
        return mergeViews(batchStats, realtimeStats);
    }

    private UserStats mergeViews(UserStats batch, UserStats realtime) {
        return UserStats.builder()
            .userId(batch.getUserId())
            .transactionCount(
                batch.getTransactionCount() + realtime.getTransactionCount())
            .totalAmount(
                batch.getTotalAmount() + realtime.getTotalAmount())
            .build();
    }
}

Kappa 아키텍처

Kappa 아키텍처는 Jay Kreps가 제안한 스트림 중심 아키텍처로, Lambda 아키텍처의 복잡성을 줄이기 위해 배치 레이어를 제거하고 모든 처리를 스트림으로 수행합니다.

Kappa 아키텍처 구조

// Kappa 아키텍처 구조 (단순화된 스트림 중심)
데이터 소스 (API, IoT, 로그)
    ↓
이벤트 스트림 (Kafka - 긴 보존 기간)
    ↓
    ├────────────────────┬────────────────────┐
    ↓                    ↓                    ↓
스트림 처리 1        스트림 처리 2        스트림 처리 N
(실시간 분석)        (이력 재계산)        (ML 파이프라인)
    ↓                    ↓                    ↓
상태 저장소          상태 저장소          상태 저장소
(RocksDB)           (RocksDB)           (RocksDB)
    ↓                    ↓                    ↓
    └────────────────────┴────────────────────┘
                         ↓
                    서빙 레이어
                (Cassandra/Elasticsearch)
                         ↓
                    쿼리 API
                         ↓
                    애플리케이션

// 핵심 원칙:
// 1. 모든 데이터는 불변 이벤트 스트림으로 표현
// 2. 과거 데이터 재처리는 스트림 재생으로 수행
// 3. 단일 코드베이스로 모든 처리 수행

Lambda vs Kappa 비교

측면Lambda 아키텍처Kappa 아키텍처
복잡도높음 (두 개의 처리 경로)낮음 (단일 처리 경로)
코드베이스배치/스트림 각각 구현단일 스트림 처리 코드
운영 부담높음 (두 시스템 관리)낮음 (하나의 시스템)
데이터 정확성매우 높음 (배치 레이어)높음 (재처리 필요)
지연 시간배치: 높음, 스트림: 낮음일관되게 낮음
재계산배치 재실행스트림 재생
저장소 요구사항HDFS + 스트림 버퍼긴 보존 기간의 Kafka
적합한 사용 사례금융, 규제 준수실시간 분석, 이벤트 소싱

Kappa 아키텍처 구현 예제

// Kafka Streams를 사용한 Kappa 아키텍처
import org.apache.kafka.streams.*;
import org.apache.kafka.streams.kstream.*;

public class KappaArchitecture {
    public static void main(String[] args) {
        Properties props = new Properties();
        props.put(StreamsConfig.APPLICATION_ID_CONFIG, "kappa-app");
        props.put(StreamsConfig.BOOTSTRAP_SERVERS_CONFIG, "localhost:9092");

        StreamsBuilder builder = new StreamsBuilder();

        // 이벤트 스트림 읽기 (모든 이력 데이터 포함)
        KStream transactions = builder
            .stream("transactions", Consumed.with(Serdes.String(),
                new JsonSerde<>(Transaction.class)));

        // 실시간 집계 (상태 저장)
        KTable stats = transactions
            .groupByKey()
            .aggregate(
                UserStats::new,
                (key, transaction, stats) -> stats.addTransaction(transaction),
                Materialized.>as("user-stats-store")
                    .withKeySerde(Serdes.String())
                    .withValueSerde(new JsonSerde<>(UserStats.class))
            );

        // 결과를 Kafka 토픽에 출력 (다른 서비스에서 소비)
        stats.toStream().to("user-stats", Produced.with(Serdes.String(),
            new JsonSerde<>(UserStats.class)));

        // 애플리케이션 시작
        KafkaStreams streams = new KafkaStreams(builder.build(), props);
        streams.start();

        // 우아한 종료
        Runtime.getRuntime().addShutdownHook(new Thread(streams::close));
    }
}

// Interactive Queries로 상태 저장소 직접 조회
@RestController
public class KappaQueryService {

    @Autowired
    private KafkaStreams streams;

    @GetMapping("/stats/{userId}")
    public UserStats getStats(@PathVariable String userId) {
        // 로컬 상태 저장소에서 직접 조회
        ReadOnlyKeyValueStore store =
            streams.store(StoreQueryParameters.fromNameAndType(
                "user-stats-store", QueryableStoreTypes.keyValueStore()));

        UserStats stats = store.get(userId);

        if (stats == null) {
            throw new NotFoundException("User not found: " + userId);
        }

        return stats;
    }
}

// 과거 데이터 재처리 (스트림 재생)
public class KappaReprocessing {
    public static void reprocessFromBeginning() {
        Properties props = new Properties();
        props.put(StreamsConfig.APPLICATION_ID_CONFIG, "kappa-reprocess-v2");
        props.put(StreamsConfig.BOOTSTRAP_SERVERS_CONFIG, "localhost:9092");

        // 처음부터 읽기 (자동으로 earliest offset 사용)
        props.put(ConsumerConfig.AUTO_OFFSET_RESET_CONFIG, "earliest");

        StreamsBuilder builder = new StreamsBuilder();

        // 새로운 로직으로 재처리
        KStream transactions = builder
            .stream("transactions");

        // 업데이트된 집계 로직
        transactions
            .groupByKey()
            .aggregate(/* 새로운 집계 로직 */)
            .toStream()
            .to("user-stats-v2");

        KafkaStreams streams = new KafkaStreams(builder.build(), props);
        streams.start();
    }
}

하이브리드 아키텍처 패턴

실무에서는 Lambda와 Kappa의 장점을 결합한 하이브리드 아키텍처를 사용하는 경우가 많습니다.

패턴설명장점사용 사례
선택적 배치중요 데이터만 배치 처리복잡도 감소, 정확성 유지금융 결산 + 실시간 모니터링
멀티 스피드여러 스피드 레이어 운영다양한 지연 요구사항 충족초단위/분단위/시간단위 집계
점진적 마이그레이션Lambda에서 Kappa로 단계적 전환리스크 최소화레거시 시스템 현대화
이벤트 소싱 + CQRS이벤트 저장소 + 읽기/쓰기 분리완전한 감사 추적은행, 전자상거래

아키텍처 선택 가이드

Lambda 아키텍처를 선택해야 하는 경우

  • 정확성이 최우선: 금융, 의료, 규제 산업
  • 복잡한 배치 처리: 여러 데이터 소스 조인, 복잡한 변환
  • 기존 배치 인프라: Hadoop 에코시스템이 이미 구축됨
  • 장기 데이터 보관: 수년치 데이터의 효율적 저장 필요
  • 감사 및 규정 준수: 완전한 데이터 이력 추적 필요

Kappa 아키텍처를 선택해야 하는 경우

  • 실시간 우선: 소셜 미디어, IoT, 실시간 추천
  • 단순성 중시: 작은 팀, 빠른 개발 주기
  • 이벤트 소싱: 모든 변경사항을 이벤트로 기록
  • 빈번한 재계산: ML 모델 재훈련, A/B 테스트
  • 클라우드 네이티브: Kafka, Kubernetes 기반 인프라

마이크로서비스와 스트리밍 아키텍처

// 이벤트 기반 마이크로서비스 아키텍처
/*
주문 서비스 → [주문 생성 이벤트] → Kafka
                    ↓
    ├───────────────┼───────────────┼───────────────┐
    ↓               ↓               ↓               ↓
재고 서비스      결제 서비스      배송 서비스      알림 서비스
(재고 차감)     (결제 처리)     (배송 준비)     (이메일/SMS)
    ↓               ↓               ↓               ↓
[재고 업데이트]  [결제 완료]     [배송 시작]     [알림 발송]
    ↓               ↓               ↓               ↓
                Kafka 이벤트 스트림
                    ↓
        ┌───────────┴───────────┐
        ↓                       ↓
    주문 상태 집계          분석/모니터링
    (CQRS 읽기 모델)       (대시보드)
*/

// 주문 서비스: 이벤트 발행
@Service
public class OrderService {

    @Autowired
    private KafkaTemplate kafkaTemplate;

    @Transactional
    public Order createOrder(CreateOrderRequest request) {
        // 주문 생성
        Order order = orderRepository.save(new Order(request));

        // 이벤트 발행 (비동기, 보장된 전달)
        OrderCreatedEvent event = new OrderCreatedEvent(
            order.getId(),
            order.getCustomerId(),
            order.getItems(),
            order.getTotalAmount(),
            Instant.now()
        );

        kafkaTemplate.send("order-events", order.getId(), event);

        return order;
    }
}

// 재고 서비스: 이벤트 소비 및 처리
@Service
public class InventoryService {

    @KafkaListener(topics = "order-events", groupId = "inventory-service")
    public void handleOrderCreated(OrderCreatedEvent event) {
        try {
            // 재고 확인 및 차감
            for (OrderItem item : event.getItems()) {
                inventoryRepository.decreaseStock(
                    item.getProductId(),
                    item.getQuantity()
                );
            }

            // 성공 이벤트 발행
            kafkaTemplate.send("inventory-events",
                new InventoryReservedEvent(event.getOrderId()));

        } catch (InsufficientStockException e) {
            // 실패 이벤트 발행 (보상 트랜잭션)
            kafkaTemplate.send("inventory-events",
                new InventoryReservationFailedEvent(event.getOrderId(), e.getMessage()));
        }
    }
}

전략설명장점단점도구

// Prometheus 메트릭 및 분산 추적
import io.micrometer.core.instrument.MeterRegistry;
import io.micrometer.core.instrument.Timer;

@Service
public class StreamingMetrics {

    private final MeterRegistry registry;
    private final Timer processingTimer;
    private final Counter eventsProcessed;
    private final Gauge currentLag;

    public StreamingMetrics(MeterRegistry registry) {
        this.registry = registry;

        // 처리 시간 측정
        this.processingTimer = Timer.builder("streaming.processing.time")
            .description("Time to process a single event")
            .tag("layer", "speed")
            .register(registry);

        // 처리된 이벤트 수
        this.eventsProcessed = Counter.builder("streaming.events.processed")
            .description("Total number of events processed")
            .tag("status", "success")
            .register(registry);

        // 컨슈머 래그 (게이지)
        this.currentLag = Gauge.builder("streaming.consumer.lag",
                this::calculateCurrentLag)
            .description("Current consumer lag")
            .register(registry);
    }

    public void recordProcessing(Runnable processing) {
        processingTimer.record(() -> {
            processing.run();
            eventsProcessed.increment();
        });
    }

    private double calculateCurrentLag() {
        // Kafka Consumer API를 통해 래그 계산
        return consumerLagMonitor.getCurrentLag();
    }
}

// 분산 추적 (OpenTelemetry)
import io.opentelemetry.api.trace.Span;
import io.opentelemetry.api.trace.Tracer;
import io.opentelemetry.context.Scope;

@Service
public class TracedStreamProcessor {

    @Autowired
    private Tracer tracer;

    public void processEvent(Event event) {
        // 스팬 시작
        Span span = tracer.spanBuilder("processEvent")
            .setAttribute("event.id", event.getId())
            .setAttribute("event.type", event.getType())
            .startSpan();

        try (Scope scope = span.makeCurrent()) {
            // 이벤트 처리
            validateEvent(event);
            transformEvent(event);
            persistEvent(event);

            span.addEvent("Event processed successfully");
        } catch (Exception e) {
            span.recordException(e);
            span.setStatus(StatusCode.ERROR);
            throw e;
        } finally {
            span.end();
        }
    }
}

요약

스트리밍 아키텍처 패턴 선택은 비즈니스 요구사항, 데이터 특성, 팀 역량, 기술 스택에 따라 달라집니다. Lambda 아키텍처는 정확성이 최우선인 경우, Kappa 아키텍처는 단순성과 실시간성이 중요한 경우에 적합합니다. 많은 조직에서는 두 패턴의 장점을 결합한 하이브리드 접근 방식을 채택하고 있습니다.
