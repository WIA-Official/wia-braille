제5장: 이벤트 소싱 및 CQRS

개요

이벤트 소싱(Event Sourcing)과 CQRS(Command Query Responsibility Segregation)는 현대적인 스트리밍 애플리케이션 설계의 핵심 패턴입니다. 이 장에서는 이벤트 스토어 구축, 명령과 쿼리 분리, 프로젝션 관리, 실전 구현 패턴을 다룹니다.

이벤트 소싱

이벤트 소싱은 애플리케이션의 모든 상태 변경을 이벤트 시퀀스로 저장하는 패턴입니다. 현재 상태만 저장하는 전통적인 CRUD 방식과 달리, 모든 변경 이력을 유지합니다.

전통적 CRUD vs 이벤트 소싱 비교

측면전통적 CRUD이벤트 소싱
저장 대상현재 상태모든 이벤트 (변경 이력)
데이터 수정UPDATE/DELETE새 이벤트 추가 (Append-only)
감사 추적별도 구현 필요기본 제공
시점 복원어려움쉬움 (이벤트 재생)
디버깅어려움전체 이력 조회 가능
복잡도낮음높음
저장 공간적음많음
적합 사례단순 애플리케이션금융, 전자상거래, 블록체인

이벤트 소싱 아키텍처

// 이벤트 소싱 흐름
1. 명령 수신
   Command: CreateOrderCommand
   └─→ 검증 및 처리

2. 이벤트 생성
   Event: OrderCreatedEvent
   └─→ 이벤트 스토어에 저장 (Append-only)

3. 이벤트 발행
   Kafka/EventStore
   └─→ 다른 서비스/프로젝션에 전파

4. 상태 재구성
   Event Stream: [OrderCreated, ItemAdded, OrderPaid]
   └─→ 이벤트 재생으로 현재 상태 계산

// 예시: 주문 상태 재구성
초기 상태: Order {}

Event 1: OrderCreatedEvent
  → Order {id: "123", status: "CREATED", items: []}

Event 2: ItemAddedEvent {itemId: "A", quantity: 2}
  → Order {id: "123", status: "CREATED", items: [{A, 2}]}

Event 3: OrderPaidEvent
  → Order {id: "123", status: "PAID", items: [{A, 2}]}

최종 상태: Order {id: "123", status: "PAID", items: [{A, 2}]}

이벤트 스토어 구현

// 이벤트 정의
public abstract class Event {
    private final String aggregateId;
    private final long version;
    private final Instant timestamp;
    private final String eventType;

    // getters...
}

public class OrderCreatedEvent extends Event {
    private final String customerId;
    private final List items;
    // getters...
}

public class ItemAddedEvent extends Event {
    private final String itemId;
    private final int quantity;
    // getters...
}

// 애그리게이트 (도메인 모델)
public class Order {
    private String orderId;
    private String customerId;
    private List items = new ArrayList<>();
    private OrderStatus status;
    private long version = 0;

    // 명령 처리 (비즈니스 로직)
    public List createOrder(String customerId, List items) {
        if (this.orderId != null) {
            throw new IllegalStateException("Order already created");
        }

        return List.of(new OrderCreatedEvent(
            UUID.randomUUID().toString(),
            version + 1,
            Instant.now(),
            customerId,
            items
        ));
    }

    public List addItem(String itemId, int quantity) {
        if (this.status != OrderStatus.CREATED) {
            throw new IllegalStateException("Cannot add items to " + status + " order");
        }

        return List.of(new ItemAddedEvent(
            this.orderId,
            version + 1,
            Instant.now(),
            itemId,
            quantity
        ));
    }

    // 이벤트 적용 (상태 재구성)
    public void apply(Event event) {
        if (event instanceof OrderCreatedEvent) {
            OrderCreatedEvent e = (OrderCreatedEvent) event;
            this.orderId = e.getAggregateId();
            this.customerId = e.getCustomerId();
            this.items = new ArrayList<>(e.getItems());
            this.status = OrderStatus.CREATED;
            this.version = e.getVersion();
        } else if (event instanceof ItemAddedEvent) {
            ItemAddedEvent e = (ItemAddedEvent) event;
            this.items.add(new OrderItem(e.getItemId(), e.getQuantity()));
            this.version = e.getVersion();
        }
        // ... 다른 이벤트 처리
    }
}

// 이벤트 스토어 인터페이스
public interface EventStore {
    void saveEvents(String aggregateId, List events, long expectedVersion);
    List getEvents(String aggregateId);
    List getEventsAfter(String aggregateId, long version);
}

// Kafka 기반 이벤트 스토어 구현
public class KafkaEventStore implements EventStore {
    private final KafkaProducer producer;
    private final KafkaConsumer consumer;
    private final String topic;

    @Override
    public void saveEvents(String aggregateId, List events, long expectedVersion) {
        // 낙관적 동시성 제어
        List existingEvents = getEvents(aggregateId);
        if (!existingEvents.isEmpty() &&
            existingEvents.get(existingEvents.size() - 1).getVersion() != expectedVersion) {
            throw new ConcurrencyException("Version mismatch");
        }

        // 이벤트 저장 (Kafka에 발행)
        for (Event event : events) {
            ProducerRecord record =
                new ProducerRecord<>(topic, aggregateId, event);
            producer.send(record).get(); // 동기 전송 (안정성)
        }
    }

    @Override
    public List getEvents(String aggregateId) {
        List events = new ArrayList<>();

        // Kafka 파티션에서 모든 이벤트 읽기
        consumer.assign(Collections.singletonList(
            new TopicPartition(topic, getPartition(aggregateId))));
        consumer.seekToBeginning(consumer.assignment());

        while (true) {
            ConsumerRecords records =
                consumer.poll(Duration.ofMillis(100));
            if (records.isEmpty()) break;

            for (ConsumerRecord record : records) {
                if (record.key().equals(aggregateId)) {
                    events.add(record.value());
                }
            }
        }

        return events;
    }
}

// 저장소 (Repository)
public class OrderRepository {
    private final EventStore eventStore;

    public void save(Order order) {
        List uncommittedEvents = order.getUncommittedEvents();
        eventStore.saveEvents(
            order.getOrderId(),
            uncommittedEvents,
            order.getVersion() - uncommittedEvents.size()
        );
        order.markEventsAsCommitted();
    }

    public Order getById(String orderId) {
        List events = eventStore.getEvents(orderId);
        if (events.isEmpty()) {
            return null;
        }

        Order order = new Order();
        events.forEach(order::apply);
        return order;
    }
}

CQRS 패턴

CQRS는 명령(Command)과 쿼리(Query)의 책임을 분리하는 패턴으로, 읽기와 쓰기에 최적화된 별도의 모델을 사용합니다.

CQRS 아키텍처

// CQRS 전체 아키텍처
┌──────────────────────────────────────────────────────┐
│                   클라이언트                          │
└──────────────────────────────────────────────────────┘
         │                                  │
         │ 명령 (변경)                      │ 쿼리 (조회)
         ↓                                  ↓
┌──────────────────┐              ┌──────────────────┐
│  명령 측 (쓰기)   │              │  쿼리 측 (읽기)   │
│                  │              │                  │
│  Command Handler │              │  Query Handler   │
│        ↓         │              │        ↓         │
│   도메인 모델     │              │    읽기 모델      │
│        ↓         │              │   (프로젝션)      │
│  이벤트 스토어    │              │        ↓         │
│   (Kafka)        │─── 이벤트 ──→│  읽기 DB         │
│                  │    발행      │ (PostgreSQL,     │
│                  │              │  Elasticsearch)  │
└──────────────────┘              └──────────────────┘

// 특징:
// - 명령 측: 비즈니스 로직, 정규화된 데이터
// - 쿼리 측: 빠른 읽기, 비정규화된 데이터
// - 이벤트로 동기화

명령 처리 구현

// 명령 정의
public abstract class Command {
    private final String commandId = UUID.randomUUID().toString();
    private final Instant timestamp = Instant.now();
    // getters...
}

public class CreateOrderCommand extends Command {
    private final String customerId;
    private final List items;
    // getters...
}

public class AddItemCommand extends Command {
    private final String orderId;
    private final String itemId;
    private final int quantity;
    // getters...
}

// 명령 핸들러
@Service
public class OrderCommandHandler {

    @Autowired
    private OrderRepository repository;

    @Autowired
    private EventBus eventBus;

    @Transactional
    public String handle(CreateOrderCommand command) {
        // 1. 애그리게이트 생성
        Order order = new Order();

        // 2. 비즈니스 로직 실행 (이벤트 생성)
        List events = order.createOrder(
            command.getCustomerId(),
            command.getItems()
        );

        // 3. 이벤트 저장
        repository.save(order);

        // 4. 이벤트 발행 (비동기)
        events.forEach(eventBus::publish);

        return order.getOrderId();
    }

    @Transactional
    public void handle(AddItemCommand command) {
        // 1. 애그리게이트 로드 (이벤트 재생)
        Order order = repository.getById(command.getOrderId());
        if (order == null) {
            throw new NotFoundException("Order not found");
        }

        // 2. 비즈니스 로직 실행
        List events = order.addItem(
            command.getItemId(),
            command.getQuantity()
        );

        // 3. 이벤트 저장 및 발행
        repository.save(order);
        events.forEach(eventBus::publish);
    }
}

// 명령 게이트웨이 (REST API)
@RestController
@RequestMapping("/api/orders")
public class OrderCommandController {

    @Autowired
    private OrderCommandHandler commandHandler;

    @PostMapping
    public ResponseEntity createOrder(@RequestBody CreateOrderRequest request) {
        CreateOrderCommand command = new CreateOrderCommand(
            request.getCustomerId(),
            request.getItems()
        );

        String orderId = commandHandler.handle(command);

        return ResponseEntity.ok(orderId);
    }

    @PostMapping("/{orderId}/items")
    public ResponseEntity addItem(
            @PathVariable String orderId,
            @RequestBody AddItemRequest request) {

        AddItemCommand command = new AddItemCommand(
            orderId,
            request.getItemId(),
            request.getQuantity()
        );

        commandHandler.handle(command);

        return ResponseEntity.accepted().build();
    }
}

프로젝션 (읽기 모델)

프로젝션은 이벤트 스트림을 소비하여 쿼리에 최적화된 읽기 모델을 구축합니다.

// 읽기 모델 (비정규화)
@Entity
@Table(name = "order_view")
public class OrderView {
    @Id
    private String orderId;
    private String customerId;
    private String customerName; // 조인 없이 조회
    private int totalItems;
    private double totalAmount;
    private String status;
    private Instant createdAt;
    private Instant updatedAt;
    // getters, setters...
}

// 프로젝션 이벤트 핸들러
@Service
public class OrderViewProjection {

    @Autowired
    private OrderViewRepository viewRepository;

    @Autowired
    private CustomerService customerService; // 외부 데이터

    @EventHandler
    public void on(OrderCreatedEvent event) {
        // 고객 정보 조회 (비정규화)
        Customer customer = customerService.getById(event.getCustomerId());

        // 읽기 모델 생성
        OrderView view = new OrderView();
        view.setOrderId(event.getAggregateId());
        view.setCustomerId(event.getCustomerId());
        view.setCustomerName(customer.getName()); // 비정규화
        view.setTotalItems(event.getItems().size());
        view.setTotalAmount(calculateTotal(event.getItems()));
        view.setStatus("CREATED");
        view.setCreatedAt(event.getTimestamp());
        view.setUpdatedAt(event.getTimestamp());

        viewRepository.save(view);
    }

    @EventHandler
    public void on(ItemAddedEvent event) {
        OrderView view = viewRepository.findById(event.getAggregateId())
            .orElseThrow();

        view.setTotalItems(view.getTotalItems() + 1);
        view.setTotalAmount(view.getTotalAmount() +
            calculateItemPrice(event.getItemId(), event.getQuantity()));
        view.setUpdatedAt(event.getTimestamp());

        viewRepository.save(view);
    }

    @EventHandler
    public void on(OrderPaidEvent event) {
        OrderView view = viewRepository.findById(event.getAggregateId())
            .orElseThrow();

        view.setStatus("PAID");
        view.setUpdatedAt(event.getTimestamp());

        viewRepository.save(view);
    }
}

// Kafka Streams 기반 프로젝션
public class OrderViewStreamProcessor {
    public static void main(String[] args) {
        StreamsBuilder builder = new StreamsBuilder();

        // 이벤트 스트림 읽기
        KStream events = builder.stream("order-events");

        // 프로젝션 계산
        KTable orderViews = events
            .groupByKey()
            .aggregate(
                OrderView::new,
                (orderId, event, view) -> {
                    if (event instanceof OrderCreatedEvent) {
                        OrderCreatedEvent e = (OrderCreatedEvent) event;
                        view.setOrderId(orderId);
                        view.setCustomerId(e.getCustomerId());
                        // ... 초기화
                    } else if (event instanceof ItemAddedEvent) {
                        ItemAddedEvent e = (ItemAddedEvent) event;
                        view.setTotalItems(view.getTotalItems() + 1);
                        // ... 업데이트
                    }
                    return view;
                },
                Materialized.as("order-views-store")
            );

        // 프로젝션을 DB에 저장
        orderViews.toStream().to("order-views-sink");

        KafkaStreams streams = new KafkaStreams(builder.build(), props);
        streams.start();
    }
}

// 쿼리 서비스
@RestController
@RequestMapping("/api/query/orders")
public class OrderQueryController {

    @Autowired
    private OrderViewRepository viewRepository;

    @GetMapping("/{orderId}")
    public OrderView getOrder(@PathVariable String orderId) {
        return viewRepository.findById(orderId)
            .orElseThrow(() -> new NotFoundException("Order not found"));
    }

    @GetMapping
    public List getOrders(
            @RequestParam(required = false) String customerId,
            @RequestParam(required = false) String status,
            @PageableDefault Pageable pageable) {

        if (customerId != null && status != null) {
            return viewRepository.findByCustomerIdAndStatus(
                customerId, status, pageable);
        } else if (customerId != null) {
            return viewRepository.findByCustomerId(customerId, pageable);
        } else if (status != null) {
            return viewRepository.findByStatus(status, pageable);
        } else {
            return viewRepository.findAll(pageable).getContent();
        }
    }
}

스냅샷 패턴

이벤트가 많을 경우 매번 재생하는 것은 비효율적입니다. 스냅샷을 사용하여 성능을 최적화합니다.

패턴설명장점단점
정기 스냅샷N개 이벤트마다 저장일정한 성능저장 공간 증가
시간 기반일정 시간마다 저장최신 상태 보장불규칙한 간격
온디맨드요청 시 생성공간 효율적느린 첫 조회
// 스냅샷 구현
public class Snapshot {
    private final String aggregateId;
    private final long version;
    private final Instant timestamp;
    private final Object state;
    // getters...
}

public class SnapshotStore {
    private final Map snapshots = new ConcurrentHashMap<>();

    public void save(String aggregateId, Object state, long version) {
        snapshots.put(aggregateId, new Snapshot(
            aggregateId,
            version,
            Instant.now(),
            state
        ));
    }

    public Optional get(String aggregateId) {
        return Optional.ofNullable(snapshots.get(aggregateId));
    }
}

// 스냅샷을 사용한 로드
public Order getById(String orderId) {
    Order order = new Order();

    // 1. 최신 스냅샷 로드
    Optional snapshot = snapshotStore.get(orderId);
    long startVersion = 0;

    if (snapshot.isPresent()) {
        order = (Order) snapshot.get().getState();
        startVersion = snapshot.get().getVersion();
    }

    // 2. 스냅샷 이후 이벤트만 재생
    List events = eventStore.getEventsAfter(orderId, startVersion);
    events.forEach(order::apply);

    // 3. 새 스냅샷 생성 (100개 이벤트마다)
    if (events.size() >= 100) {
        snapshotStore.save(orderId, order, order.getVersion());
    }

    return order;
}

// 이벤트 스키마 진화
// V1: 초기 버전
public class OrderCreatedEventV1 extends Event {
    private String customerId;
    private List itemIds;
}

// V2: 수량 추가
public class OrderCreatedEventV2 extends Event {
    private String customerId;
    private List items; // {itemId, quantity}
}

// 업캐스터 (이전 버전 → 최신 버전)
public class OrderCreatedEventUpcaster {
    public OrderCreatedEventV2 upcast(OrderCreatedEventV1 v1) {
        List items = v1.getItemIds().stream()
            .map(id -> new OrderItem(id, 1)) // 기본 수량 1
            .collect(Collectors.toList());

        return new OrderCreatedEventV2(
            v1.getAggregateId(),
            v1.getVersion(),
            v1.getTimestamp(),
            v1.getCustomerId(),
            items
        );
    }
}

결과적 일관성 처리

문제: 명령 처리 후 즉시 조회하면 읽기 모델에 반영되지 않을 수 있습니다.

해결책:

  • 클라이언트 폴링: 일정 시간 후 재조회
  • 버전 번호: 명령 응답에 버전 포함, 읽기 시 확인
  • 알림: WebSocket/SSE로 업데이트 알림
  • 낙관적 UI: 즉시 UI 업데이트 후 서버 확인

요약

이벤트 소싱과 CQRS는 복잡한 도메인 로직, 감사 추적, 확장 가능한 읽기 모델이 필요한 시스템에 적합합니다. 이벤트 스토어는 모든 변경 이력을 유지하며, CQRS는 읽기와 쓰기를 분리하여 각각 최적화합니다. 프로젝션을 통해 다양한 쿼리 요구사항을 충족할 수 있습니다.
