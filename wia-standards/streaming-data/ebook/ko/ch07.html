제7장: 스트리밍 분석 및 CEP

개요

복합 이벤트 처리(Complex Event Processing, CEP)는 스트리밍 데이터에서 의미 있는 패턴과 이벤트 시퀀스를 실시간으로 탐지하는 기술입니다. 이 장에서는 윈도우 연산, 패턴 매칭, 실시간 분석, CEP 구현 전략을 다룹니다.

복합 이벤트 처리 (CEP)

CEP는 여러 이벤트 간의 관계와 패턴을 분석하여 복잡한 상황을 탐지합니다.

CEP 사용 사례

도메인사용 사례패턴액션
금융사기 탐지연속된 대액 출금계정 동결, 알림
전자상거래장바구니 이탈장바구니 추가 → 10분 대기할인 쿠폰 발송

보안침입 탐지실패한 로그인 5회IP 차단
물류배송 지연예상 시간 + 2시간 미도착고객 알림

Flink CEP 구현

// Flink CEP 라이브러리 사용
import org.apache.flink.cep.CEP;
import org.apache.flink.cep.PatternStream;
import org.apache.flink.cep.pattern.Pattern;
import org.apache.flink.cep.pattern.conditions.SimpleCondition;

// 사기 탐지: 10분 내 3회 이상 대액 거래
public class FraudDetectionCEP {
    public static void main(String[] args) throws Exception {
        StreamExecutionEnvironment env =
            StreamExecutionEnvironment.getExecutionEnvironment();

        // 거래 이벤트 스트림
        DataStream transactions = env
            .addSource(new TransactionSource())
            .assignTimestampsAndWatermarks(...);

        // 패턴 정의
        Pattern fraudPattern = Pattern
            .begin("first")
            .where(new SimpleCondition() {
                @Override
                public boolean filter(Transaction tx) {
                    return tx.getAmount() > 10000; // 고액 거래
                }
            })
            .next("second")
            .where(new SimpleCondition() {
                @Override
                public boolean filter(Transaction tx) {
                    return tx.getAmount() > 10000;
                }
            })
            .next("third")
            .where(new SimpleCondition() {
                @Override
                public boolean filter(Transaction tx) {
                    return tx.getAmount() > 10000;
                }
            })
            .within(Time.minutes(10)); // 10분 이내

        // 패턴 스트림 생성
        PatternStream patternStream = CEP.pattern(
            transactions.keyBy(Transaction::getUserId),
            fraudPattern
        );

        // 매칭된 패턴 처리
        DataStream alerts = patternStream.select(
            (Map> pattern) -> {
                List first = pattern.get("first");
                List second = pattern.get("second");
                List third = pattern.get("third");

                return new Alert(
                    "FRAUD_SUSPECTED",
                    first.get(0).getUserId(),
                    "3 large transactions in 10 minutes",
                    first.get(0).getAmount() +
                        second.get(0).getAmount() +
                        third.get(0).getAmount()
                );
            }
        );

        // 알림 전송
        alerts.addSink(new AlertSink());

        env.execute("Fraud Detection CEP");
    }
}

// 반복 패턴 (1회 이상)
Pattern pattern = Pattern
    .begin("start")
    .where(...)
    .oneOrMore()  // 1회 이상 반복
    .greedy();    // 최대한 많이 매칭

// 조건부 패턴 (followedBy vs followedByAny)
Pattern strictPattern = Pattern
    .begin("first")
    .where(...)
    .followedBy("second")  // 다음 매칭 이벤트 (중간에 다른 이벤트 있으면 실패)
    .where(...);

Pattern relaxedPattern = Pattern
    .begin("first")
    .where(...)
    .followedByAny("second")  // 언젠가 나타나는 매칭 이벤트
    .where(...);

// 부정 패턴 (NOT)
Pattern notPattern = Pattern
    .begin("first")
    .where(...)
    .notFollowedBy("unwanted")  // 이 이벤트가 나타나면 매칭 실패
    .where(...)
    .followedBy("second")
    .where(...);

// 타임아웃 처리
PatternStream patternStream = CEP.pattern(input, pattern);

OutputTag timeoutTag = new OutputTag("timeout"){};

SingleOutputStreamOperator result = patternStream
    .select(
        timeoutTag,
        // 타임아웃 콜백
        (Map> pattern, Long timestamp) -> {
            return new TimeoutEvent(pattern, timestamp);
        },
        // 매칭 콜백
        (Map> pattern) -> {
            return new Alert(pattern);
        }
    );

DataStream timeoutStream = result.getSideOutput(timeoutTag);

윈도우 연산

윈도우는 무한 스트림을 유한한 청크로 나누어 집계 연산을 가능하게 합니다.

윈도우 타입 비교

윈도우 타입설명시각화사용 사례
Tumbling고정 크기, 겹치지 않음[0-5] [5-10] [10-15]5분마다 집계
Sliding고정 크기, 슬라이드[0-5] [2-7] [4-9]1분마다 최근 5분
Session비활동 갭 기반[0-3] ... [10-15]사용자 세션
Count개수 기반100개마다배치 처리
Global모든 데이터전체전역 집계

// 윈도우 함수: Aggregate (증분 집계 - 메모리 효율적)
public class AverageAggregator
    implements AggregateFunction, Double> {

    @Override
    public Tuple2 createAccumulator() {
        return new Tuple2<>(0.0, 0L);
    }

    @Override
    public Tuple2 add(SensorReading reading,
                                     Tuple2 acc) {
        return new Tuple2<>(
            acc.f0 + reading.getTemperature(),
            acc.f1 + 1
        );
    }

    @Override
    public Double getResult(Tuple2 acc) {
        return acc.f0 / acc.f1;
    }

    @Override
    public Tuple2 merge(Tuple2 a,
                                       Tuple2 b) {
        return new Tuple2<>(a.f0 + b.f0, a.f1 + b.f1);
    }
}

// 윈도우 함수: ProcessWindowFunction (전체 윈도우 접근)
public class TopNFunction
    extends ProcessWindowFunction {

    @Override
    public void process(
            String key,
            Context context,
            Iterable events,
            Collector out) {

        // 윈도우 메타데이터
        TimeWindow window = context.window();
        long start = window.getStart();
        long end = window.getEnd();

        // 전체 이벤트 처리
        List eventList = new ArrayList<>();
        events.forEach(eventList::add);

        // Top N 추출
        eventList.sort(Comparator.comparing(Event::getValue).reversed());
        List topN = eventList.subList(0, Math.min(10, eventList.size()));

        out.collect("Top 10 in window [" + start + ", " + end + "]: " + topN);
    }
}

// 증분 + 전체 처리 결합 (최적화)
input.keyBy(...)
    .window(TumblingEventTimeWindows.of(Time.minutes(5)))
    .aggregate(
        new AverageAggregator(),  // 증분 집계
        new WindowMetadataFunction()  // 윈도우 정보 추가

스트림 조인

여러 스트림을 결합하여 풍부한 분석을 수행합니다.

조인 타입설명윈도우사용 사례
Window Join같은 윈도우 내 조인필수클릭 + 구매
Interval Join시간 간격 내 조인필수로그인 후 30분 내 활동
Temporal Join버전 기반 조인선택환율 조회
Lookup Join외부 데이터 조인없음사용자 프로필
// Window Join (Flink)
DataStream clicks = ...;
DataStream purchases = ...;

DataStream enriched = clicks
    .join(purchases)
    .where(Click::getUserId)
    .equalTo(Purchase::getUserId)
    .window(TumblingEventTimeWindows.of(Time.minutes(5)))
    .apply(new JoinFunction() {
        @Override
        public Enriched join(Click click, Purchase purchase) {
            return new Enriched(click, purchase);
        }
    });

// Interval Join (시간 간격 조인)
DataStream intervalJoined = clicks
    .keyBy(Click::getUserId)
    .intervalJoin(purchases.keyBy(Purchase::getUserId))
    .between(Time.minutes(-10), Time.minutes(10))  // 전후 10분
    .process(new ProcessJoinFunction() {
        @Override
        public void processElement(
                Click click,
                Purchase purchase,
                Context ctx,
                Collector out) {
            out.collect(new Enriched(click, purchase));
        }
    });

// Temporal Join (버전 테이블 조인 - 시간에 따라 변하는 데이터)

DataStream transactions = ...;

public class UserProfileLookupFunction
    extends RichAsyncFunction {

public class AnomalyDetectionJob {

        // 학습된 모델 로드

public class TensorFlowScoreFunction extends RichMapFunction {

요약

스트리밍 분석과 CEP는 실시간 패턴 탐지, 윈도우 집계, 스트림 조인을 통해 복잡한 이벤트를 처리합니다. Flink CEP는 강력한 패턴 매칭을 제공하며, 윈도우 연산으로 시간 기반 분석을 수행하고, 조인으로 여러 데이터 소스를 통합합니다. 실시간 대시보드와 머신러닝 통합으로 즉각적인 인사이트를 제공할 수 있습니다.
