[AAC] 제3장: WIA AAC 표준 개요

홍익인간 (弘益人間)

"어떤 센서를 사용하든, 어떤 소프트웨어를 사용하든, 동일한 방식으로 작동한다."

이것이 WIA AAC 표준의 핵심 약속입니다.

3.1 미션과 목표

3.1.1 WIA AAC 미션

WIA AAC 표준은 모든 보조 입력 장치와 모든 의사소통 소프트웨어 사이에 보편적인 통신 브릿지를 만들어, 기술 비호환성으로 인해 어떤 사람도 의사소통에서 배제되지 않도록 하는 것을 목표로 합니다.

3.1.2 구체적 목표

목표 설명 이점
센서 표준화 모든 AAC 센서의 통합 출력 형식 모든 센서가 모든 소프트웨어와 작동
API 통일 소프트웨어 개발자를 위한 표준 인터페이스 개발 시간 단축, 더 넓은 지원
프로토콜 규격화 표준화된 통신 방식 신뢰성 있고 예측 가능한 연결
생태계 통합 WIA 표준 제품군과 연결 AAC에서 수어, 점자, 음성으로

3.3 지원 센서 유형

3.3.1 시선 추적 (Eye Tracking)

시선 추적기 신호 표준:

{
    "type": "eye_tracker",
    "version": "1.0.0",
    "timestamp": 1702468800000,
    "data": {
        "gaze_x": 0.456,          // 정규화 0.0-1.0
        "gaze_y": 0.321,          // 정규화 0.0-1.0
        "fixation": true,          // 현재 고정 중
        "dwell_time_ms": 850,      // 현재 지점의 시간
        "pupil_diameter_mm": 4.2   // 선택적
    },
    "confidence": 0.95
}

[i] 사용 사례: 전체 화면 제어, 응시 기반 선택, 시선-스위치 하이브리드, 시선 타이핑

3.3.2 스위치 입력 (Switch Input)

스위치 신호 표준:

{
    "type": "switch",
    "version": "1.0.0",
    "timestamp": 1702468800000,
    "data": {
        "switch_id": 1,            // 어떤 스위치 (1-8)
        "state": "pressed",        // pressed | released | held
        "duration_ms": 150,        // 누른 시간
        "press_count": 1           // 다중 탭 감지용
    },
    "confidence": 1.0
}

[i] 사용 사례: 스캐닝 선택, 모스 부호 입력, 단일 스위치 탐색, 다중 스위치 직접 선택

3.3.3 EMG (근전도 센서)

EMG 신호 표준:

{
    "type": "emg",
    "version": "1.0.0",
    "timestamp": 1702468800000,
    "data": {
        "channel": 1,              // 센서 채널
        "amplitude_uv": 85,        // 마이크로볼트
        "activation": true,        // 임계값 초과
        "muscle_group": "facial",  // facial | hand | other
        "gesture_detected": "eyebrow_raise"  // 선택적
    },
    "confidence": 0.88
}

[i] 사용 사례: 안면 제스처 제어, 잔여 움직임 감지, 표정 기반 입력

3.3.4 EEG/BCI (뇌-컴퓨터 인터페이스)

BCI 신호 표준:

{
    "type": "eeg_bci",
    "version": "1.0.0",
    "timestamp": 1702468800000,
    "data": {
        "channels": ["Fp1", "Fp2", "F3", "F4"],
        "band_power": {
            "alpha": 15.2,         // 8-13 Hz 파워
            "beta": 8.7,           // 13-30 Hz 파워
            "theta": 6.3           // 4-8 Hz 파워
        },
        "classification": "select", // 해석된 명령
        "attention_level": 78       // 0-100
    },
    "confidence": 0.82
}

[i] 사용 사례: 정신 명령 선택, 주의력 기반 트리거, SSVEP 선택

3.3.5 호흡 센서 (Breath Sensor)

호흡 신호 표준:

{
    "type": "breath",
    "version": "1.0.0",
    "timestamp": 1702468800000,
    "data": {
        "action": "sip",           // sip | puff | neutral
        "intensity": 0.75,         // 0.0-1.0
        "duration_ms": 320         // 동작 길이
    },
    "confidence": 0.96
}

[i] 사용 사례: 이진 선택 (sip=예, puff=아니오), 강도 기반 제어, 탐색

3.3.6 머리 움직임 (Head Movement)

머리 움직임 신호 표준:

{
    "type": "head_movement",
    "version": "1.0.0",
    "timestamp": 1702468800000,
    "data": {
        "pitch": -5.2,             // 위/아래 각도
        "yaw": 12.3,               // 좌/우 각도
        "roll": 0.8,               // 기울기 각도
        "gesture_detected": "nod"  // nod | shake | tilt | none
    },
    "confidence": 0.91
}

[i] 사용 사례: 커서 제어, 제스처 명령, 머리-스위치 하이브리드

3.4 설계 원칙

3.4.1 핵심 원칙

  1. 보편적 호환성

    모든 호환 센서는 수정 없이 모든 호환 소프트웨어와 작동해야 합니다.

  2. 우아한 성능 저하

    시스템은 부분 데이터로도 작동해야 합니다. 선택적 필드는 기능을 향상시키지만 필수는 아닙니다.

  3. 실시간 성능

    신호 처리는 실시간 요구사항을 충족해야 합니다 (일반적으로 50ms 미만 지연).

  4. 확장성

    기존 구현을 깨지 않고 새로운 센서 유형과 데이터 필드를 추가할 수 있습니다.

  5. 인간 중심 설계

    모든 결정은 기술적 편의보다 사용자 의사소통 필요를 우선시합니다.

3.5 개발 Phase

3.5.1 Phase 개요

개발 타임라인:

Phase 1: 신호 형식 표준
  기간: 3-4개월
  초점: 모든 센서 유형에 대한 JSON 스키마 정의
  산출물:
    - 신호 형식 사양
    - JSON 스키마 파일
    - 검증 도구
    - 예제 데이터셋

Phase 2: API 인터페이스 표준
  기간: 4-5개월
  초점: 표준 프로그래밍 인터페이스
  산출물:
    - API 사양 문서
    - 참조 구현 (Rust)
    - SDK (TypeScript, Python)
    - 개발자 문서

Phase 3: 통신 프로토콜
  기간: 3-4개월
  초점: 전송 계층 사양
  산출물:
    - Bluetooth LE GATT 프로필
    - USB HID 리포트 디스크립터
    - WiFi/TCP 메시지 형식
    - 시리얼 프로토콜 정의

Phase 4: 생태계 통합
  기간: 4-5개월
  초점: WIA 제품군과 연결
  산출물:
    - ISP (수어) 통합
    - WIA Braille 통합
    - WIA Talk (TTS) 통합
    - 완전한 파이프라인 데모
