2.1 The Fragmented AAC Landscape

The current AAC market is characterized by fragmentation at every level - from hardware protocols to software interfaces, from data formats to communication standards.

2.2 Technical Barriers

2.2.1 Proprietary Signal Formats

Each manufacturer defines their own data format for sensor output:

Tobii Eye Tracker Output (Proprietary):
{
    tobii_gaze_point: {
        x: 0.456,
        y: 0.321,
        validity: 1,
        timestamp_us: 1702468800000000
    },
    tobii_pupil: {
        diameter_mm: 4.2,
        validity: 1
    }
}

EyeTech Eye Tracker Output (Different Proprietary Format):
{
    et_gaze: {
        screen_x: 912,
        screen_y: 456,
        confidence: 0.95,
        time_ms: 1702468800000
    },
    et_eye_data: {
        pupil_size: 0.42,
        blink_detected: false
    }
}

LC Technologies Eye Tracker Output (Yet Another Format):
{
    LCET_Data: {
        GazeX: 0.456,
        GazeY: 0.321,
        TimeStamp: "2025-01-15T10:00:00.000Z",
        Quality: 95
    }
}

[!] Result: Software developers must implement separate integrations for each device, multiplying development costs and limiting support.

2.2.3 SDK Fragmentation

Development Requirements for Multi-Device Support:

To support 5 eye trackers:
  - 5 different SDKs
  - 5 different APIs
  - 5 different documentation sets
  - 5 different licensing agreements
  - 5 different update schedules

To support 4 switch systems:
  - 4 more SDKs
  - 4 more integration points

To support 3 BCI devices:
  - 3 more SDKs
  - Complex signal processing requirements

Total: 12+ separate integrations for reasonable device coverage
Estimated development time: 6-12 months
Ongoing maintenance: Continuous

[i] Developer Reality: Most AAC software only supports 1-2 device brands due to integration complexity, limiting user choice.

2.4 Human Impact

2.4.1 User Stories

Story 1: The Technology Maze

"When my eye tracker died after warranty, I had two choices: pay $4,000 for a repair on a 3-year-old device, or buy a new system for $12,000. Either way, my insurance wouldn't cover it as a 'replacement.' I went two months without my communication device."

- Maria, 42, Multiple Sclerosis

Story 2: The Incompatibility Crisis

"I loved my communication software - I had spent years customizing it with my vocabulary and phrases. But when I needed to switch to eye control, the software didn't support any eye tracker I could afford. I had to start over completely with unfamiliar software."

- James, 58, ALS

Story 3: The Caregiver Burden

"I've learned four different AAC systems as my daughter's needs have changed. Each time, I become the unpaid tech support, trainer, and troubleshooter. I've spent hundreds of hours on this while trying to care for her and work."

- Parent of a child with cerebral palsy

2.4.2 The Communication Gap

During AAC Transitions, Users Experience:

Week 1-2: Device setup and basic calibration
  - Communication ability: 10-20% of normal
  - Frustration level: Extremely high
  - Essential needs expressed only

Week 3-4: Initial learning curve
  - Communication ability: 30-40% of normal
  - Basic messages possible
  - Complex thoughts unexpressible

Month 2: Growing familiarity
  - Communication ability: 50-60% of normal
  - Moderate conversations possible
  - Personality begins to show through

Month 3-6: Approaching proficiency
  - Communication ability: 70-85% of normal
  - Most needs expressible
  - Still slower than previous system

Month 6+: Full adaptation
  - Communication ability: 85-95% of previous
  - New optimizations discovered
  - Muscle memory developed

[!] Reality: For progressive conditions, this cycle may repeat 4-6 times, each during periods of increasing physical decline.

2.5 Industry Analysis

2.5.1 Why Standards Don't Exist Yet

Barrier Description Impact
Market Protection Proprietary systems create lock-in Companies resist standardization
Small Market AAC is niche compared to mainstream tech Limited investment in standards work
Technical Diversity Wide range of sensor types and needs Difficult to create unified approach
Regulatory Complexity Medical device regulations vary by region Standards must navigate compliance
Funding Priorities Research focuses on new technologies Interoperability undervalued

2.5.2 Previous Standardization Attempts

Historical Efforts:

1. Symbol Set Standards (1980s-1990s)
   - PCS, Blissymbols, Widgit
   - Outcome: Fragmented, proprietary implementations

2. ARASAAC (2000s)
   - Open pictogram library
   - Outcome: Adopted but not universal

3. ISAAC (International AAC Association)
   - Industry coordination efforts
   - Outcome: Guidelines but no technical standards

4. USB HID for Switches (2010s)
   - Basic switch standardization
   - Outcome: Partial adoption, limited scope

5. Various Research Protocols
   - Academic signal format proposals
   - Outcome: Not adopted commercially

Common Failure Points:
  - Industry resistance to change
  - Lack of comprehensive technical specification
  - No reference implementations
  - No certification or compliance framework
  - Limited developer engagement
