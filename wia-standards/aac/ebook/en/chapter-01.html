1.1 What is AAC?

AAC (Augmentative and Alternative Communication) refers to all methods, tools, and technologies that help people who have difficulty communicating through speech or writing.

[i] Definition: AAC encompasses any form of communication that supplements or replaces natural speech and writing for individuals with impairments in the production or comprehension of spoken or written language.

1.1.1 The Two Components of AAC

Augmentative Communication:

  • Supplements existing speech abilities
  • Enhances communication that is already present but insufficient
  • Example: Using a communication board alongside limited speech

Alternative Communication:

  • Replaces speech entirely
  • Used when speech is not possible or functional
  • Example: Using eye-tracking device as primary communication method

1.3 Types of AAC Systems

1.3.1 No-Tech AAC

Communication methods that do not require any external devices:

  • Facial expressions - Conveying emotions and responses
  • Gestures - Pointing, nodding, shaking head
  • Body language - Posture and movement
  • Vocalizations - Non-speech sounds to communicate
  • Sign language - Formal sign systems (ASL, BSL, KSL)

1.3.2 Low-Tech AAC

Simple, non-electronic communication aids:

  • Communication boards - Printed boards with symbols or text
  • Picture Exchange Communication System (PECS) - Using picture cards
  • Alphabet boards - Letter-by-letter spelling
  • Eye gaze frames - Simple pointing systems
  • Choice cards - Yes/No or multiple choice options

1.3.3 High-Tech AAC

Electronic devices and software-based solutions:

  • Speech-Generating Devices (SGDs) - Dedicated communication devices
  • Eye-tracking systems - Gaze-controlled communication
  • Switch-based scanning systems - Single or multiple switch input
  • Brain-Computer Interfaces (BCI) - Direct neural input
  • Mobile AAC applications - Tablet and smartphone apps
  • EMG sensors - Muscle activity detection
  • Head tracking systems - Movement-based input

1.4 The Importance of AAC Standards

1.4.1 Current Challenges

[!] Problem: The AAC industry currently lacks unified standards, creating significant barriers:

  1. Device Incompatibility
    • Each manufacturer uses proprietary protocols
    • Sensors from one company don't work with software from another
    • Users locked into specific ecosystems
  2. High Costs
    • Proprietary systems command premium prices
    • Limited competition due to closed ecosystems
    • Many users cannot afford necessary devices
  3. Limited Choice
    • Users must choose entire systems rather than components
    • Cannot mix preferred hardware with preferred software
    • Innovation is stifled by fragmentation
  4. Transition Difficulties
    • Progressive conditions require changing input methods
    • Each change means learning new systems
    • Settings and preferences don't transfer

1.4.2 The ALS Patient Journey

Consider the typical progression for an ALS patient:

Disease Progression and AAC Needs:

Stage 1 (Early): Fingers functional
  - Input: Standard keyboard
  - Challenge: Typing speed decreases

Stage 2 (Mid-Early): Wrist control only
  - Input: Joystick, trackball
  - Challenge: New device, new software

Stage 3 (Mid): Head control only
  - Input: Head mouse, head tracker
  - Challenge: Another complete system change

Stage 4 (Mid-Late): Eye control only
  - Input: Eye tracking device
  - Challenge: New device, new calibration, new interface

Stage 5 (Late): Facial muscles only
  - Input: EMG sensor (cheek, eyebrow)
  - Challenge: Specialized equipment, new learning curve

Stage 6 (End-Stage): Brain signals only
  - Input: Brain-Computer Interface (BCI)
  - Challenge: Most complex system, significant adaptation

At EACH stage:
  - Purchase new equipment ($5,000 - $20,000+)
  - Learn new software interface
  - Reconfigure all settings
  - Lose previous customizations
  - Experience communication disruption during transition

[!] Critical Issue: Each transition occurs during a time when the patient is already struggling with disease progression. The additional burden of learning new technology can be devastating.

1.5 The WIA AAC Standard Solution

The WIA AAC Standard addresses these challenges through:

1.5.1 Unified Signal Format

All sensors output data in a standard format, regardless of type or manufacturer.

Before WIA AAC Standard:

  Eye Tracker A → Protocol A → Software A only
  Eye Tracker B → Protocol B → Software B only
  Switch C → Protocol C → Software C only
  EMG Sensor D → Protocol D → Software D only

After WIA AAC Standard:

  Eye Tracker A ─┐
  Eye Tracker B ─┤
  Switch C ──────┼──→ WIA AAC Standard Format → ANY Compatible Software
  EMG Sensor D ──┤
  BCI Device E ──┘

1.5.2 Standard API

Software developers can support all compliant devices through a single interface:

// Universal code works with ANY WIA AAC compliant sensor
const aac = new WiaAAC();
await aac.connect({ any_sensor_type });

aac.on('input', (data) => {
    // Same code handles:
    // - Eye tracker gaze data
    // - Switch press events
    // - EMG activations
    // - BCI signals
    // - Head movements
    // - Breath patterns
});

1.5.3 Seamless Transitions

When a user changes input methods:

  • [OK] Software remains the same
  • [OK] Settings and preferences preserved
  • [OK] Only sensor hardware changes
  • [OK] Minimal learning curve
  • [OK] Continuous communication ability
