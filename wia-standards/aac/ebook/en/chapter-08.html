8.2 Quick Start Guide

8.2.1 TypeScript/JavaScript

// Installation
npm install wia-aac

// Basic Usage
import { WiaAAC } from 'wia-aac';

async function main() {
    // Initialize
    const aac = new WiaAAC();

    // Discover devices
    const devices = await aac.discoverDevices();
    console.log('Found devices:', devices);

    // Connect to first eye tracker
    const eyeTracker = devices.find(d => d.type === 'eye_tracker');
    if (eyeTracker) {
        await aac.connect({
            type: 'eye_tracker',
            deviceId: eyeTracker.deviceId
        });
    }

    // Handle signals
    aac.on('signal', (signal) => {
        console.log('Signal:', signal.type, signal.data);
    });

    // Handle text output
    aac.on('text', (text) => {
        console.log('User typed:', text);
    });
}

main();

8.2.2 Python

# Installation
pip install wia-aac

# Basic Usage
import asyncio
from wia_aac import WiaAAC

async def main():
    # Initialize
    aac = WiaAAC()

    # Discover devices
    devices = await aac.discover_devices()
    print(f"Found {len(devices)} devices")

    # Connect
    await aac.connect(sensor_type="eye_tracker")

    # Handle signals
    @aac.on("signal")
    async def handle_signal(signal):
        print(f"Signal: {signal.type} - {signal.data}")

    @aac.on("text")
    async def handle_text(text):
        print(f"User typed: {text}")

    # Keep running
    await aac.run()

asyncio.run(main())

8.2.3 Rust

// Cargo.toml
[dependencies]
wia-aac = "1.0"
tokio = { version = "1.0", features = ["full"] }

// main.rs
use wia_aac::{WiaAAC, SensorType, Signal};

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    // Initialize
    let aac = WiaAAC::new_default()?;

    // Discover devices
    let devices = aac.discover_devices().await?;
    println!("Found {} devices", devices.len());

    // Connect
    aac.connect(SensorType::EyeTracker, None).await?;

    // Handle signals
    let mut rx = aac.subscribe();
    while let Some(signal) = rx.recv().await {
        println!("Signal: {:?}", signal);
    }

    Ok(())
}

8.3 Testing Your Implementation

8.3.1 Signal Validation

import { SignalValidator } from 'wia-aac';

const validator = new SignalValidator();

// Test signal
const testSignal = {
    type: 'eye_tracker',
    version: '1.0.0',
    timestamp: Date.now(),
    data: {
        gaze_x: 0.5,
        gaze_y: 0.5,
        fixation: true
    },
    confidence: 0.95
};

// Validate
const result = validator.validate(testSignal);

if (result.valid) {
    console.log('[OK] Signal is valid');
} else {
    console.log('[!] Validation errors:');
    result.errors.forEach(e =>
        console.log(`  - ${e.field}: ${e.message}`)
    );
}

8.3.2 Compliance Test Suite

WIA AAC Compliance Test Categories:

1. Signal Format Tests
   - Schema validation
   - Required fields present
   - Data types correct
   - Value ranges valid
   - Timestamp accuracy

2. Protocol Tests
   - Connection establishment
   - Command handling
   - Response format
   - Error responses
   - Disconnection handling

3. Performance Tests
   - Signal latency (<50ms)
   - Throughput (signals/second)
   - Memory usage
   - CPU usage
   - Battery impact (mobile)

4. Reliability Tests
   - Connection stability
   - Reconnection handling
   - Error recovery
   - Edge case handling

5. Interoperability Tests
   - Works with reference SDK

   - Cross-platform compatibility

Running Tests:
npx wia-aac-test --device [device-id] --full

  - Application review: 1 week

  - Total: 4-6 weeks

8.5 Best Practices

8.5.1 User Experience Guidelines

AAC User Experience Best Practices:

1. Responsiveness
   - Immediate visual feedback (<100ms)
   - Smooth animations
   - Progress indicators for long operations

2. Configurability
   - Dwell time adjustment
   - Sensitivity controls
   - Layout customization
   - Voice/output selection

3. Error Recovery
   - Graceful degradation
   - Clear error messages
   - Easy recalibration
   - Undo functionality

4. Accessibility
   - High contrast options
   - Large targets
   - Simple navigation
   - Reduced motion option

5. Personalization
   - Save user preferences
   - Custom vocabularies
   - Predictive text
   - Frequently used phrases

8.5.2 Technical Best Practices

Technical Implementation Best Practices:

1. Signal Processing
   - Validate all incoming signals
   - Handle missing/invalid data gracefully
   - Apply appropriate filtering
   - Log anomalies for debugging

2. Connection Handling
   - Implement robust reconnection
   - Handle multiple devices
   - Graceful disconnection
   - Battery status monitoring

3. Performance
   - Minimize main thread blocking
   - Use efficient data structures
   - Profile and optimize hotspots
   - Lazy load non-critical features

4. Security
   - Encrypt stored calibration data
   - Validate device certificates
   - Implement session management
   - Log security events

5. Testing
   - Automated test coverage >80%
   - Test with real devices
   - User acceptance testing
   - Performance regression testing

8.6 Troubleshooting Guide

8.6.1 Common Issues

Common Issues and Solutions:

Issue: Device not discovered
  - Check device is powered on
  - Verify Bluetooth/USB permissions
  - Check for driver installation
  - Try different USB port/cable
  - Reset device and retry

Issue: Connection fails
  - Check device not connected elsewhere
  - Verify device firmware version
  - Check transport compatibility
  - Review error logs
  - Try different transport method

Issue: High latency
  - Check CPU/memory usage
  - Reduce signal processing
  - Check network conditions (WiFi)
  - Use USB instead of Bluetooth
  - Profile application performance

Issue: Signal validation errors
  - Check signal format version
  - Verify required fields present
  - Check data type correctness
  - Review value ranges
  - Update SDK version

Issue: Calibration poor
  - Ensure proper lighting
  - Check device positioning
  - Recalibrate with more points
  - Clean sensor lens/surface
  - Check user positioning
