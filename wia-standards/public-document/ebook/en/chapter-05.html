Chapter 05: Digital Signatures and PKI Infrastructure

弘益人間 - "Cryptographic signatures transform documents into tamper-proof evidence of authenticity."

05.1 Public Key Infrastructure Overview

Public Key Infrastructure (PKI) provides the cryptographic foundation for digital signatures, enabling governments to issue documents that are mathematically provable as authentic and unaltered. WIA-SOC-013 mandates PKI for all public documents requiring legal validity.

Core PKI components include:

  • Certificate Authority (CA): Trusted entity that issues digital certificates
  • Registration Authority (RA): Verifies certificate requests before CA issuance
  • Certificate Revocation List (CRL): Published list of revoked certificates
  • Online Certificate Status Protocol (OCSP): Real-time certificate validation
  • Hardware Security Modules (HSM): Tamper-resistant key storage devices

Signature Creation Example

import { DigitalSigner } from 'wia-soc-013';

const signer = new DigitalSigner({
  algorithm: 'EdDSA-Ed25519',
  privateKey: governmentPrivateKey,
  certificateChain: [issuingCert, intermediateCert, rootCert]
});

const signature = await signer.sign({
  documentId: 'doc:wia:soc013:abc123',
  documentHash: sha256Hash,
  timestamp: true,
  includeChain: true
});

// Embed signature in PDF
await pdfDocument.embedSignature(signature);

05.3 Certificate Hierarchies and Trust Chains

Government PKI typically follows a hierarchical structure:

  • Root CA: National government authority (e.g., U.S. Federal PKI Root)
  • Intermediate CA: Departmental authorities (e.g., State Department, Social Security Administration)
  • Issuing CA: Local agencies (e.g., County Registrar, DMV Office)
  • End-Entity Certificates: Individual signing keys for document issuance

Certificate Validation

import { CertificateValidator } from 'wia-soc-013';

const validator = new CertificateValidator({
  trustedRoots: [usRootCA, euRootCA, globalTrustRoot],
  checkRevocation: true,
  ocspEnabled: true
});

const validation = await validator.validate({
  certificate: documentSignatureCert,
  timestamp: signatureTimestamp
});

if (validation.valid) {
  console.log('Certificate chain valid');
  console.log('Issuer:', validation.issuer);
  console.log('Valid from:', validation.notBefore);
  console.log('Valid until:', validation.notAfter);
} else {
  console.error('Validation failed:', validation.errors);
}

05.4 Timestamp Services

Trusted timestamps prove a document existed at a specific point in time, critical for legal validity and non-repudiation.

RFC 3161 Timestamp Authority

import { TimestampService } from 'wia-soc-013';

const tsa = new TimestampService({
  url: 'https://tsa.government.gov/rfc3161',
  algorithm: 'SHA-256'
});

const timestamp = await tsa.create({
  documentHash: sha256Hash
});

// Timestamp includes:
// - Hash of document
// - Timestamp authority signature
// - Certificate chain
// - Nonce for uniqueness
// - Policy OID

console.log('Timestamp:', timestamp.time); // 2025-01-15T10:30:00Z
console.log('TSA:', timestamp.authority); // Government Timestamp Authority

05.6 Long-Term Signature Validation (LTV)

Signatures must remain verifiable for decades, even after certificates expire. WIA-SOC-013 implements PAdES-LTV (PDF Advanced Electronic Signatures - Long Term Validation):

LTV Components

  • Embedded Certificate Chain: Complete chain from signing cert to root
  • OCSP Responses: Snapshot of certificate validity at signing time
  • CRL: Revocation lists current at signature creation
  • Timestamp: Trusted timestamp proving signature time
  • Document Timestamp (DTS): Additional timestamp after embedding validation info
import { LTVEnabler } from 'wia-soc-013';

const ltv = new LTVEnabler();

await ltv.enable({
  pdfDocument: signedPDF,
  embedCertificateChain: true,
  embedOCSPResponses: true,
  embedCRL: true,
  addDocumentTimestamp: true
});

// Now signature remains verifiable for decades
// even if certificate expires or CRL/OCSP servers go offline

05.7 Blockchain Anchoring

Complement traditional PKI with blockchain for immutable audit trails:

import { BlockchainAnchor } from 'wia-soc-013';

const anchor = new BlockchainAnchor({
  network: 'ethereum-mainnet',
  contractAddress: '0x...',
  signerKey: governmentEthereumKey

const txHash = await anchor.anchor({

05.8 Multi-Party Signatures

Some documents require multiple signatories (e.g., marriage certificates require both spouses):

import { MultiSigner } from 'wia-soc-013';

const multiSigner = new MultiSigner({
  requiredSignatures: 2,
  signingOrder: 'parallel' // or 'sequential'
});

// First signature
await multiSigner.addSignature({
  documentId: 'doc:wia:soc013:abc123',
  signerId: 'registrar-jane-smith',
  signature: signature1
});

// Second signature
await multiSigner.addSignature({
  documentId: 'doc:wia:soc013:abc123',
  signerId: 'county-clerk-john-doe',
  signature: signature2
});

const isComplete = await multiSigner.isComplete('doc:wia:soc013:abc123');
// true - all required signatures collected

05.9 Signature Verification Workflow

Comprehensive verification checks multiple aspects:

import { SignatureVerifier } from 'wia-soc-013';

const verifier = new SignatureVerifier({
  trustedRoots: governmentCAList,
  checkRevocation: true,
  validateTimestamp: true,
  verifyBlockchainAnchor: true
});

const result = await verifier.verify({
  documentId: 'doc:wia:soc013:abc123',
  document: pdfDocument
});

console.log('Verification Results:');
console.log('- Signature valid:', result.signatureValid); // true
console.log('- Certificate chain:', result.chainValid); // true
console.log('- Not revoked:', !result.revoked); // true
console.log('- Timestamp valid:', result.timestampValid); // true
console.log('- Blockchain anchor:', result.blockchainValid); // true
console.log('- Document integrity:', result.integrityValid); // true

if (result.allValid) {
  console.log('Document is authentic and unmodified');
}

05.10 Key Management and Rotation

Signing keys must be rotated periodically for security:

Key TypeRotation PeriodRationale
Root CA10-20 yearsMaximum stability for trust
Intermediate CA5-10 yearsBalance stability and security
Issuing CA2-5 yearsRegular security refresh
Document Signing1-2 yearsMinimize exposure window

Key Rotation Process

import { KeyRotation } from 'wia-soc-013';

const rotation = new KeyRotation({
  currentKey: 'gov-key-2024',
  newKey: 'gov-key-2025',
  overlapPeriod: '30 days' // Both keys valid during transition
});

await rotation.initiate({
  notifyUsers: true,
  updateDNS: true,
  publishNewCertificate: true
});

// During overlap period, verify both keys
// After overlap, revoke old key
await rotation.complete({
  revokeOldKey: true,
  reason: 'keyRotation'
});

Conclusion

Digital signatures and PKI infrastructure provide the cryptographic foundation for trustworthy public documents. By implementing EdDSA signatures, maintaining robust certificate hierarchies, embedding long-term validation information, and anchoring to blockchain, governments can issue documents with mathematical proof of authenticity that remains verifiable for decades.
