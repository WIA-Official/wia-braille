제1장

프라이버시 보호 입문

프라이버시 위기

상호 연결된 디지털 세계에서 개인 데이터는 귀중한 자산인 동시에 잠재적인 위험이 되었습니다. 매일 수십억 명의 사람들이 의식적으로든 무의식적으로든 조직과 정보를 공유하고, 이러한 조직은 데이터를 수집, 처리, 분석합니다. 이러한 데이터 기반 접근 방식이 혁신, 개인화, 과학적 발견을 촉진하지만, 동시에 전례 없는 프라이버시 위험도 만들어냅니다.

弘益人間 (홍익인간) - 널리 인간을 이롭게 하라
이 고대 한국 철학은 "인류 전체에게 이익이 되도록 한다"는 의미로, 우리의 프라이버시 보호 접근 방식을 안내합니다. 진정한 혁신은 개인의 존엄성과 권리를 보호하면서 데이터의 유익한 사용을 가능하게 함으로써 인류의 최선의 이익에 기여해야 합니다.

프라이버시 보호란 무엇인가?

프라이버시 보호는 개인 데이터를 수집, 처리, 저장, 공유할 때 정당한 목적을 위한 데이터 유용성을 유지하면서 개인의 프라이버시를 보호하는 관행입니다. 이는 모든 데이터를 숨기거나 모든 분석을 방지하는 것이 아니라, 프라이버시와 유용성 사이의 최적의 균형을 찾는 것입니다.

프라이버시-유용성 트레이드오프

모든 프라이버시 보호 기술은 프라이버시 보호와 데이터 유용성 사이의 트레이드오프를 수반합니다. 완벽한 프라이버시(아무것도 공개하지 않음)는 유용성을 제공하지 않습니다. 완벽한 유용성(모든 것을 공개)은 프라이버시를 제공하지 않습니다. 우리의 목표는 각 사용 사례에 대해 허용 가능한 범위 내에서 둘 다 최대화하는 것입니다.

프라이버시 ←――――――――― 최적 균형 ―――――――→ 유용성

프라이버시 강화 기술 (PETs)

프라이버시 강화 기술은 다음을 통해 프라이버시를 보호하는 기술적 및 조직적 방법입니다:

  • 최소화: 필요한 것만 개인 데이터 수집
  • 익명화: 개인 식별을 방지하기 위한 데이터 익명화
  • 암호화: 무단 액세스를 방지하기 위한 데이터 암호화
  • 제어: 권한 및 정책을 통한 개인 정보 액세스 제어

WIA-SEC-023이 중요한 이유

WIA-SEC-023 프라이버시 보호 표준은 실제 애플리케이션에서 프라이버시를 보호하기 위한 포괄적이고 구현 가능한 프레임워크를 제공합니다. 이론적 접근 방식과 달리, 이 표준은 다음에 대한 명확한 지침과 함께 오늘 배포할 수 있는 실용적인 기술에 중점을 둡니다:

  • 사용 사례에 적합한 프라이버시 기술 선택
  • 수학적 엄밀성을 가진 프라이버시 보장 구현
  • 프라이버시 수준 측정 및 보고
  • 글로벌 프라이버시 규정(GDPR, CCPA, HIPAA) 준수
  • 비즈니스 요구와 프라이버시 보호의 균형
실제 사례: 의료 분석

병원이 치료 결과를 개선하기 위해 환자 데이터를 분석하려고 합니다. 전통적인 접근 방식은 민감한 환자 정보를 노출하거나 귀중한 분석을 방지합니다. WIA-SEC-023을 사용하면:

  1. k-익명성을 적용하여 환자 인구통계를 일반화
  2. 차등 프라이버시를 사용하여 집계 통계에 노이즈 추가
  3. 안전한 계산을 위해 동형 암호화 사용
  4. 프라이버시 준수에 대한 검증 가능한 증명 생성

결과: 수학적 확실성으로 환자 프라이버시를 보장하면서 의료 개선을 위한 귀중한 통찰력을 얻습니다.

제2장

차등 프라이버시 이해하기

차등 프라이버시가 특별한 이유

차등 프라이버시(DP)는 최선의 노력 약속이 아닌 수학적 보장을 제공하기 때문에 프라이버시 보호의 골드 스탠다드입니다. 이 보장은 공격자가 임의의 외부 정보에 액세스할 수 있는 경우에도 유지됩니다.

Pr[M(D₁) ∈ S] ≤ exp(ε) × Pr[M(D₂) ∈ S] + δ

이 공식은 귀하의 데이터가 포함되어 있는지 여부에 관계없이 계산 출력이 거의 변경되지 않음을 나타냅니다. 매개변수 ε(엡실론)은 정확도를 위해 기꺼이 거래할 프라이버시의 양을 제어합니다.

차등 프라이버시의 직관

회사가 급여 조사를 실시한다고 상상해 보세요. 프라이버시 보호 없이는 귀하의 정확한 급여가 공개될 수 있습니다. 차등 프라이버시를 사용하면:

  • 회사는 결과에 신중하게 보정된 무작위 노이즈를 추가합니다
  • 집계 통계(평균 급여)는 여전히 유용합니다
  • 귀하의 개별 급여는 확실하게 결정할 수 없습니다
  • 다른 사람의 급여를 모두 알고 있더라도 귀하의 급여는 비공개로 유지됩니다

프라이버시 예산 (엡실론)

엡실론(ε)을 쿼리에 응답할 때 소비하는 프라이버시 예산으로 생각하십시오. 각 쿼리는 일부 예산을 소비하며, 소진되면 프라이버시를 손상시키지 않고는 더 이상 쿼리에 응답할 수 없습니다.

엡실론 값 선택:
• ε ≤ 0.1: 매우 높은 프라이버시 (의료 기록)
• 0.1 < ε ≤ 1.0: 높은 프라이버시 (금융 데이터)
• 1.0 < ε ≤ 5.0: 중간 프라이버시 (일반 분석)
• ε > 5.0: 낮은 프라이버시 (공공 통계)

라플라스 메커니즘

차등 프라이버시를 달성하는 가장 일반적인 방법은 쿼리 결과에 라플라스 노이즈를 추가하는 것입니다:

function addLaplaceNoise(trueValue, sensitivity, epsilon) { const scale = sensitivity / epsilon; const u = Math.random() - 0.5; const noise = -scale * Math.sign(u) * Math.log(1 - 2 * Math.abs(u)); return trueValue + noise; } // 예: DP를 사용한 평균 연령 const trueAverage = 35.2; const privateAverage = addLaplaceNoise(trueAverage, 1.0, 1.0); // 약 35.2 ± 일부 노이즈 반환

구성: 프라이버시 예산 관리

여러 쿼리를 수행하면 프라이버시 보장이 구성됩니다. ε₁, ε₂, ..., εₖ의 순차 쿼리에 대한 총 프라이버시 손실은 다음과 같습니다:

총 ε = ε₁ + ε₂ + ... + εₖ

이것은 모든 쿼리에 걸쳐 프라이버시 예산을 신중하게 관리해야 함을 의미합니다. 예산이 소진되면 추가 프라이버시 손실 없이 더 많은 쿼리에 응답할 수 없습니다.

실제 사례: 미국 인구 조사

2020년 미국 인구조사는 응답자를 보호하기 위해 차등 프라이버시를 사용한 최초의 조사였습니다. 총 프라이버시 예산 ε = 19.61로:

  • 다양한 지리적 수준에 걸쳐 예산 할당
  • 소규모 인구에 더 많은 노이즈 적용
  • 주 수준 총계가 정확하게 유지되도록 보장
  • 수학적 보장으로 개인 프라이버시 보호
제3장

k-익명성과 그 너머

k-익명성의 개념

k-익명성은 데이터 세트의 각 사람이 최소한 k-1명의 다른 사람과 구별할 수 없도록 보장합니다. 이는 공격자가 1/k보다 큰 확률로 귀하를 식별할 수 없음을 의미합니다.

k-익명성의 작동 방식

k-익명성의 한계

k-익명성은 식별을 방지하지만 중요한 제한 사항이 있습니다:

1. 동질성 공격

그룹의 모든 사람이 동일한 민감한 값을 가지고 있으면 식별 없이도 해당 값이 공개됩니다.

2. 배경 지식 공격

외부 지식을 가진 공격자는 때때로 여전히 개인을 식별하거나 민감한 정보를 알아낼 수 있습니다.

l-다양성: 동질성 문제 해결

l-다양성은 각 그룹이 민감한 속성에 대해 최소한 l개의 고유한 값을 가지도록 요구합니다. 이는 동질성 공격을 방지합니다.

t-근접성: 분포 일치

t-근접성은 각 그룹의 민감한 값 분포가 전체 분포에 가까워야 한다는 요구 사항을 추가합니다.

// 몬드리안 k-익명성 알고리즘 (단순화) function anonymize(data, k, quasiIdentifiers) { // 데이터를 재귀적으로 분할 function partition(records) { if (records.length < 2 * k) { return [generalize(records)]; } // 분할할 최적의 차원 찾기 const dim = findBestSplit(records, quasiIdentifiers); // 분할 및 재귀 const [left, right] = split(records, dim); return [...partition(left), ...partition(right)]; } return partition(data); }
k 값 선택:
• k ≥ 10: 민감한 데이터에 대한 높은 프라이버시
• 5 ≤ k < 10: 일반 용도에 대한 중간 프라이버시
• 3 ≤ k < 5: 낮은 프라이버시, 최소 허용
• k < 3: 불충분한 프라이버시 보호
제4장

동형 암호화

암호화된 데이터에서 계산

동형 암호화는 암호화된 데이터를 해독하지 않고 계산을 수행할 수 있습니다. 이 혁명적인 기능은 완전한 데이터 기밀성을 유지하면서 클라우드 컴퓨팅을 가능하게 합니다.

E(x) ⊕ E(y) = E(x + y)

이 속성은 암호화된 숫자를 추가하고 암호화된 합계를 얻을 수 있음을 의미합니다—원래 숫자를 보지 않고도!

동형 암호화의 유형

  • 부분 동형: 덧셈 또는 곱셈 중 하나만 지원
  • 일부 동형: 제한된 수의 연산
  • 완전 동형: 무제한 임의 계산
의료 사례

환자가 클라우드 분석에 보내기 전에 의료 데이터를 암호화합니다:

  1. 환자: Encrypt(심박수 = 75) → encrypted_data
  2. 클라우드: encrypted_data 처리 → encrypted_analysis
  3. 환자: Decrypt(encrypted_analysis) → "정상 범위"

클라우드는 실제 심박수 값을 절대 보지 못합니다!

제5장

안전한 다자간 계산

신뢰 없는 공동 계산

안전한 다자간 계산(SMPC)은 여러 당사자가 개인 입력을 서로에게 공개하지 않고 입력에 대한 함수를 공동으로 계산할 수 있게 합니다.

백만장자 문제

두 백만장자가 실제 재산을 공개하지 않고 누가 더 부유한지 알고 싶어합니다:

  • Alice: $1,500,000 (비밀)
  • Bob: $2,000,000 (비밀)
  • 결과: "Bob이 더 부유함" (공개됨)
  • 프라이버시: 누구도 상대방의 정확한 재산을 알지 못함

비밀 공유

많은 SMPC 프로토콜의 기반은 비밀을 개별적으로는 아무것도 드러내지 않는 조각으로 나누는 비밀 공유입니다.

제6장

영지식 증명

공개하지 않고 증명하기

영지식 증명(ZKP)을 사용하면 무엇을 알고 있는지 공개하지 않고도 무언가를 알고 있음을 증명할 수 있습니다. 이 불가능해 보이는 위업은 영리한 암호화 프로토콜을 통해 가능해집니다.

나이 확인

정확한 나이를 공개하지 않고 18세 이상임을 증명:

  • 전통적: 생년월일이 포함된 신분증 제시 (너무 많이 공개)
  • 영지식: 나이 > 18의 암호화 증명 생성
  • 검증자 확인: "예, 18세 이상" (다른 것은 알지 못함)

zk-SNARK

영지식 간결한 비대화형 지식 논증은 빠르게 검증할 수 있는 작은 증명을 제공하여 블록체인 프라이버시와 익명 자격 증명을 가능하게 합니다.

구현 가이드

2. 프라이버시 기술 선택

의사결정 매트릭스:
• 집계 통계 필요? → 차등 프라이버시

• 클라우드 계산? → 동형 암호화
• 다자간 분석? → 안전한 MPC
• 자격 증명 검증? → 영지식 증명
