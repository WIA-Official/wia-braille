Chapter 5: Phase 2 - API Interface

In this chapter: We explore the RESTful API specifications for unified ID operations, including authentication, authorization, endpoint design, rate limiting, and SDK development for common programming languages.

5.1 API Architecture

The WIA-UNI-002 API follows REST principles with JSON payloads, OpenID Connect authentication, and comprehensive error handling. All endpoints use HTTPS with TLS 1.3+ for transport security.

Base URL

https://api.unified-id.kr/v1/

Core Endpoints

Endpoint Method Description Auth Required
/credentials POST Issue new credential Government Authority
/credentials/{id} GET Retrieve credential Citizen or Verifier
/verify POST Verify credential or proof Service Provider
/revoke POST Revoke credential Authority or Citizen
/proofs/zk POST Generate zero-knowledge proof Citizen

5.2 Authentication

The API uses OAuth 2.0 with OpenID Connect for authentication, supporting multiple client types:

Authorization Flow

  1. Client Registration: Service providers register with the Unified ID Authority
  2. Token Request: Client exchanges credentials for access token
  3. API Access: Include access token in Authorization header
  4. Token Refresh: Use refresh token to obtain new access token

Example Token Request

POST /oauth/token HTTP/1.1
Host: auth.unified-id.kr
Content-Type: application/x-www-form-urlencoded

grant_type=client_credentials&
client_id=sp_abc123&
client_secret=secret_xyz789&
scope=verify:credentials

5.4 Verification API

Service providers use this endpoint to verify credentials and zero-knowledge proofs:

Basic Verification

POST /v1/verify HTTP/1.1
Host: api.unified-id.kr
Authorization: Bearer eyJhbGciOiJSUzI1NiIs...
Content-Type: application/json

{
  "credential": {
    "@context": ["https://www.w3.org/2018/credentials/v1"],
    "type": ["VerifiableCredential", "UnifiedIDCredential"],
    ...
  }
}

Response:
{
  "verified": true,
  "checks": {
    "signature": "valid",
    "expiration": "valid",
    "revocation": "not_revoked",
    "issuer": "trusted"
  },
  "timestamp": "2025-01-15T14:30:00Z"
}

5.5 Zero-Knowledge Proof API

Citizens can generate privacy-preserving proofs for specific claims:

Age Verification Example

POST /v1/proofs/zk HTTP/1.1
Host: api.unified-id.kr
Authorization: Bearer eyJhbGciOiJSUzI1NiIs...
Content-Type: application/json

{
  "unifiedId": "UNI-KR-900515-1234",
  "proofType": "age-over-18",
  "parameters": {
    "currentDate": "2025-01-15"
  }
}

Response:
{
  "proof": {
    "type": "zk-SNARK",
    "proof": "0x...",
    "publicInputs": {
      "currentDate": "2025-01-15",
      "ageThreshold": 18
    }
  },
  "message": "Proof generated successfully"
}

5.6 Rate Limiting and Quotas

To prevent abuse and ensure fair access, the API implements rate limiting:

Client Type Requests/Hour Burst Limit
Government Authority 100,000 1,000
Certified Service Provider 10,000 100
Standard Service Provider 1,000 50
Individual Citizen 100 10

5.7 Error Handling

The API uses standard HTTP status codes with detailed error messages:

Status Code Error Type Example
400 Bad Request Invalid JSON or missing required fields
401 Unauthorized Missing or invalid access token
403 Forbidden Insufficient permissions for operation
404 Not Found Credential does not exist
429 Rate Limit Exceeded Too many requests
500 Internal Server Error System malfunction

5.8 SDK Development

Official SDKs are provided for popular programming languages:

JavaScript/TypeScript

import { UnifiedIdClient } from '@wia/unified-id-sdk';

const client = new UnifiedIdClient({
  apiKey: 'your-api-key',
  environment: 'production'
});

const result = await client.verify({
  credential: verifiableCredential
});

console.log(result.verified); // true

Python

from wia_unified_id import UnifiedIdClient

client = UnifiedIdClient(api_key='your-api-key')

result = client.verify(credential=verifiable_credential)

print(result.verified)  # True
