제4장: 데이터 집계

"수백 개의 센서에서 나오는 데이터를 통합하여 의미 있는 통찰로 변환하는 것, 이것이 데이터 집계의 핵심입니다."

4.1 데이터 집계 아키텍처

IoMT 데이터 집계는 다층 구조로 이루어집니다:


┌─────────────────────────────────────────┐
│       응용 계층 (Application)            │
│   EMR, Analytics, ML, Dashboards         │
└───────────────┬─────────────────────────┘
                │
┌───────────────▼─────────────────────────┐
│       집계 계층 (Aggregation)            │
│   Data Fusion, Normalization, Storage    │
└───────────────┬─────────────────────────┘
                │
┌───────────────▼─────────────────────────┐
│       전처리 계층 (Preprocessing)        │
│   Filtering, Validation, Transformation  │
└───────────────┬─────────────────────────┘
                │
┌───────────────▼─────────────────────────┐
│       수집 계층 (Collection)             │
│   Gateway, Edge Devices, IoT Hub         │
└───────────────┬─────────────────────────┘
                │
┌───────────────▼─────────────────────────┐
│       센서 계층 (Sensors)                │
│   Wearables, Devices, Implants           │
└─────────────────────────────────────────┘

📥 데이터 수집 패턴

패턴 설명 사용 사례
Push 기기가 능동적으로 전송 긴급 알림, 이벤트 기반
Pull 서버가 주기적으로 요청 정기 모니터링
Streaming 연속 데이터 스트림 실시간 ECG, EEG
Batch 데이터 축적 후 일괄 전송 활동량, 수면 데이터

4.2 데이터 정규화

다양한 소스의 데이터를 통일된 형식으로 변환:

🔄 단위 변환

// 온도 정규화 예제
{
  "temperature": {
    "raw": {
      "value": 98.6,
      "unit": "°F",

    },

      "precision": 0.1

📊 시간 동기화

정확한 시간 스탬프가 필수적입니다:

  • UTC 표준 — 모든 타임스탬프는 UTC로 저장
  • NTP 동기화 — 네트워크 시간 프로토콜 사용
  • 타임존 처리 — 표시 시 로컬 시간 변환
  • 정밀도 — 밀리초 단위 정확도

4.3 데이터 융합

여러 센서의 데이터를 결합하여 더 정확한 통찰 도출:

🔀 센서 융합 기법

기법 방법 예시
칼만 필터 확률적 추정 GPS + 가속도계 위치
베이지안 융합 조건부 확률 다중 센서 낙상 감지
가중 평균 신뢰도 기반 평균 다중 온도 센서
딥러닝 융합 신경망 기반 ECG + PPG 융합

4.4 데이터 검증

수집된 데이터의 품질과 신뢰성 확인:

✅ 검증 단계

  1. 범위 검증 (Range Validation)
    • 생리학적으로 가능한 범위 확인
    • 예: 심박수 30-220 bpm
    • 예: 체온 35-42°C
  2. 일관성 검증 (Consistency Check)
    • 시간적 일관성 (급격한 변화 탐지)
    • 센서 간 일관성
  3. 무결성 검증 (Integrity Check)
    • 체크섬 검증
    • 데이터 손실 탐지
    • 중복 제거
  4. 맥락 검증 (Contextual Validation)
    • 환자 프로파일과 비교
    • 활동 상태 고려
    • 약물 영향 고려

⚠️ 이상치 처리

{
  "validation": {
    "dataPoint": {
      "value": 250,
      "type": "heart_rate",
      "timestamp": "2025-12-26T10:00:00Z"
    },
    "checks": [
      {
        "type": "range_check",
        "status": "warning",
        "message": "Value exceeds typical range (220 bpm max)"
      },
      {
        "type": "consistency_check",
        "status": "fail",
        "message": "Sudden increase from 72 to 250 bpm"
      }
    ],
    "action": "flagged_for_review",
    "confidence": 0.30,
    "recommendation": "Request manual verification"
  }
}

4.5 데이터 저장 전략

의료 데이터는 장기 보관과 빠른 접근이 모두 필요합니다:

💾 스토리지 계층화

계층 기술 용도 보관 기간
Hot Storage SSD, 메모리 DB 실시간 접근 24-48시간
Warm Storage HDD, RDS 자주 조회 1-12개월
Cold Storage S3 Glacier 장기 보관 1-7년
Archive Tape, Deep Archive 규제 준수 7-50년

🗄️ 데이터베이스 선택

  • 시계열 DB — InfluxDB, TimescaleDB (연속 모니터링)
  • 문서 DB — MongoDB (복합 의료 기록)
  • 관계형 DB — PostgreSQL (환자 정보, 메타데이터)
  • 그래프 DB — Neo4j (의료 지식 그래프)

4.6 데이터 집계 성능

대규모 IoMT 시스템의 성능 요구사항:

⚡ 처리량

규모 기기 수 초당 이벤트 일일 데이터
소규모 클리닉 100-1,000 100-1,000 10-100 GB
중형 병원 1,000-10,000 1,000-10,000 100 GB - 1 TB
대형 의료 시스템 10,000-100,000 10,000-100,000 1-10 TB
국가 규모 100,000-1,000,000+ 100,000-1,000,000+ 10-100 TB

🚀 최적화 전략

  • 로드 밸런싱 — 트래픽 분산
  • 캐싱 — 자주 조회되는 데이터
  • 인덱싱 — 빠른 쿼리 응답
  • 파티셔닝 — 데이터 분할
  • 압축 — 저장 공간 절약
