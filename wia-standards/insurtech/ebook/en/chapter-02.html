Chapter 2: Architecture & Data Models

2.1 System Architecture Overview

The WIA-FIN-019 standard defines a four-layer architecture for modern insurtech platforms:

Layer 1: Data Layer

Core data models for policies, claims, customers, and risk profiles. Supports both relational (PostgreSQL) and document (MongoDB) databases with blockchain integration for immutable records.

Layer 2: Service Layer

Microservices architecture with RESTful APIs for quote generation, underwriting, claims processing, and customer management. Each service is independently deployable and scalable.

Layer 3: Integration Layer

Connectors for legacy systems, IoT devices, third-party data providers, and regulatory systems. Message queues (Kafka, RabbitMQ) ensure reliable communication.

Layer 4: Presentation Layer

Mobile apps, web portals, chatbots, and voice interfaces provide multi-channel customer access with consistent experiences.

2.3 API Architecture

RESTful API Endpoints

POST   /api/v1/quotes              - Generate insurance quote
POST   /api/v1/policies            - Create new policy
GET    /api/v1/policies/{id}       - Get policy details
PUT    /api/v1/policies/{id}       - Update policy
POST   /api/v1/claims              - File new claim
GET    /api/v1/claims/{id}         - Get claim status
POST   /api/v1/underwriting        - Request underwriting decision
GET    /api/v1/customers/{id}/risk - Get customer risk profile

GraphQL Schema

type Query {
  policy(id: ID!): Policy
  customer(id: ID!): Customer
  claims(policyId: ID!): [Claim]
}

type Mutation {
  generateQuote(input: QuoteInput!): Quote
  createPolicy(input: PolicyInput!): Policy
  fileClaim(input: ClaimInput!): Claim
}
